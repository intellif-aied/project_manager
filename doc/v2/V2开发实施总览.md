# Aida V2 开发实施总览

## 1. 文档状态

- 状态：开发中；阶段 1、阶段 2A、阶段 2B 与阶段 3 受控影子链路已落地，所有生产切换门禁仍保持关闭
- 产品基线：`doc/v2/V2产品需求总稿.md`
- 技术基线：`doc/v2/V2核心数据契约.md`
- 用途：约束三个专题的依赖、任务边界、实施顺序和发布门槛
- 非用途：不定义共享字段、Token 公式或完整接口结构

## 2. 三个开发专题

### 2.1 Session 增量上传与内容管理

对应文档：`Session增量上传与内容管理开发方案.md`

负责：

- CLI 专用认证、升级和换电脑；
- Session 列表、分页、最近活动排序和 summary 展示；
- source prepare、原始 Chunk 增量上传、游标、hash 和幂等；
- 独立 worker/outbox、内容事件投影和内容索引水位；
- Session 内容状态、清除、恢复和管理员彻底删除；
- 将已接收原始 Chunk 交给内容投影和 Usage 解析两类任务。

不负责 Token 权威解析、成本计算和报告来源选择。

### 2.2 个人报告来源选择

对应文档：`个人报告来源选择开发方案.md`

负责：

- 个人日报、个人周报的 Session/活动范围选择；
- 生成开始时固化来源快照；
- 前端选择面板、managed Agent 参数和 Report MCP 读取契约；
- 内容清除或彻底删除后的来源行为。

不负责 Session 上传、Token 日切片和小组/部门报告数据路径。

### 2.3 Token 统计与成本管理

对应文档：`Token统计与成本管理开发方案.md`

负责：

- 服务端 Provider Parser 和 Usage parser checkpoint；
- 不可变 Usage Observation、Logical Usage Event 折叠和 Token 归一化；
- Metering Envelope、重建高水位和并发激活门禁；
- Metrics Revision、质量状态和逐层对账；
- 按日期、模型、人员、小组、部门的统计；
- 历史组织归属、价格版本、汇率和成本快照；
- 我的 Token、管理分析和价格管理页面。

不负责原始 Chunk 上传协议和报告来源选择。

## 3. 依赖和并行关系

```text
阶段 0：冻结核心契约 + Golden Fixtures + Parser/Reducer 原型
阶段 1：Session 原始入口 + worker + Content Projection（仅内部）
阶段 2A：个人报告来源选择与 MCP  ┐
阶段 2B：Token Usage 影子解析     ├─ 可在阶段 1 稳定后并行
阶段 3：组织历史、成本和页面      ┘
阶段 4：回填、最终 catch-up、联合生产切换
阶段 5：稳定期验证与旧路径清理
```

报告来源选择不依赖 Token 成本；Token 统计也不读取报告来源选择记录。报告来源依赖 Session Content Projection，Token 依赖 Usage Observation/Event 链路，二者共同消费不可变 Chunk。新版 CLI、Token 查询和 Report MCP 在迁移期不能独立生产切换。

## 4. 实施阶段

### 阶段 0：核心契约和 Golden Fixtures

1. 确认身份、状态机、时间、Token 归一化、部门归属和删除语义。
2. 从真实 Claude Code、Codex 日志提取脱敏 Golden Fixtures。
3. 固定重复 usage、跨 Chunk 累计值、reasoning token、缓存 token、跨日和子 Agent 预期值。
4. 核心契约状态变更为“可开发”后才能开始数据库迁移。

### 阶段 1：Session 原始数据入口

1. 建立 source、generation、Chunk 和内容 tombstone。
2. 实现 prepare、Chunk 上传、连续游标和重试幂等。
3. 建立独立 worker、lease/retry/dead-letter、Content Projection 和四级处理水位。
4. CLI 分页、增量上传、summary 诊断和跨设备续传先由测试账号完成 E2E，再作为认证用户统一当前路径发布，不建立用户级功能开关。
5. 将原始 Chunk 持久化后分别触发内容投影和 Usage 解析，不采用客户端 Token 作为权威值。
6. 验证旧整包接口不能覆盖已进入 Chunk 模式的测试 Session。

### 阶段 2A：个人报告来源选择

1. 建立来源选择和不可变运行快照。
2. 前端改用 Session/连续活动范围选择。
3. managed Agent、Report MCP 和默认 Skill 使用同一参数契约。
4. 验证生成开始后继续上传不会改变本次输入。

当前进度：以上实现已完成，并通过全新数据库 migration、分页、越权、后续追加不漂移、clear-content 锁竞态和 `content_epoch` 恢复失效测试。认证用户统一走来源快照路径，前端不再按用户回退旧 slice。尚未执行六类真实 Agent 回归、Ad-hoc 固定查询快照和部署验收。

### 阶段 2B：Token Usage 解析

1. 建立 Usage Observation、Logical Usage Event、parser checkpoint、Metrics Revision 和模型级贡献。
2. 实现 Claude 单调快照折叠、非单调冲突和 Codex 累计值差分。
3. 实现五类互斥 Token 归一化和精确对账。
4. 先完成影子对账，再统一切换当前 Token 页面，不长期保留按用户双轨。
5. 按 Session 核对新结果、旧结果和 Golden Fixtures。

### 阶段 3：Token 成本和分析页面

1. 建立用户小组、小组部门和直属部门成员有效期，以及价格手册、模型别名、价格版本和汇率版本。
2. 由 active Metrics Revision 生成每日统计和不可变成本快照。
3. 实现个人、小组、部门分析和 Session 查询。
4. 展示 incomplete、estimated、conflict、unpriced 等真实状态。

当前进度：阶段 3 实现已完成，包括 migration 022、组织有效期与活动时点快照、价格/汇率版本、decimal 成本、重算审计、物化查询快照、权限 API 和前端页面。空库迁移及组织/成本/快照集成测试通过；Token 页面统一使用新分析 API，旧 `/tokens` 仅保留接口兼容。未完成旧数据回填、全量 Token 对账、浏览器交互验收和部署切换。

### 阶段 4：回填与联合切换

1. 将旧原始对象回填为 Source/Generation/Chunk，生成 Content Projection 和 Metrics Revision。
2. 按 Session、日期、模型、用户完成 Token 影子对账，并完成 MCP 默认/显式模式和六类报告 E2E。
3. 切换窗口停止旧写入或加等价写入锁，完成最终增量 catch-up，确认内容和 Usage 水位追平 Source 高水位。
4. 在同一发布窗口统一切换 Token 查询、Report MCP、默认 Skill/参数模板和 Chunk CLI 最低版本门禁，不按用户保留两套产品行为。
5. 测试账号先完成真实上传、个人报告和 Token/MCP 对账；通过后统一发布，不允许只切换 CLI、Token 或 MCP 之一。
6. 新 Chunk 被 ack 后进入 forward-only 数据入口。发生故障时暂停新写入或明确显示 pending，依靠已保存原始 Chunk修复并重放；禁止回退到不包含新 Chunk 的 legacy 查询并显示成完整数据。

### 阶段 5：稳定期和清理

1. 稳定期验证无双计、漏计、MCP 截断、越权和不可解释差异。
2. 清理旧整包上传、整体替换 activity slice 和客户端权威 Token 路径。
3. 清理 `selected_session_slice_keys`，统一使用来源快照契约。
4. 保留 revision、计量和成本审计，不保留两套线上统计口径。

## 5. 硬性停线条件

出现以下任一情况立即停止当前阶段，不得通过降低断言或隐藏状态继续发布：

1. Golden Fixture 出现任何无法解释的整数差异、负 Token、跨 Source 双计或 active Component 重复。
2. Source 高水位与内容/Usage 水位不一致，但 API/MCP 仍把结果标记 complete。
3. MCP selection 无法校验用户/run/type/period，或分页存在静默截断、重复、跳项。
4. Metering Envelope 未覆盖全部 cursor 就允许物理删除原始内容。
5. 新 CLI 数据只能被 Session、Token、MCP 三者中的部分链路读取。
6. 迁移或切换没有可执行的暂停写入、worker 停止和 forward-fix/replay 操作手册。
7. 部门权限仍混用 `departments.director_user_id`、`teams.director_user_id` 或把总监用户 ID 当作部门 ID。
8. 对象尚不可恢复或 Chunk 数据库事务未提交就向 CLI 返回 ack。
9. clear-content 后旧 epoch worker 仍能写回可读内容，或恢复 generation 与旧 Metrics Revision 同时进入统计。

## 6. Codex 任务输入规则

每次开发任务只能指定一个专题，并向 Codex 提供：

1. `V2产品需求总稿.md` 中对应章节；
2. `V2核心数据契约.md`；
3. 对应专题开发方案；
4. 本次明确允许修改的代码目录；
5. 对应验收编号。

不得只把本总览交给 Codex 开发，也不得同时引用 `archive/` 或旧合并方案。

## 7. 跨专题发布门槛

- `CROSS-001`：同一 Claude usage 事件重复出现不重复计数。
- `CROSS-002`：Codex 累计值跨 Chunk、CLI 升级和换电脑后结果不变。
- `CROSS-003`：普通重试结果不变，新增活动只增加对应日期。
- `CROSS-004`：Parser 修正允许原子替换并降低错误统计，旧 revision 不进入查询。
- `CROSS-005`：内容清除后 Token/成本保留，报告来源不可再读取内容。
- `CROSS-006`：显式恢复不增加第二份 Token。
- `CROSS-007`：管理员彻底删除后内容、Token 和成本按影响预览移除。
- `CROSS-008`：个人来源快照不因后续上传改变。
- `CROSS-009`：人员调组、停用不改写已经确认的历史归属和历史总量。
- `CROSS-010`：六类报告回归通过，小组/部门报告不遍历全部成员 Session。
- `CROSS-011`：Claude 同一 message 的单调 Usage 快照只计算最终值，非单调分叉阻止 revision 激活。
- `CROSS-012`：revision 重建期间并发上传后，激活水位追平 Source 且不重不漏。
- `CROSS-013`：内容清除后可从 Metering Envelope 重建相同 Token，MCP 无法读取已清除正文。
- `CROSS-014`：候选、selection 和 MCP 只读取已完成 Content Projection 的范围。
- `CROSS-015`：MCP selection 校验用户/run/type/period，多页结果无静默截断且全部被默认 Skill 消费。
- `CROSS-016`：新版 CLI 上传的 Session 在生产切换后同时可见于 Session、Token 和个人报告来源，不存在单链路可见。
- `CROSS-017`：父/子 Agent、不同 Source 和 generation/revision 切换中的同一 Provider 事实最多贡献一次。
- `CROSS-018`：Logical Event 的后续 Usage 快照不会把已确认 Token 移到新的日期、团队或模型。
- `CROSS-019`：Token 卡片、趋势、排名、Session 明细和分页复用同一查询快照，追加/修正期间仍逐项对账。
- `CROSS-020`：raw generation、Content Projection 和 Metrics Revision 独立换指针，任一派生失败都不造成报告/Token 空窗或新旧双计。
- `CROSS-021`：全部 MCP 读取工具校验 run context、显式分页/完整性，组织 inventory 与实际读取报告集合一致。
- `CROSS-022`：超过 JavaScript 安全整数的 Token 与 decimal 成本在数据库、API、前端和导出中无精度损失。
- `CROSS-023`：用户调组、小组调部门和总监变更后，历史组织快照、当前权限、部门排名和部门报告范围分别保持正确。
- `CROSS-024`：对象存储成功但数据库回滚不 ack；数据库提交后响应丢失可安全重试，cursor 和任务不重复。
- `CROSS-025`：clear-content 与上传、解析、selection、MCP 并发时，旧 epoch 任务不能恢复已清除内容。
- `CROSS-026`：显式恢复完成后 Content Projection 与 Metrics Revision 独立激活，同一原始事实不重复生成 Token 或成本。
