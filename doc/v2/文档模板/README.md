# 产品到交付文档模板

本目录用于约束产品需求、架构、开发和测试文档的职责边界，避免未经验证的设计判断被直接拆成开发任务。

## 使用顺序

1. `01-需求文档模板.md`：只确定产品行为、范围和验收口径；
2. `02-架构设计模板.md`：先记录代码事实，再提出最小方案并完成关键决策；
3. `03-开发方案模板.md`：只拆解已确认的架构决策；
4. `04-测试与验收模板.md`：从需求和确认后的架构风险派生验证项。

## 内容分类

文档中的关键内容必须标记为以下一种：

- 产品规则；
- 已验证代码事实（事实本身不能创建产品范围或开发任务）；
- 必要推导（必须写明推导链）；
- 建议方案（未确认前不得进入开发任务）。

## 停止条件

- 需求未定稿：不拆开发任务；
- 关键代码事实未核对：不确定架构；
- 架构决策未确认：只允许验证任务，不允许实现任务；
- 开发任务无法同时追溯到需求和架构决策：不得实施；
- 出现新增表、迁移、服务、协议、状态机、配置项或大范围重构：必须在决策摘要中单列并获得确认。
