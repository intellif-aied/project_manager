### 范围判定规则

- “发布”必须有实现、测试和部署证据；
- “仅核对”必须说明为什么不需要代码变更，并验证兼容性；
- “不涉及”必须经过依赖检查，不能仅凭修改文件列表判断；
- “阻断”意味着禁止生产发布；
- 任何长时间回填或清理任务必须单独写出开始时间、进度、暂停条件、失败数、最终对账和是否继续运行；
- 不能用“镜像已构建”“健康检查正常”替代业务验收。

## 3. 代码、迁移和数据证据

- [ ] 工作区无未纳入范围的修改；
- [ ] API/Web/CLI 具体提交 SHA 已冻结；
- [ ] migration 在独立数据库和生产数据副本验证；
- [ ] 迁移幂等、回滚边界和备份已验证；
- [ ] 新写入、历史回填、清理动作分别列出；
- [ ] 数据前后数量、哈希、状态和关键业务结果完成对账；
- [ ] 没有把测试服异常数据结论直接继承到生产。

## 4. 功能、接口和性能验收

- [ ] 受影响 API 的成功、失败、权限、分页和兼容字段回归；
- [ ] Digest、MCP、Session、Token、报告和工作台等消费者逐项确认；
- [ ] 新上传、重试、重复上传、恢复和清理链路回归；
- [ ] 真实规模数据的 p95/p99、执行计划、并发条件和超时结果已记录；
- [ ] 前端人工验收项、截图或录屏证据已记录（如本次涉及 Web）。

## 5. 构建、部署和备份

- [ ] 生产数据库完整备份及 SHA256；
- [ ] `.env`、Compose、Nginx 和当前镜像信息已备份；
- [ ] API/Web 使用不可变镜像标签和 digest；
- [ ] Skill/MCP/Agent owner、version、sha256 和地址一致；
- [ ] 部署后容器版本、migration、配置和 Skill 绑定一致；
- [ ] `/health`、`/health/ready` 和关键业务接口通过；
- [ ] 观察窗口内错误率、队列、慢查询和依赖状态正常。

### 立即停止条件

- 关键接口 p95/p99 超阈值；
- 生产 5xx、队列 dead job 或数据库锁等待异常；
- 数据对账不平、对象 hash 不一致或消费者返回空内容；
- 任何清理任务无法确认可恢复。

## 7. 最终发布判定

发布负责人必须明确填写：

```text
本次范围已完整列出：是 / 否
所有发布项均有证据：是 / 否
所有阻断项均为 0：是 / 否
生产可以发布：是 / 否
```

只要任一项为“否”，发布状态必须是“未发布/阻断”，不能写“已完成”。
