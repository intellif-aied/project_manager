### R2.2 Reader 必须满足

- 输入包含 session/source/generation/revision/start cursor/end cursor；
- legacy 从 `sessions.raw_log_url` 读取单对象；
- V2 从 `session_upload_chunks.raw_object_key` 按 cursor 顺序读取多 Chunk；
- 校验对象状态、Chunk 边界、内容 hash 和完整 JSONL 行；
- 支持 context 取消、超时和背压；
- 对对象缺失、hash 错误、cursor 断裂返回明确错误；
- 禁止把错误降级为空内容成功；
- 禁止把完整大对象一次性读入内存。

### R2 验收

- [ ] 单 Chunk、跨 Chunk、Chunk 边界和 legacy 单对象测试；
- [ ] 对象缺失、hash 错误、cursor 重叠/间隙、不完整尾行测试；
- [ ] Digest V1/V2 source hash、included/omitted、最终 Digest 对账；
- [ ] MCP full 多页无重复遗漏，page cursor 可重试；
- [ ] V2 Session 详情/导出、权限、清理状态回归；
- [ ] 生产代码不再读取 `session_content_events.content_payload`；
- [ ] 321 万事件/7GB 等量测试记录耗时、内存和数据库扫描行数。

R2 未全部通过，禁止进入 R3。

## 8. 进度更新规则

每完成一个任务，只更新对应 R 编号，必须同时填写：

```text
状态：未开始 / 进行中 / 已完成 / 验收通过 / 阻断
修改文件：真实路径
提交：Git SHA
测试：命令与结果
数据：数量与对账结果
剩余阻断：具体 R 编号
```

没有 R 编号、修改文件和验收证据的内容，不算开发进度。
