# 需求与技术方案

## 1. 建设目标

当前 Session 原始 JSONL 保存在 MinIO，解析后的完整事件 JSON 又保存在 PostgreSQL `session_content_events.content_payload`。目标是消除这份重复内容，并保证列表、Token、Digest 和报告链路不再扫描大事件载荷。

完成后的存储边界：

- MinIO 是 Session 原始内容的唯一事实源；
- PostgreSQL 保存 Session 关系、Chunk、cursor、状态、摘要、Digest、Usage、Token、成本和审计数据；
- 候选列表与 Token 查询只读预计算读模型；
- 需要完整 Session 内容时，通过统一读取器从 MinIO 流式获取。

## 2. 产品契约

### 2.1 Session 与 Report Source

- 一次成功增量上传形成一个切片，Session 无需结束；
- Report Source 展示已就绪的上传切片，不显示或计算 Token；
- `period_start/period_end` 只表示报告周期，不过滤候选；
- 只有显式传入 `activity_from/activity_to` 才按活动时间过滤；
- 选择后冻结 slice、generation、revision 和 cursor，Session 后续上传不改变已冻结报告。

### 2.2 Token

- Token 与成本在上传后的异步 Usage/Metering 链路中固定，查询不重新解析 JSONL；
- 顶层 Session 统计包含自身及所有 Subagent，Subagent 继承的父历史不重复计数；
- Session 总量、按日汇总、按新增 Chunk 汇总来自同一组 Contribution 事实；
- summary、trends、rankings 和 sessions 使用同一个查询快照。

### 2.3 Digest 与 MCP

- Digest 在切片完成内容投影后异步生成，不在用户点击 AI 生成时现场扫描；
- Digest 未就绪仍返回 `REPORT_SOURCE_DIGEST_NOT_READY`；
- attached digest 继续读取 PostgreSQL 中已冻结的 Digest，不依赖实时 MinIO；
- attached full 的外部 MCP Schema、分页 cursor、权限和返回结构不变，仅内部数据源改为 MinIO；
- `write_report_result` 的完整读取、版本和 hash 门禁不得弱化。

## 3. 当前架构

```text
Aida 增量上传
  -> MinIO JSONL / Chunk
  -> Content Projection
  -> session_content_events
       |- cursor/time/type/summary/hash
       `- content_payload (完整 JSONB)
            |- Digest V1/V2
            `- MCP/report full

MinIO Chunk
  -> Usage/Metering
  -> Observation -> Logical Event -> Contribution
  -> Session Family / Daily / Chunk Rollup
  -> Token API / Web / MCP
```

现有 `report_source_slice_catalog` 已承担 Report Source 候选分页。Token 查询已读 Contribution、Rollup 和 Snapshot。未完成的是内容消费链路和 PostgreSQL Payload 清理。

## 4. 目标架构

```text
Aida 增量上传
  -> MinIO JSONL / Chunk (唯一原文)
  -> Content Projection
  -> session_content_events (轻量索引，不含 content_payload)
  -> report_source_slice_catalog

MinIO Content Reader
  |- Digest V1/V2
  |- MCP/report full
  `- Session 详情与导出

MinIO Chunk
  -> Usage/Metering
  -> Contribution / Rollup / Snapshot
  -> Token API / Web / MCP
```

## 5. 统一内容读取器

读取器放置在 `api/internal/contentreader/`，输入为已冻结的 content revision 和 `[start_cursor, end_cursor)`。

它负责：

1. 根据 revision 和 cursor 查找相交的 `session_upload_chunks`；
2. V2 从 `raw_object_key` 读取多 Chunk，legacy 从 `sessions.raw_log_url` 读取单对象；
3. 按 cursor 顺序流式解析 JSONL，支持跨 Chunk；
4. 校验对象状态、Chunk 边界、完整 JSONL 行和 SHA256；
5. 输出带 cursor、时间、类型、摘要、payload 和 hash 的有序事件流；
6. 支持 context 取消、超时和背压，不将完整大对象读入内存。

对象缺失、hash 不符、cursor 间隙/重叠或 JSONL 损坏必须返回可识别错误，不得伪装为空内容成功。

## 6. PostgreSQL 轻量索引

最终沿用 `session_content_events` 作为轻量事件索引，保留：

```text
id
content_projection_revision_id
chunk_id
source_start_cursor / source_end_cursor
occurred_at
event_type
summary / excerpt
content_sha256
created_at
```

不再保存 `content_payload`。不长期维护两张功能重复的事件索引表。

历史清理不对 321 万行执行大批量 `UPDATE content_payload = NULL`。采用紧凑表迁移：

1. 建立不含 Payload 的紧凑表并复制轻量字段；
2. 建立约束与索引，对账行数、revision、cursor 和 hash；
3. 暂停 Content Projection，复制最后增量，使用短事务切换表名；
4. 恢复 Projection，保留旧表作为数据回退；
5. 回滚窗口结束且功能、数据、空间验收通过后删除旧表。

## 7. 消费者改造

| 消费者 | 当前路径 | 目标路径 |
| --- | --- | --- |
| Content Projection | `api/internal/sessionsync/content_projection_processor.go` 写 Payload | 只写轻量索引 |
| Digest V1 | `api/internal/sessiondigest/processor.go` 读 Payload | 读 Content Reader |
| Digest V2 | `api/internal/sessiondigestv2/processor.go` 读 Payload | 读 Content Reader |
| MCP/report full | `api/internal/reportsource/service.go` 读 Payload | 读冻结 revision/cursor 的 Content Reader |
| Session 内容 | `api/handler/session.go` legacy 已读 MinIO | 保持 legacy，补齐 V2 多 Chunk |
| Usage/Metering | `api/internal/usage/` 已读 MinIO | 不改 |
| Token Analytics | `api/internal/tokenanalytics/` 已读 Rollup/Snapshot | 不改 |

Digest 迁移只改原始内容数据源，不改触发时机、调度、版本、脱敏、source hash、Digest hash、冻结与 MCP attached digest 行为。

## 8. 性能与运行约束

- Report Source 列表不读事件表、Usage 明细、Digest JSON 或 MinIO；
- Token 查询不读 JSONL、`session_content_events`、Usage Observation 或高基数 Component；
- Content Reader 只用于 Digest、full 内容和 Session 详情/导出，不进入普通列表路径；
- 后台迁移任务使用独立并发上限，数据库 CPU、I/O、连接池或前台 p95 超阈值时停止；
- MinIO 异常使未生成 Digest/full 读取明确失败，不影响已冻结 Digest 和 Token Rollup 查询。

## 9. 数据与接口影响

| 模块 | 影响 |
| --- | --- |
| Aida 上传协议 | 无变化 |
| Report Source API | 无 Schema 变化，最终性能回归 |
| Digest Worker | 数据源改为 MinIO Reader |
| MCP attached digest | 无变化 |
| MCP attached full | 内部数据源变化，外部契约不变 |
| Session 详情/导出 | V2 改读多 Chunk，权限和返回结构不变 |
| Token API/Web/MCP | 无新改造，只做回归 |
| 内容清理/恢复 | 需同步处理 MinIO、轻量索引、Digest 和审计状态 |

## 10. 完成标准

- PostgreSQL 新写入不再产生完整 `content_payload`；
- 历史 Payload 已完成对账、紧凑表切换和空间回收；
- Digest、MCP full 和 Session 内容已不再读 Payload；
- Report Source 和 Token 查询不随 JSONL 字节数或事件行数增长；
- Token 家族总量、按日和按 Chunk 继续精确对账；
- 所有功能、性能、迁移、发布和回滚验收项通过。
