# 开发实施计划

## 1. 执行原则

- 严格按下列顺序开发，前一阶段验收通过后才进入下一阶段；
- 任务状态只记录为：未开始、进行中、已验收、阻断；
- “已验收”必须同时记录 Git SHA、修改路径、测试命令与结果；
- 未完成的后续阶段不得随当前任务顺带实现。

## 4. 内容消费者迁移

**状态：未开始，等待统一内容读取器验收。**

开发顺序：

1. Digest V2：修改 `api/internal/sessiondigestv2/processor.go`；
2. Digest V1：修改 `api/internal/sessiondigest/processor.go`；
3. MCP/report full：修改 `api/internal/reportsource/service.go`；
4. V2 Session 详情/导出：修改 `api/handler/session.go`；
5. 全仓检索 `content_payload`，确认不存在未登记的读取消费者。

每个消费者必须先完成新旧结果对账，再移除旧读取代码。完成条件：Digest hash/覆盖范围一致，MCP full 无重漏，Session legacy/V2 内容完整，外部 Schema 与权限不变。
