## 2. 实施时必须遵守的查询约束

### Report Source 候选 SQL 白名单

允许读取：

- `report_source_slice_catalog`；
- 必要的轻量权限关系表。

禁止读取：

- `session_content_events`；
- `session_content_event_index`；
- Usage/Token 组件明细；
- Digest JSON；
- MinIO。

### Content Reader 约束

- 输入必须包含冻结 revision/cursor；
- 读取对象必须进行哈希或等价完整性校验；
- 不得用“最新 Session 内容”替代冻结内容；
- 对象缺失或损坏必须显式失败并可重试；
- 日志不得输出用户原始内容。

### Token 约束

- 五类 Token 分项、价格版本、汇率和权限语义保持；
- Contribution、family membership 和三套 Rollup 回填必须幂等、版本化；
- Claude Logical Event Advance 只把增量归入新增 Chunk；
- 同一 Snapshot 的 family total、daily、chunk、summary、trends、rankings 和 sessions 必须可对账；
- 全局汇总不得同时累加父 family 行和 Subagent member 行；
- Token 方案不依赖 Report Source catalog 是否上线。

## 3. 尚待人工确认但不阻塞 R1 的事项

| 编号 | 待确认项 | 默认处理 |
| --- | --- | --- |
| Q-01 | MinIO 原始对象最终保留期限和冷存储策略 | 继续保留，不自动过期 |
| Q-02 | 历史载荷表下线前的业务观察期 | 开发方案建议至少一个完整发布观察周期，最终人工确认 |
| Q-03 | 模糊搜索是否需要 trigram | 先查 catalog；只有压测不达标才增加 |
| Q-04 | MinIO bucket versioning/异地备份能力 | R2 上线前由运维核实，不在代码中假设 |

这些事项不能被解释为“方案不完整”：R1 的切片目录、日期契约和分页路径已经可以独立开发与验收。

## 4. 禁止自行扩展的范围

- 不新增无关前端页面或操作；Token 只允许增加三维模型明确要求的附加字段和成员下钻；
- 不改变个人日报/周报选择来源流程；
- 不顺手重做 Session 管理；
- 不超出 Contribution、Session family、三维 Rollup 所需范围修改 Token/成本算法；
- 不把平台监控中心、日志系统并入本专项；
- 不在未授权情况下执行生产 SQL、迁移、发布或清理；
- 文档确认不等于开发授权，开发完成不等于发布授权。
