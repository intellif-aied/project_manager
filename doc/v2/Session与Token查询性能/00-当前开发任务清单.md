## 4. DEV-02：统一 MinIO Content Reader

### 接口职责

Reader 输入：

```text
session_id
source_id
generation_id
projection_revision_id
start_cursor
end_cursor
```

Reader 输出：

```text
source_start_cursor
source_end_cursor
occurred_at
event_type
summary
excerpt
payload
content_sha256
```

### 必须支持

- legacy：`sessions.raw_log_url` 单个 JSONL 对象；
- V2：`session_upload_chunks.raw_object_key` 多 Chunk；
- 按 byte cursor 定位，跨 Chunk 连续读取；
- 校验对象状态、Chunk cursor、内容 SHA256 和完整 JSONL 行；
- 支持 context 取消、超时和背压；
- 对对象缺失、hash 错误、cursor 断裂返回明确错误；
- 禁止把错误降级成空内容成功；
- 禁止把完整对象一次性读入内存。

### 单元测试

- [ ] 单 Chunk；
- [ ] 跨 2 个及多个 Chunk；
- [ ] start/end 正好位于 Chunk 边界；
- [ ] legacy 单对象；
- [ ] 对象缺失；
- [ ] hash 错误；
- [ ] cursor 间隙/重叠；
- [ ] 不完整 JSONL 尾行；
- [ ] 超大单行；
- [ ] 请求取消和超时。

## 5. DEV-03/04：轻量索引与历史回填

轻量索引至少包含：

```text
projection_revision_id
chunk_id
source_start_cursor
source_end_cursor
occurred_at
event_type
summary
excerpt
content_sha256
```

明确禁止保存：

```text
content_payload
完整 message/tool input/tool output
完整 JSONL 行
```

回填必须：

- 从 MinIO 读取，不从旧 `content_payload` 复制；
- 小批次、幂等、可暂停、可续跑；
- 输出 eligible/scanned/succeeded/failed/pending；
- 对账 revision、cursor、event count 和 hash；
- 失败来源保留原因，禁止强行标记成功。
