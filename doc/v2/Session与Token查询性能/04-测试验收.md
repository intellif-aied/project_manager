## 2. 功能验收矩阵

| 模块 | 必须通过的场景 |
| --- | --- |
| Report Source | 首/中/末页无重漏，total 正确，period/activity 语义正确，冻结来源不漂移 |
| Content Reader | legacy 单对象、V2 单/多 Chunk、跨边界、重试一致性 |
| Reader 异常 | 对象缺失、hash 错、cursor 间隙/重叠、坏尾行、超大行、取消与超时 |
| Digest V1/V2 | 事件顺序、数量、included/omitted、source hash、Digest hash 与基线一致 |
| Digest 时序 | fully indexed 后异步生成，未就绪返回 NOT_READY，MinIO 异常不生成空 Digest |
| MCP attached digest | 冻结字节、版本、hash、覆盖和 `write_report_result` 门禁不变 |
| MCP attached full | 多页无重漏，cursor 可重试，selection/run/period 校验和权限不变 |
| Session 详情/导出 | legacy/V2 的数量、顺序、内容、权限和取消行为正确 |
| 上传 | Claude、Codex、Subagent、重复增量上传；请求不等待 Projection/Digest/Token |
| 新写入 | 轻量索引完整，Payload 为 NULL，Catalog/Digest/Usage/Token/成本状态正确 |
| 清理/恢复 | MinIO、轻量索引和 Digest 按内容生命周期处理；已确认 Token/成本/审计事实保留 |
| Token | family total = daily sum = chunk sum = active Contribution sum，Subagent 不重复 |
| Token 查询 | summary/trends/rankings/sessions 共享快照，后续页复用快照，Web 不全量翻页汇总 |
| MCP ad-hoc | 日期、权限、活动时间和 Token 口径与 API 一致 |

## 3. 性能验收

| 路径 | 标准 | 证据 |
| --- | --- | --- |
| Report Source | p95 ≤ 300ms，p99 ≤ 800ms；SQL 不读事件/Usage/MinIO | 数据规模、p50/p95/p99、SQL plan、扫描行数 |
| Token summary/sessions | p99 ≤ 3s，不物化 Component 明细 | Rollup/Snapshot 行数、SQL plan、p50/p95/p99 |
| Content Reader | 内存不随对象总大小线性增长，取消及时 | 吞吐、字节、峰值内存、MinIO 请求数、失败类型 |
| 紧凑表迁移 | 前台 p95 回归不超 5%，无长锁 | 耗时、批次、WAL、锁、磁盘峰值、暂停/续跑记录 |

## 4. 数据一致性验收

- MinIO legacy/V2 对象数、字节、hash、cursor 与 active revision 一致；
- Reader 输出事件数、顺序、cursor 和 hash 与旧 Payload 基线一致；
- 紧凑表的行数、revision 分布、cursor 范围、hash 聚合与旧表一致；
- Token family/daily/chunk/Contribution 总量和成本精确对账；
- 中断续跑不重复处理已完成批次；
- 备份文件 SHA256 正确，恢复后数据与关键接口正常。

## 5. 验收停止条件

- Digest hash、事件顺序或覆盖范围差异无法解释；
- 任一业务消费者仍读 `content_payload`；
- MinIO 完整性错误被当作空内容成功；
- Token 三维、成本或权限对账不一致；
- 迁移导致前台 p95 回归超 5%、长锁、WAL/磁盘空间风险；
- 备份没有完成真实恢复验证。
