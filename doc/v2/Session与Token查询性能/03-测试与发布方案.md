## 2. 功能测试

### 2.1 Report Source

- 首页、中间页、末页无重复和遗漏，`total` 正确；
- `period_*` 不过滤候选，`activity_*` 按活动范围相交过滤；
- SQL 不访问 `session_content_events`、Usage 明细、Digest JSON 和 MinIO；
- 选择后的 revision/cursor 不随 Session 后续上传漂移。

### 2.2 Content Reader

- legacy 单对象、V2 单 Chunk、V2 多 Chunk 和跨 Chunk 区间；
- start/end 位于 Chunk 边界；
- 对象缺失、hash 错误、cursor 间隙/重叠和不完整 JSONL 尾行；
- 超大单行、context 取消、超时和大对象内存上限；
- 同一 revision/cursor 重试输出序列完全一致。

### 2.3 Digest、MCP 与 Session

- Digest V1/V2 的事件顺序、数量、included/omitted、source hash 和 Digest hash 与基线一致；
- Digest 未就绪返回既有错误，MinIO 异常不生成空 Digest；
- MCP attached digest 的冻结内容、版本和完整性门禁不变；
- MCP attached full 多页无重复/遗漏，cursor 可重试，selection/run/period 不匹配时仍拒绝；
- 未完整读取时 `write_report_result` 仍拒绝写入；
- Session legacy/V2 详情与导出的数量、顺序、内容、权限和取消行为正确。

### 2.4 上传和派生数据

- Claude、Codex、Subagent 和重复增量上传全部通过；
- 上传请求不等待 Projection、Digest 或 Token Rollup；
- 新事件保留索引字段且 `content_payload` 为 NULL；
- Catalog、Digest、Usage、Contribution、Rollup 和成本均进入正确状态；
- 重复上传不重复建索引、Digest 或 Token 事实。

### 2.5 Token 回归

- Session family total = daily sum = chunk sum = active Contribution sum；
- summary、trends、rankings 和 sessions 的同一快照总量一致；
- `/tokens/sessions` 后续页复用首页快照，工作台不全量翻页后在浏览器汇总；
- root Session 与 Subagent 不重复计数；
- MCP ad-hoc 的日期、权限、活动时间和 Token 口径与 API 一致。

## 3. 性能验收

| 路径 | 验收标准 | 必须保存的证据 |
| --- | --- | --- |
| Report Source | p95 ≤ 300ms，p99 ≤ 800ms | 数据规模、p50/p95/p99、SQL plan、扫描行数 |
| Token summary/sessions | p99 ≤ 3s，不物化 Component 明细 | Rollup/Snapshot 行数、SQL plan、p50/p95/p99 |
| Content Reader | 内存不随对象总字节线性增长，取消及时 | 读取字节、吞吐、峰值内存、对象请求数、失败类型 |
| 紧凑表迁移 | 前台 p95 回归不超过 5%，无长时间锁 | 耗时、批次、WAL、锁等待、磁盘峰值、暂停/续跑记录 |

## 4. 数据迁移验收

生产操作前必须在等量副本完成：

- [ ] legacy `raw_log_url` 与 V2 `raw_object_key` 可读性盘点；
- [ ] MinIO 对象、字节、hash、cursor 与 active revision 对账；
- [ ] 紧凑表行数、revision 分布、cursor 范围、hash 聚合对账；
- [ ] 中断后可续跑，已完成批次不重复；
- [ ] 最终增量同步与短事务表切换成功；
- [ ] 备份文件 SHA256 已校验，恢复后数据与关键接口正常；
- [ ] 删除旧表后 PostgreSQL 实际空间回收符合演练结果。

## 5. 生产发布设计

不使用用户灰度、百分比 rollout 或运行时双模式开关。数据依赖要求生产分三步执行：

### 5.1 内容读链路发布

发布 Reader 及全部消费者迁移，暂时保留 Payload 写入。发布后对账 Digest、MCP full 和 Session 内容。回滚目标是本步发布前镜像。

### 5.2 停止 Payload 写入发布

只有内容读链路通过验收后才发布。发布后审计新上传事件。回滚目标是上一步 Reader 版本，不得回滚到依赖 Payload 读取的版本。

### 5.3 历史数据紧凑

只有新 Payload 已停止且生产等量副本演练通过后才执行。切换后保留旧表作为数据回退；回滚目标是停写 Payload 的 Reader 版本。旧表删除是独立且最后的不可逆操作。

## 7. 强制停止条件

出现以下任一情况立即停止当前阶段：

- Digest hash、事件顺序或覆盖范围差异无法解释；
- 任一业务消费者仍读取 `content_payload`；
- MinIO 缺失/hash/cursor 错误被当作空内容成功；
- Token 三维、成本或权限对账不一致；
- 迁移任务造成前台 p95 回归超过 5%、长锁、WAL/磁盘空间接近安全下限；
- 备份未验证可恢复，或回滚命令与当前数据状态不匹配。
