# Aida V2 产品需求总稿

## 文档状态

- 状态：产品定稿
- 日期：2026-07-14
- 适用产品：Aida 项目管理平台、Aida CLI
- 本期范围：Session 上传与管理、个人报告来源选择、Token 使用与成本分析
- 后续独立范围：报告内容压缩
- 文档定位：本文是 V2 页面形态、用户流程、角色权限、产品文案和验收口径的唯一依据，不定义接口、数据表或代码实现

技术方案不得自行改变本文定义的产品行为。会议纪要、旧修复方案和评审草稿只作为背景资料，不作为实现依据。

## 1. 产品背景

Aida 已经具备 Session 上传、个人/小组/部门报告和基础 Token 查看能力，但当前产品存在三类问题：

1. Session 使用体验不稳定：列表过长、长期 Session 难找、重复上传不可解释、换电脑衔接不明确、macOS summary 不可见。
2. 报告来源不灵活：个人日报和周报按自然日切片选择，无法表达跨天任务和多个历史 Session。
3. 管理分析不足：总监和小组长看不到完整的小组/人员排名、模型结构和统一 API 等价成本。

V2 的目标不是建设完整 AI 网关，也不是用 Token 直接评价员工产出，而是让 Session 数据可靠、来源可核查、统计可解释。

## 2. 产品原则

1. **一个 Session 只有一个用户可识别身份**：跨天活动不把它拆成多条 Session。
2. **重复上传是安全操作**：没有新内容时不重复，新内容只增加，不改写已确认历史。
3. **换电脑不等于重新开始**：平台同步状态不依赖原电脑本地缓存。
4. **内容与统计分开管理**：用户可以清除原始内容，但不能通过普通操作抹除管理统计。
5. **报告来源与 Token 日统计分开**：报告可以选跨天内容，Token 仍可按自然日统计。
6. **个人报告选 Session，组织报告汇总下级报告**：小组和部门报告不默认遍历所有成员原始 Session。
7. **有活动不等于有完整 Token**：活动、Token 完整性和计价状态分别表达。
8. **成本是 API 等价估算**：不冒充 Plus、Pro、Credits 或实际账单。
9. **产品只有一个正式口径**：本文未定义的页面、指标和权限不得在开发阶段自行增加。

## 3. 本期范围

### 3.1 Session 上传与管理

- CLI 专用登录凭证长期有效。
- CLI 升级、重新安装和换电脑后的连续使用。
- Session 按最近活动排序。
- CLI Session 列表和上传选择分页。
- 只同步新增活动并提供明确结果。
- macOS、Linux 一致展示 summary。
- 用户清除自己的 Session 内容。
- 用户显式恢复并重新上传已清除内容。
- 管理员彻底删除错误或测试数据。

### 3.2 报告来源选择

- 个人日报、个人周报支持跨天、多 Session 和历史 Session 选择。
- 支持选择完整 Session 或连续活动范围。
- 同一 Session 可以选择多个不同活动范围。
- 一次报告生成使用固定来源，不受后续上传影响。
- 小组和部门报告继续汇总下级已保存报告。

### 3.3 Token 使用与成本分析

- 所有角色拥有“我的 Token”。
- 小组长、总监、管理员拥有“Token 使用分析”。
- 支持时间、组织、人员和模型筛选。
- 支持 Token、成本趋势和小组/人员排名。
- 支持“部门 -> 小组 -> 成员”的固定两层组织范围；PM、总监可以直接归属部门。
- 支持真实 Session ID、summary 搜索和逐日下钻。
- 提供人民币 API 等价成本。
- 管理员维护模型价格、美元汇率和未计价模型。

### 3.4 本期不包含

- 报告内容压缩、去重、长文本截断、首尾截取或二次总结。
- 自动后台上传和常驻客户端。
- 删除用户电脑上的 Claude Code/Codex 原始日志。
- 用户逐条选择底层上传片段。
- 小组和部门报告批量读取成员原始 Session。
- Plus、Pro、Credits 和套餐利用率计算。
- 外部模型网关、路由、限流、耗时和可用率监控。
- 自动发布模型价格或汇率。
- 多级部门、矩阵汇报、一人同时归属多个部门等复杂组织模型。

## 4. 用户与权限

| 角色 | 我的 Session | 清除内容 | 个人报告来源 | 管理分析/成员 Session | 价格管理 | 彻底删除 |
| --- | --- | --- | --- | --- | --- | --- |
| 工程师 | 自己 | 自己 | 自己 | 否 | 否 | 否 |
| PM | 自己 | 自己 | 自己 | 否 | 否 | 否 |
| 小组长 | 自己 | 自己 | 自己 | 本小组 | 否 | 否 |
| 总监 | 自己 | 自己 | 自己 | 本部门 | 否 | 否 |
| 管理员 | 自己；管理查询可看全平台 | 自己 | 自己 | 全平台 | 是 | 是 |

权限规则：

1. 管理角色能查看授权范围的统计和成员 Session 列表，不代表可以清除成员的 Session 内容。
2. 个人报告只能选择当前登录用户自己的 Session。
3. 小组长只能分析本小组。
4. 小组长可以从成员排名点击本组成员，查看该成员的 Session 列表和统计详情。
5. 总监只能分析当前由自己负责的部门；范围包括该部门直属 PM/总监及部门下小组成员，不因角色身份获得全平台权限。总监可以从小组或人员排名下钻，查看本部门成员的 Session 列表和统计详情。
6. 管理下钻不授予成员原始日志下载、内容清除或个人报告来源选择权限。
7. PM 和工程师不能进入管理分析接口或页面。
8. 只有管理员可以维护价格和彻底删除数据。
9. 停用和归档账号的数据保留，但不进入本期当前成员排名和人数统计。

## 5. 统一术语

| 术语 | 产品定义 |
| --- | --- |
| Session ID | 本地 Claude Code/Codex 产生的真实 `session_ref`，是页面展示和搜索的唯一 Session ID |
| 最近活动 | Session 最后一次有效活动时间，不是启动时间或正式结束时间 |
| Summary | 用于识别 Session 的内容概览，不等价于任务名称 |
| 活动范围 | 用户在一个 Session 中选作报告来源的连续内容时间范围 |
| 活跃日 | 存在有效用户、助手或工具活动的业务自然日，不要求 Token 大于 0 |
| API 等价成本 | 按平台审核的官方 API 价格和对应汇率估算的人民币金额，不是实际账单 |
| 清除内容 | 删除平台原始日志和可读内容，但保留 Session 身份及 Token/成本统计 |
| 彻底删除 | 管理员删除内容及统计的纠错操作 |
| 无数据 | 所选范围内没有可统计活动，不能直接解释成用户没有上传 |

页面禁止把数据库内部 UUID 展示成 Session ID。

## 6. CLI 登录与跨设备使用

### 6.1 CLI 专用凭证

- 继续使用现有 CLI 专用凭证。
- 凭证不会因为时间经过自动过期。
- 凭证无效、账号停用或 Aida 权限关闭时仍应拒绝访问。
- 本期不增加设备管理、动态刷新或新的 Token 管理页面。
- 网页和其他业务登录不适用该长期有效规则。

### 6.2 CLI 升级

- 正常升级不得删除登录信息。
- 升级后不要求用户重新登录。
- 升级不得丢失已确认的上传进度。
- 新版重新检查历史 Session 时不得重复生成 Session 或重复 Token。

### 6.3 更换电脑

用户在新电脑安装 Aida 后，输入同一个 CLI 专用凭证即可继续使用。

用户可见行为：

- 平台已有 Session、报告和统计继续存在；
- 相同 Session 能识别平台已同步部分；
- 完整迁移到新电脑的长期 Session 可以继续同步新增活动；
- 新电脑没有本地日志时不影响平台已有数据，但无法恢复本地原始内容；
- 本地记录与平台历史明显不一致时停止自动续传，并提示重新完整同步。

## 7. CLI Session 列表

### 7.1 排序和分页

- `aida sessions` 默认展示最近 48 小时有本地日志更新的 Session，并在该结果集内分页。
- `aida sessions --all` 展示全部本地可发现的历史 Session，并在完整结果集内分页。
- 默认按最近活动时间倒序。
- 默认每页 10 条。
- 可切换每页 10、20、50 或 100 条。
- 支持上一页、下一页和跳页。
- 显示当前页、总页数和 Session 总数。
- 翻页期间顺序保持稳定。
- 分页只影响展示，不改变 Session 扫描范围，也不改变后续 `upload --all` 的范围。

```text
Session 列表                                      第 1 / 8 页，共 153 条
────────────────────────────────────────────────────────────────────────
1   Codex   今天 10:42   019f...   修复需求看板弹窗显示异常
    project_manager · GPT-5.4 · 3h12m · 28.6M Token · 2 个 sub-agent

2   Claude  今天 09:18   019e...   梳理 Session 上传与报告来源选择
    project_manager · Claude 4.7 · 48m · 17.2M Token

[上一页] [下一页] [跳转页码]                      每页 [20 ▼]
```

### 7.2 Summary

- macOS 和 Linux 都必须可见。
- 宽终端可单行，窄终端自动采用两行布局。
- 中文、英文、emoji 和多行首条消息正常显示。
- 无法提取时显示“暂无摘要”，不能留空。
- 列表可以省略过长内容，但必须保留可识别开头。

### 7.3 展示字段

- 序号；
- Agent 类型；
- 最近活动时间；
- Session ID；
- summary；
- 项目或工作目录；
- 主要模型；
- 持续时长；
- Token 总量或数据状态；
- sub-agent 数量，有 sub-agent 时显示。

新增分页和窄终端两行布局不得删除当前 CLI 已经展示的信息。上传选择列表与 Session 列表使用同一组摘要字段，只增加选择状态。

## 8. CLI 上传

### 8.1 选择

- 与 Session 列表使用相同排序和分页。
- 支持跨页多选，翻页后选择不丢失。
- 每项保留 Agent、最近活动、Session ID、summary、项目/CWD、模型、持续时长、Token 和 sub-agent 数量，不简化成只显示 ID 和 summary。
- 确认前展示已选数量和 Session 摘要。
- 用户选择 Session，不需要理解底层上传片段。
- 支持按完整 Session ID 直接选择。
- 交互式 `aida upload` 的候选集是全部本地可发现且存在待上传内容的 Session，分页只用于浏览该候选集。
- 交互界面的“选择全部待上传”覆盖本次固定扫描结果的全部页面，不是只选择当前页；文案同时显示将选择的总数。

```text
选择要上传的 Session                            已选择 3 条
────────────────────────────────────────────────────────────────────────
[x] 1  019f...  修复需求看板弹窗显示异常
       Codex · 今天 10:42 · project_manager · GPT-5.4 · 3h12m · 28.6M Token
[ ] 2  019e...  梳理 Session 上传与报告来源选择
       Claude · 今天 09:18 · project_manager · Claude 4.7 · 48m · 17.2M Token
[x] 3  019d...  排查生产日报回写失败

[上一页] [下一页] [跳转] [选择全部待上传（共 37 条）] [确认上传]
```

### 8.2 重复上传

- 无新活动时不重复上传。
- 有新活动时只同步新增部分。
- 网络超时后可以直接重试，不重复计算已成功内容。
- 同一 Session 在主列表始终只显示一条。
- 后续上传不得降低或移动既有日期的数据。
- 晚上传的历史活动可以补充对应历史日期。

`aida upload --all` 表示检查全部本地可发现的 Session，并同步其中尚未同步的新活动。它不受 `aida sessions` 当前页、最近 48 小时默认范围或交互选择页影响，也不表示重新发送全部历史内容。

### 8.3 结果状态

| 状态 | 用户文案 | 含义 |
| --- | --- | --- |
| 已上传 | 已同步新增内容 | 本次存在新活动 |
| 无变化 | 已是最新 | 没有需要同步的内容 |
| 已存在 | 平台已接收，无需重复上传 | 重试内容已经处理 |
| 内容已清除 | 已跳过，请显式恢复 | 普通上传不能恢复已清除内容 |
| 失败 | 明确原因和重试建议 | 本次未完成同步 |

部分失败不回退已成功 Session。结果必须列出成功数、失败数和逐项原因。

## 9. Session 内容管理

### 9.1 用户清除内容

普通用户操作统一命名为“清除内容”，不使用“撤回”或“永久删除 Session”。

清除：

- 平台原始日志；
- summary、excerpt 等可读内容；
- 报告生成读取能力；
- 原始日志下载能力。

保留：

- Session ID；
- 活动日期和最近活动时间；
- 模型；
- Token 和 API 等价成本；
- 任务、需求等统计关联；
- 已保存报告正文；
- “内容已清除”状态。

确认文案：

> 清除后，平台将不再保存或展示该 Session 的原始内容，也不能再将其选择为报告来源。Token、模型、活动时间和成本统计仍会保留。此操作不会删除你电脑上的原始文件。

### 9.2 清除后的展示

```text
019f...   内容已清除   最近活动 07-14 10:42   28.6M Token
```

- 不显示旧 summary；
- 不提供日志下载；
- 不允许作为新报告来源；
- 继续进入授权范围内的 Token、模型、活动日和成本统计。

### 9.3 恢复并重新上传

- 普通 `upload --all` 不自动恢复。
- 用户必须显式选择“恢复并重新上传”。
- 恢复前明确提示将再次向平台提供原始内容。
- 本机没有原始日志时无法恢复内容。
- 恢复后生成新的内容版本，不自动重写已保存报告。

### 9.4 管理员彻底删除

仅用于误传、测试数据和确认错误的统计。

管理员操作前必须看到：

- 用户和 Session ID；
- 日期范围；
- Token 和成本影响量；
- 关联报告、任务和需求提示。

管理员必须填写原因并二次确认。彻底删除后内容和统计均移除，并保留操作审计。

## 10. 个人报告来源选择

### 10.1 适用范围

仅个人日报和个人周报展示 Session 来源选择。小组日报、周报、部门日报和周报不展示成员 Session 选择器。

### 10.2 默认行为

- 用户不选择时，继续使用报告周期内现有个人数据来源。
- 用户显式选择后，选中来源是本次个人报告的优先来源。
- 报告日期只决定保存周期，不限制可选择的历史 Session。
- AI 生成是初稿，用户仍可编辑和保存。

### 10.3 Session 来源选择面板

沿用当前“AI 生成”旁展开、收起的紧凑 Session 选择面板。日报中可以位于现有报告弹窗内，周报中可以位于现有页面内；本期不要求替换为新的独立大弹窗，也不推翻已有的分页、跨页保留选择、日期筛选、清空选择和紧凑布局。

- 一行一个 Session，不按自然日重复显示。
- 默认展示报告周期附近 Session，可查看更早历史。
- 支持 Session ID 和 summary 搜索。
- 支持分页和多选。
- 支持完整 Session、连续活动范围。
- 同一 Session 可以选择多个不同范围。
- 显示已选数量和范围。
- 页面展示真实 `session_ref`，不展示数据库内部 Session UUID。
- 选择范围可以通过当前面板内的行展开或等价紧凑交互完成，不新增第二层嵌套弹窗。

```text
Session 来源                                             已选 2 项  [清空] [收起]
──────────────────────────────────────────────────────────────────────
[搜索 Session ID 或摘要________________]  [日期不限 ▼]

[x] 019f...  修复需求看板弹窗显示异常
    最近活动：07-14 10:42  ·  活动范围：07-12 至 07-14
    来源范围：[07-12 09:30 至 07-14 10:42 ▼]

[x] 019e...  排查日报回写失败
    最近活动：07-11 18:20  ·  已选完整 Session

[上一页] [下一页]                                      第 1 / 6 页
```

### 10.4 稳定性规则

1. 已清除内容的 Session 不可选择。
2. 无权访问的 Session 不出现在结果中。
3. 生成开始后，本次来源固定。
4. 生成过程中或完成后继续上传，不改变本次来源。
5. 再次生成时可以沿用或重新选择。
6. 页面保留本次来源数量和时间范围用于核对。

### 10.5 报告内容边界

本期只解决“选择哪些 Session 和范围”，保持当前 summary、excerpt 等报告内容能力。

- 不新增内容压缩算法；
- 不采用临时首尾截取；
- 不承诺因本期改动提升长 Session 总结质量；
- 不允许因为没有压缩能力就无限扩大原始日志输入。

报告内容压缩单独立项。

## 11. 小组与部门报告

- 小组日报和周报以成员已保存的个人报告为主要来源。
- 部门日报和周报以已保存小组报告及必要下级报告为主要来源。
- 组织归属以报告日期确定：日报使用报告日期，周报使用周结束日；一份下级报告只归入一个小组/部门范围。
- 小组长和总监不逐个选择成员 Session。
- 系统默认流程不遍历全部成员原始 Session。
- Session 数和 Token 数不能代替报告覆盖人数。
- 个人报告支持跨天来源不改变组织报告路径。

## 12. Token 页面信息架构

V2 保留两个 Token 页面，不能合并成一个大页面。

### 12.1 我的 Token

- 所有角色可见。
- 始终只看当前登录用户。
- 小组长、总监和管理员也从这里查看个人数据。
- 路由沿用 `/tokens`。

```text
我的 Token（当前登录人）                              [最近7天 ▼]
──────────────────────────────────────────────────────────────────────
总 Token       API等价成本       活跃天数       Session 数
182.6 M        ¥1,716.62         6 天           14 条

Token / 成本趋势                         模型使用

我的 Session [搜索 Session ID 或摘要________________________]

```

### 12.2 Token 使用分析

- 仅小组长、总监和管理员可见。
- PM、工程师不显示菜单且无接口权限。
- 小组长页签：小组概览、成员排名、Session 查询。
- 总监页签：部门概览、小组排名、人员排名、Session 查询。
- 管理员页签：整体概览、部门排名、小组排名、人员排名、Session 查询。
- “Session 查询”是内部页签，不是第三个菜单或独立页面入口。

### 12.3 价格管理

- 仅管理员可见。
- 总监不显示入口。
- 展示生效价格、待发布价格、未计价模型、价格历史、USD/CNY 汇率和操作审计。

## 13. Token 筛选与联动

| 筛选项 | 产品规则 |
| --- | --- |
| 时间范围 | 默认最近 7 个 `Asia/Shanghai` 自然日，即今天及前 6 天；支持自定义；不可清空 |
| 统计范围 | 我的 Token 固定自己；管理分析按角色固定授权范围 |
| 部门 | 总监固定本部门；管理员可筛选部门；小组长不显示 |
| 小组 | 小组长固定本组；总监只筛选本部门小组；管理员可筛选授权范围内小组 |
| 人员 | 只在管理分析中出现，并受组织权限限制 |
| 模型 | 单选或全部，默认全部 |

修改任何筛选后，总量、趋势、排名、模型和 Session 明细必须同步刷新。

## 14. Token 核心指标与趋势

### 14.1 主指标

| 页面 | 四项主指标 |
| --- | --- |
| 我的 Token | 总 Token、API 等价成本、活跃天数、Session 数 |
| 小组长管理分析 | 小组总 Token、API 等价成本、活跃成员、无数据成员 |
| 总监/管理员管理分析 | 管理范围总 Token、API 等价成本、活跃人数、无数据人数 |

输入、输出、缓存读取和缓存写入属于辅助信息，不与主指标竞争视觉优先级。

### 14.2 趋势

- 支持 Token 和 API 等价成本切换。
- 默认按日；长范围可按周或月聚合。
- 选择小组、人员或模型后同步刷新。
- 首期不提供任意多模型复杂折线。

## 15. 排名与活跃度

### 15.1 部门排名

仅管理员可见，展示部门名称、总 Token、API 等价成本、活跃人数和小组数。总监固定查看本部门，不展示跨部门排名。

### 15.2 小组排名

总监和管理员可见，至少展示：

- 排名、小组名称；
- 总 Token；
- API 等价成本；
- 活跃人数/小组人数；
- 人均 Token。

点击小组后同步进入该小组的人员、模型和 Session 范围。

### 15.3 人员排名

- 默认同时展示前 5 和后 5。
- 当前范围不足 10 人时展示全部，不重复人员。
- 支持 Token、API 等价成本、活跃天数排序。
- 提供完整分页排名。
- 包含当前授权范围内零数据的已启用用户。
- Token 并列时按最近活动、人员名称稳定排序。
- 低 Token 只作为管理线索，不自动评价“使用不足”。
- 部分未计价和未计价用户不与完整成本混排。
- 点击人员后进入 Session 查询，并自动保留该人员筛选；小组长只能下钻本组成员，总监只能下钻本部门成员，管理员可以下钻全平台成员。

### 15.4 活动、Token 和计价状态

三个状态维度独立：

| 维度 | 状态 |
| --- | --- |
| 活动状态 | 有活动、无数据 |
| Token 状态 | 完整、不完整、异常、无 Token |
| 计价状态 | 已计价、部分未计价、未计价 |

活跃日由有效活动事件决定，不能只用 Token 大于 0 判断。有活动但缺少 Token 时仍是活跃，只将 Token 标为不完整。

平台目标是所有工作 Session 都应上传，但页面不展示上传覆盖率，也不根据无数据直接判断用户未上传。

## 16. Session 查询与搜索

Session 主列表始终一条 Session 一行，跨天数据只在详情展开。

至少展示：

- Session ID和概览；
- 用户、部门、小组（仅授权角色）；
- 最近活动；
- 模型；
- Token；
- API 等价成本或未计价状态；
- 内容已清除状态。

支持：

- 完整 Session ID精确定位；
- Session ID连续片段；
- summary 关键词；
- 服务端分页搜索，不只筛当前页。

完整 Session ID命中时，可以跨当前日期和模型筛选定位该 Session，但仍必须受角色权限限制。无结果提示不得泄露无权限 Session 是否存在。

从小组或人员排名进入 Session 查询时，页面应保留对应 `team_id`、`user_id` 筛选。查看成员 Session 仅包含列表、概览、活动范围、模型、Token、成本和逐日统计，不提供成员原始日志下载、内容清除或个人报告来源选择。

内容已清除的 Session 保留 ID、统计和状态，但不参与旧 summary 搜索，也不能下载日志。

## 17. API 等价成本产品口径

### 17.1 基本规则

- 平台审核价格是唯一计费基准。
- 使用 Token 实际活动日期对应的价格和汇率。
- 默认价格口径为官方 API 等价。
- 官方单价以 USD 保存，用户页面统一显示人民币。
- 页面固定说明：

> 成本按平台已审核价格估算，不代表实际订阅或企业合同账单；部分或全部无法计价时会明确标识未计价。

### 17.2 不计入的概念

- Plus、Pro 月费；
- 套餐 allowance；
- Credits 余额或消耗；
- API 等价成本/订阅月费的所谓利用率；
- 内部模型未经确认的 GPU 成本。

### 17.3 计价状态

- 已计价：全部 Token 有有效价格和汇率。
- 部分未计价：展示已计价人民币小计并标注缺失，不计算覆盖百分比。
- 未计价：金额显示“未计价”，不能显示 0。

价格和汇率缺失不阻断 Session 上传、Token 统计或报告生成。

## 18. 价格管理

### 18.1 人工审核

- 管理员依据供应商官方页面或企业确认资料录入。
- 未发布价格不参与计算。
- 发布后价格版本不可直接编辑或删除。
- 新价格只影响对应生效日期。
- 错误价格通过纠正版本和显式重算处理。

### 18.2 AI 辅助查询

- 由管理员主动触发。
- 返回官方来源链接、查询时间、模型、USD 单价和不确定项。
- 只回填候选值，不自动保存或发布。
- 无官方依据时必须明确失败。

### 18.3 USD/CNY 汇率

- 表达为 `1 USD = N CNY`。
- 管理员填写生效日期、来源和备注。
- 新汇率不静默修改已有历史成本。
- 普通用户只看人民币；详情和管理端可追溯 USD 原值和汇率。

## 19. 数据变化产品规则

### 19.1 后续上传

- 新活动增加对应日期的活动和 Token。
- 晚上传的历史活动可以补充历史日期。
- 新增数据会使历史聚合增加，但不能覆盖已经确认的单价和汇率记录。
- 普通重复上传不能降低历史数据。

### 19.2 内容清除

- 清除内容不改变 Token、模型、成本、活跃日和排名。
- 页面概览改为“内容已清除”。
- 旧 summary 不再搜索或展示。
- 管理员彻底删除后，统计才从聚合中移除。

### 19.3 价格变化

- 新价格不静默改写历史成本。
- 迟到活动按活动日期对应的历史价格新增成本。
- 显式纠错保留原因和历史记录。

## 20. 异常提示

| 场景 | 用户提示 |
| --- | --- |
| CLI 凭证无效 | 登录凭证无效，请重新获取 |
| 账号停用 | 当前账号未启用 Aida 使用权限 |
| 网络超时 | 上传未完成，可直接重试；成功内容不会重复计算 |
| 本地与平台历史不一致 | 检测到 Session 历史不一致，请重新完整同步 |
| 本地日志不完整 | 当前电脑缺少完整本地记录，无法继续同步 |
| 内容已清除 | 平台内容已清除；需要显式恢复后才能重新上传 |
| Summary 缺失 | 暂无摘要 |
| 报告来源已清除 | 该 Session 内容已清除，请重新选择来源 |
| 部分上传失败 | 显示成功数、失败数和逐项原因 |
| 模型未计价 | 当前模型尚未配置有效价格 |
| 汇率缺失 | 目标日期缺少已发布核算汇率 |

错误提示必须给出下一步操作，不能只展示内部错误码。

## 21. 产品验收标准

### 21.1 CLI 与 Session

1. CLI 升级后不需要重新登录。
2. CLI 专用凭证经过较长时间仍可使用；账号停用后拒绝。
3. 换电脑并输入同一凭证后可以继续平台已有 Session。
4. 500 条 Session 可以分页浏览和跨页选择。
5. `aida sessions` 与 `aida sessions --all` 分别按最近 48 小时和全部历史范围分页。
6. `aida upload --all` 处理全部页面中的待上传 Session，不受当前页影响。
7. 分页改造后，Agent、最近活动、Session ID、summary、项目/CWD、模型、持续时长、Token 和 sub-agent 数量不丢失。
8. 最近仍活跃的长期 Session 排在前面。
9. macOS 80 列终端中 summary 可见。
10. 同一 Session 连续三天上传，主列表始终一条。
11. 重复和超时重试不产生重复 Token。
12. 后续上传不降低以前日期数据。

### 21.2 内容管理

1. 用户清除内容后，summary、日志下载和新报告读取立即不可用。
2. Token、模型、活动时间和成本继续保留。
3. 普通 `upload --all` 不自动恢复。
4. 显式恢复后内容重新可用。
5. 管理角色不能清除成员内容。
6. 管理员彻底删除后内容和统计均移除并有审计。

### 21.3 报告来源

1. 个人日报可以选择跨两天的 Session。
2. 个人周报可以选择多个历史 Session。
3. 同一 Session 在列表只显示一行。
4. 可以选择完整 Session 或连续活动范围。
5. 报告周期外的显式来源可正常使用。
6. 生成开始后上传新内容不改变本次来源。
7. 小组和部门报告不出现成员 Session 选择器。
8. 继续使用现有紧凑 Session 来源选择面板，切换新来源契约后不退化成新的嵌套弹窗。

### 21.4 Token 与成本

1. 所有角色能查看个人 Token 和人民币 API 等价成本。
2. 小组长、总监、管理员能查看授权范围排名，PM 和工程师不能进入。
3. 总监不能越权读取其他总监负责的部门。
4. 总监可以点击本部门中的任一成员，查看该成员的 Session 列表和统计详情；不能借此读取其他部门或下载成员原始日志。
5. 前 5、后 5 和完整排名结果稳定且不重复。
6. 有活动但缺少 Token 的记录不被标记为无活动。
7. Session 列表跨天不重复，支持真实 ID 和概览搜索。
8. 已计价、部分未计价、未计价状态准确。
9. 未计价 Token 不按零成本处理。
10. 任一金额可追溯到价格和汇率来源。
11. 页面不展示上传覆盖率、价格覆盖率或订阅利用率。

## 22. 已确认产品决策

1. 本文是 V2 唯一产品依据。
2. CLI 专用凭证不会因时间自动过期，本期不引入新的 Token 产品。
3. 平台同步状态不能只依赖原电脑。
4. 用户清除内容但保留 Token、成本和活动统计。
5. 管理员拥有带影响预览和审计的彻底删除能力。
6. 上传选择面向 Session，不暴露底层上传片段。
7. 个人报告支持跨天、多 Session 和历史范围。
8. 报告周期不限制显式来源日期。
9. 小组和部门报告汇总下级已保存报告，不默认读取原始 Session。
10. 报告内容压缩独立立项，不混入本期。
11. 活跃状态不以 Token 大于 0 作为唯一条件。
12. 所有角色看个人成本，小组长、总监、管理员按权限看管理分析。
13. API 等价成本以人民币展示，不等于订阅或实际账单。
14. 价格和汇率由管理员审核发布，AI 只能提供候选值。
15. `aida upload --all` 和交互式“选择全部待上传”都覆盖全部页面中的待上传 Session，不受当前页影响。
16. CLI 分页改造保留现有 Session 展示字段，不以简化界面为由删除 Duration 或 sub-agent 信息。
17. 总监可以下钻查看本部门每个成员的 Session 列表和统计详情，但不能越权或下载成员原始日志。
18. 个人报告沿用当前紧凑 Session 来源选择面板，只更换数据契约和行内容，不改成新的嵌套弹窗。
