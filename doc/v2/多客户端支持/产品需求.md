# 多客户端 Session 支持产品需求

> 文档状态：待最终评审；本文描述目标行为，不表示相关客户端已经可用。
> 评审日期：2026-07-21（增加腾讯 WorkBuddy）
> 适用范围：新增客户端发现、Session 上传、Session 切片、报告来源以及独立的 Token/成本能力评估。
> 关联基线：`doc/v2/Session增量上传与报告来源/产品需求.md`。
> 统一入口：同目录 `README.md`；Aida CLI 自身交互与升级见 `../Aida客户端重构/README.md`。

## 0. 文档边界

本文只描述未来新增客户端能力，不绑定当前 Aida CLI 发布版本。现有 Claude Code/Codex 的选择器、摘要、自更新和 readiness 属于 Aida 客户端重构，不在本文重复定义。多客户端进入开发前必须重新评审，且不得修改已经验收的 Claude Code/Codex Token 与成本口径。

## 1. 背景

Aida 当前只自动发现并上传 Claude Code 和 Codex 的本地 Session。用户同时使用 OpenCode、Kimi Code、OpenClaw、harness、ZCode、腾讯 WorkBuddy 等工具时，这些工作记录无法进入 Aida 的 Session 切片，也就无法作为个人日报、个人周报的事实来源。

本需求希望扩展客户端覆盖，但不能破坏现有口径：

1. Session 仍由用户在本机明确选择后上传，不做后台自动上传。
2. 一次成功上传的新增内容仍形成一个完整上传切片，不按自然日拆分。
3. 用户显式选择的 Session 切片仍是个人报告的最高优先级来源。
4. 用户未选择切片时，仍由后端按报告周期冻结相交的完整切片。
5. 小组和部门报告仍汇总下级已保存报告，不直接扫描成员的新客户端 Session。
6. Token、成本和报告内容是不同能力；不能因为能够读取会话正文，就宣称 Token 和成本也准确。

## 2. 目标

- 为 AIDA CLI 建立可扩展但受控的 Session 客户端适配机制。
- 复用 Aida CLI 已有的统一 Session 选择和上传入口。
- 首期优先让 OpenCode 和 Kimi Code 的 Session 可用于个人日报、个人周报。
- 在明确标注能力差异的前提下，让 OpenClaw 和 `harness.lol` 的记录可用于报告内容。
- 为 ZCode 保留接入位置，但在缺少稳定官方导出协议时不承诺正式支持。
- 为腾讯 WorkBuddy 保留接入位置；在取得稳定机器可读 Session 契约前，仅做受控发现与样本验证，不承诺报告、Token 或成本能力。
- 新增客户端后，现有四类角色、六类报告、Session 切片和默认 Agent 流程保持一致。
- 只有拿到可核对的逐事件 Token 数据时才进入 Token 与成本统计；不支持时展示“暂不支持”，不能展示为 0。
- 对具备 Token 能力的客户端，允许各 Adapter 按各自原生格式解析，但必须输出同一 Aida Usage 事实，并达到逐请求、单 Session、Session family 三层零误差对账。

## 3. 非目标

- 不在本需求中让 Aida 启动、控制或编排第三方编码客户端。
- 不接管第三方客户端的账号、模型密钥、OAuth 凭据或 MCP 凭据。
- 不直接读取第三方客户端的凭据文件、诊断日志或未选择的会话正文。
- 不修改小组、部门报告的汇总层级。
- 不修改个人报告“显式选择优先、未选择自动冻结”的来源规则。
- 不允许用户安装并执行任意第三方 Aida 适配器插件；首期适配器随 AIDA 二进制发布。
- 不因第三方客户端自带费用字段而直接写入 Aida 成本；Aida 成本仍由归一化 Token 和生效价格版本计算。
- 不把 ZCode 的“导出诊断日志”当成稳定 Session 导出接口。
- 不逆向读取腾讯 WorkBuddy 的未公开本地数据库，也不抓取其云端接口或分享页面作为生产 Session 来源。

## 4. 名词与能力等级

### 4.1 名词

- **客户端**：产生编码会话的工具，例如 `opencode`、`kimi_code`。
- **原生 Session**：第三方客户端内部定义的一次会话或任务。
- **适配器**：AIDA CLI 中负责发现、读取和标准化某类客户端 Session 的内置模块。
- **标准事件流**：适配器写出的 Aida Canonical Event JSONL；服务端只依赖这一稳定格式处理新增客户端。
- **报告内容能力**：会话可以形成 Aida 上传切片，并被报告 Agent 读取。
- **Token 能力**：Aida 可以从稳定的逐事件数据中归一化 Token，且重复上传、generation 重建和父子 Session 复制不会重复计数。
- **计费事实**：一次真实模型调用产生的唯一 usage；同一事实即使出现在父 Session、subagent、fork 或包装器日志中，也只能归属并计数一次。
- **成本能力**：Token 已通过核对、模型可识别、价格已配置后，Aida 可以计算成本。

### 4.2 能力维度

内容和 Token 是两个正交能力，不能用一个状态互相覆盖：

| 字段 | 取值 | 定义 | 产品展示 |
|---|---|---|---|
| `content_capability` | `detected` | 只能发现会话元数据，尚不能正式上传 | 实验性，不进入普通用户列表 |
| `content_capability` | `report` | 可上传内容、形成切片并用于报告 | 正常显示 Session 和切片 |
| `usage_capability` | `unavailable` | 没有可核对的逐事件 Token | Token 显示“暂不支持”或 `--` |
| `usage_capability` | `estimated` | 有 Token 数据，但来源或拆分只能估算 | 显示估算标记，不参与精确对账结论 |
| `usage_capability` | `exact` | 每个计费事实有跨 generation、跨父子 Session 稳定身份，并通过逐请求、Session、Session family 零误差对账 | 正常显示 Token，可进入成本计算 |

能力组合按客户端和已验证版本确定，不按“文件存在”自动提升。例如 OpenClaw 可以是 `report + unavailable`，并不影响其报告能力正式发布。

## 5. 客户端范围与发布优先级

以下是开发目标，不表示当前已经支持：

| 客户端 | 正式依据 | 首期目标 | Token/成本目标 | 发布结论 |
|---|---|---|---|---|
| Claude Code | 现有本地 JSONL | 保持现状 | 保持现状 | 已有能力，必须无回归 |
| Codex | 现有 rollout JSONL | 保持现状 | 保持现状 | 已有能力，必须无回归 |
| OpenCode | 官方 `session list --format json` 与 `export` JSON | `report` | 对账前 `unavailable`；通过后可升为 `exact` | 第一批正式候选 |
| Kimi Code | 官方 `session_index.jsonl`、`state.json`、`wire.jsonl` | `report` | 逐版本验证后决定 `exact`、`estimated` 或 `unavailable` | 第一批正式候选 |
| OpenClaw | 官方 Session 列表与 trajectory 导出 | `report`，默认仅展示明确选择的会话 | 首期 `unavailable` | 第二批，隐私风险较高 |
| harness.lol | 官方统一 NDJSON 与本地 Session 日志 | `report` | 首期 `unavailable`，避免和底层客户端重复 | 第二批，按包装器处理 |
| ZCode | 官方只确认本地 Session/用量存在，未公布稳定导出格式 | `detected` 受控试验 | `unavailable` | 未满足正式发布前置条件 |
| 腾讯 WorkBuddy | 官方确认本地数据库、任务历史和 transcript/replay，但未公布稳定机器可读 Session 导出契约 | `detected` 受控试验 | `unavailable` | 未满足正式发布前置条件 |

“Harness”在本文默认指 `harness.lol` 的开源统一编码 Agent CLI，不是 Harness.io SaaS。若产品所指为 Harness.io，需要另立需求，因为其 Chat History 是服务端托管数据，不属于本地 Session 扫描范围。

“WorkBuddy”在本文指腾讯出品的 WorkBuddy 桌面客户端，不是开源的 `work-buddy` Claude Code/Obsidian 项目，也不是 WorksBuddy SaaS。其他同名产品需要另立需求并重新评估数据来源、授权和身份契约。

## 6. 产品需求

### MC-PRD-001：自动发现

1. `aida sessions` 继续扫描最近 48 小时的会话，`--all` 继续扫描全部可发现会话。
2. Aida 只启用当前版本内置且通过发布门禁的适配器。
3. 未安装某个客户端、目录不存在或官方只读命令不可用时，该适配器静默跳过，不影响其他客户端。
4. ZCode 和腾讯 WorkBuddy 在未达到正式支持门禁前，不进入普通用户默认列表。
5. 发现阶段可以读取会话索引和必要元数据；正文只在建立本地索引或用户选择上传时读取，不向服务端自动发送。

### MC-PRD-002：统一列表与选择

1. Claude Code、Codex 和新增客户端 Session 出现在同一个 Bubble Tea Session 列表中。
2. 每条 Session 必须显示客户端来源，不能把模型名称当作客户端名称。
3. 正式交互使用方向键、搜索、客户端筛选、空格多选和 Enter 上传，不保留手写分页命令循环。
4. 列表采用虚拟滚动或组件分页，用户不需要输入页码和每页数量。
5. 排序仍按最后活动时间倒序；时间统一解析为绝对时间后展示。
6. 用户可以同时选择多个不同客户端的 Session 上传。
7. 不增加独立“客户端管理中心”；版本、能力和 Adapter 异常在统一 TUI 中表达。
8. 无交互模式使用稳定 Session 身份和 JSON，不使用当前列表编号作为永久参数。

### MC-PRD-003：Session 身份

1. Aida Session 身份继续由当前用户、客户端类型和原生 Session ID 共同确定。
2. 同一原生 Session 反复上传必须命中同一 Aida Session。
3. 不同客户端即使使用相同 Session ID，也必须是不同 Aida Session。
4. 主 Session 与子 Agent Session 有稳定原生身份时，分别保存，并保留父子关系。
5. 客户端无法提供稳定 Session ID 时，不得使用标题、时间或正文摘要作为唯一身份；该客户端不能进入正式支持。
6. fork/subagent 必须同时保留稳定父 Session ID、fork 时间和关系来源；关系缺失或冲突时，该 Session family 不得标记 Token `exact`。

### MC-PRD-004：上传与切片

1. 新增客户端必须复用现有 Prepare、Chunk、Finalize 增量上传协议。
2. 首次上传当前完整内容形成一个切片。
3. 后续追加内容时只上传新增内容，并形成一个新切片。
4. 无新增、失败或重复上传不形成新切片。
5. 第三方客户端编辑、压缩、删除或重排历史导致已上传前缀变化时，Aida 必须重建该 Session 的活动版本，不能把变化后的快照错误追加到旧内容后。
6. 重建后旧版本不得继续出现在可选切片中；不能重复计入报告来源或 Token。
7. 一次上传横跨多天仍只形成一个完整上传切片。

### MC-PRD-005：报告来源

1. 新客户端切片与 Claude Code、Codex 切片使用同一选择弹窗和来源快照协议。
2. 用户明确选择切片时，只使用已选切片；客户端类型不改变该优先级。
3. 未选择切片时，按报告周期选择活动区间相交的完整上传切片。
4. 个人日报和个人周报可以混合使用多个客户端切片。
5. 默认 Agent、默认 MCP 和默认 Skill 不增加按客户端分支；它们只读取已冻结的统一来源快照。
6. 小组日报、个人周报、小组周报、部门日报和部门周报的既有来源层级不变。
7. 新客户端不允许绕过当前用户身份和 Session 所有权校验。

### MC-PRD-006：内容质量

1. 适配器至少提供会话开始时间、最后活动时间、客户端、Session ID、项目目录或工作目录、可读摘要和标准事件流。
2. 摘要优先使用首个有效用户目标；没有可读目标时使用明确的降级提示。
3. 报告内容保留用户指令、Agent 可读结果和工具名称；不要求上传第三方 UI 状态、二进制附件或完整诊断日志。
4. 单条超大消息必须安全拆分，不能因超过当前 8 MiB JSONL 行限制而破坏整个 Session。
5. 无法解析的单条事件计入质量状态，但其他合法事件仍可用于报告；若有效事件为 0，则本次上传不能形成可用切片。

### MC-PRD-007：Token 与成本

1. 报告内容可用不代表 Token 可用。
2. 每个客户端允许使用自己的原生 Token 字段、累计方式和 fork 语义；这些差异必须封装在对应内置 Adapter 内，服务端和 Token Analytics 只读取统一 Aida Usage 事实。
3. `usage_capability=exact` 必须满足：每次真实模型调用有稳定计费事实 ID、原始归属 Session 明确、输入/缓存写入/缓存读取/输出口径明确、累计/增量语义明确、跨日归属可验证。
4. 主 Session、subagent、fork 或包装器复制同一计费事实时只能计算一次，并归属到最初产生该调用的 Session；子 Session 自己产生的新调用归属子 Session。
5. Session family 必须满足 `family_total = self_total + unique_subagent_total`，且逐请求、单 Session、Session family 与客户端或 Provider 原始记录的所有整数 Token 字段误差均为 0。
6. 只有累计计数、但缺少稳定 fork 基线、计数器作用域或重置边界时，最多标记为 `estimated`；只能拿到会话总量或账号汇总时同样不得标记 `exact`。
7. 缺少稳定计费事实 ID、原始归属 Session 或可验证父子关系时，不生成 `exact` usage；没有可靠 Token 数据时显示“暂不支持”或 `--`，不能显示 0。
8. 客户端直接给出的金额不作为 Aida 成本事实；Aida 仍根据归一化 Token、模型和价格版本计算。
9. 未配置模型价格时沿用现有“Token 可统计、成本待配置”的规则，不反向修改历史原始 Token。
10. 新客户端开启 Token 能力前必须证明重复上传、generation 重建、父子乱序上传、嵌套 subagent 和历史 compaction 均不会造成重复或漏计。

### MC-PRD-008：包装器与重复来源

1. `harness.lol` 被视为底层编码客户端的包装器，不视为新的模型提供商。
2. Harness Session 首期只进入报告内容，不进入 Token 和成本统计。
3. 如果 Harness 日志能够给出稳定的底层客户端 Session ID，Aida 列表优先保留底层原生 Session，并把 Harness 记录标记为重复来源。
4. 无法证明重复时不得用时间、目录、标题的模糊匹配自动删除记录；允许两条记录存在，但必须标明来源。
5. 用户同时选择内容相同的 Harness 和底层 Session 时，来源快照应提示可能重复；首期不做基于正文的自动合并。

### MC-PRD-009：隐私与安全

1. Aida 不读取或上传第三方客户端的凭据目录、认证文件、全局诊断日志和模型密钥。
2. 只读命令必须使用固定参数调用，不通过 shell 拼接 Session ID 或路径。
3. 临时导出目录和标准化缓存使用当前用户私有权限，并在成功或失败后按策略清理。
4. ZIP 或目录导出必须防止路径穿越、符号链接越界和超大文件。
5. 用户在上传前仍需看到敏感内容检查提示；Aida 不承诺自动识别文本中的所有秘密。
6. OpenClaw 可能包含聊天渠道和非编码内容，首期只允许用户显式选择上传，不提供 `--all` 无确认批量上传 OpenClaw 的快捷行为。
7. Aida 服务端只接受当前登录用户上传的数据，客户端声明不能改变数据所有者。

### MC-PRD-010：失败与降级

1. 一个适配器解析失败不能阻断其他适配器列表和上传。
2. 列表应指出失败客户端、版本和简短原因，但不显示原始敏感内容。
3. 官方格式升级导致适配器不兼容时，该客户端降级为不可上传，不得上传空内容或错误内容。
4. 上传中断继续使用现有断点状态；再次执行时从服务端确认游标恢复。
5. 服务端尚未支持标准事件格式时，新版 CLI 必须给出明确“不支持该客户端”的错误，不能悄悄回退到旧批量接口。

### MC-PRD-011：兼容性

1. Claude Code 和 Codex 当前扫描、上传、原生 Token parser、事实去重、Session/family 汇总和成本结果全部冻结，不迁移到统一 Adapter 或 Canonical Event。
2. 老请求不携带 canonical 标识时，服务端继续执行当前 Prepare、事务、错误码和 parser 语义；新增客户端不得改变这条分支。
3. 新增客户端使用独立 canonical 上传入口和 parser 分发；canonical 请求失败、禁用或版本不兼容时，不得回退到 Claude/Codex 原生链路。
4. 服务端只接受发布清单声明的最新 Aida 客户端和当前协议版本。
5. 旧客户端收到 `CLI_UPGRADE_REQUIRED` 后必须升级，服务端不长期维护旧上传协议；但升级不得改变已冻结的 Claude Code/Codex 统计口径。
6. 历史 Session 不强制重新上传；不得为本需求重算或回填 Claude Code/Codex 历史 usage。
7. 前端遇到未知客户端值时显示可读原值，不空白、不报错。

### MC-PRD-013：客户端分发前置依赖

多客户端 Adapter 随 Aida CLI 正式版本分发，不建立第二套安装或升级机制。升级、回退和三平台产物规则以 `../Aida客户端重构/客户端上传与升级方案.md` 为准，本需求只增加各客户端独立能力开关和兼容版本声明。

### MC-PRD-012：发布门禁

一个客户端只有同时满足以下条件才能标记为正式支持：

1. 有官方文档或官方开源代码证明稳定的会话身份和机器可读来源。
2. 至少准备 3 份脱敏真实会话：短会话、长会话、跨日/子 Agent 会话。
3. 覆盖 Linux、macOS、Windows 中该客户端正式支持的平台；未测试平台不得宣称支持。
4. 首次、增量、无变化、历史重写、失败恢复全部通过。
5. 真实 Session 能在 14.157 形成切片，并由默认 Agent 生成个人日报和个人周报。
6. 四类角色、六类报告完整回归通过。
7. 标记 Token 能力时，Token 与成本专项对账通过；其中 `exact` 必须覆盖父子乱序上传、fork 继承历史和至少二级 subagent，任何整数差异均阻止开启。
8. 隐私、凭据排除和临时文件权限测试通过。
9. 实际支持版本范围写入用户指南和发布说明。

## 7. 首期交互

### 7.1 `aida sessions`

- 默认进入 Bubble Tea 统一列表。
- 客户端列/标记支持：Claude、Codex、OpenCode、Kimi Code、OpenClaw、Harness。
- Token 不可用时显示 `--`，并可通过状态文案说明“该客户端暂不提供精确 Token”。
- 解析失败的 Session 不进入可选编号；错误在列表结束后汇总。
- 支持搜索、来源筛选、键盘多选和虚拟滚动。
- `--json` 时不启动 TUI。

### 7.2 `aida upload`

- 默认复用 Bubble Tea Session 列表和确认流程。
- 同一次可上传不同客户端 Session。
- OpenClaw Session 必须逐项选择；`--all` 默认排除 OpenClaw，除非未来增加二次明确确认。
- 上传过程显示扫描、准备、Chunk、服务端处理、ready 和失败。
- 只有服务端确认 Session 可用于日报后才显示最终完成。
- Headless 模式通过稳定 Session ID 上传，不依赖 TUI 编号。

### 7.3 Web

- Session 页面、报告 Session 选择弹窗增加正确的客户端显示映射。
- Token 不支持时不得显示 0 Token 或 0 元。
- 不新增新的报告生成步骤，不要求用户理解适配器、事件格式或上传游标。

## 9. 验收结论口径

- “支持某客户端”至少表示该客户端的真实 Session 已能上传、形成切片并通过默认 Agent 个人日报/周报。
- “完整支持某客户端”表示同时达到 `content_capability=report` 和 `usage_capability=exact`；仅有报告能力时必须写明“仅报告内容”。
- “支持 Token”必须另有真实对账证据，并明确标注 `usage_capability`。
- “支持成本”必须同时满足 Token 准确、模型识别和价格配置。
- 文档、单元测试或 Mock 通过不能代替 14.157 真实客户端、真实接口和真实默认 Agent 验收。
- 任一客户端失败不影响已经正式支持的其他客户端，但该客户端不得随整体版本被误报为已支持。
