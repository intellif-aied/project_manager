## 1. 测试目标

验证多客户端接入不仅“能解析文件”，还满足以下完整链路：

```text
真实客户端创建 Session
-> 新版 AIDA 发现并选择
-> 首次/增量上传
-> 服务端内容投影和上传切片 ready
-> Web 可选择切片
-> 默认 Agent 读取统一来源
-> 个人日报/周报正确生成
-> 四类角色、六类报告无回归
-> 支持 Token 的客户端完成 Token/成本对账
```

单元测试、静态 fixture、Mock、HTTP 200 或直接调用 Skill 都不能代替完整真实流程。

## 3. 测试数据与版本证据

### 3.1 每个客户端的 Golden Fixture

每个候选客户端至少准备以下脱敏样本：

1. **短会话**：1 条用户消息、1 条 Agent 回复、至少 1 次工具调用。
2. **长会话**：超过 500 个事件或超过 4 MiB，包含多次工具调用和多模型/模型切换场景。
3. **跨日会话**：按 `Asia/Shanghai` 横跨两个自然日，但一次上传仍形成一个切片。
4. **子 Agent 会话**：客户端支持子 Agent 时必须包含主/子关系。
5. **历史变化样本**：同一 Session 的追加版本，以及编辑/compact/重排后的非前缀版本。
6. **异常样本**：缺字段、坏 JSON、超大行、无效 UTF-8、末尾半行。

每份 fixture 配套 manifest：

```yaml
client_type: opencode
client_version: 1.18.1
os: linux-amd64
native_session_ref: ses_xxx
parent_session_ref: ""
source_sha256: ...
expected:
  canonical_events: 42
  first_activity_at: 2026-07-14T15:00:00Z
  last_activity_at: 2026-07-15T02:00:00Z
  tool_calls: 6
  usage_capability: unavailable
  usage_facts: 0
  self_total_tokens: 0
  subagent_total_tokens: 0
```

不得提交真实账号 Token、OAuth 文件、模型密钥、公司源代码或未经脱敏的对话。

### 3.2 客户端版本矩阵

正式支持版本至少包含：

- 开发时最新稳定版本；
- 团队生产实际使用版本；
- 若两者不同，再覆盖中间一个版本或明确只支持范围。

每次第三方客户端大版本升级必须重新运行 adapter contract suite。没有证据的平台和版本不得写入支持列表。

## 4. Adapter Contract 测试

所有 adapter 共用同一套 contract tests。

| 编号 | 场景 | 预期 |
|---|---|---|
| ADP-001 | 客户端未安装/目录不存在 | 返回空结果，不影响其他 adapter |
| ADP-002 | 发现 3 个会话 | Session ID、时间、cwd、摘要准确，按最后活动时间排序 |
| ADP-003 | 两客户端使用相同原生 ID | 生成不同 Aida Session 身份 |
| ADP-004 | 同一输入 Materialize 两次 | canonical 文件 SHA256 完全一致 |
| ADP-005 | 原生仅追加事件 | 新 canonical 以旧文件为逐字节前缀 |
| ADP-006 | 原生历史编辑/compact | 检测为非前缀变化，进入 rebuild 路径 |
| ADP-007 | 缺稳定 Session ID | 拒绝进入正式可上传列表，不用标题替代 |
| ADP-008 | 时间含时区 | 转换 UTC 后保持同一时刻，日期归属正确 |
| ADP-009 | 时间不含时区且无法确认 | 返回质量错误，不猜本机时区 |
| ADP-010 | 主/子 Agent | 身份独立且 parent ref 正确 |
| ADP-011 | 单条消息超过 4 MiB | 稳定拆分，每行低于服务端限制 |
| ADP-012 | 末尾半行 | 不上传半行，后续补全后可继续 |
| ADP-013 | 单条坏 JSON | 记录 diagnostic；其他合法事件继续 |
| ADP-014 | 所有事件无效 | 不生成可上传 Session |
| ADP-015 | 原始文本含 NUL/无效 UTF-8 | 安全替换且不破坏 JSONL |
| ADP-016 | 凭据/日志目录存在 | 不读取、不进入 canonical、不出现在 diagnostics |
| ADP-017 | symlink 指向允许目录外 | 拒绝读取 |
| ADP-018 | adapter 自身失败 | 其他客户端仍正常返回 |
| ADP-019 | fork 复制父 Session 历史 usage | 复制事件保持相同 `usage_fact_id` 和父 Session `owner_session_ref` |
| ADP-020 | subagent 自己发起新模型调用 | 新事实使用新 `usage_fact_id`，`owner_session_ref` 为子 Session |
| ADP-021 | 原生 usage 只有时间、游标或正文哈希可做身份 | 不得标记 `exact` |
| ADP-022 | 累计计数存在但 fork 基线或重置边界缺失 | 降为 `estimated`/`unavailable`，不补 0 |

## 5. Canonical Event 测试

在进入 Canonical Event 测试前，先冻结 Claude Code/Codex legacy Golden：

| 编号 | 基线 | 必须保持不变 |
|---|---|---|
| LEG-001 | Claude Code 原生 fixture | parser 逐事实 Token、模型、时间、fingerprint 和质量状态完全一致 |
| LEG-002 | Codex rollout fixture（含 fork/compaction） | delta、fork baseline、claim、Session/family 汇总完全一致 |
| LEG-003 | 老 CLI Prepare/Chunk/Finalize | HTTP 请求、状态、错误码、checkpoint、rebuild 和 upload-state 结果一致 |
| LEG-004 | usage processor 与 rollup | contribution、claim、self/subagent/family、每日/模型维度整数值一致 |
| LEG-005 | 成本与前端输出 | 价格版本、成本精度、不可用/估算/exact 展示一致 |
| LEG-006 | canonical 关闭或失败 | Claude Code/Codex 仍能独立上传、处理、查询，不进入 canonical handler/parser |

LEG-001 至 LEG-006 任一失败时，不得继续新增客户端开发；不能用更新 Golden 接受差异，除非另立 Claude/Codex 需求并独立评审。

### 5.1 Schema

| 编号 | 场景 | 预期 |
|---|---|---|
| CAN-001 | 合法 7 类事件 | JSON Schema 全部通过 |
| CAN-002 | schema 版本未知 | 服务端明确拒绝，不按旧格式猜测 |
| CAN-003 | event_id 缺失/重复 | 解析失败或标记冲突，不重复写内容/Token |
| CAN-004 | timestamp 非 RFC3339 | 事件进入 malformed，不能进入错误日期 |
| CAN-005 | payload 含配置/credentials 对象 | adapter allowlist 排除 |
| CAN-006 | 二进制附件 | 只保留元数据，不内联内容 |
| CAN-007 | JSON key/事件顺序 | 同一输入跨三次运行完全稳定 |

### 5.2 Chunk 边界不变性

对每份 fixture 执行：

1. 整文件解析。
2. 每 1 行一块。
3. 500 行一块。
4. 4 MiB 上限分块。
5. 在所有合法换行边界随机切分 100 轮。

内容事件、malformed 数量、usage 记录、游标和最终归一化结果必须一致。

### 5.3 Usage

| 编号 | 场景 | 预期 |
|---|---|---|
| USE-001 | capability unavailable | usage job 成功空处理，不重试、不产生 0 Token 记录 |
| USE-002 | delta exact | 每个 event_id 只计一次，合计准确 |
| USE-003 | Adapter 输入 cumulative exact | Adapter 正确求增量并只输出 Canonical delta；服务端拒绝直接上传 cumulative；计数下降进入 conflict |
| USE-004 | 重复 chunk | 不重复写 usage component |
| USE-005 | 同事件经重建 generation 出现 | 按稳定事实去重，不翻倍 |
| USE-006 | 缺 model | Token 可记录为不完整，成本不计算 |
| USE-007 | 模型无价格 | Token 保留，成本显示待配置，不写 0 元结论 |
| USE-008 | 第三方提供 total_cost_usd | 不直接写入 Aida 成本 |
| USE-009 | estimated | UI 和 API 保留估算质量，不并入精确对账 |
| USE-010 | 父子 Session 含相同 `usage_fact_id` 和相同内容 | 复用现有跨 source claim，只保留一份贡献并归属 `owner_session_ref` |
| USE-011 | 两个无关 Session 的原生短 ID 相同 | Adapter 生成不同 `usage_fact_id`，两次真实调用分别计数 |
| USE-012 | 同一 `usage_fact_id` 的 Token、模型或时间不同 | revision 进入 conflict，不静默选择 |
| USE-013 | 子 Session source 先上传、父 Session source 后上传 | 同一 Prepare 已先原子登记完整 family manifest；最终总量和归属与父先子后完全一致 |
| USE-014 | 二级 subagent | 每个新调用只计一次，family total 等于 self 加所有唯一后代贡献 |
| USE-015 | `owner_session_ref` 缺失、跨用户或关系冲突 | 不激活 exact revision，不把 usage 归给当前上传 Session |
| USE-016 | exact 客户端累计计数经过 fork/compaction/reset | 只有稳定作用域、基线和重置边界齐全时由 Adapter 求差并输出 delta；否则阻止 exact |

## 6. 增量上传协议测试

| 编号 | 场景 | 操作 | 预期 |
|---|---|---|---|
| SYN-001 | 首次上传 | 上传完整 canonical | 1 个 active generation、1 个切片 |
| SYN-002 | 追加上传 | 原生新增事件后再上传 | 只传新 chunk，新建 1 个切片 |
| SYN-003 | 无变化 | 原样再次上传 | `unchanged`，不新增切片 |
| SYN-004 | 上传中断 | 第二 chunk 后断网 | 重试从服务端确认 cursor 继续 |
| SYN-005 | 末尾半行 | 文件正在写入 | 完整行上传，半行 pending；补全后上传 |
| SYN-006 | prefix mismatch | 修改早期事件 | 新 generation rebuild，旧 generation superseded |
| SYN-007 | rebuild 已 finalize、内容 worker 尚未完成 | 查询候选 | 不返回新旧混合数据；允许该 Session 短暂不可选，并显示处理中状态 |
| SYN-008 | rebuild 激活后 | worker 完成 | 只显示新活动 generation 的切片 |
| SYN-009 | source format 冲突 | 同 source key 改 parser | 明确拒绝，不混合两种格式 |
| SYN-010 | 老 CLI | Claude/Codex 继续调用 legacy Prepare | 请求、事务、错误码、parser 和统计结果与冻结 Golden 完全一致 |
| SYN-011 | 新 CLI 连旧 API | 上传新增客户端 | capability 检查明确阻止；不得回退 legacy；Claude/Codex 仍可用 |
| SYN-012 | 并发上传同 Session | 两个进程同时上传 | advisory lock/游标保证不重复、不跳过 |
| SYN-013 | 服务端关闭一个 agent type | 上传该客户端和其他客户端 | 被关闭客户端返回稳定错误；其他客户端不受影响 |
| SYN-014 | 两个无关 Session 的原生短 usage ID 相同 | 上传并重建 | Adapter 使用原生作用域生成不同 `usage_fact_id`，分别计数 |
| SYN-015 | canonical 父子 Session 复制同一计费事实 | 调换 manifest 成员顺序，并分别让子/父 source 先完成 | canonical Prepare 先原子登记相同 family；两种顺序都只计一次，且归属原始 owner Session；legacy 路径未被调用 |
| SYN-016 | fork 后父子并行追加 | 分别追加并交错上传 | 父、子新事实分别归属，继承历史不重复，family total 稳定 |
| SYN-017 | family manifest 缺少 usage owner 或关系成环 | 提交 Prepare | 不创建任何 generation/job；报告内容可重试，usage 不得进入 exact |

### 7.5 ZCode

ZCode 在前置条件满足前只执行 Spike，不执行正式验收。Spike 至少回答：

1. 是否有官方/版本化的机器可读 Session 列表？
2. Session ID 是否稳定？
3. 正文、工具、模型、时间和 usage 字段语义是否明确？
4. 能否不读取凭据和诊断日志？
5. Windows、macOS、Linux 的数据位置和格式是否一致？

任一答案为否，则结论保持“暂不正式支持”，不能靠逆向私有数据库绕过。

### 7.6 腾讯 WorkBuddy

腾讯 WorkBuddy 在稳定输入契约满足前只执行 Spike，不执行正式验收。Spike 至少回答：

1. 是否有官方、版本化、机器可读的任务/Session 列表和单 Session 正文导出入口？
2. 普通任务、助理远程任务、自动化任务是否具有稳定且互不冲突的 Session ID？
3. 历史对话、工具调用、子 Agent、产物、时间和模型字段是否具有稳定语义？
4. 是否能只读取用户明确选择的任务，同时排除登录凭据、连接器配置、记忆、其他任务和本地文件正文？
5. Token/积分记录能否按稳定事件 ID、模型和 Session 对账，而不是只有账号级或任务级累计值？
6. Windows、macOS 的数据位置和格式是否一致；Linux 未正式支持时不得宣称覆盖？

任一关键答案为否，则保持 `detected + unavailable`。不得用逆向本地数据库、抓取内部云端接口或解析分享页面绕过门禁。

| CLI-019 | 正在写入且存在 pending tail | 显示 CURRENT/snapshot-only，不显示 Done |

## 10. 默认 Agent 核心回归

这是重点门禁，不能只直接调用 MCP。

### 10.1 个人日报

对 OpenCode、Kimi Code 分别执行：

1. 默认 1 天，不选 Session：自动来源只包含周期相交切片。
2. 默认 1 天，选择跨天 Session：完整切片进入报告，不按日期裁剪。
3. 默认 1 天，选择多个跨天 Session 和当天未自动选中的 Session：显式选择为最高优先级，未选切片不混入。

### 10.2 个人周报

重复上述三组场景，周期改为周；验证已保存日报与显式 Session 来源规则没有被客户端类型改变。

### 10.3 混合客户端

- 同一报告选择 Claude/Codex/OpenCode/Kimi Code 切片。
- 报告正文必须包含各自唯一事实标记。
- 来源快照数量、MCP 翻页和最终正文一致。
- 重新生成仍保持已选切片优先，不被已有正文覆盖。

### 10.4 四角色、六类型

使用真实默认 Agent 分别生成并保存：

1. 个人日报
2. 个人周报
3. 小组日报
4. 小组周报
5. 部门日报
6. 部门周报

验证：

- employee 只能看到和生成个人范围。
- team leader 汇总本小组已保存个人报告。
- PM 行为按现有授权不变。
- director 按 `departments.director_user_id` 权威关系汇总部门下小组报告。
- 小组/部门报告不直接读取成员新增客户端原始 Session。
- 六类报告的默认 MCP、Skill 版本、Agent 绑定和保存接口均为测试环境实际生效版本。

### 10.5 直接 MCP 对照

默认 Agent 验收通过后，再用测试环境实际生效的 MCP 直接执行相同来源读取：

1. 使用同一个 report source selection ID 读取全部分页。
2. 核对 Session、slice key、client/agent type、cursor、唯一事实标记与默认 Agent 运行时证据一致。
3. 核对显式选择中未选切片不会被日期/type 参数重新加入。
4. 直接 MCP 仅作为定位和对照证据，不能替代默认 Agent 生成与保存。

### 10.6 分阶段客户端门禁

- 阶段 1：OpenCode、Kimi Code 完整执行 10.1 至 10.5。
- 阶段 2：OpenClaw、Harness 至少分别执行个人日报、个人周报和混合客户端场景，再重跑四角色六类型回归。

## 12. Token 与成本专项对账

只有计划发布 `usage_capability=exact` 或 `usage_capability=estimated` 的客户端执行该门禁。

### 12.1 对账步骤

1. 保存原生 fixture、客户端统计截图/导出和预期逐事件 usage。
2. 首次上传，等待 usage jobs 和 metrics revision 完成。
3. 按 Session、日期、模型核对输入、缓存、输出、推理和总 Token。
4. 无变化重复上传，核对统计不变。
5. 追加事件后上传，核对只增加新增 usage。
6. 历史 rebuild，核对旧 revision 失效且总量不翻倍。
7. 配置价格后核对成本；未配置模型保持“待配置”。
8. 跨日 Session 按 usage 实际发生时间归属，不按上传日归属。
9. 对支持 subagent/fork 的客户端，分别执行父先子后、子先父后、父子交错、二级 subagent 和 compaction/reset；核对每个 `usage_fact_id` 只有一个有效 claim。
10. 分别核对 self、每个直接/间接 subagent 和整个 Session family；family 合计必须等于所有唯一计费事实之和。

### 12.2 误差门禁

- `usage_capability=exact`：逐调用、单 Session、每日、模型和 Session family 的所有整数 Token 字段必须完全一致，允许误差 0。
- `usage_capability=estimated`：必须记录估算算法和差异，不得在精确总计中混用。
- 成本按数据库精度和现有四舍五入规则核对。
- 任一重复计数、负增量或日期错位均阻止该客户端 Token 能力发布，但不必阻止已通过的 `report` 能力。
- fork/subagent 关系缺失、`usage_fact_id` 不稳定、原始 owner 无法确定或上传顺序改变最终归属时，必须阻止 `exact`。

## 14. 性能与稳定性

建议门禁：

- 10,000 个 Session 的索引扫描不一次性读取全部正文。
- 缓存命中后二次 `aida sessions` 的耗时不超过首次的 20%，并记录实际数据。
- 单 Session 1 GiB 时保持流式处理，常驻内存不随文件线性增长。
- OpenCode export 并发不超过 2；外部命令失败可取消。
- 一个 8 MiB 坏事件不能使 worker 崩溃或无限重试。
- 100 次重复无变化上传不增加切片、chunk、usage 或成本记录。

具体绝对耗时以阶段 0 基准机测量后冻结，不在无数据时预设虚假 SLA。

## 16. 发布停止条件

出现任一情况，停止该客户端发布：

- Claude Code/Codex 任一 legacy Golden、逐事实 Token、Session/family 汇总、成本或展示结果发生变化；该项停止整个多客户端开发，不只是单个客户端发布。
- 无稳定原生 Session ID。
- 官方格式无法通过版本化 fixture 固定。
- 首次/增量/rebuild 产生重复或丢失内容。
- 有效内容为 0 却形成可选切片。
- 凭据、全局诊断日志或其他 Session 内容被读取/上传。
- 默认 Agent 未真实使用选中切片。
- 四角色六类报告有权限或来源回归。
- Token 被展示为 0 但实际是不可用。
- 宣称 exact 的 Token 对账有任何整数差异。
- 同一计费事实被父 Session、subagent、fork 或包装器重复计算。
- `owner_session_ref` 无法验证，或父子上传顺序会改变 self/subagent 归属。
- 浏览器交互失败或关键视觉结果未人工确认。

某一个新增客户端被停止，不阻止已经独立通过门禁的其他客户端；发布说明必须逐客户端列出实际能力。
