### 1.2 当前同步链路的问题

当前手工报告链路位于一个 HTTP 请求内：

```text
StartReportAgentRun
  -> CreateAttachedRun
     -> Digest 未 ready 直接返回 409，且不创建 Run
  -> reportContext.Build
  -> CreateCredential
  -> CreateSession
  -> attachSessionAIRun
  -> 返回 Run
```

它无法满足以下要求：

- Digest 等待期间已经存在可查询的 `run_id`；
- HTTP 返回后、页面关闭后继续；
- Worker 释放执行槽位后由 Digest 完成事件恢复；
- 服务重启后根据持久化状态继续；
- 外部调用和状态落库之间崩溃后安全重试。

### 1.3 删除上一版错误设计

本方案删除并禁止：

- Digest 未 ready 时不创建 `ai_run`；
- 使用 prepared Selection 作为等待凭据；
- 启动接口返回 `preparing + selection_id + retry_after_ms`；
- 前端重试启动接口推动流程；
- Digest ready 后再由前端请求创建 Run；
- 页面关闭后停止推进、重开后靠 Selection 恢复；
- 向用户展示 missing/pending/building、提权或 Worker 状态；
- 用户显式“重新准备 Digest”；
- 新建平行的报告准备请求表。

### C. 已确认但不进入本期的外部能力

- AIHub CreateSession 接受幂等请求键并支持按该键查询 Session；
- AIHub CreateSession 接受明确的 `agent_version_id`；

C 类没有当前可用的外部接口，不进入 D01-D12、测试通过条件或 P0 发布阻塞项。完成前沿用《架构设计》的 [`submitting_agent`](架构设计.md#44-submitting_agent) 保守失败和[第一阶段冻结](架构设计.md#21-第一阶段创建-run-时冻结)中的 Agent Version 风险口径。
