# Aida 客户端上传与强制升级方案

> 文档状态：方案评审稿
> 更新时间：2026-07-16
> 目标版本：Aida CLI `0.1.11`
> 范围：本期实现上传状态反馈、轻量 TUI 和强制升级；checkpoint 身份隔离保留为后续项
> 非目标：不改变 Session 切片、Token、模型名称或成本统计口径。
> 统一入口：同目录 `README.md`；存在冲突时以总方案为准。

## 0. 当前版本结论

`0.1.11` 实施自动升级、轻量 Bubble Tea Session 选择器和上传 readiness 状态修复，不实施多客户端或上传协议调整。Claude Code、Codex 的扫描解析、checkpoint 格式、Session、Token 和成本口径必须与 `0.1.5` 一致。

生产 `0.1.5` 已配置 `release_url` 和 `auto_update: true`，可以自行下载 `0.1.11`，不需要用户再次执行 `install.sh`。由于 `0.1.5` 最多 24 小时检查一次，服务端发布期间必须继续兼容 `0.1.5`。

## 1. 背景

当前 Aida 客户端已经支持 Session 分页选择、增量 Prepare/Chunk/Finalize 上传、超大 Session 和断点续传。

生产使用中发现，客户端在 finalize HTTP 成功后立即显示：

```text
Done. ... processed.
```

但 finalize 成功只代表服务端接受了当前上传前缀。服务端仍需异步完成内容 projection，Session 达到 `available` 后才会出现在 Session 列表和日报来源中。

服务端“projection 成功后 Session 仍停在 `uploading`”的问题已由提交 `abbca02` 修复并发布生产。客户端 `0.1.11` 通过服务端权威 readiness 状态给出准确反馈，不再把 finalize HTTP 成功直接显示为 Done。

## 2. 范围说明

本版本处理以下问题：

1. finalize HTTP 成功后过早显示最终 `Done`；
2. 处理中、失败、超时和部分成功缺少明确区分；
3. 无参数 `aida upload` 的 Session 选择效率不足；
4. 当前自动更新可关闭且 24 小时才检查一次，旧客户端可以长期继续运行。

以下已确认问题保留为后续兼容性任务，不纳入本次 P0 补丁：

- `upload-state.json` 绑定服务端和用户身份；
- `aida upload --json`、稳定退出码和结构化结果。

以下问题明确不在本版本处理：

- LiteLLM 或其他上游在标准 `model` 字段中返回内部模型标识；
- 模型名称映射、规范化或显示转换；
- 针对 `/nfs/...`、`___` 等模型值增加客户端特殊规则；
- 历史模型名称和成本数据修正。

上游模型字段异常后续单独处理。Aida 客户端继续按协议采集原始 `message.model`，不猜测、不转换。

## 3. 当前问题

### 3.1 上传完成语义不准确

当前流程：

```text
Prepare
-> Chunk 上传
-> Finalize HTTP 200
-> 客户端显示 Done
-> 服务端异步构建 content/usage/metrics projection
```

风险：

- 用户看到 `Done`，但 Session 列表暂时没有数据；
- 用户重复上传；
- projection 失败或长时间处理中时，客户端仍可能误报成功；
- 正在写入的 Session 只上传了当前完整前缀，但用户误认为整个 Session 已结束。

### 3.2 checkpoint 缺少身份边界

当前 `upload-state.json` 的 key 主要由以下信息组成：

```text
agent_type + session_ref + source_key
```

没有绑定：

- 服务端地址；
- 当前用户 ID；
- Token 对应账号身份。

用户切换账号或测试服/生产地址后，存在复用其他身份 checkpoint 的风险。

### 3.3 上传结果缺少结构化总结

当前终端输出主要是 `OK/SKIP/FAIL/Done`，没有清楚区分：

- 本次没有变化；
- 上传已接受、服务端处理中；
- 已完成并可用于日报；
- 当前 Session 仍在生成，只上传了完整前缀；
- 主 Session 成功但 sub-agent 部分失败；
- projection 失败或等待超时。

## 4. 产品目标

客户端显示最终 `Done` 必须同时满足：

```text
generation 已 finalize
active content projection 已就绪
session.content_status = available
```

Token、Digest 等后续异步任务不阻断 Session 内容可用。客户端可以展示这些任务仍在处理，但不能将其描述成上传失败。

## 5. 详细方案

### 5.1 服务端 readiness 契约

优先复用现有接口；如现有接口不能稳定表达状态，则补充：

```http
GET /api/v1/session-syncs/{generation_id}/status
```

建议响应：

```json
{
  "generation_id": "uuid",
  "generation_status": "active",
  "content_status": "available",
  "content_projection_status": "active",
  "usage_status": "processing",
  "metrics_status": "processing",
  "ready_for_reports": true,
  "error_code": "",
  "error_message": ""
}
```

状态至少区分：

```text
accepted
processing
ready
failed
```

客户端以 `ready_for_reports` 和 `content_status` 为权威，不自行推断服务端是否完成。

### 5.2 客户端等待逻辑

1. finalize HTTP 成功后开始轮询；
2. 前 10 秒每 1 秒查询一次，之后每 2 秒查询；
3. 默认最多等待 60 秒；
4. `ready_for_reports=true` 时显示最终 `Done`；
5. 超时但未失败时显示“上传已接收，服务端仍在处理”；
6. 明确失败时显示服务端错误码并返回非零退出码；
7. `pendingTail=true` 时显示“已上传当前完整前缀，Session 仍可能继续产生内容”；
8. `unchanged` 且服务端已经 available 时直接完成，不重复等待。

正常输出：

```text
[UPLOAD]  019f...  3 chunks accepted
[WAIT]    服务端正在解析 Session...
[READY]   Session 已可用于日报和列表

Done. 1 ready, 0 processing, 0 failed.
```

等待超时：

```text
[PROCESSING] 019f... 上传已接收，服务端仍在处理

Completed. 0 ready, 1 processing, 0 failed.
```

等待超时不能打印最终成功语义的 `Done`。

### 5.3 checkpoint 身份隔离

`upload-state.json` 升级为版本 2，每条状态至少绑定：

```json
{
  "server_origin": "http://113.100.143.91:9180",
  "user_id": "14",
  "agent_type": "claude_code",
  "session_ref": "019f...",
  "source_key": "claude_code:019f...:main"
}
```

要求：

- `server_origin + user_id + agent_type + session_ref + source_key` 共同组成状态边界；
- 登录成功后通过鉴权接口取得稳定 `user_id`，不得从 JWT 文本自行猜测；
- 服务端地址切换时不得复用旧 checkpoint；
- 用户切换时提示尚未完成的上传；
- v1 状态文件只允许在确认当前服务端和账号后迁移；
- 无法确认身份时丢弃本地 checkpoint，以服务端 checkpoint 为准；
- Token 不写入状态文件。

### 5.4 错误输出和退出码

建议固定退出码：

| 退出码 | 含义 |
| --- | --- |
| `0` | 所选 Session 全部 ready 或 unchanged |
| `2` | 至少一个上传已接受但仍 processing |
| `3` | 部分成功、部分失败 |
| `4` | 鉴权或账号状态失败 |
| `5` | 本地 Session 解析或预检失败 |
| `6` | 服务端拒绝或 projection failed |
| `7` | 网络错误或请求超时 |

增加可选 JSON 输出：

```bash
aida upload --json
```

JSON 必须包含：

```text
session_ref
upload_status
generation_id
uploaded_chunks
pending_tail
content_status
ready_for_reports
error_code
```

### 5.5 强制升级

- 客户端目标版本为 `0.1.11`；
- 除 `version/help/update` 外，每次启动都请求现有 `aida-latest.txt`；
- 发布清单地址必须在登录前可用，不能依赖用户配置后才知道；
- 本地版本低于 latest 时安装新版；
- 不保留 24 小时检查间隔，不允许关闭更新门禁；
- 更新完成后自动重新执行用户原命令；
- 下载内容必须校验 SHA256，替换必须原子化；
- 发布清单不可达时告警并继续；已确认存在新版但下载、校验或替换失败时阻止业务命令；
- `0.1.11` 发布期间服务端继续兼容 `0.1.5`；
- 客户端回退仍走安装脚本或重新发布更高修复版本，本期不实现自动降级；
- 更新保留 Token、服务端配置、Session Index 和 checkpoint。

## 6. 开发拆分

### 第一阶段：必须完成

1. 每次业务命令检查 `aida-latest.txt`；
2. 编译期默认发布地址；
3. 下载和 SHA256 校验；
4. 原子替换；
5. 更新后重新执行原命令；
6. `0.1.5 -> 0.1.11` 过渡验收；
7. 真实 TTY 的 Bubble Tea Session 搜索、多选和取消；
8. readiness 查询及 `READY/PROCESSING/FAILED/CURRENT` 状态；
9. Claude Code、Codex 与 Token 全量回归。

### 后续阶段：延期项

1. checkpoint 身份隔离；
2. `aida upload --json`；
3. 更完整的上传处理进度视图；
4. `aida upload --resume` 汇总未完成上传；
5. 完整 Application Service/TUI 分层重构。

## 7. 测试方案

### 7.1 上传状态

| 用例 | 预期 |
| --- | --- |
| 首次上传新 Session | projection ready 后才显示 Done |
| finalize 成功、projection 延迟 | 显示 WAIT，最终转 READY |
| 等待超过 60 秒 | 显示 PROCESSING，退出码 2 |
| projection failed | 显示错误码，退出码 6 |
| Session 文件仍在追加 | 显示当前前缀已上传，不宣称 Session 已结束 |
| 无变化再次上传 | 显示 unchanged，不重复上传 |
| 主 Session 成功、sub-agent 失败 | 显示部分成功，退出码 3 |
| 服务端重启 | 客户端继续查询或明确显示处理中 |

### 7.2 身份隔离

| 用例 | 预期 |
| --- | --- |
| 同一机器切换账号 | 不复用旧账号 checkpoint |
| 测试服切换生产 | 不复用测试服 checkpoint |
| 删除本地状态后上传 | 从服务端 checkpoint 接续 |
| v1 状态升级到 v2 | 仅身份一致时迁移 |
| Token 更新但 user_id 相同 | 可继续使用同一身份状态 |
| 账号切换时存在未完成上传 | 明确提示，不静默串用 |

### 7.3 平台

至少覆盖：

- Linux amd64；
- Windows amd64；
- macOS arm64；
- Claude Code Session；
- Codex Session；
- 小 Session、超大 Session、超大单行、pending tail；
- 网络断开、请求超时、服务端重启。

### 7.4 强制升级

| 用例 | 预期 |
| --- | --- |
| 已是最新版 | 每次检查，不重复下载，继续原命令 |
| 存在新版 | 下载、校验、替换后自动继续原命令 |
| 发布清单不可达 | 告警并继续现有业务 |
| SHA256 不一致 | 不覆盖旧二进制并明确失败 |
| 服务端收到 `0.1.5` | 过渡期继续接受，等待自动升级覆盖 |
| 两个进程同时升级 | 最终二进制校验正确，不产生损坏文件 |
| Windows 更新 | 替换完成后自动重启原命令 |

## 8. 发布与回退

发布顺序：

```text
14.157 自动升级与既有流程验收
-> Aida 0.1.11 三平台构建和 SHA256
-> 测试账号安装包验收
-> 上传全部平台产物
-> 最后切换 aida-latest.txt
-> 服务端继续兼容 0.1.5
-> 用户升级通知
```

回退原则：

- `0.1.11` 出现问题时停止继续切换发布文件，并发布更高修复版本；
- 必须回退时使用安装脚本重新安装已验证版本；
- 不回滚服务端，不修改已上传数据；
- 本期没有 checkpoint 格式变化。

## 9. 验收门禁

以下条件全部满足才能发布 `0.1.11`：

1. 每次业务命令都执行版本检查；
2. 有新版时完成更新后才继续；
3. 发布清单不可达时现有业务继续；
4. 已发现新版但安装失败时旧命令不继续；
5. `0.1.5` 无需安装脚本即可升级；
6. 三平台安装包和 SHA256 验证通过；
7. 配置、Token 和现有 checkpoint 不丢失；
8. Claude Code、Codex 上传行为不变；
9. Token 和成本统计对账一致；
10. Bubble Tea TTY 与非 TTY 兼容通过；
11. projection 延迟、失败、超时和 pending tail 均不误报 Done；
12. 默认 Agent 核心流程通过。
