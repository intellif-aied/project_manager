# 第六阶段需求文档：通用 Report Context V1

> 文档状态：最终需求版  
> 日期：2026-07-20  
> 适用报告：个人日报、个人周报、小组日报、小组周报、部门日报、部门周报

## 1. 背景

当前六类报告的基础取数方式不一致：部分个人报告已由平台准备 Report Context，其他报告仍依赖 Agent 根据 Skill 自行查询报告、需求和任务。

这会导致相同的报告对象和周期，因模型、Skill 或调用路径不同而获取不同数据，并增加工具调用、Token 消耗、运行时间和失败概率。

第六阶段将六类报告统一到通用 Report Context V1：平台按确定规则准备报告事实，Agent 基于这些事实完成语义归并和最终表达。

## 2. 产品目标

1. 六类报告均使用平台确定的默认来源；
2. 相同用户、报告对象、报告周期和权限范围下，基础数据范围稳定可预期；
3. 同一次报告生成及其重试使用同一份输入；
4. Agent 不再自由扫描基础业务数据，只负责理解事实、归并成果和生成正文；
5. 组织报告能表达覆盖成员和下级报告是否可用，不因报告缺失而遗漏成员；
6. 需求和任务同时支持组织关联与个人负责人关联；
7. 平台不通过 Top-K、重要性排名或其他语义判断静默删除有效来源；
8. 不改变现有 Session 上传、Digest、usage、metering 和 Token Analytics 链路。

## 3. 产品原则

### 3.1 平台决定基础事实范围

报告类型、对象、周期、权限、组织关系和用户选择共同决定基础事实。Skill 和 Agent 不得临时扩大或缩小该范围。

### 3.2 同一次运行输入不变

报告生成开始后，本次已采用的下级报告正文、需求、任务、Session Digest、组织覆盖和权限范围保持不变。新的报告生成才重新读取当时的最新数据。

### 3.3 不静默裁剪

用户明确选择的 Session 以及按产品规则命中的下级报告、需求和任务，不得为了完成生成而被静默删除。

### 3.4 来源不可用不等于没有工作

下级报告不存在或不可用，只表示本次缺少该来源，不能被表述为对应成员或组织没有工作、没有活动或没有产出。

## 4. 六类报告的默认来源

### 4.1 个人日报

- 本人当日符合默认来源规则的 Session Digest；
- 本人在报告周期内相关的需求和任务。

用户明确选择 Session 时，本次只使用被选 Session 作为 Session 来源；需求和任务仍然保留。

### 4.2 个人周报

- 报告周期内本人现有个人日报；
- 本人在报告周期内相关的需求和任务。

未手动选择 Session 时，不自动读取整周 Session。明确选择 Session 时，所选 Session Digest 作为默认来源的补充。

### 4.3 小组日报

- 当前小组成员在报告日期内的现有个人日报；
- 小组范围内的需求和任务；
- 当前小组成员及其个人日报是否可用。

不读取成员 Session，也不在成员个人日报不可用时自动补取 Session。

### 4.4 小组周报

- 当前小组成员在报告周期内的现有个人周报；
- 小组范围内的需求和任务；
- 当前小组成员及其个人周报是否可用。

不读取成员 Session，也不在个人周报不可用时自动读取个人日报或其他更低层来源。

### 4.5 部门日报

- 当前部门直属小组在报告日期内的现有小组日报；
- 未被任何直属小组覆盖的部门直属成员在当日的现有个人日报；
- 部门范围内的需求和任务；
- 直属小组、直属成员及对应报告是否可用。

不在小组日报不可用时自动读取该组成员个人日报或 Session。

### 4.6 部门周报

- 当前部门直属小组在报告周期内的现有小组周报；
- 未被任何直属小组覆盖的部门直属成员在该周期内的现有个人周报；
- 部门范围内的需求和任务；
- 直属小组、直属成员及对应报告是否可用。

不在小组周报不可用时自动读取该组成员个人周报、个人日报或 Session。

## 5. 需求和任务的业务范围

### 5.1 周期范围

V1 使用现有系统能稳定识别的业务对象更新时间，选取在报告周期内发生更新的需求和任务。

该口径只能说明事项在本期发生过系统可识别的更新，不能据此断言具体字段或状态发生了什么变化。长期阻塞但本期没有任何更新的事项，不自动进入 V1 的本期事实。

### 5.2 个人范围

- 本人创建、负责或关注的需求；
- 本人创建、负责或关注的任务；
- 同一事项通过多个关系命中时只保留一份。

关注关系只影响个人报告，不把事项提升为小组或部门的工作来源。

### 5.3 小组范围

“小组范围内的需求和任务”不要求业务对象必须显式指定小组，包括：

- 显式关联当前小组的需求；
- 未指定小组，但由当前小组成员直接负责的需求；
- 由当前小组成员直接负责的任务，无论父需求是否指定小组。

仅由小组成员创建，但既未关联当前小组、也没有当前小组成员负责的事项，不因创建人身份自动进入小组来源。父需求进入小组范围，也不会将其他小组或部门直属成员负责的全部子任务带入当前小组。

### 5.4 部门范围

- 直属小组显式关联或部门范围内成员直接负责的需求；
- 由直属小组成员或部门直属成员直接负责的任务；
- 未指定小组但直接指定给上述成员的需求和任务；
- 同一事项通过多个小组或成员命中时只保留一份。

父需求进入部门范围，不会自动带入没有部门范围负责人命中的全部子任务。

## 6. Session Selection 产品语义

### 6.1 个人日报

- 未提交有效选择：使用当日默认 Session 来源；
- 提交明确非空选择：只使用用户选择的 Session；
- 手动选择只替换 Session 来源，不替换需求和任务。

### 6.2 个人周报

- 未提交有效选择：不读取整周 Session；
- 提交明确非空选择：所选 Session 作为个人日报、需求和任务的补充。

V1 不把空选择定义为“明确不使用 Session”的第三种产品状态，也不得因空选择自动加载整周 Session。

## 7. 组织覆盖和下级报告

### 7.1 小组报告

小组成员名单与个人报告是否可用是两类独立事实。成员个人报告不可用时，成员仍必须保留在小组覆盖中。

### 7.2 部门报告

- 属于直属小组的成员由该小组报告覆盖；
- 未被任何直属小组覆盖的部门直属成员由本人报告覆盖；
- 已由小组覆盖的成员不再以个人报告重复进入部门默认来源；
- 组织关系异常时明确记录，不由 Agent 猜测。

### 7.3 来源是否可用

产品需要区分：

- `available`：报告存在且正文可作为来源；
- `missing`：报告不存在；
- `invalid`：报告存在，但正文为空、周期不匹配或因明确原因无法使用。

面向用户可以统一表达为“来源不可用”，但系统必须保留具体原因。第六阶段不因来源不可用而自动读取更低层数据。

## 8. 确定性和重试

- 下级报告必须按报告类型、报告对象和准确周期唯一选择；
- 不使用“最近一条”、模糊日期或 Agent 判断代替确定规则；
- 发现同一对象和周期存在重复下级报告时，本次 Context 构建失败，不任意选择或静默忽略；
- 同一次报告重试时不重新读取已变化的当前正文或业务事实；
- 更换模型视为新的报告生成，重新按当时数据准备来源并重新判断容量。

## 9. 容量体验

- 平台对完整 Context 进行统一容量检查；
- 超过产品提醒阈值时，用户可确认继续；
- 确认后继续使用同一份已准备的 Context，不重新取数；
- 超过平台稳定性保护上限时，停止本次生成并返回明确容量结果；
- 不将字节大小伪装成精确 Token 或模型上下文判断；
- 未超过平台保护上限但被外部系统拒绝时，按外部执行失败呈现，不伪装为来源缺失。

## 10. 权限和数据安全

- 手动生成以当前发起用户为有效执行用户；
- 定时生成以定时任务所属用户为有效执行用户；
- 报告数据范围始终按有效执行用户的权限计算；
- 一次报告运行的标识不是授权凭据，不能用于读取其他用户或其他运行的 Context；
- Context 读取和结果写回使用一致的用户、运行和报告对象校验。

## 11. 默认 Skill 和 Agent 产品边界

平台交付一份能稳定完成六类报告的默认 Skill。该 Skill 使用平台准备的 Report Context，不再自由扫描基础数据。

Agent 负责：

- 识别和归并工作成果；
- 基于 Context 中的真实事实判断完成、进行中、失败和阻塞；
- 处理 Context 内事实的语义关系；
- 生成并写回最终正文。

Agent 不负责决定基础数据范围，不自行发现组织成员、下级报告或跨组任务。

## 12. 产品验收标准

1. 六类报告均能按本文定义的默认来源生成 Context 和最终报告；
2. 同一次报告重试时使用同一份输入；
3. 个人日报和个人周报的 Session Selection 行为符合本文定义；
4. 未指定小组但由小组成员直接负责的需求和任务，进入对应小组及部门报告；
5. 父需求进入报告范围时，不会自动将其他组织成员负责的全部任务归入当前组织；
6. 组织成员或直属小组不会因下级报告不可用而从覆盖范围消失；
7. 报告不存在和报告存在但不可用能够被区分；
8. 下级报告唯一、精确地按对象和周期选择，重复数据不被任意取用；
9. 容量提醒确认后不重新取数，超过保护上限时不静默删除来源；
10. 手动和定时生成均使用正确的有效执行用户和权限范围；
11. 默认 Agent 每次运行只读取一次完整 Context，不再自由扫描基础数据；
12. Session 上传、Digest、usage、metering 和 Token Analytics 行为不变。

## 13. 非目标

- 不修改 Session Digest 提取和清洗规则；
- 不读取组织成员原始 Session；
- 不做来源缺失后的自动降级汇总；
- 不做证据下钻、多轮取数或 Evidence Ref；
- 不检测上下级报告过期，不自动重新生成；
- 不新增任务状态历史系统、精确 Token 估算或模型能力版本体系；
- 不做成员贡献排名或服务端正文质量门禁；
- 不新增需求、小组或部门归属算法；
- 不设计跨 Run Context 或 Digest 复用；
- 不将用户自定义 Skill 产品化纳入第六阶段。
