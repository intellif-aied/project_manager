# 第六阶段测试与验收方案：通用 Report Context V1

> 文档状态：主体用例已确定；容量与 Run 级安全用例待对应决策补齐协议细节  
> 日期：2026-07-20  
> 需求基线：[01-需求文档](01-需求文档.md)  
> 架构基线：[02-架构设计](02-架构设计.md)

## 1. 测试原则

- 产品验收只从需求文档派生；
- 技术风险验证只引用已确认架构决策；
- 通过 Report Context 的公开构建/读取入口和真实报告链路验证，不绑定内部 Reader、类或包拆分；
- 构建成功不能替代真实 Agent 生成和最终报告人工检查；
- A-04、A-05、A-06 未确认前，只保留目标级用例，不伪造接口字段或状态码。

## 2. 六类报告主链路

| 用例 | 需求引用 | 场景 | 可观察结果 | 层级 |
|---|---|---|---|---|
| R-01 | 4.1、5.2、6.1 | 个人日报未手动选择 Session | 使用当日默认 Session Digest，并包含本人相关需求任务 | 集成 + 真实 Agent |
| R-02 | 4.2、5.2、6.2 | 个人周报未选择 Session | 使用个人日报和本人需求任务，不自动读取整周 Session | 集成 + 真实 Agent |
| R-03 | 4.3、5.3、7.1 | 小组日报 | 使用成员个人日报、小组需求任务和完整成员覆盖 | 集成 + 真实 Agent |
| R-04 | 4.4、5.3、7.1 | 小组周报 | 使用成员个人周报，不降级读取日报或 Session | 集成 + 真实 Agent |
| R-05 | 4.5、5.4、7.2 | 部门日报 | 使用直属小组日报和未被小组覆盖的直属成员个人日报，覆盖不重复 | 集成 + 真实 Agent |
| R-06 | 4.6、5.4、7.2 | 部门周报 | 使用直属小组周报和直属成员个人周报，不读取组织成员 Session | 集成 + 真实 Agent |

## 3. 来源范围和组织覆盖

| 用例 | 需求引用 | 场景 | 可观察结果 |
|---|---|---|---|
| S-01 | 5.1 | 事项 `updated_at` 在周期内/外 | 仅周期内事项进入；结果不声称具体字段发生变化 |
| S-02 | 5.2 | 用户以创建、负责、关注多重关系命中同一事项 | 个人 Context 只保留一份 |
| S-03 | 5.3 | 需求未指定小组，但小组成员直接负责 | 需求进入该小组 Context |
| S-04 | 5.3 | 任务未指定小组概念，但小组成员直接负责 | 任务进入该小组 Context |
| S-05 | 5.3 | 父需求进入小组，子任务由其他小组或直属成员负责 | 子任务不被扩散到当前小组 |
| S-06 | 5.4 | 未指定小组的需求/任务直接指定部门范围成员 | 进入部门 Context |
| S-07 | 7.1 | 小组成员没有个人报告 | 成员仍在覆盖中，来源为 missing |
| S-08 | 7.2 | 部门成员属于直属小组 | 只由小组覆盖，不重复加入个人报告 |
| S-09 | 7.2 | 部门直属成员无小组 | 由本人报告覆盖 |
| S-10 | 7.3 | 报告记录存在但正文为空 | 状态为 invalid，保留报告标识和原因，不等同 missing |
| S-11 | 8 | 同一对象、类型、精确周期出现异常重复记录 | Context 构建失败并保留可排查原因，不任意取一条 |

## 4. Session Selection

| 用例 | 需求引用 | 场景 | 可观察结果 |
|---|---|---|---|
| SS-01 | 6.1 | 个人日报未提交有效 Selection | 使用当天默认 Session 来源 |
| SS-02 | 6.1 | 个人日报提交非空 Selection | 只替换 Session 来源；需求任务仍存在 |
| SS-03 | 6.2 | 个人周报未提交有效 Selection | 不自动读取整周 Session |
| SS-04 | 6.2 | 个人周报提交非空 Selection | 所选 Digest 补充个人日报和需求任务 |
| SS-05 | 6 | 空选择 | 不形成独立第三态，不触发整周 Session 自动加载 |
| SS-06 | 3.3、6 | 多个明确选择的大 Session | 全部选择被完整冻结，不做 Top-K 或静默裁剪 |

## 5. 冻结、确定性和重试

| 用例 | 需求引用 | 场景 | 可观察结果 |
|---|---|---|---|
| F-01 | 3.2、8 | Context 构建后修改下级报告正文 | 同一 Run 重读仍为原正文和原 Hash |
| F-02 | 3.2、8 | Context 构建后修改需求、任务或组织关系 | 同一 Run 重读不变；新 Run 读取新事实 |
| F-03 | 8 | 同一 Run 重试 | 不重新执行来源查询，不覆盖 Context |
| F-04 | 8 | 更换模型 | 创建新 Run，重新冻结默认来源并重新判断容量 |
| F-05 | 8 | 服务端内部多页来源 | 所有页成功后才生成 Context；任一页失败则 Run 构建失败 |
| F-06 | 8 | 相同冻结输入重复规范化 | 数组顺序、序列化结果和 Hash 稳定 |

## 6. 权限和定时任务

| 用例 | 需求引用 | 场景 | 可观察结果 |
|---|---|---|---|
| A-01 | 10 | 手动 Run | 有效执行用户为发起用户 |
| A-02 | 10 | 定时 Run | 有效执行用户为 `schedule.user_id`，周期使用 Schedule 时区 |
| A-03 | 10 | 其他用户携带目标 `run_id` 读取 Context | 返回不可区分的未授权/不存在结果，不泄露内容 |
| A-04 | 10 | 同一用户的 Agent 凭据尝试读取另一个 Run | 被 Run 作用域校验拒绝 |
| A-05 | 10 | 凭据写回非绑定 Run 或非绑定报告对象 | 被拒绝，且读取与写回规则一致 |
| A-06 | 10 | 全局平台身份直接访问用户 Context | 不能绕过有效执行用户和当前 Run 约束 |

A-04～A-06 的具体请求形式在 A-05 架构决策确认后补齐，但产品预期不变。

## 7. 容量和失败边界

| 用例 | 需求引用 | 场景 | 可观察结果 |
|---|---|---|---|
| C-01 | 9 | 完整 Context 未达软提醒 | 直接启动当前 Run |
| C-02 | 9 | 完整 Context 达到软提醒 | 返回轻量确认；Context 已冻结 |
| C-03 | 9 | 用户确认继续 | 使用同一 Run、同一 Hash，不重新取数 |
| C-04 | 9 | 用户更换模型 | 新建 Run 并重新容量判断，不复用旧判断 |
| C-05 | 9 | 达到经验证的 Aida 平台保护上限 | 停止生成并返回明确容量结果，不静默删除来源 |
| C-06 | 9 | 未达平台保护但外部 Agent/模型拒绝 | 记录外部执行失败，不标记来源缺失 |
| C-07 | 9 | 检查容量展示与日志 | 明确为字节口径，不显示伪精确 Token |

C-02～C-05 的边界值和协议细节在 A-04、A-06 确认后填写。C-06 只验证外部拒绝被正确归类，不尝试推导统一模型上限。

## 8. 默认 Agent 和报告结果

| 用例 | 需求引用 | 场景 | 可观察结果 |
|---|---|---|---|
| M-01 | 11、12 | 六类默认 Agent 运行 | 每次只调用一次 `get_report_context`，不调用基础扫描工具 |
| M-02 | 3.4、7.3 | Context 有 missing/invalid 来源 | 报告不表述为成员没有工作或没有产出 |
| M-03 | 11 | Context 含多个 Session/报告/事项 | Agent 归并成果、状态和风险，最终正文可人工核对到 Context |
| M-04 | 11 | Agent 未调用 Context 或未写回 | Run 不得标记为真正成功 |

真实验收至少为六类报告各运行一次，并保存：Run ID、Context Hash/Bytes、Agent Session ID、MCP 调用日志、最终报告正文和人工结论。

## 10. 发布门禁

- A-04、A-05、A-06 已验证并确认；
- R-01～R-06 全部通过真实 Agent 链路；
- S、SS、F、A、C、M、G 各组无未解释失败；
- 同一 Run 的 Context 可复现，确认容量后不重新取数；
- 默认 Agent 没有自由扫描基础数据；
- 没有静默裁剪、自动降级或第六阶段外能力；
- Session、Digest、usage、metering 和 Token Analytics 回归通过。
