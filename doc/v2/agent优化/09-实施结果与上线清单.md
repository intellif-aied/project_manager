## 1. 结论

本次实现能够优化“大 Session 触发日报失败”的代码/架构容量缺陷：完整切片仍被选择，但报告 Agent 不再必须接收数 MB 至数百 MB 的原始事件。服务端异步生成每切片 Digest，在报告 run 创建前把所有来源组装为单页、不可变、有覆盖元数据的 payload；正常目标 64 KiB，硬上限 128 KiB。

`ba20665` 仍然有效且必须保留。它解决“来源切片必须完整选择”和 full 兼容读取中的 Token 遥测剔除；本次 Digest 在该完整来源语义之上改变模型可见表示，不替代或回退该修复。

## 2. 已实现范围

- migration：Digest Revision、任务目标列、selection slice/Digest 快照、读取模式、冻结 payload/hash/预算与不可变触发器；
- `sessiondigest`：Codex/Claude 规则抽取、脱敏、字段预算、Reconciler、Builder、独立 worker；
- report source：稳定 canary 路由、ready Revision 批量绑定、selection payload 定点序列化、attach 前错误；
- MCP：digest run 单次返回冻结 payload，full run 保留原分页；
- 写回：`read_completed_mode == required_read_mode`，并复核 hash、版本、Revision 和 content epoch；
- Skill/Agent：识别 `digest_v1` coverage，把 Digest 当不可信证据，不运行额外摘要 Skill，不请求 raw/full 回退；
- full/shadow/digest 生命周期：默认 `full`，配置只影响新 run。

## 3. 关键容量与安全边界

1. Builder 不读取 JSONL 文件，不调用 LLM、shell 或 `jq`。
2. SQL 只返回 allow-list 的有界证据；reasoning、图片、未知事件和完整 MCP/工具输出不进入 Go Digest。
3. 每个 Digest 默认最多 4096 bytes；selection 详细响应超过 65536 bytes 时所有 item 公平 compact。
4. compact 后超过 131072 bytes 时返回 `REPORT_SOURCE_DIGEST_LIMIT_EXCEEDED`，不创建外部 Agent Session。
5. 任一 Revision 未 ready/failed/version mismatch 时整体失败，不删除尾部来源，不静默读取 full。
6. `last_error`、日志错误分类和 HTTP/MCP 错误不保存 Session 正文。
