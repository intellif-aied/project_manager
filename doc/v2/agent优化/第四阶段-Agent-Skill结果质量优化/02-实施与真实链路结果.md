# 实施与真实链路结果

> 执行日期：2026-07-17
> 最终测试候选：`100866/aida-report@1.0.37`
> 结论：真实链路通过，内容完整性通过；默认报告内部定位信息清理未达到生产验收线

## 1. 实施内容

### 1.1 Skill 可发现性与加载

基线 `1.0.33` 的 `SKILL.md` 没有 YAML frontmatter。Agent Session 虽显示 Skill 已挂载，但模型可能只看到资产名称而不调用 `Skill` 工具，写作规则实际上没有进入上下文。

本轮修复：

- 为 `SKILL.md` 增加 `name` 和 `description` frontmatter；
- 在默认报告运行协议中要求真实调用 `Skill` 工具并观察 tool result；
- 明确输入文本里出现 `/aida-report` 不等于 Skill 已加载；
- Prompt 只负责加载顺序、参数和 MCP 回写，不包含日报内容裁剪规则。

这项修复是本轮最关键的架构发现。仅发布新 Skill 版本但不保证真实加载，无法稳定评价 Skill 优化效果。

### 1.2 默认日报写作规则

`aida-report` 增加了四类跨样本规则：

1. 对同一工作对象按时间线采用最后一个有证据支持的纠正、回退、取消或范围决策；
2. 开发、测试、沙箱和未知环境不得强化为生产环境；
3. Digest 的工作单元数、事件数、活动时长、Agent 类型等结构统计不得当成工作量；
4. 默认报告应把内部定位证据改写成读者可理解的结论，同时保留项目、结果、失败、决策、版本和高层验证信息。

第 4 类规则包含显式例外：运行输入明确要求，或另一个明确选中的用户 Skill 要求时，可以保留精确定位值，避免系统默认 Skill 阉割用户自定义报告能力。

## 6. 结论

本轮证明了两件事：

1. 默认 Agent 过去并不稳定加载 Skill；frontmatter 加显式、可观察的 Skill 工具调用是必要修复。
2. 在 Skill 已完整加载的前提下，MiniMax-M2.5 仍会违反内部定位信息清理规则。继续堆叠同义禁令只会增加 Skill token 和运维复杂度，不能证明可以稳定解决。

因此 `1.0.37` 适合作为第四阶段开发候选和后续模型/Skill 对照基线，但当前不建议直接发布生产。若生产目标要求“默认不展示私有地址、hash、路径”是硬门槛，应先决定：

- 接受其为模型/默认 Skill 的软约束，允许用户二次编辑；或
- 在不审查用户自定义 Skill 的前提下，设计仅对系统默认 Skill 生效的结构化写作链路。

本阶段不选择第二条，也不修改 Digest 或服务端正文。

完整未改写输出见 [十样本 Agent 日报原文](04-十样本Agent日报原文.md)。
