# 十样本基线与评分表

> 基线：`100866/aida-report@1.0.33`
> Digest：`session-digest/v2.9.0`
> 原始运行证据：第三阶段《第三轮真实链路与 Agent 验收》《第三轮 Agent 日报原文》

## 1. 评分维度

每份日报按以下六项校对，不使用单一总分掩盖致命问题：

| 维度 | 通过标准 |
| --- | --- |
| 语义覆盖 | 每个实质工作对象、结果、决策、失败和未解决项均有合理表达 |
| 最终状态 | 同一主线按时间线采用最后一个有证据支持的状态 |
| 完成度 | 不把讨论升级为完成，不把部分完成升级为全部完成 |
| 术语准确 | 环境层级、版本、项目和功能名称不被擅自强化或改写 |
| 表达可读 | 以用户能识别的工作对象组织，不以 Digest 内部结构组织 |
| 内部噪音 | 默认不展示与日报理解无关的机器定位信息和原始证据清单 |

任一项出现关键事实遗漏、错误当前状态、错误完成度或环境层级误写，均判为该样本未通过；不能靠其他维度的可读性抵消。

## 2. 基线问题和本轮观察点

| 批次 | 样本重点 | `1.0.33` 基线问题 | 本轮必须观察 |
| --- | --- | --- | --- |
| B01 | Dashboard、Token 权限、自动化、历史、分页、UI | 采用了弹窗自动关闭的早期状态；生成无可靠依据的 45/8/2 统计 | 最终回退边界正确；无内部计数；主线仍完整 |
| B02 | Session 切片、MCP、文档、测试与发布 | 概览状态数字与正文不一致 | 不再自行统计；不删实质成果 |
| B03 | 插件、UI、安全、分析 | 把最终否决的批量上报列为待跟进 | 明确保持单事件即时上报；不生成虚假待办 |
| B04 | P0 修复、Aida、候选查询、Bug、架构 | 暴露 Session ID、commit、主机等证据 | 删除定位噪音但保留完整交付内容 |
| B05 | AutoRound 根因、修复边界、文档 | 暴露哈希、绝对路径、行号、权限 | 保留根因、边界和交付；省略机器定位信息 |
| B06 | 审计与产品实现 | 基线表现正确 | 保持“审计已交付、产品部分完成”和测试失败 |
| B07 | HWM、Labgrid、映射、Review | 将 36 开发环境误写为生产环境 | 环境层级必须准确；内容覆盖不缩水 |
| B08 | 代码问答、MoE、PDF、Skill | 暴露事件数、highlight 数和跨日活动跨度 | 不展示 Digest 统计；四类工作均保留 |
| B09 | 远程访问验证 | 暴露私有地址和 commit hash | 短日报仍保留唯一实质结果，不打印定位值 |
| B10 | SkillOpt、推理配置、基础设施、Aida logout | 技术证据过多 | 保留四类结果；省略 commit、主机、路径和配置证据 |

## 3. 基线结论

`1.0.33` 已能覆盖主要工作，问题集中在写作层，而不是 Digest 缺失。第四阶段不能通过继续裁剪 Digest、固定 Top-K 或禁止所有技术细节解决这些问题。

本轮正向控制是 B06：任何新规则若使其测试失败、部分完成或未解决项消失，即使其他样本更简洁，也视为回归。
