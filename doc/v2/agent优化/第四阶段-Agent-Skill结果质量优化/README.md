# 第四阶段：默认 Report Skill 结果质量优化

> 建立日期：2026-07-17
> 开发分支：`feat/report-agent-quality-stage4`
> 状态：十样本开发测试已完成，候选未发布生产

## 1. 目标

在冻结 `session-digest/v2.9.0`、同一模型和同一批 B01-B10 真实样本的前提下，只优化平台默认 `aida-report` Skill 的日报表达：

- 完整覆盖 Digest 已保留的实质成果、决策、失败、阻塞和待办；
- 同一工作主线按时间线采用最后一个有证据支持的状态；
- 不把开发、测试、沙箱或未知环境擅自写成生产环境；
- 不把 Digest 结构统计当成工作量或工时；
- 默认不展示只用于机器定位证据的内部标识，同时保留其支持的工作结论；
- 保留用户能识别的项目、功能、文档、产品版本和高层验证结果。

本阶段不追求固定模板或完全消除技术细节。允许一定噪音，内容完整性优先于简短。

## 3. 修改边界

本阶段只修改：

- `api/service/daily_report_skill.go`；
- 对应的 Skill 契约测试；
- 默认报告 Agent 的 Skill 加载协议及其契约测试；
- 本阶段评测文档。

明确不修改：

- Digest 提取、预算、去噪或排序；
- Agent Prompt 中的日报内容规则；Prompt 仅允许增加可观察的 Skill 加载顺序和写回协议；
- 服务端正文校验器或内容审查；
- MCP 接口与写回协议；
- Session 上传、原文、Token 统计和 Aida 客户端；
- 用户自定义 Skill；
- Web。

## 4. 十样本验收规则

### 4.1 必须满足

1. 10/10 真实 Agent run 成功读取完整 Digest，并调用 `write_report_result`。
2. B01、B03 采用后续纠正或最终决策，不把已回退/已否决方案写成当前成果或待办。
3. B07 保持证据中的环境层级，不得把开发环境升级为生产环境。
4. B01、B02、B08 不新增来自 Digest 结构的工作数、状态数、类别分布、活动时长或 Agent 类型统计。
5. B04、B05、B08、B09、B10 默认不展示 UUID、Session/run 标识、精确 commit/hash、内网地址、私有仓库 URL、绝对路径、行号、权限和原始命令；但其支持的业务或交付结论必须保留。
6. B06 必须继续表达“审计已交付、产品仅部分完成”，并保留有意义的测试失败或未解决项。
7. 10 个样本中每个实质工作对象都应可识别，不能为降噪压缩成少数空泛类别。
8. 没有明确来源时，不生成通用的“继续优化”“持续验证”等后续计划。

### 4.2 允许保留

- 项目、功能、Bug、文档和设计决策名称；
- 用户能理解的产品版本；
- 能证明交付状态或解释阻塞的高层测试结果；
- 对完成度有意义的失败、回退、部分完成和风险；
- 对读者确实必要、或用户明确要求的技术定位信息。

## 5. 迭代和停止条件

- 每一版必须先通过仓库测试，再发布为测试 owner 下新的不可变 Skill 版本。
- 每一版都使用同一批 B01-B10，不为单一样本加入专用关键词或特殊分支。
- 若新增规则使关键事实遗漏、完成度被错误升级、报告明显空泛，立即回退该规则。
- 最多进行三轮有实质差异的校对；达到跨样本验收规则后停止，不追求无限优化。
- 本阶段结果只用于测试环境，生产发布另行决策。
