## 1. 本期任务

### D-01：冻结 Presentation Profile

- 对应需求：验收 3、4、11；
- 当前位置：`api/internal/reportcontext/types.go`、`service.go`、现有 `projection.go`；
- 最小改动：增加 `PresentationProfile`、`Payload.PresentationProfile *PresentationProfile` 和包内 `presentationProfileFor(reportType)`；使用 `omitempty` 保持历史 Payload 不变，只对 `work_evidence` 表示要求 Profile；
- 完成标准：六类映射逐项确定；Profile 与 Payload 一起 Hash；历史 Context 不变；
- 真实依赖：现有冻结 `report_type` 和 `report_run_contexts`；无外部依赖。

### D-02：精简全局 Skill

- 对应需求：验收 5、8、9、10；
- 当前位置：`api/service/daily_report_skill.go`、`daily_report_skill_test.go`；
- 最小改动：删除六类来源路由和 Digest 内部路径，只保留架构文档第 3 节七项通用职责、证据安全和写回规则；Git 信息只保留在 Context 中辅助溯源，Skill 不据此判断成果，不生成提交或分支操作清单；
- 完成标准：Skill 不要求模型选择来源或报告模板；Profile 存在时严格使用当前 Profile；历史无 Profile 时只使用一条通用兼容规则；Git 操作不成为独立工作项或成果依据，独立 Evidence 支持的真实成果完整保留；
- 真实依赖：D-01。

### D-03：Summary 写回、最终 Content 组合和幂等

- 对应需求：验收 1、10；
- 当前位置：`api/handler/report_mcp_tools.go`、`report_mcp_write.go`、`report_mcp_test.go`；`report_context_representation` 位于 `ai_runs.execution_input_json`，当前 `aiRunGuard` 尚未读取；
- 最小改动：Tool Schema 声明 Summary 字符串但保持历史兼容；扩展 Guard 查询读取现有 execution input 中的冻结表示；服务端对新 `work_evidence` Run 归一并校验 Summary，组合“工作总结 + 正文”为最终 Content；现有 Hash 继续计算最终 Content；
- 完成标准：缺失或空 Summary 不能完成新 Run；历史 Run 继续原样写 Content；MCP 参数不能伪造表示；最终 Content 相同则幂等，不同则冲突；历史已成功 Run 的重试 Hash 不变；
- 真实依赖：现有 Run Input 中的 `report_context_representation`。

### D-04：收敛默认 Agent Prompt

### D-05：精简默认 Agent MCP Toolset

- 真实依赖：D-02～D-05。

## 2. 开发顺序

```text
D-01 Profile 纯函数与 Context 测试
  -> D-02 Skill 精简与静态契约测试
  -> D-03 Summary 写回、最终 Content 组合与幂等测试
  -> D-04 默认 Agent Prompt 收敛
  -> D-05 默认 Agent MCP Toolset 精简
  -> D-06 资源文档与验收脚本
  -> 全量自动化
  -> 测试服六类真实报告
```

D-01、D-02 完成后必须先用冻结 Context 离线验证 Profile 只改变组织规则、不改变 Evidence，再进入写回组合开发。

## 3. 事务和失败

- Profile 构建失败：沿用 Context 构建失败，不启动 Agent；
- Summary 缺失：`write_report_result` 返回稳定业务错误 `REPORT_SUMMARY_REQUIRED`，Run 不写成功；
- 正文首个非空行是 `## 工作总结`：返回 `REPORT_CONTENT_DUPLICATE_SUMMARY`，不写入重复章节；
- 最终 Content 入库失败：事务回滚，报告和 Run 均不进入成功；
- 页面请求失败：不改变后端报告状态；
- 外部 Agent 失败：沿用现有 Run 失败同步；
- 不增加自动重试、补偿任务或第二次 Summary 生成。

## 4. 回退

- 回退顺序：先回退后端应用镜像，再按系统资源文档回退 Skill；禁止只回退 Skill、保留强制 Summary 的新后端；
- 无数据库迁移和前端资源需要回退；
- Profile：回退后新 Run 不再写入，历史 Context 保持不可变；
- 已生成报告的“工作总结”已经属于 Content，随报告保留，不批量删除。

## 5. 不修改的代码

- Digest 提取、Digest Job、Worker、urgency 和队列；
- Report Projection 的事实保留与紧凑编码规则；
- 六类来源查询、Selection、Generation、组织范围和权限；
- `get_report_context` 的 run_id 单参数 Interface；
- Agent Platform 模型和 Session 创建契约；
- Codex、Claude Code 上传、usage 和 Token Analytics。

## 6. 开发完成定义

只有同时满足以下条件才算完成：

1. D-01～D-06 全部完成；
2. [04-测试与验收.md](04-测试与验收.md)全部自动化门禁通过；
3. 六类测试服真实报告均成功写入单一最终 Content，且包含工作总结与完整正文；
4. 用户确认 Summary 能替代人工二次概括，正文归并质量不下降；
5. 没有模型切换、额外模型调用、来源变化或上传/Token 回归；
6. 完成实际 Skill 版本、发布镜像和回退版本记录。
