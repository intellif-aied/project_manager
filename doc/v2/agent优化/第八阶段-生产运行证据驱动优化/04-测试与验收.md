## 1. 测试原则

- 每项优化使用冻结的相同 Report Context、相同 Agent 输入和相同模型做修改前后对照；
- 构建成功不能代替真实 Agent 链路验收；
- 精确 Token 使用供应方或 Langfuse usage；
- 质量结论必须人工核对事实覆盖，不能只依赖字数或模型评分；
- 未确定的代码改动不预设内部实现测试。

## 4. 回归范围

- Codex 与 Claude Code Session 上传和增量游标；
- Token usage、Subagent fork 去重和 Token analytics；
- 报告 Selection、Generation 与冻结 Context；
- `get_report_context(run_id)` 权限以及紧凑 Context 单次读取；
- 默认 Skill 的确定性加载；
- Digest Job、Claim、Worker、urgency、重试和队列指标；
- Agent Session 创建、状态同步和失败处理；
- `write_report_result` 写回和 `ai_run` 最终状态；
- 个人与组织六类报告现有入口。

## 5. 真实链路验收

每项优化至少选择一个原问题样本、一个同类独立样本和一个原本正常的回归样本。固定输出修改前后的事实覆盖、错误、Digest 构建耗时、队列最老等待时间、Projection CPU/内存/耗时、MCP 调用数、模型调用数、输入/输出/缓存 Token、成本和写回状态。输入、模型或 Context 不一致时，该结果不得作为优化对照。

### 5.1 2026-07-23 首轮测试服回放

回放使用测试用户、隔离 Skill、隔离 Agent 和专用 `ai_run`，未修改系统默认 Skill/Agent，未读取或写入生产环境。结论如下：

| 模型健康检查 | GLM-5.2，仅回复 `OK` | 7 秒成功 | 模型服务可执行 |

| 完整报告回放 | GLM-5.2，同一 10,911-byte Context | 303 秒后完成 Skill 加载；继续运行至 1,242 秒仍未调用 MCP，人工取消；Run 正确进入 `failed` | 外部 Agent 执行未到达 Context，不用于评价 Projection；Aida 失败边界正常 |

## 6. 发布门禁

- 所有目标问题的对照用例通过；
- 所有高风险架构用例通过；
- 既有上传、Token 和报告链路无回归；
- Git 操作噪声样本不再生成工作项或成果结论；只有独立 Evidence 支持的功能、修复、发布或故障处理结果才进入报告；
- 没有未解释的成本或耗时上升；
- 已准备单项关闭或版本回退方式；
- 未决架构项不进入发布。
