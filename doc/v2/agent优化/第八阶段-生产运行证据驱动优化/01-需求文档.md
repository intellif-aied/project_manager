# 第八阶段需求文档：生产运行证据驱动的报告 Agent 优化

> 文档状态：已定稿
> 日期：2026-07-23
> 适用范围：Aida 托管报告 Agent 的生成链路

## 1. 背景

生产中已经出现普通模型无法稳定完成报告、MCP 返回过大、工具调用异常、最终报告空泛以及高成本模型可完成但成本过高等问题。现有 Agent Platform 已持久化 Session、Thread、工具调用和结果事件，Aida 已持久化 `ai_run` 与 `external_session_id`，具备从真实运行证据定位问题的基础。

## 2. 产品目标

1. 用生产真实证据定位报告质量、耗时、成本和稳定性问题所在层级；
2. 在 Agent 平台规定的固定报告模型下提高报告稳定性，不由 Aida 切换模型规避问题；
3. 每项优化均使用相同输入和平台规定的同一模型进行修改前后对照；
4. 保持现有上传、Digest、Token 统计、报告权限和写回语义不变。

## 3. 产品规则

### 3.1 生产证据是优化入口

- 每项优化必须关联具体 `run_id` 或 `external_session_id`；
- 必须保留关键事件、错误、耗时和结果证据；
- 普通优化至少由三个不同 Session 的同类问题或稳定复现支持；
- 数据错误、权限错误、重复执行/写回或报告无法生成等 P0，可由一个已确认且可复现的生产事件立项。

### 3.2 固定问题归属

问题只能归入以下一类主责层级，其他层级记录为影响因素：

1. 输入与 Report Context；
2. Agent Prompt 与 Skill；
3. MCP 工具契约和调用流程；
4. Agent Platform 模型可用性（只记录归因，不由 Aida 修改模型）；
5. Agent Platform 执行与 Aida 写回。

不得在根因未确认时同时修改多个层级。

### 3.3 内容与模型边界

- Digest 不代替 Agent 判断用户内容价值，不新增内容硬限制；
- 不恢复 Top-K、静默裁剪或残缺报告；
- 报告模型由 Agent 平台规定；Aida 不自动切换、不降级、不提供备用模型，也不通过请求参数临时覆盖模型；
- 精确 Token 只采用模型供应方或 Langfuse 的 usage 数据，不用字符数估算；
- Digest 构建和 Report Projection 不新增 LLM 调用，语义归并只由最终 Report Agent 执行。

### 3.4 Agent-facing Context 契约

- Agent 只依赖报告业务语义，不依赖 `sessions[].digest.report_period_summary.days[].highlights` 等 Digest 内部存储路径；
- 每个 Run 仍对应一份不可变 Report Context 和一个 `context_hash`；
- 新 Run 在创建事务中冻结 `report_context_representation=work_evidence`；没有该标记的历史 Run 继续构建和读取旧 Context 结构；
- Agent 启动输入只有 `run_id`，并通过一次 `get_report_context(run_id)` 获取适合生成报告的紧凑 Context；
- 不使用分页掩盖总输入过大；先以生产样本定位重复和膨胀来源，再确定不静默裁剪事实的收敛结构；
- Report Projection 是现有 Report Context Builder 内部的确定性模块，不创建新 Job、队列、表或外部调用；
- Projection 只做整块去重、统一事实表达、查找表复用和自描述列式编码，不按重要性排序，不做语义主题归并；列定义只出现一次，每行字段位置由列定义唯一确定，查找表引用从 1 开始并必须可解析；
- Digest 冻结的每条报告结果事实、`work_unit_ref` 和 `evidence_refs` 必须全部进入 Projection；Digest 仅以计数表示的非结果 Work Unit 继续保留覆盖计数，Projection 不伪造其正文；
- 同一目标下的跨功能、文档、部署、验证和修复归并继续由最终 Report Agent 完成；
- Projection 失败时 Run 明确失败，不允许退回超大原始 Context 或生成残缺报告。

### 3.5 生产安全与隐私

- 数据采集只读；
- 先从目标 `ai_run` 确认生产用户 ID，再以该用户身份获取其 Agent Platform Session；
- 取证 Token 只允许存在于单次采集进程内，不打印、不落盘、不复用；
- 不把 Authorization、凭据、MCP Secret 或生产原始正文提交 Git；
- Git 中只保留脱敏后的证据摘要、指标和结论；
- 分析期间不修改生产 Agent、Skill、MCP、模型或服务配置。

### 3.6 报告摘要与展示结构

用户确认的增量需求以[《报告摘要与 Presentation Profile》](报告摘要与Presentation-Profile/01-需求与现状差距.md)为唯一详细口径：六类托管报告均以工作总结开头，正文不使用“重点工作”固定标题；Agent 内部生成 Summary 和正文，后端组合后仍只保存和返回现有 Content；前端无改动；后端按冻结 report_type 将当前类型唯一 Profile 放入 Context；全局 Skill 不再同时携带六类结构规则；默认 Agent Instructions、Start Prompt、运行时 Message 和 Skill 的重复协议同步收敛。

## 4. 用户流程

本阶段不改变用户流程：

```text
用户创建报告 Run
  -> 后端准备 Context 并启动托管 Agent
  -> 用户查看现有生成中状态
  -> Agent 写回报告
  -> Run 成功或失败
```

## 5. 验收标准

| 编号 | 产品规则 | 可观察结果 |
| --- | --- | --- |
| R-01 | 3.1 | 每项进入开发的问题均有真实运行标识、时间线、根因和影响范围 |
| R-02 | 3.2 | 每项改动只有一个主责层级，跨层改动均有独立必要性证据 |
| R-03 | 3.3 | 对照测试使用相同输入和模型，并报告质量、耗时、调用次数及精确 usage |
| R-04 | 3.3 | Digest 不新增内容硬限制，不以静默裁剪换取模型成功 |
| R-05 | 3.5 | 仓库中不存在生产 Token、Secret 或未脱敏原始正文 |
| R-06 | 兼容性 | Codex、Claude Code 等上传、Token 统计、Selection、Context 权限及报告写回回归通过 |
| R-07 | 3.4 | Skill 不再包含 Digest 内部路径，Agent 从稳定的业务证据集读取事实 |
| R-08 | 3.4 | 最大生产样本的单次 Agent Context 不超过执行引擎工具结果上限，且输入规模、事实覆盖和精确 Token 均有对照证据 |
| R-09 | 3.3、3.4 | Digest 和 Projection 外部模型调用数保持为 0，不新增 Processing Job，Digest 队列吞吐不因本改动下降 |
| R-10 | 3.6 | 六类新托管报告的单一 Content 均包含非空工作总结和完整正文；数据库、报告接口和前端不新增 Summary 字段 |
| R-11 | 3.6 | 每个新 Context 只包含当前 report_type 的唯一 Profile，Skill 不再包含六类来源和结构路由 |
| R-12 | 3.6 | 默认 Agent 四层 Prompt 各自只有一个职责，相同的 Skill 加载、Context、MCP、凭据、范围和写回协议不重复投递 |
| R-13 | 3.6 | 默认 Agent 只加载三个必要 Report MCP Tool Schema；旧工具、自定义 Agent 和历史 Agent 保持兼容 |
| R-14 | 3.6 | Git 提交、分支和同步操作不能单独证明成果，不形成日报工作项、结果或流水；只有独立 Evidence 支持时才表达实际工作结果 |

## 6. 非目标

- 不建设新的日志平台、通用评测平台或工作流系统；
- 不修改 Agent Platform 的任务状态机；
- 不凭单个样本扩充 Digest 确定性语义规则；
- 不在 Digest 或 Projection 中引入 LLM Workstream Consolidation；
- 不把生产原始 Session 批量复制到仓库；
- 不修改报告数据库结构、公开接口、前端、编辑、复制或提交流程；
- 不在证据分析完成前预设具体代码重构。
