> 原则：只读、限量、脱敏、可追溯

## 1. 数据源

| 数据源 | 固定入口 | 用途 |
| --- | --- | --- |
| Agent Platform 任务列表 | `GET /api/task/list?scope=all&limit=100&offset=N` | 发现候选任务 |
| Agent Platform Session | `GET /api/session/{session_id}` | 获取 Agent、模型、Skill、MCP、Thread 和事件 |
| Agent Platform 实时事件 | `GET /api/session/{session_id}/events` | 仅观察运行中或卡住的 Session |
| Agent Platform 只读诊断 | `GET /api/admin/ops/runs/session/{session_id}/diagnosis` | 仅补充卡住任务证据 |
| Aida Run | 按 `ai_run.id`、`external_session_id` 只读查询 | 获取业务状态、Context 和写回关联 |
| Langfuse/供应方 usage | 按已验证的 Session/Run 标识查询 | 获取调用、Token、延迟和成本 |

禁止调用任何取消、中断、结束、强制终止、记录修复或删除接口。

## 2. 生产用户身份取证

固定流程：

```text
从目标 ai_run 读取 user_id 和 external_session_id
  -> 按该生产 user_id 生成单次采集 Token
  -> Token 仅通过进程内变量传给一次或一批受控 GET 请求
  -> 读取该用户的 Session
  -> 采集进程结束并清空变量
```

Token 不写入命令行参数、Shell 历史、脚本、临时文件、HTTP 调试日志或 Git。Aida CLI 所需接口不得因为 Token 的 `exp` 已过期而拒绝请求；签名算法、`nbf`、用户存在和账号启用状态仍按现有认证规则校验。这里的“单次采集”只约束取证过程不保存和复用 Token，不表示改变 CLI Token 的不过期产品规则。

## 3. 样本范围

总样本固定为 30～50 个，分组允许重叠：

- 10 个质量正常的成功任务；
- 10 个空泛、遗漏事实或错误降级的任务；
- 耗时最高的 5 个；
- 精确成本最高的 5 个；
- 工具调用次数最高的 5 个；
- 时间范围内全部失败、超时、Context/工具结果超限任务；
- 至少 3 组由 Agent Platform 规定的同一报告模型处理同类报告的可比样本；
- 时间范围内所有包含 Subagent 的报告任务。

样本不足时记录实际数量，不用重复任务凑数。

## 5. 固定分析顺序

1. 从 Run 确认生产用户 ID、Session 和 Trace 身份；
2. 检查 Context 是否准备成功且与 Run 一致；
3. 按时间展开根 Thread 和 Subagent Thread；
4. 标记首次有效错误、工具调用及返回大小；
5. 标记重复调用、无效重试和取得充分证据后的额外步骤；
6. 核对最终输出与 Aida 写回；
7. 从权威 usage 记录 Token、延迟和成本；
8. 归入唯一主责层级并判断是否达到开发准入。

## 6. 优先级

- P0：数据或权限错误、重复外部执行/写回、正常请求无法完成、错误报告进入生产结果；
- P1：稳定复现的明显事实遗漏、平台固定模型因工具或流程问题失败、显著重复调用或成本放大；
- P2：表达质量、非阻塞耗时和小幅成本优化。

优先级由影响决定，不由修复难度决定。
