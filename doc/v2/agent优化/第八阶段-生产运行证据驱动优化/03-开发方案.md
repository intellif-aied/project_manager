D-08 的实现规则调整为：每个包含有效报告事实的 Digest Work Unit 都必须进入 Projection；`status`、`category` 和时间先后不作为删除依据。每条结果按段落删除已知代码围栏、纯命令、纯路径、纯 Git、传输包装和内部交接/执行过程话术，完整保留成果、验证、失败、风险和未解决事项，不按字符数截断。扁平文本中的成对围栏只删除已知代码/序列化语言正文，`text/plaintext/txt` 与未知类型正文保留，未闭合围栏保留后文；围栏处理后继续解析其后的结果。Git 只删除可独立识别的纯操作片段，混合业务句无法安全拆分时整句保留。Markdown 标题和表格分隔语法规范化，但表格事实保留；技术细节标题不触发整段跳过。完全相同事实仅在日期、类别和状态相同时聚合：`occurrence_count` 累计次数，`first_observed_at` 保留首次时间，`observed_at` 保留最新时间；不同类别或状态始终分开保留。不新增模型、Job、队列、表、公开接口、第三方解析依赖或前端改动。

## 7. 开发顺序与停止条件

```text
验证身份关联与 usage
  -> 分层采样
  -> 重建执行时间线
  -> 确认根因和基线
  -> 更新架构决策与代码落点
  -> 实现纯函数 Report Projection
  -> 最大样本覆盖与性能测试
  -> 确认 Digest 队列指标不劣化
  -> 同输入同模型对照
  -> 全链路回归
  -> 进入发布评审
```

出现以下任一情况立即停止代码开发：根因只能靠猜测、需要新增 LLM/Job/队列/表、需要改变产品规则、无法取得同一 Digest→Projection 对照、任一删除结果无法明确解释为已确认的结构噪声、生产证据与文档冲突。
