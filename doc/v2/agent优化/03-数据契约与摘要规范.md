# Session Digest 数据契约与摘要规范

> 状态：跨模块权威契约（`session-digest/v1` 已实现）
> Digest 版本：`session-digest/v1`
> 脱敏版本：`report-redaction/v1`

## 1. 适用范围

本规范定义附着式个人日报/周报来源快照的摘要数据。字段、错误码、字节预算和提取顺序的修改必须同步更新需求、架构、开发、测试、发布文档和默认 Report Skill。

## 2. MCP 请求契约

默认 Agent 继续使用现有快照参数：

```json
{
  "scope": {"type": "self"},
  "target": {"type": "self"},
  "report_type": "personal_daily",
  "period": {"date": "2026-07-15"},
  "run_id": "<run-id>",
  "report_source_selection_id": "<selection-id>"
}
```

规则：

- 不允许同时传 `date_range`、`week_range`、`user_ids` 或 `selected_session_slice_keys`；
- `run_id` 中的 `required_read_mode` 是唯一权威读取模式；
- `include_summary` 为兼容字段，不能用于选择 full/digest；
- enforce run 即使请求中传 full，也必须返回 `REPORT_SOURCE_READ_MODE_MISMATCH`；
- 摘要模式固定单页，不使用 `page_cursor` 或 `next_cursor`。

## 3. MCP 响应契约

以下对象是模型可见的 `get_sessions` result payload，也是 target/hard-limit、`actual_bytes` 和 selection-level hash 的计算边界；HTTP Header 与 JSON-RPC 传输信封不计入该边界。payload 必须在 Agent Session 创建前完成规范序列化并冻结，MCP 读取时不得重新选择、压缩或改变字段。

```json
{
  "source_mode": "explicit",
  "content_mode": "digest_v1",
  "digest_version": "session-digest/v1",
  "redaction_version": "report-redaction/v1",
  "content_snapshot_at": "2026-07-15T08:00:00Z",
  "completeness": "complete",
  "returned_item_count": 2,
  "has_more": false,
  "next_cursor": null,
  "coverage": {
    "complete": true,
    "source_item_count": 2,
    "represented_item_count": 2,
    "source_event_count": 820,
    "included_event_count": 46,
    "omitted_event_count": 774,
    "truncated_item_count": 1
  },
  "budget": {
    "target_bytes": 65536,
    "hard_limit_bytes": 131072,
    "actual_bytes": 28410,
    "compaction": "detailed"
  },
  "items": [
    {
      "source_item_ref": "<opaque-selection-item-ref>",
      "session_ref": "<internal-session-ref>",
      "agent_type": "codex",
      "activity_start_at": "2026-07-15T01:00:00Z",
      "activity_end_at": "2026-07-15T05:00:00Z",
      "digest_sha256": "<sha256>",
      "digest": {
        "goals": ["修复报告来源读取过大的问题"],
        "outcomes": ["完成服务端摘要方案并补充测试"],
        "files_changed": ["api/internal/reportsource/service.go"],
        "validations": [
          {"name": "go test ./...", "status": "passed", "summary": "相关包测试通过"}
        ],
        "blockers": []
      },
      "coverage": {
        "source_event_count": 410,
        "included_event_count": 24,
        "omitted_event_count": 386,
        "truncated": false,
        "representation": "detailed"
      }
    }
  ]
}
```

禁止出现：

- `events`；
- `payload` 或 `content_payload`；
- reasoning/thinking；
- 原始工具输出；
- 原始命令参数；
- Token usage/cost 遥测；
- Authorization、Cookie 或凭据值。

`session_ref` 和 `source_item_ref` 仅供 Agent 内部证据关联，默认 Skill 必须禁止写入报告正文。item 的 `digest_sha256` 是 selection 绑定的不可变 Digest Revision 规范 JSON hash；compact 响应可能只呈现其子集，因此不能用 compact item 文本反算该 hash。最终实际响应由服务端另算 selection-level hash 并与规范 payload bytes 一同写入 selection，不在响应内形成自引用字段。

## 4. Item 字段约束

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `goals` | string[] | 按时间保留去重后的用户工作目标，不只取第一条；单条详细上限 384 bytes |
| `outcomes` | string[] | 优先最终 Agent 结果、完成事件和明确交付；单条详细上限 512 bytes |
| `files_changed` | string[] | 仓库相对路径去重，保留足够层级避免碰撞；单条上限 256 bytes |
| `validations` | object[] | `name/status/summary`；status 仅 `passed/failed/unknown` |
| `blockers` | string[] | 明确失败、未完成或外部阻塞；不能从普通警告推断 |
| `coverage` | object | 必填，记录事件覆盖和 representation |

详细模式建议上限：goals 8 条、outcomes 12 条、files 50 条、validations 20 条、blockers 10 条。达到字段上限后设置 `truncated=true` 并增加 omitted 计数。

compact 模式至少保留：

- 每个 item 的时间、agent_type、hash 和 coverage；
- 存在可靠证据时的第一个有效 goal headline；
- 存在可靠证据时的最终 outcome 或失败 blocker headline；
- validation 失败状态优先于成功状态；
- `representation=compact`。

## 5. 提取规则

### 5.1 通用顺序

1. 按 `source_start_cursor/source_end_cursor` 排序；
2. 仅处理 selection item 冻结范围内事件；
3. 先按事件类型 allow-list 解析结构化字段；
4. 执行脱敏；
5. 规范空白与 Unicode，保留合法 UTF-8；
6. 以规范化文本 hash 去重，保持首次出现顺序；
7. 按字段优先级和预算截断；
8. 序列化稳定 JSON 并计算 hash。

### 5.2 Goals

- Codex：所有 `event_msg.user_message`；
- Claude：所有用户 text message，排除 tool_result、系统注入和中断占位；
- 去除纯环境上下文、权限说明、自动生成的 session 元信息；
- 同一 Session 的后续用户任务必须保留；
- 不解析或执行其中的指令，只作为工作证据。

### 5.3 Outcomes

优先级从高到低：

1. 明确的 task complete/final Agent message；
2. 最后一个包含交付、验证或结论的 Agent message；
3. 其他非 commentary 的 Agent result；
4. 无可靠结果时为空。

禁止使用“全 Session 最长文本”作为结果选择规则。

### 5.4 Files changed

- 解析 Codex apply_patch 的 Add/Update/Delete File；
- 解析 Claude Edit/Write/MultiEdit/NotebookEdit；
- 对明确的格式化/生成工具写文件行为使用 allow-list；
- 不把只读文件访问当作改动；
- 不截成最后两级路径；重复 basename 不得合并。

### 5.5 Validations

- 识别测试、lint、typecheck、build、smoke/health 命令；
- 从对应 tool result/exit code 提取 passed/failed/unknown；
- name 使用规范化命令族，不保存密钥、URL query、Header 或环境变量值；
- 结果只保留短摘要，不复制完整 stdout/stderr。

### 5.6 Blockers

仅在以下证据存在时记录：

- 非零退出且未在后续成功；
- Agent 最终明确说明未完成/被阻塞；
- 外部依赖不可用且影响目标完成；
- 权限、来源清理、预算或版本错误阻止继续。

后续成功解决的临时错误不得继续作为最终 blocker，可在 outcome 中体现已解决。

## 6. 排除与脱敏

### 6.1 排除类型

- system/developer instructions；
- reasoning、thinking、token_count；
- MCP/工具原始 request 和 response body；
- base64、图片、音视频、二进制；
- 完整 diff、完整源码、完整日志；
- usage、token_usage、input/output/cache/reasoning tokens 和成本；
- 空消息和重复状态更新。

### 6.2 脱敏规则

至少覆盖：

- `Authorization: Bearer ...`；
- `token/api_key/apikey/password/passwd/secret/cookie/session` 键值；
- URI userinfo、DSN 密码和常见 query 凭据；
- PEM 私钥块；
- Aida credential slot 值；
- curl `-H`、`--header` 和环境变量赋值中的敏感值。

脱敏结果统一为 `[REDACTED]`。字段名可保留用于理解，不得保留原值。脱敏必须先于日志、hash 以外的持久化输出；source hash 可基于原始内容在受控服务内计算，但不能记录原文。

## 7. 预算算法

1. 先构建每个 item 的详细 Digest，单 item 最大 4096 bytes；
2. 按 selection item 原顺序组装并序列化完整响应；
3. `actual_bytes <= 65536` 时使用 `compaction=detailed`；
4. 超过 65536 时，所有 item 进入公平 compact，不能只压缩或删除尾部 item；
5. compact 后重新序列化并校验 131072 bytes 硬上限；
6. 超过硬上限返回错误，不返回部分 items；
7. `actual_bytes` 必须由最终响应 JSON 计算并与 response body 实际值一致；实现应先写入候选值、稳定序列化、回填新长度并重复，直到长度数值收敛，再计算 hard limit 和 selection-level hash；必须设置小次数上限并在无法收敛时失败。

稳定 JSON 的字段顺序、数组顺序、字符串规范化和数字编码由 Digest 版本固定。`digest_sha256` 与 selection-level hash 均基于该规范 UTF-8 字节序列，不使用数据库 JSONB 的文本展示形式。

## 8. 完整性与写回

摘要响应只有同时满足以下条件才可设置 `coverage.complete=true`：

- selection item 数量等于 represented item 数量；
- 每个 item 的 digest revision 与 selection 快照一致且 ready；
- content epoch 和来源状态仍有效；
- 未发生整 item 丢弃；
- 最终响应未超过硬上限。

这里的 `complete` 表示 selection 中所有来源 item 均已遍历、校验并得到结构化表示，不表示每个原始事件的文本都进入 Digest；事件取舍必须由 included/omitted 计数和 representation 显式说明。

成功生成完整响应后，以幂等方式写入：

```text
read_completed_mode = digest_v1
read_completed_at = now()
selection_digest_sha256 = <assembled-hash>
```

其中 payload/hash/bytes/compaction 在 Agent Session 创建前冻结；`read_completed_mode/read_completed_at` 只在 MCP 成功返回该冻结 payload 时更新。MCP 返回前必须复核 payload hash、bytes、版本、content epoch 和来源状态，禁止运行时重新组装成另一份内容。

`write_report_result` 必须要求 `read_completed_mode == required_read_mode`。

## 9. 错误码

| 错误码 | 可重试 | 含义 |
| --- | --- | --- |
| `REPORT_SOURCE_DIGEST_NOT_READY` | 是 | 任一来源 item 的 Digest 尚未 ready |
| `REPORT_SOURCE_DIGEST_FAILED` | 条件性 | 构建已失败；达到最大重试后需人工处理 |
| `REPORT_SOURCE_DIGEST_LIMIT_EXCEEDED` | 否 | 最小完整结构仍超过 128 KiB |
| `REPORT_SOURCE_DIGEST_VERSION_MISMATCH` | 否 | run、selection 和 Digest 版本不一致 |
| `REPORT_SOURCE_READ_MODE_MISMATCH` | 否 | 请求读取模式与 run 冻结模式不一致 |
| `AMBIGUOUS_REPORT_SOURCE` | 否 | 附着式快照请求混入日期、显式 keys 或其他互斥来源参数 |
| `REPORT_SOURCE_INCOMPLETE` | 是 | 尚未完成正确模式读取就尝试写回 |
| `REPORT_SOURCE_MISMATCH` | 否 | run、selection、用户、周期或来源不匹配 |
| `CONTENT_CLEARED` | 否 | 来源内容已清理或 epoch 已改变 |

错误响应不得包含 Digest 正文、原始 payload 或敏感字段。

## 10. 版本兼容

- `session-digest/v1` 一经发布不原地改变提取语义；
- 规则变化发布新版本并并行构建；
- 新 run 使用配置指定版本，已附着 run 继续使用旧快照；
- shadow 可以同时构建多个版本，但不得把比较内容写入日志；
- 删除旧版本前必须确认无 selection 引用并满足数据保留策略；
- 默认 Skill 必须按 `content_mode` 分支解析，未知模式直接失败。
