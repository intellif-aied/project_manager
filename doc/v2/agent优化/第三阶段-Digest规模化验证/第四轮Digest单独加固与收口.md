# 第四轮 Digest 单独加固与收口

> 执行日期：2026-07-17
> Digest 语义基线：`session-digest/v2.9.0`
> 当前状态：已完成并收口，未发布生产

## 1. 本轮结论依据

第三轮 10 个冻结真实 Session 已完成原文、Digest、真实 Agent run 和回写日报对照：

- 10/10 Digest 能恢复报告日期内的真实工作；
- 10/10 Agent run succeeded，10/10 调用 `write_report_result`；
- 最终日报暴露的问题均能在 Digest 中找到原始事实，未发现新的跨样本 Digest 遗漏；
- 最大完整 Digest 为 956,548 字节，约占 1 MiB 的 91.2%；
- B01/B03 的最终纠正已存在于 Digest，B07 的“生产环境”不在 Digest，不能通过继续裁剪服务端内容修复。

因此本轮不增加新的内容选择规则，只把已经验证正确的低损耗语义固化为代码契约。

## 2. 修改范围

### 2.1 移除未使用的语义排序与改写路径

主链路已经按时间顺序保留全部报告相关 Work Unit，但包内仍残留未使用的历史代码：

- 按证据、类别和完成度给工作单元评分；
- 按主题和版本推断旧工作被新工作替代；
- 将同主题工作合并到最多三条结果；
- 按内置产品文案重写 Report-facing 文本；
- 删除或截短低优先级日报 highlight。

这些代码不属于 Digest 的当前职责，并存在未来被误接回主链路、重新引入 Top-K 或隐式遗漏的风险。本轮删除该失效路径，并以“同主题版本历史仍全部保留”的契约测试替代。

### 2.2 不完整 coverage 时 fail-open 保留语义

当字节目标已超过、但 daily outcome coverage 不完整时，服务端无法证明详细 Work Unit 是重复内容。本轮改为：

- 不排序；
- 不删除 pending/unknown 工作；
- 不压缩语义正文；
- 允许载荷超过成本目标，交给选择级硬上限处理。

只有 `source_count = represented_count` 且 coverage 完整时，才允许移除已被 daily summaries 完整表达的重复工程证据。

### 2.3 增强离线评测可观测性

`session-digest-eval` 增加：

- 原始文件 SHA-256；
- Digest 目标字节和是否超过目标；
- Digest/原始文件万分比；
- outcome source/represented 数量；
- coverage complete；
- outcome text 是否发生压缩。

这些字段只用于离线评测，不进入 Agent MCP 正文，不增加用户 Token。

### 2.4 固化超过 1 MiB 的保护性语义

增加超过 1 MiB 的合成回归：即使全部有意义结果超过成本提醒目标，也必须保持：

- 全部结果条目仍存在；
- 结果文字不因目标阈值缩短；
- coverage 完整；
- 返回载荷可以超过 1 MiB。

1 MiB 仍是成本提醒，不是服务端裁剪线。

## 3. 明确非目标

本轮不修改：

- Report Skill、Agent Prompt、模型或服务端日报校验器；
- Session 上传协议、Aida 客户端、原始 Session、Token/usage/metering；
- MCP 工具和 selection 数据契约；
- 内网地址、路径、commit 等非凭据技术事实的保留规则；
- Digest 版本号和当前有效 JSON 语义。

Agent Skill 相关问题单独记录在 [下一轮 Agent Skill 与日报表达问题清单](下一轮-Agent-Skill与日报表达问题清单.md)。

## 4. 验收与停止条件

达到以下条件后本轮停止，不继续为了“更完美”增加启发式规则：

1. Digest 和 reportsource 相关 Go 测试全部通过；
2. 全量 API Go 测试通过；
3. 10 个冻结样本相对 `b82cc49` 的 Digest SHA-256、字节数和报告期结果保持一致；
4. 超 1 MiB 回归证明不丢结果；
5. 代码中不存在未使用的主题排序、成果合并和 Report-facing 文案重写路径；
6. Skill、Prompt、上传、Token 和 MCP 没有代码改动。
