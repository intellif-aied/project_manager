# 第一轮 Digest 内在质量基线

> 评测日期：2026-07-17  
> 基线版本：`session-digest/v2.8.0`  
> 样本：第一轮冻结的 S01-S10 真实 Session  
> 结论状态：层 A 已完成；基线不满足进入层 B 的条件

## 1. 结论

`v2.8.0` 已解决“大 Session 无法进入日报链路”的容量问题，但还不能作为结果质量合格基线。

当前可以确认：

- 10/10 样本均完成上传并进入 `ready`，178.38 MiB、97.70 MiB、64.74 MiB 等大 Session 均能生成 Digest；
- 原始工具输出、图片编码和重复事件得到数量级压缩，所有 Digest 均远低于 1 MiB；
- Asia/Shanghai 日期切分正确，S10 的 7 月 17 日事件没有进入 7 月 16 日视图；
- 但 10 个样本中有 7 个出现“最终回答存在于原文、Digest 日报视图未保留”的情况；
- 3 个样本出现凭据或大块图片编码未被正确清理；
- 2 个样本把注入的 `AGENTS.md` 或 `<turn_aborted>` 当成用户工作；
- 多个只读分析、问答和故障定位结果因为没有文件变更或测试证据，被标记为 `unknown`，并从日报视图中消失。

因此第一轮结论是：

1. 容量能力通过；
2. 确定性清噪部分通过；
3. 有意义内容召回、敏感信息清理和状态表达不通过；
4. 暂不使用本轮 Digest 反向评价 Report Skill 或模型，否则会把服务端输入缺失误判为生成能力问题。

## 4. 共性根因

### 4.1 结果定义过窄

当前只有文件变更、通过的验证或失败/阻塞，才稳定成为 `result_statements`。没有工具证据的最终回答只写入 `agent_claims`，状态通常为 `unknown`；而 daily summary 只接纳 `result_statements`、unresolved、failed 或 blocked。

这会系统性删除以下真实工作：

- 调研结论和架构判断；
- 故障根因与解决建议；
- 代码讲解和技术问答；
- 只读审计结果；
- Git/网络等只读验证结论。

这是 Digest 提取与投影问题，不是 Report Skill 或模型问题。

### 4.2 64 KiB/16 KiB 预算与产品口径冲突

代码中的单 Slice 默认预算为 64 KiB，报告周期投影默认预算为 16 KiB。超过预算后会依次：

1. 压缩工作单元和每日结果文本；
2. 删除 `agent_claims`、evidence、changes 和 validations；
3. 若 daily outcome 被认为完整，删除全部详细工作单元，仅保留 daily summaries。

该机制只保证“当前算法已经认定为结果”的条目数不丢，无法保证原文中全部有意义内容不丢。1 MiB 在产品上是上下文成本提醒阈值，不应被实现为 16/64 KiB 的提前语义裁剪。

### 4.3 截断后的结构化输入未恢复

服务端安全投影先把用户消息截到 8 KiB。多模态 JSON 或序列化 `AGENTS.md` 在截断后不再是合法 JSON，通用解析退化为整段文本，造成：

- 系统注入被识别成用户目标；
- 图片 Base64 前缀进入 Digest；
- 同一个用户文本同时生成“结构化图片目标”和“纯文本目标”。

### 4.4 敏感信息规则覆盖不足

现有规则能清理 `Authorization:`、`password=`、URL 用户密码等结构化形式，但没有覆盖：

- 独立出现的 JWT；
- “密码是 …”“口令为 …”等中文自然语言；
- `pass <value>` 等非键值表达。

文档不记录原始凭据，只记录样本和问题类型。

### 4.5 验证失败覆盖交付结果

只读审计或分析已经交付时，附带的仓库测试失败会把整个工作单元标记为 `failed`。正确表达应区分：

- 用户要求的审计/分析是否已经交付；
- 被审计项目自身的测试是否失败；
- 产品实现本身是完成、部分完成还是未完成。

## 6. 第二轮最小修复边界

第二轮只修改 Digest，不修改 Report Skill、Agent Prompt、模型、上传协议或 Token 统计：

1. 将每个真实用户工作单元的最终 Agent 回答保留为结果内容，即使没有文件或测试证据；证据等级仍明确区分为未验证；
2. 报告日期视图保留所有有意义工作单元，不做 Top-K 或固定条数选择；
3. 把单项语义压缩预算提高到 1 MiB，并让 1 MiB 继续作为用户成本提醒而非强制阻断；
4. 恢复截断序列化消息中的文本字段，过滤 `AGENTS.md`、`<turn_aborted>`、图片编码和重复多模态壳；
5. 扩充确定性的 JWT 与自然语言密码清理；
6. 已交付分析但附带验证失败时表达为 `partial`，不把交付结果整体改写为失败；
7. 将纯 `OK`/`Agree` 作为相邻工作单元的确认信号，不生成“已完成：Agree”之类独立成果。

第二轮必须用同一批 10 个原始 SHA-256 样本离线回放，再使用独立测试二进制上传到 14.157。任何修复不得调用 14.159 已安装的 Aida 客户端。

## 7. 层 B 暂停条件

在以下条件满足前，不执行 10 份真实 Agent 日报：

- S08 的代码问答和研究结论进入报告日期视图；
- S09 的单一成功结果进入报告日期视图；
- S06 不再包含系统注入和中断包装；
- S04/S05/S07 不再包含已识别的敏感信息；
- S01/S02/S07 不因 16/64 KiB 提前语义裁剪；
- 全部样本日期边界与 coverage 保持正确。

这样可以避免用缺失的输入测试 Skill 和模型，并避免继续为单个日报结果反向修改 Digest。
