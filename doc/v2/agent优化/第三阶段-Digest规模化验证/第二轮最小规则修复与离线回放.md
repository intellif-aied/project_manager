# 第二轮最小规则修复与离线回放

> 执行日期：2026-07-17  
> 候选版本：`session-digest/v2.9.0`  
> 对照版本：`session-digest/v2.8.0`  
> 样本身份：沿用 S01-S10 原始文件 SHA-256，不替换样本

## 1. 本轮目标

只修复第一轮由跨样本证据确认的 Digest 共性问题：

- 不再把“缺少文件/测试证据”的最终回答排除出日报输入；
- 不做 Top-K、固定条数或主题优先级删除；
- 去除确定性的传输噪音和敏感信息；
- 1 MiB 只作为成本提醒目标，不作为语义裁剪或运行阻断；
- 保持上传协议、Session/Token 统计、Report Skill、Agent Prompt 和模型不变。

## 2. 代码改动

### 2.1 全部有意义工作进入报告日期视图

- 每个真实用户工作单元的最终 Agent 回答均生成 `result_statement`；
- 有工具证据的结果继续使用原证据等级；
- 没有工具证据的回答标记为 `agent_claim`，不伪造成已验证结果；
- 未得到回答但具有实际内容的用户目标也保留，避免中断任务彻底消失；
- daily summary 接纳全部报告相关工作单元，不做数量排序和截断。

### 2.2 预算语义修正

- 单 Slice 默认目标从 64 KiB 调整为 1 MiB；
- 报告周期投影目标从 16 KiB 调整为 1 MiB；
- 超过目标时优先删除重复的工程证据副本；
- 若有意义内容本身仍超过 1 MiB，返回完整内容，由冻结 selection 的精确字节数触发前端确认；
- selection 级 64 MiB 基础设施 hard limit 保持不变。

因此 1 MiB 的含义是“提醒用户本次可能消耗较多 Token”，不是“服务端只给 Agent 1 MiB”，也不是“自动只保留最重要内容”。

### 2.3 传输噪音恢复与过滤

- 对被 8 KiB 安全投影截断的序列化消息，只恢复 `text/input_text/output_text` 字段；
- 不把 `input_image`、`image_url`、`data:image/...;base64` 作为用户目标；
- 过滤注入的 `AGENTS.md`、`<turn_aborted>` 和图片传输包装；
- 保留图片对应的用户文字问题和 Agent 最终回答。

### 2.4 敏感信息清理

在原结构化规则上增加：

- 独立 JWT；
- “密码是/口令为”等中文自然语言形式；
- `password <value>`、`pass <value>` 等受限英文形式。

规则测试只验证敏感值不再出现，文档不保存原始凭据。

### 2.5 状态与确认信号

- 已交付分析、同时存在验证失败时，工作状态为 `partial`，保留交付结论和失败验证；
- 纯 `OK`、`Agree`、`验收通过` 等信号附着到前一工作单元；
- 不再生成“已完成：Agree”之类独立成果。

## 6. 自动化验证

新增或加强的回归覆盖：

- 截断多模态 JSON 只恢复文字；
- 图片/Base64 不进入 Digest；
- 系统注入、中断和图片传输包装不生成工作；
- 无工具证据的最终回答进入报告日期视图；
- `Agree` 附着前一工作单元；
- 分析已交付且验证失败时保留 partial 结论；
- 超过 1 MiB 目标时不缩短完整报告结果；
- JWT 和自然语言密码清理。

验证结果：

- `go test ./internal/sessiondigest ./internal/sessiondigestv2 ./internal/reportsource`：通过；
- `go test ./...`：通过；
- `git diff --check`：通过。

最终代码审查后重新编译评测器并对同一 SHA 的 10 个样本全量回放。S01、S02 在最终预算实现下删除了已由 `daily_summaries` 完整表达的重复详细 Work Unit，同时把每条报告结果的可读上下文从旧上限扩展到最终上限，因此事实单元数不变、日期视图文字更完整、完整 Digest 反而更小；S03-S10 的日期视图与上一轮逐字节一致。上表已统一改为最终代码结果。

脱敏专项审查还发现 `pass <value>` 可能误删普通英文 `pass through`。最终规则只在值含密码式数字或 `@` 标记（或为长数字 PIN）时处理，并增加“普通 pass 短语必须保留”的回归。10 个冻结样本中没有命中该差异，因此已生成的服务端 Digest 内容不受影响。

## 7. 第二轮结论

从层 A 看，`v2.9.0` 已修复第一轮确认的共性问题：

- 全部 10 个样本的报告日期均可从 Digest 理解当天真实工作；
- 关键问答和只读分析不再因缺少工具证据而消失；
- 没有通过 Top-K 或结果排名换取体积；
- 确定性清噪没有删除对应文字问题和最终回答；
- 10 个完整 Digest 均在 1 MiB 以内。

下一步只验证真实 MCP/Agent/回写层。若最终日报仍遗漏已进入 `v2.9.0` 报告日期视图的事实，应归因到 Report Skill、Agent Prompt 或模型，不再反向收紧 Digest。
