# 下一轮：Agent Skill 与日报表达问题清单

> 来源：第三阶段 10 个冻结真实 Session 的 Digest 与 Agent 日报对照
> 状态：仅登记，本轮不开发

## 1. 已确认问题

| 问题 | 样本 | 证据与归因 |
| --- | --- | --- |
| 内部技术证据进入默认日报 | B04、B05、B08、B09，其他样本也有少量 | Session ID、绝对路径、内网地址、commit、哈希存在于 Digest；默认日报不一定需要展示，属于 Skill/模型表达问题 |
| 没有稳定采用同一主线的最终纠正 | B01、B03 | 早期状态和后续纠正均已按时间存在于 Digest，最终日报仍采用早期状态 |
| 状态数字与正文不一致 | B01、B02 | Digest 提供完整工作单元，但模型自行统计的完成/进行中/待处理数量与正文条目不一致 |
| 环境术语误写 | B07 | Digest 原文为 36 开发环境，日报写成生产环境 |
| Skill 版本可观测性不足 | 全批次运行元数据 | Agent 查询返回绑定 `100866/aida-report@1.0.33`，但运行响应没有可核验的 Skill SHA-256 与 Prompt 哈希 |

## 2. 下一轮边界

- 优先调整默认 Report Skill 的写作指导和样本评测，不修改 Digest；
- Agent Prompt 继续只负责参数、MCP、凭据和回写协议，不增加内容裁剪；
- 不使用服务端校验器强制日报结构或删除用户内容；
- 不限制用户自定义 Skill；
- 不要求默认日报输出精确工作数量，除非数量来自可靠结构化字段；
- 对时间线冲突优先采用明确的后续纠正，但不得隐去仍有价值的阶段过程；
- 默认隐藏非必要内部证据，但凭据安全仍由服务端 Redaction 负责。

## 3. 建议复测样本

- B01：验证早期实现与后续回退的最终状态；
- B03：验证“暂不批量上报”的最终决策；
- B07：验证开发/测试/生产环境术语；
- B09：验证短 Session 是否避免输出私有地址和 commit；
- B06：作为 partial/unresolved 状态正确表达的对照组。

下一轮应固定同一份 Digest snapshot、模型和 Agent 版本，比较 Skill 修改前后结果。若 Digest 已包含事实而日报仍误写，不得反向增加 Digest 删除规则。
