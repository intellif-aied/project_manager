# Session Digest 第一阶段：容量与稳定性优化

> 状态：`session-digest/v1` 已完成并上线
> 版本：1.1
> 日期：2026-07-16
> 前置代码基线：`fea.0.0.1` / `ba20665`（完整来源切片修复，继续有效）
> 上级目录：[报告 Agent Session Digest 优化](../README.md)

## 1. 目标

本目录定义个人日报、个人周报生成时的 Session 上下文压缩方案。目标是在 Session 内容进入模型上下文之前，由 Aida 后端生成确定性、可审计、有总量上限的摘要，避免报告 Agent 逐页读取大量原始事件后再次总结。

本方案只优化报告 Agent 的 Session 来源读取，不改变 Session 增量上传、完整切片快照、Token/成本统计、六类报告来源层级、权限和报告写回语义。

## 2. 核心决策

1. 摘要在 Aida 服务端生成，不在 Agent 沙箱中运行 `jq` 脚本。
2. 摘要生成不调用 LLM，使用版本化的规则提取器。
3. 摘要对象绑定完整上传切片及其内容投影版本；报告来源快照继续保持不可变。
4. 托管个人报告由服务端决定读取模式，Agent 不能自行回退到原文模式。
5. 摘要响应不包含 `events`、原始 `payload`、thinking/reasoning、完整工具输出或累计 Token 遥测。
6. 默认详细预算为 64 KiB，硬上限为 128 KiB；任何切片不得被静默丢弃。
7. 摘要无法就绪或无法在硬上限内表达全部来源时，明确失败，不回退到原文。
8. `tmp/session-digest` 仅可作为规则探索和测试样本参考，不是生产 Skill，也不要求修改 `sandboxed-agent-platform`。

## 5. 统一术语

| 术语 | 定义 |
| --- | --- |
| 原始事件 | `session_content_events` 中由 JSONL 投影得到的事件及其原始 `content_payload` |
| 完整上传切片 | `session_content_slices` 中一次成功增量上传对应的完整 cursor 范围 |
| Digest | 服务端从一个完整上传切片提取的结构化、无 LLM 摘要 |
| Digest Revision | 绑定内容投影、切片范围、提取器版本和脱敏版本的不可变摘要版本 |
| 来源快照 | `report_source_selections` 及其 items 冻结的本次个人报告 Session 来源 |
| 详细预算 | 正常情况下整个来源快照 Digest 响应不超过 64 KiB |
| 硬上限 | Digest 响应绝不能超过 128 KiB |
| 完整覆盖 | 来源快照中的每个 item 都被完整遍历并在 Digest 响应中有对应记录，同时提供事件覆盖元数据；不表示复制全部原始事件文本 |
| 原文模式 | 返回 `items[].events[]` 和原始 payload 的兼容读取模式 |
| 摘要模式 | 返回版本化 `session-digest/v1` 或 `session-digest/v2` 结构且不返回原始事件的托管报告读取模式 |

## 6. 当前状态边界

截至 2026-07-16，第一阶段服务端 migration、`sessiondigest` Reconciler/Builder、selection payload 冻结、MCP `digest_v1` 单页读取、正确模式写回和默认 Report Skill 分支均已实现、完成测试并上线。

上线后的用户反馈表明，v1 已解决大 Session 容量问题，但对“实际交付结果”的表达仍弱于“对话内容概括”。第二阶段方案独立维护在 [第二阶段-结果质量优化/](../第二阶段-结果质量优化/README.md)，目标是增加 Work Unit、结果证据、完成状态和真实 Session 质量评测，不原地改变 v1 契约。
