# 报告 Agent Session 摘要优化测试与验收方案

> 状态：自动化与独立 PostgreSQL 集成已通过；真实 Agent、Token A/B、浏览器和生产灰度待执行
> 说明：已执行证据见第 13 节；未执行项仍不得用静态检查替代。

## 1. 测试原则

- 规则测试、服务集成、MCP 合约、真实 Agent 和 Token 对比缺一不可；
- 原文基线与摘要模式必须使用同一来源快照、模型、提示词和账号；
- 单元测试或 HTTP 200 不能代替报告事实核对；
- 测试环境实际生效的 API、MCP 和 Skill 才可作为 E2E 证据；
- 浏览器交互、自动化断言和人工内容 Review 分开记录；
- 未运行写“未运行”，失败写“失败”，不得用“静态检查通过”代替真实运行；
- 测试数据必须脱敏，安全 fixture 使用虚构密钥。

## 6. Skill 与 Agent 测试

### 6.1 静态契约

- `daily_report_skill_test.go` 断言 Digest mode、coverage、禁止执行证据、禁止自行 full fallback；
- `managed_agent_test.go` 断言 run 冻结 read mode，用户 start_prompt 不能覆盖；
- 保留六类报告 scope 矩阵、显式来源优先级、Token 禁止累加、内部 ID 禁止输出等现有断言；
- 未知 content mode 必须失败。

### 6.2 真实 Agent 对比

同一来源快照执行 A/B：

```text
A：MANAGED_AGENT_REPORT_SESSION_READ_MODE=full
B：MANAGED_AGENT_REPORT_SESSION_READ_MODE=digest_v1
其他：同用户、同 model_id、同报告类型、同 period、同补充说明
```

统计口径：

- Claude 与 Codex 各至少选取 10 个原始来源不小于 1 MiB 的快照，按 snapshot 配对比较；
- A/B 执行顺序交替，避免总是由后一组获得缓存优势；失败重试不能只从一侧删除；
- Token 主指标使用平台现有计量链路记录的整次报告模型输入 Token，不自行重算、不改变成本口径；
- 同时记录 MCP 原始响应 bytes、cache read/write、output tokens 和总时延，用于解释差异，但不得把它们相加成新的“总 Token”；
- 分别报告 Claude、Codex 和合并样本的中位数、P25/P75 及样本数，合并门禁不能掩盖任一 Agent 类型的质量失败。

人工和自动检查：

- Golden 必须事实召回 100%；
- 不得出现未在来源中的事实；
- 显式选择的唯一事实必须进入正文；
- 后续用户任务不能丢失；
- blocker、失败验证和成功验证状态正确；
- 报告正文不得出现内部 refs、UUID、Digest 字段或敏感值；
- 记录 MCP response bytes、平台 input tokens、总时延和模型输出 tokens。

若摘要模式 Token 降低但关键事实缺失，判定失败。

## 7. 六类报告真实回归

使用 14.157 的 6 个真实测试账号，覆盖普通成员、小组负责人、部门负责人、管理员，至少 2 个小组：

| 报告 | 重点 |
| --- | --- |
| 个人日报 | digest_v1 完整来源、显式/默认/空来源 |
| 个人周报 | 已保存个人日报为主，Digest 为固定补充 |
| 小组日报 | 仍汇总个人日报，不读取成员 Digest/Session |
| 小组周报 | 仍汇总个人周报，缺失成员准确 |
| 部门日报 | 仍汇总小组日报，范围和覆盖准确 |
| 部门周报 | 仍汇总小组周报，不降级 self/all |

同时执行直接 MCP 调用和浏览器实际生成。浏览器自动化验证交互与状态，报告内容需要人工 Review；二者不能互相代替。

## 8. 性能与容量测试

### 8.1 Builder

- 1、10、50、100 MiB 等价事件规模；
- 1/20/100/200 slices；
- Reconciler 空扫描、有缺口扫描、历史回填与多实例冲突率；
- 单 worker 与并发 worker；
- 测量 CPU、峰值 RSS、DB rows scanned、构建耗时、重试和队列积压；
- 验证上传响应时延不因 Builder 增加同步等待。

### 8.2 MCP

- ready Digest 冷/热缓存读取；
- 20/100/200 item selection；
- P50/P95/P99 和响应字节；
- P95 目标 500 ms，硬上限 128 KiB；
- 并发报告不得锁住 Session 上传和 Token worker。

### 8.3 Token

对原文来源 >=1 MiB 的样本验证：

- MCP response bytes 降低 >=90%；
- 真实运行 Session 来源相关 input tokens 中位数降低 >=70%；
- 输出质量门禁同时通过。

## 9. 安全测试

- 跨用户、跨团队和伪造 run/selection；
- prompt injection、命令注入文本和伪造 system message；
- 密钥、Cookie、DSN、PEM、curl Header 脱敏；
- 恶意超长字段、深层 JSON、重复字段和 Unicode；
- 日志、指标、错误响应、数据库失败字段不含敏感正文；
- Agent 不执行 Digest 中命令，不访问额外 URL；
- full 模式不能绕过 enforce run。

## 10. 发布与回退测试

1. full -> shadow：报告结果完全不变；
2. shadow 回填限速：业务 P95、DB、队列无明显回归；
3. shadow -> digest_v1 canary：目标账号只读 Digest；
4. 配置切回 full：只影响新 run，已附着 run 保持快照模式；
5. schema rollback：旧代码可忽略 nullable 新字段；
6. Digest 表保留不影响 full 运行；
7. 回退后 raw fallback 指标的变化与操作记录一致；
8. 清理/恢复和历史 selection 在回退前后均正确。

## 12. 验收证据与停止条件

验收包至少包含：代码提交、migration 结果、自动化日志、Golden diff、MCP 请求/脱敏响应、A/B Token 表、六类报告 ID、浏览器截图、人工内容 Review、指标截图和回退记录。

以下任一情况立即停止：

- 整个来源 item 被静默丢失；
- 发现原始 payload、密钥、内部 ID 泄漏；
- Agent 回退 full 或执行 Digest 指令；
- Token/成本对账变化；
- 关键事实缺失或出现新增幻觉；
- 小组/部门 scope 回归；
- 超过 128 KiB；
- 写回未校验正确 read mode；
- shadow/canary 造成业务性能或队列明显回归。
