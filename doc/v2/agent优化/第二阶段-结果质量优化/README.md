# Session Digest 第二阶段：结果质量优化

> 状态：v2.4 已实现并部署到 14.157 测试环境；当前会话已按真实上传、选择、Agent 生成、MCP 写回全链路验收通过
> 方案版本：2.4（选择级汇总与结果质量门禁版）
> 目标 Digest 版本：`session-digest/v2.4`
> 日期：2026-07-16
> 上级目录：`doc/v2/agent优化/`

## 1. 结论

第一阶段 `session-digest/v1` 已解决“大 Session 无法在运行时限内读完、输入 Token 失控”的容量问题，但生产反馈和样本复盘表明，当前摘要仍偏向“聊了什么”，不能稳定回答“最终做成了什么、依据是什么、还有什么没完成”。

第二阶段不回滚第一阶段，也不重新把原始 Session 交给报告 Agent。方案是在服务端增加结果导向的确定性结构：

```text
Session 原始轨迹
  -> Work Unit 分段
  -> 结果证据提取
  -> 目标/结果/验证/未完成项关联
  -> 单切片报告期摘要
  -> 选择级跨切片归并与最终状态覆盖
  -> session-digest/v2.4
  -> 结果优先的 Report Skill
  -> 服务端正文质量门禁
  -> 日报
```

核心原则：

1. 生产 Digest Builder 继续不调用 LLM，不运行 Session 中的命令，也不依赖 Agent 自己总结。
2. 不把最终回复、文件列表或测试命令单独视为完成结果。
3. 每条结果必须带可追溯证据；讨论、设计决定、代码实现、验证、发布必须明确区分。
4. `digest_v1` 保持可回退，`digest_v2` 使用独立版本与读取模式，不静默改变已上线契约。
5. 14.159 当前存量 Session 用作全量离线回放语料；其中人工标注的分层样本作为质量门禁。
6. 不允许擅自做隐藏账号灰度。测试和生产切换必须有明确配置、版本和操作记录。
7. RTK 只作为工具输出 reducer 的参考，不引入二进制、Hook、命令改写、tee 或 raw fallback。
8. v2 使用独立 job type、默认关闭和单并发；Session 上传与 Token 统计不改，但必须作为非回归门禁。

## 2. 当前典型证据

目标样本 `019f4575-4fe7-72a1-86d8-b6a4c719a73e` 的第一阶段生产投影与
14.159 当前本地原文件不是同一个冻结快照，因此不能把两组字节数当作严格
A/B；但可用于判断结果结构是否改善：

| 指标 | v1 已上线样本 | v2 当前本地回放 |
| --- | ---: | ---: |
| 原始来源大小 | 47,632,200 bytes | 53,743,142 bytes |
| 原始事件数 | 18,008 | 19,545 |
| 完整 Revision 大小 | 3,255 bytes | 64,521 bytes |
| 2026-07-16 报告期投影 | 不适用 | 14,035 bytes |
| 报告期 highlights | 不适用 | 8 |
| 报告期结果声明 | 扁平 outcomes | 16 |
| 会话级验证结果 | 扁平列表 | 8 |
| 未完成项 | 关键词 blocker | 3 |
| 系统指令误识别目标 | 存在 | 0 |

该样本证明 v2 仍保持强压缩，同时能把 Agent 最终语义、文件变更、测试状态
和未完成项关联到工作单元。第一阶段暴露的问题包括：

- `AGENTS.md` 指令被包装在 JSON 字符串中后进入 `goals`；
- 最后两条问答式回复进入 `outcomes`，覆盖了更早的实际交付；
- 普通产品讨论中出现“阻塞”字样，被误判为最终 blocker；
- 文件、测试和最终结论彼此没有关联，Report Agent 只能自行猜测。

详细复盘见 [09-典型样本复盘.md](09-典型样本复盘.md)。

## 4. 权威顺序

发生冲突时按以下顺序处理：

1. `doc/v2/Session增量上传与报告来源/产品需求.md`；
2. 第一阶段 `doc/v2/agent优化/第一阶段-容量与稳定性优化/01-需求方案.md` 的来源完整性与安全边界；
3. 本目录 `01-需求与问题定义.md`；
4. 本目录 `03-Digest-v2数据模型与提取规范.md`；
5. 架构、开发、测试和发布文档；
6. 示例与评测结果。

第二阶段不得改变 Session 上传协议、Token 统计口径、报告来源权限和 `write_report_result` 的完整读取要求。

## 6. 完成定义

只有同时满足以下条件，第二阶段才可称为完成：

- 14.159 全量 Session 结构回放无崩溃、无泄密、无超限；
- 人工 Gold 集关键结果召回 100%，结果声明均有证据；
- 讨论内容被包装成“已实现”的严重错误为 0；
- 典型样本强制断言全部通过；
- 相同模型和来源下，v2 日报质量不低于原文基线，明显优于 v1；
- Token、时延和响应字节仍满足第一阶段容量门禁；
- 固定 fixture 证明 Token 数值和统计口径不变；
- Session Prepare/Chunk/Finalize、Aida 客户端请求和上传状态机不变；
- 混合负载下上传 P95、content/usage/metering job age 和 API/数据库资源通过门禁；
- v1/v2 使用独立 job type，v2 默认关闭且首期单并发；
- v1 回退路径与历史报告不受影响。
