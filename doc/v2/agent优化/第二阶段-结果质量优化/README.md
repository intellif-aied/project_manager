# Session Digest 第二阶段：结果质量优化

> 当前状态：v2.8 低损耗成果投影正在开发与 14.157 验收；v2.7.9 为上一版历史基线
> Report Skill：`100866/aida-report@1.0.19`
> 日期：2026-07-17
> 环境边界：仅开发测试环境，未操作生产

## 0. 当前权威方案

用户验收发现 v2.7.9 的“最多 5 条最终成果”会漏掉长 Session 中不同意义的方案、开发、部署和质量优化。当前实现改为 v2.8 低损耗 Digest：服务端不做 Top-K，只做确定性结构化和均匀压缩；最终语义归并交给 Report Agent。

当前方案、开发和测试基准见 [v2.8-低损耗Digest/README.md](v2.8-低损耗Digest/README.md)。本文件下方 v2.7.9 的结论仅保留为历史基线，不再代表当前产品约束。

## 1. 当前结论

第一阶段解决了大 Session 原文分页、Token 超限和运行超时；第二阶段解决“虽然能生成，但日报更像聊天记录总结”的结果质量问题。

当前产品流程为：

```text
本地 Session
  -> Aida 正常上传
  -> 服务端原始事件与 Token 数据照常保存
  -> Digest Builder 确定性提取 Work Unit 和结果证据
  -> 单 Session 报告期成果投影
  -> 选择级跨 Session 精确来源合并
  -> 完整低损耗 report_period_summary（不做 Top-K）
  -> Report Agent 组织自然语言
  -> 服务端正文质量门禁
  -> MCP 写回生成的日报
```

关键设计：

1. Digest Builder 不调用 LLM、不执行 Session 中的命令，也不让 Report Agent 重读原始 Session。
2. 选择级 `report_period_summary` 是 Report Agent 的唯一成果输入；每个 item 下不再重复嵌套摘要，避免模型绕过归并结果。
3. 摘要只保留面向用户的最终成果，过滤文件、路径、命令、测试状态、主机、账号、资产标识、文档数量和发布检查过程。
4. 跨 Session 只做来源引用级精确去重，不再按主题或版本替用户删除成果。
5. Report Skill 负责语义归并和表达，服务端门禁负责完整性与安全校验，不限制成果条目数。

## 4. 不变边界

本阶段不修改：

- Aida 客户端上传命令与上传协议；
- Session prepare/chunk/finalize 状态机；
- Session 原始事件、content projection、usage 和 metering 数据；
- Token 采集、Session Token 数值及 Token analytics 统计口径；
- 来源候选 API 的产品语义；
- MCP 写回接口、来源权限和完整读取要求；
- 数据库表结构与迁移。

因此本次优化只改变“报告 Agent 看到的 Digest 报告期投影”和“允许写回的日报正文质量”，不改变 Session 上传、存储和 Token 统计。

## 5. 仍需持续观察

- 规则主要覆盖中英文工程协作语料，新语言和未知工具输出可能保守省略成果；
- 模型对 Skill 的服从度仍有波动，服务端只对确定可判定的问题做门禁，不能替代完整语义评审；
- v2.8 不再设置最多 5 条成果；Agent 可合并重复主线，但必须覆盖全部实质成果；
- 复杂专业领域仍可能保留较多技术术语，需要继续用真实生成日报做人工校对；
- 完整 Session manifest、Human Gold 和正式 v1/v2 配对 A/B 仍属于后续质量体系建设，不影响本轮测试环境验收结论。
