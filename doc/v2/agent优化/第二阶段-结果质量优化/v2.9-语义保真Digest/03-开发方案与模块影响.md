# 03 开发方案与模块影响

## 1. 开发目标

将当前 `result_focused` 投影替换为 `semantic_transcript` 投影，同时保留 v2.8 已验证的原始数据保护、异步构建、版本 Hash、冻结快照、单页读取和安全脱敏能力。

本轮不是在现有 highlights 上继续增加关键词，而是把服务端职责从“判断成果”收缩为“确定性清噪”。

## 2. 分步实施

### 2.1 建立事件可见性映射

为 Codex、Claude Code 等已支持格式建立结构化映射：

- user 可见消息 -> 保留；
- assistant commentary/final/user-visible text -> 保留；
- system/developer/reasoning/tool/usage -> 按原因删除；
- 未知事件 -> 不执行、不直接进入 Agent，保留原始数据并设置分类不完整；若不能证明其不含用户可见语义，则阻止冻结而不是静默省略。

禁止先把事件文本截断后再分类，否则长消息后半部分永远无法恢复。

### 2.2 拆分清噪器和语义投影器

建议结构：

```text
sessiondigestv2/
  event_visibility.go     # 结构化事件分类
  redaction.go            # 复用并收窄敏感信息脱敏
  semantic_blocks.go      # 有序完整语义块
  semantic_coverage.go    # 原因码与覆盖审计
  processor.go            # 异步构建、版本与持久化
```

旧 Work Unit 结构可暂时保留给离线对比，但不得作为 Agent 的 canonical 输入。

### 2.3 调整冻结载荷

选择级 payload 只包含：

- 来源快照元数据；
- 报告期与时区；
- 有序 Semantic Blocks；
- 精简 coverage；
- 实际上下文字节数和提醒状态。

删除重复的 item 级 Digest、Work Units、Daily Highlights、Evidence 和选择级二次摘要。

### 2.4 调整容量处理

- 删除 `DefaultPeriodItemBytes=16 KiB` 对 Agent canonical 输入的限制；
- 删除选择级 64 KiB 目标压缩与 128 KiB 产品硬失败；
- 新增 `context_warning_bytes`，默认 1 MiB；
- 选择创建后返回 `context_bytes` 与 `warning_required`；
- 运行创建在 `warning_required=true` 时要求用户显式确认；
- 确认只用于证明用户看过提示，不改变 payload 内容。

### 2.5 调整 Report Skill

Skill 需要：

- 读取完整 `semantic_blocks`；
- 按时间理解需求、纠正、决定和最终结果；
- 生成结果型日报，避免逐轮聊天复述；
- 不把缺少文件证据的明确决定降级为“未完成”；
- 不输出系统、工具、文件和验证过程；
- 不按每个 block 机械生成 bullet；
- 在写回前进行语义自检，但不使用引用数量强制正文条目数量。

### 2.6 调整写回门禁

保留：

- 凭据、内部 ID、UUID、主机和原始 URL 泄漏校验；
- 日期、星期和报告期一致性；
- 明确空日报与来源存在活动的冲突校验；
- 报告必须真实写回后 run 才算成功。

移除或重构：

- 顶层 bullet 数量必须不少于 highlight 数；
- 依赖 v2.8 `work_unit_ref` 的 coverage 查询；
- 过宽的“测试通过/验证完成”正则误伤用户可见质量成果。

## 3. 预计代码影响

| 模块 | 影响 | 说明 |
| --- | --- | --- |
| `internal/sessiondigestv2` | 高 | canonical 数据模型和提取逻辑变化 |
| `internal/reportsource` | 高 | 冻结 payload、容量提示和完整读取契约变化 |
| Report MCP `get_sessions` | 中 | digest_v2/v2.9 返回结构增加或切换为 semantic blocks |
| `service/daily_report_skill.go` | 中 | 从 highlights 改为完整语义块总结 |
| `handler/managed_agent.go` | 中 | 默认 Agent 指令、运行提示和大上下文确认 |
| `handler/report_content_validation.go` | 中 | 移除条目计数门禁，收窄过程正则 |
| Web 前端 | 中 | 选择后展示大上下文提示并支持继续生成 |
| Aida 客户端 | 无 | 上传协议和 readiness 行为不因本轮变化 |
| Token analytics | 无 | 不修改 usage 数据与统计口径 |
| Session 候选列表 | 低 | 选择语义不变；可选展示内容大小但不自动筛选 |
| 数据库迁移 | 待实现确认 | 优先复用现有 digest JSON；若需持久化确认状态再单独评审 |

## 4. API 产品契约建议

来源选择准备完成后，服务端可返回：

```json
{
  "id": "selection-id",
  "status": "prepared",
  "context_bytes": 1123456,
  "warning_required": true,
  "warning_code": "LARGE_CONTEXT"
}
```

创建运行时：

```json
{
  "report_type": "personal_daily",
  "period": {"date": "2026-07-16"},
  "target": {"type": "self"},
  "report_source_selection_id": "selection-id",
  "large_context_confirmed": true
}
```

约束：

- `warning_code` 仅供前端选择文案，不展示 Digest 内部术语；
- 小于阈值时忽略 `large_context_confirmed`；
- 大于阈值且未确认时返回可重试业务响应，不创建 Agent run；
- 确认后不得重新构建或替换选择快照。

## 5. 不受影响的链路

- Aida `prepare/chunk/finalize`；
- readiness 状态查询；
- Session slice key 和用户手动选择语义；
- Session 原始内容、content projection 和清理周期；
- Token usage、metering 和 analytics；
- 报告权限、目标用户和 MCP 写回身份；
- 已保存日报的编辑冲突保护。

## 6. 兼容策略

1. 新 Digest 使用新版本号和明确 representation；
2. 已冻结的 v2.8 run 继续读取原快照，不在运行中切换版本；
3. 新建选择只绑定 ready 的 v2.9 revision；
4. 版本切换触发异步重建，不修改原始 Session；
5. 不允许 v2.9 失败后静默回退 raw/full；
6. 测试环境验收通过前不修改生产配置；
7. 回滚时恢复 v2.8 运行配置和 Skill，v2.9 revision 可保留供排查。

## 7. 删除和收敛建议

实现完成后应删除或明确隔离以下未进入 v2.8 主链路的遗留代码：

- `report_text.go` 中按业务关键词删除内容和 Aida 专用固定改写；
- 未调用的 `dailyWorkUnitPriority`、`lowestPriorityIndex`；
- 未调用的模糊 supersede 与 Top-K 辅助函数；
- 未调用的 highlight 尾部裁剪函数。

目的不是机械减代码，而是保证“生产实际规则”能够由调用链和测试直接审计。

## 8. 开发顺序

1. 先补事件可见性与完整语义块测试；
2. 建立 v2.8/v2.9 离线同源对比，不改变运行配置；
3. 改造选择级冻结与 coverage；
4. 实现 1 MiB 提醒 API；
5. 更新 Skill 和默认 Agent 指令；
6. 收窄写回门禁；
7. 构建 14.157 测试镜像；
8. 等待用户在页面手动选择 Session；
9. 跟踪真实 Agent 并输出最终日报；
10. 完成人工验收后再讨论发布。
