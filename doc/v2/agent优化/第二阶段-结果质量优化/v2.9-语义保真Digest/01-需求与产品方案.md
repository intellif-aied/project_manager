# 01 需求与产品方案

## 1. 问题定义

v2.8 在 14.157 的固定长 Session 验收中，将约 33.6 MB 原始切片转换为约 13.6 KiB 报告期冻结载荷，并成功生成日报。该结果证明容量链路可用，但不能证明 Session 的全部有效语义都被保留。

当前主要缺陷是：

- 用户消息和 Agent 文本存在逐条字节截断；
- Agent 中间回复通常只保留最后一条，详细推理后的用户可见结论可能缺失；
- 文件变更或验证证据影响 Work Unit 是否成为结果；
- 纯方案、产品决定、架构分析、风险判断可能因没有代码证据而消失；
- 报告期输入只剩 highlights，Agent 无法恢复提取前丢失的信息；
- 16/64/128 KiB 多层预算仍会持续缩短文本，128 KiB 还是硬失败；
- 顶层条目数量门禁只能证明“覆盖已提取项”，不能证明语义完整。

因此，下一版首先修复服务端输入信息损失，再评估 Agent 模型和 Skill 的总结能力。

## 2. 产品目标

### 2.1 首要目标

在不让 Agent 读取几十 MB 原始 JSONL、工具输出和图片数据的前提下，保留报告期内所有用户可见对话语义，让 Agent 基于完整上下文生成结果型日报。

### 2.2 产品原则

- 宁可多保留一些用户可见噪音，也不由服务端猜测哪段话不重要；
- 清噪规则必须是确定性、可解释、可测试的内容类型判断；
- 语义块一旦判定保留，就不得静默截断；
- Token 成本由清晰提醒和用户选择管理，不由平台偷偷删内容管理；
- 用户感知的是“会话内容较多”，不是 Digest 或清洗实现。

## 3. 产品流程

```text
Aida 正常上传 Session
  -> 服务端保存完整原始事件
  -> v2.9 确定性清噪并生成有序语义块
  -> 用户在页面手动选择一个或多个 Session
  -> 服务端冻结本次选择的完整清噪上下文
  -> 大于 1 MiB 时页面提示成本与模型风险
  -> 用户取消，或确认继续
  -> Report Agent 读取完整冻结上下文
  -> Agent 归纳成果、决定、进展和待跟进
  -> 正文安全门禁
  -> MCP 写回可编辑日报
```

## 4. 功能需求

| 编号 | 需求 |
| --- | --- |
| SF-001 | 保存所有用户可见 user 消息和 Agent 用户可见回复，保持角色、时间和顺序 |
| SF-002 | 删除系统/开发者注入、推理过程、原始工具调用、大工具输出、图片二进制和遥测 |
| SF-003 | 对完全相同且属于同一持久化重复的事件做精确去重，不做语义相似去重 |
| SF-004 | 保留语义块不得使用逐条字节截断、Top-K、证据等级门槛或成果评分 |
| SF-005 | 输出清噪覆盖信息：来源数量、保留数量、按原因删除数量、脱敏数量和保留字节数 |
| SF-006 | 冻结快照必须可通过 Hash 和来源游标复核，Agent 不请求 raw/full 回退 |
| SF-007 | 清噪后上下文超过可配置提醒阈值时返回用户提示状态，默认阈值为 1 MiB |
| SF-008 | 用户确认继续后不得因产品阈值再次裁剪或拒绝生成 |
| SF-009 | 页面测试和正式使用都由用户手动选择 Session，服务端不得自动替用户选来源 |
| SF-010 | Report Agent 负责从完整上下文归纳结果，不再要求一条来源块机械生成一条日报 bullet |
| SF-011 | 日报正文继续隐藏凭据、内部 ID、主机、路径、命令和纯验证过程 |
| SF-012 | 日期继续使用 Asia/Shanghai 业务时间；本轮不改变来源切片日期语义 |

## 5. 用户提示

超过提醒阈值时建议文案：

> 所选会话内容较多，可能消耗较多 Token，部分模型可能无法完整处理。你可以更换模型、减少所选会话，或继续生成。

按钮建议：

- `返回调整`
- `继续生成`

禁止出现：

- “Digest 过大”；
- “清洗后内容”；
- “压缩比例”；
- “系统删除了部分内容”；
- 内部字节预算、版本号和错误码。

## 6. 手动选择 Session 的测试要求

真实流程测试必须在以下节点暂停：

1. 后端部署并确认候选 Session 已 ready；
2. 打开 14.157 日报来源页面；
3. 由用户本人勾选一个或多个 Session；
4. 用户点击生成后，测试人员才开始跟踪 selection、run、Agent 和报告写回。

测试脚本不得调用创建选择接口替用户选 Session，也不得根据大小、日期或预期结果自动挑选来源。

## 7. 非功能需求

- Digest Builder 不调用 LLM、不执行 Session 中的命令；
- 相同输入、版本和配置产生相同输出与 Hash；
- 单个清噪规则必须有单元测试和稳定原因码；
- 不新增或改变 Session Token 统计口径；
- 不改变 Aida prepare/chunk/finalize 上传协议；
- 不因清噪构建失败破坏原始 Session 和已上传切片；
- 失败任务必须明确失败，不能 completed 但没有报告写回。

## 8. 明确不做

- 不使用 LLM、Embedding、向量检索或 Map-Reduce 生成 Digest；
- 不按模型上下文窗口自动删除内容；
- 不替用户挑选 Session；
- 不把工具原文重新塞回 Agent；
- 不在本轮调整 Token analytics、候选 Session 查询性能或 Aida 上传协议；
- 不在文档阶段声明生产发布。

## 9. 验收定义

1. 用户手动选择的全部 Session 均进入同一冻结快照；
2. 所有允许保留的语义块均能从来源事件映射到冻结 payload；
3. `semantic_blocks_truncated=0`；
4. 删除项全部属于允许的确定性噪音类型并带原因码；
5. 不存在 Top-K、成果评分、证据等级或“有文件变更才保留”的逻辑；
6. 小于 1 MiB 可直接运行，大于 1 MiB 能提示并允许用户继续；
7. Agent 真实调用 `get_sessions` 和 `write_report_result`；
8. 最终 Markdown 交给用户人工核对，重点验证方案、决定、实现、发布和质量优化没有遗漏；
9. 正文不泄漏内部技术细节；
10. 全流程只发生在明确指定的测试环境和测试账号。
