# v2.5-v2.7.9 三轮真实生成日报质量优化

> 日期：2026-07-16
> 环境：14.157 开发测试环境
> 最终 Digest：`session-digest/v2.7.9`
> 最终 Report Skill：`100866/aida-report@1.0.19`
> 结论：三轮优化、稳定化、真实上传、真实 Agent 生成、MCP 写回和生成日报校对均已完成；未操作生产。

## 1. 问题定义

第一阶段已经解决大 Session 无法生成日报的问题，但用户反馈生成结果仍偏向：

- 概括“和 Codex 聊了什么”，而不是“最终完成了什么”；
- 把文件修改、测试状态、验证过程和部署检查写入日报；
- 多个 Session 汇总时由一个强势 Session 占满结果；
- 将旧版本、阶段性尝试和最终状态并列；
- 在没有待跟进事项时仍生成空章节；
- 模型没有完整使用已提供的最终成果。

这既不是单纯的模型能力问题，也不是单一 Prompt 问题。根因由三层共同组成：

1. 早期 Digest 的结果投影仍混有过程证据；
2. 多 Session 选择级归并缺少稳定的最终状态和来源覆盖语义；
3. Report Agent 对 Skill 的遵循存在随机性，不能只靠提示词保证正确输出。

因此本轮采用“确定性服务端投影 + 结果型 Skill + 最小服务端写回门禁”，而不是不断扩大 Prompt 或重新读取原始 Session。

## 3. 三轮优化

### 3.1 第一轮：v2.5，去除明显过程噪声

主要改动：

- 过滤系统指令、Skill、审批转录和伪用户目标；
- 区分已完成、进行中和尚待处理；
- 降低纯验证工作优先级；
- 初步去除文件、命令、测试、环境和内部标识。

真实结果：

- selection：`c2987a19-5ddd-4fb7-900e-0634a21e583d`
- run：`8ced4244-7aae-42d6-b664-638aa0526a12`

校对结论：单 Session 噪声明显减少，但多 Session 汇总仍被强势来源占满。

### 3.2 第二轮：v2.6，修复跨 Session 丢失

主要改动：

- 选择级成果携带来源引用；
- 先在单 Session 内归并，再做跨 Session 最终状态覆盖；
- 在成果预算内优先保留各已选来源的代表结果；
- 对同一产品的旧版本和阶段性结果进行归并。

真实结果：

- selection：`025cc769-6a72-4c00-8c0f-7eec7cd60425`
- run：`2a292782-f009-4aae-b750-a0a19fad4f99`

校对结论：3 个来源均能进入选择级摘要，但正文仍混入实现文件、测试和验证过程。

### 3.3 第三轮：v2.7，面向用户成果投影

主要改动：

- 新增独立的 report-facing 确定性文本投影；
- 只保留实际交付、已修复能力、发布结果和有效待跟进；
- 过滤代码块、链接、路径、命令、文件清单、测试状态、主机、账号、资产标识、文档和行数统计；
- 对 Aida CLI、Aida Report、Bubble Tea TUI、目录列和前端发布等结果做稳定归一；
- 模糊目标从实际结果反推，不把“开始吧”等短指令写成工作目标。

### 3.4 稳定化：v2.7.1-v2.7.9

真实 Agent 校对暴露出仅靠 Skill 无法稳定解决的边缘问题，因此继续做小步稳定化：

- 选择级 `report_period_summary` 成为唯一权威成果输入；
- 删除 item 内重复的嵌套成果摘要，防止模型绕过选择级最终归并；
- 读取完整性校验同步要求嵌套摘要必须为空；
- 进一步过滤文档数量、文件数量、测试通过、发布检查表和未完成部署尾项；
- 选择级成果上限收敛为 5，避免模型在 6 个候选中随机遗漏关键结果；
- Report Skill 明确禁止从 item 重建成果，覆盖校验改用 `work_unit_ref`；
- 服务端写回门禁拒绝“进行中与待跟进：无/暂无”等空章节；
- 每次变更都提升不可变 Digest/Skill 版本，最终为 `v2.7.9 / 1.0.19`。

稳定化期间曾在测试环境发现一次读取校验仍要求旧嵌套摘要，导致
`SNAPSHOT_INTEGRITY_FAILED`；校验契约修正后，最终真实流程通过。

结果：通过。

### Review 2：架构与影响边界

实际影响模块：

- `api/internal/sessiondigestv2`：提取、归并、面向报告的文本投影；
- `api/internal/reportsource/digest_v2.go`：跨来源选择级合并和冻结结构；
- `api/service/daily_report_skill.go`：Report Agent 输出规范；
- `api/handler/report_content_validation.go`：可确定的正文空章节门禁。

明确不影响：

- Aida 客户端和上传协议；
- Session prepare/chunk/finalize；
- Session 原始事件和内容存储；
- usage、metering、Token 数值及 Token analytics 统计口径；
- MCP 工具接口、权限和报告来源完整读取语义；
- 前端；
- 数据库结构与迁移。

设计判断：

- 清洗只发生在 Digest 报告投影层，不触碰原始事实和计量事实；
- 跨 Session 最终归并必须由服务端完成，不能依赖模型自行重建；
- 模型负责自然语言表达，服务端负责结构、容量、来源和有限的确定性门禁；
- 不引入 RTK 二进制、Hook、命令改写、tee 或 raw fallback。

结果：通过。
