# 04 风险与三轮 Review

> 本文已合并开发 Review 与 14.157 真实日报三轮校对结论。

## Review 1：信息完整性

### 发现

1. 日级固定 6 项和选择级固定 5 项会直接丢失成果；
2. 资产版本启发式会把包含多个成果的 Work Unit 改写为单一发布项；
3. 相似主题 supersede 无法可靠区分“重复状态”和“不同生命周期阶段”；
4. 正文写回门禁仍限制个人日报最多 6 项，即使 Digest 完整也会被拒绝。

### 修正

- 两层上限全部移除；
- 生产链路不再调用启发式 supersede 和产物摘要重写；
- 选择级只按来源引用精确去重；
- 增加可机器校验的 `outcome_coverage`；
- 删除正文最多 6 项限制。

### 结论

服务端不再承担主观成果排序，符合“节省 Token，而不是提前代写日报”的产品边界。

## Review 2：容量与稳定性

### 风险

- 不做 Top-K 会增加冻结 payload 和 Agent 输入；
- 极端 Session 可能有大量短成果，单靠缩短文本仍超过硬上限；
- 若直接提高上限，可能重新引入 Token 和基础设施风险。

### 修正

- 保持 64 KiB 目标和 128 KiB 选择硬上限；
- 对所有成果均匀压缩文本，而不是按优先级删项；
- 删除 Evidence、Changes、Validations 等重复证明数据；
- item 详细 Work Units 与选择级 daily summary 不重复发送；
- 超过硬上限明确失败，禁止静默降级到残缺结果。

### 剩余风险

若真实用户一天产生数百个独立成果，仍可能容量失败。后续可设计“完整成果分页”或分层索引，但不在本次稳定修复中引入。

## Review 3：Agent 输出与模块影响

### 风险

- 完整清单中噪音增加后，Agent 可能逐项照抄；
- Agent 也可能沿用旧提示只保留 3～5 项；
- Skill、默认 Agent 指令和正文门禁若版本不一致，会造成假验收；
- Digest 版本升级可能被误认为影响上传或 Token 统计。

### 修正

- Skill 和运行指令同时声明：读取全部 highlights、无固定条目上限；
- Agent 写回前按 `work_unit_ref` 做静默覆盖映射；
- 允许同主线自然合并，但不同意义的生命周期阶段不可丢；
- Skill 采用新的不可变版本发布，并确认默认 Agent 实际指向该版本；
- 自动化测试允许个人日报超过 6 项；
- 真实验收必须核对 Agent 日志和持久化正文，不能只看 run completed。

### 真实日报三轮校对

1. 第一轮：Digest 已提供 18/18 成果，Agent 合并为 12 项；发现“测试环境误写生产”和旧版本覆盖后续结果。
2. 第二轮：增加忠实合并规则后环境误写消失，但模型仍会输出路径、文档计数和纯测试证据。
3. 第三轮：严格噪音门禁使模型通过“删条目”规避，一度仅剩 8 项；该结果被判定为方向跑偏，未采用。

最终收敛为“噪音可重写，成果不可删除”：回写时从冻结 Digest 计算报告期 canonical highlight 数，个人日报顶层条目少于该数时要求 Agent 重写。固定样本最终为 18/18，不再做 Top-K。

### 模块影响结论

| 模块 | 影响 |
| --- | --- |
| Aida 客户端上传 | 无 |
| Session 同步/切片 | 无 |
| Session 列表 | 无 |
| Token 统计与 analytics | 无 |
| Digest 构建 | 有，版本和投影策略变化 |
| report source 冻结 | 有，增加成果完整性校验 |
| Report Skill / Agent 指令 | 有，取消固定条目上限 |
| 日报正文门禁 | 有，取消最多 6 项限制；安全规则不变 |
| 数据库迁移 | 无 |
| 前端 | 无接口形态变更，不要求同步开发 |

## 当前发布判断

- 14.157 测试环境：功能、容量、真实 Agent 回写和 18/18 成果完整性通过。
- 生产：本文不自动给出发布授权；需同时确认 Aida 0.1.11 所依赖的 Session readiness API 代码已由对应会话正式提交。
- 剩余质量风险：为避免遗漏，正文会保留开发并行可行性、端到端链路等低价值但有结果的项；这是当前低损耗产品选择，不是服务端再做重要性判断。
