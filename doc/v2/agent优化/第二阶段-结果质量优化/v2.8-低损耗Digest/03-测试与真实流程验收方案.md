# 03 测试与真实流程验收方案

## 1. 测试原则

本轮不能只验证“任务完成”，必须分别证明：

1. Session 完整上传；
2. Digest 没有静默丢成果；
3. Agent 确实读取 v2.8 冻结快照；
4. 报告真实回写；
5. 最终 Markdown 语义合理。

禁止用手工构造日报、直接写数据库报告正文或仅调用内部 Digest 函数替代真实链路。

## 2. 自动化测试

### 2.1 提取与投影

- 超过 6 个结果 Work Unit 时全部保留；
- 传入旧的 limit 参数也不能截断；
- 方案、开发、部署与版本字符串共存时不得被资产发布摘要替换；
- failed、blocked、unresolved 必须纳入；
- 顺序稳定且 JSON 输出可重复。

### 2.2 选择级合并

- 三个 Session 共 8 项时保留 8 项；
- 相同产品的不同生命周期阶段不得合并；
- 只消除相同来源引用的完全重复项；
- 每天 `source_count=represented_count=len(highlights)`。

### 2.3 预算

- 大量证据引用可被裁剪；
- 多个长成果文本可被均匀缩短；
- 压缩前后成果条目数量不变；
- 选择超过硬上限返回容量错误；
- 不允许 `complete=true` 与实际条目数不一致。

### 2.4 Agent 与写回门禁

- Skill 必须包含完整读取、无 Top-K 和引用级覆盖检查；
- 默认 Agent 指令与 Skill 一致；
- 个人日报包含 7 项以上实质成果可以写回；
- 内部 ID、UUID、主机、路径、命令等仍会被拒绝。

## 3. 固定真实样本

| 项 | 值 |
| --- | --- |
| Session ID | `019f668c-2eb5-7c92-b08f-358ee84af865` |
| 来源 | 14.159 本机 Codex Session 文件 |
| 测试环境 | 14.157 |
| 测试用户 | t01 / uid 303 |
| 报告类型 | `personal_daily` |
| 报告日期 | `2026-07-16` |
| 时区 | `Asia/Shanghai` |

v2.7.9 已知基线：该日期提取到的结果 Work Unit 多于最终提供给 Agent 的成果数，日级和选择级分别受固定上限影响。v2.8 验收以实际完整文件重新计算，不硬编码历史文件大小。

## 4. 真实流程

### 4.1 清理旧测试数据

- 只清理 uid 303 下该 Session 的测试上传、选择和测试日报；
- 不清理其他用户和其他 Session；
- 清理后确认候选列表中没有旧切片干扰。

### 4.2 完整上传

1. 定位本机完整 JSONL 文件；
2. 记录文件大小、行数和 SHA256；
3. 使用隔离 HOME 和 t01 配置执行正式 `aida upload`；
4. 服务端确认上传起点为 cursor 0；
5. 确认最终 cursor 等于文件 EOF；
6. 确认 active slice 的 start/end cursor 覆盖完整内容。

### 4.3 Digest 验证

等待 `session-digest/v2.8.0` ready 后检查：

- 目标日期存在；
- `highlights_truncated=false`；
- `outcome_coverage.complete=true`；
- 三个计数相等；
- 每个结果 Work Unit 都能由 `work_unit_ref` 映射到一个 highlight；
- 包含 Session Digest 方案、开发和部署的结果文本没有被资产版本摘要覆盖；
- 冻结 payload 小于 128 KiB。

### 4.4 真实 Agent 日报

1. 通过公开 API 创建 `report-source-selection`；
2. 通过默认 Report Agent 创建 run；
3. 轮询 run，不跳过 Agent；
4. 从运行日志确认调用 `get_sessions`；
5. 确认 Agent 读取的版本为 v2.8.0 且 coverage 完整；
6. 确认调用 `write_report_result`；
7. 从报告 API 读取持久化正文；
8. 输出原始 Markdown 供用户人工核对。

## 5. 人工校对清单

- 是否把方案设计写成实际产出，而不是“参与讨论”；
- 是否覆盖开发实现、测试环境落地和后续质量优化；
- 是否把明显同一件事的重复状态合并得自然；
- 是否错误遗漏独立成果；
- 是否把纯测试过程、路径或命令当成成果；
- 是否出现内部账号、主机、ID、UUID 或证据引用；
- 是否存在“暂无”空章节；
- 是否严格属于 2026-07-16。

## 6. 通过条件

自动化测试全部通过，真实上传完整，Digest 覆盖率完整，Agent 成功回写，且最终日报经人工阅读没有关键成果遗漏，才允许把 v2.8 标记为测试环境验收通过。
