# V1 实施、测试与回退

## 1. 实施顺序

### 步骤 1：个人报告 Context Builder

- 复用现有 selection 冻结 Digest 读取与完整性校验；
- 对 B01-B10 生成 `report-context/v1`；
- 对照原 Digest 和第四阶段日报，确认实质工作对象没有消失；
- 记录 Context 大小、构建耗时和重复 hash。

任何样本发生实质事实遗漏，立即停止，不进入数据库和 MCP 开发。

### 步骤 2：持久化和完整性校验

- 新增 `report_run_contexts`；
- Run 创建后构建一次 Context；
- 完整性通过才允许启动 Agent；
- 构建失败复用现有 Run 失败状态；
- 不增加新的失败状态体系。

迁移文件为 `022_report_context_v1.sql`。编号 `021` 已由并行主分支的候选 Session 目录占用；本迁移只增加 `report_run_contexts`，不改现有业务表字段。

### 步骤 3：MCP 和默认 Agent

- 增加 `get_report_context(run_id)`；
- 默认 Agent 改为读取一次 Context；
- 继续复用 Skill 加载和现有写回；
- 个人 Context 路径精简为一次读取，团队/部门旧路由继续保留；
- 只在测试 owner 创建新 Agent Version。

### 步骤 4：真实链路验收

- 使用 B01-B10 跑 selection、Run、Context、Agent、写回完整流程；
- 人工校对新旧日报；
- 验收后再决定是否进入生产发布方案。

## 2. 测试范围

### 2.1 完整性

- B01-B10 实质工作对象覆盖率不降低；
- 不出现固定条数、Top-K 和重要性排序；
- 决策、失败、阻塞和明确待办保留；
- 相互冲突事实同时进入 Context；
- 空数据时返回明确合法状态。

### 2.2 稳定性

- 同一冻结 Run 重复构建 hash 一致；
- 相同输入字段顺序不同不影响 hash；
- Context 只构建一次并复用；
- Context 构建失败不启动 Agent；
- Agent 和写回失败使用现有 Run 失败流程。

### 2.3 权限

- run_id 泄露不能绕过认证；
- 不同用户、团队和部门不能交叉访问；
- Agent 不能覆盖 period、target、selection 和 scope；
- 过期、取消和无权 Run 被拒绝；
- Digest 中的提示注入文本只作为证据，不作为指令执行。

### 2.4 容量和成本

- 小、中、大冻结 Digest Context；
- 多 Session 和跨 Session 同一项目；
- Context Builder 耗时和响应体大小；
- Agent input tokens、总运行时间和写回成功率；
- 数据库平均、P95 和最大 `context_payload` 大小；
- 本批只验收个人日报/周报，组织报告做兼容回归。

容量测试不能通过静默裁剪。

### 2.5 兼容性

确认不影响：

- Session 上传和增量游标；
- Session 原文、Slice 和 Digest；
- usage、metering、Token analytics；
- 现有报告存储和查询；
- 前端 Session 选择；
- 旧 Agent Version；
- 用户自定义 Skill。

## 3. V1 观测

- context_build_duration；
- context_bytes；
- context_hash_mismatch_count；
- context_build_failure_count；
- Agent input/output tokens；
- write_report_result 成功率；
- 十样本人工校对的事实遗漏和完成度误判。

不建设通用质量评分平台，内部指标不得进入用户日报。

## 4. 回退

- 默认 Agent 重新绑定旧 Skill 和旧读取流程；
- `report_run_contexts` 是旁路数据，不修改 Session 和原报告；
- 停止调用 `get_report_context` 后，旧低层 MCP 工具仍可用；
- 不删除已生成记录，保留问题分析证据。

## 5. 已确认实现基准

- Report Run 复用 `ai_runs(business_type='report_agent_run')`；
- Builder 在 API 创建 Run 后、创建 Agent credential/session 前同步执行；
- selection 读取完成后继续满足现有写回完整性校验；
- Context 仅保存冻结 Digest，不修改 Digest、上传和 Token 统计；
- 团队/部门报告保持旧链路。
