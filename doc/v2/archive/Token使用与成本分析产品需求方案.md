# Token 使用与成本分析产品需求方案

## 文档状态

- 状态：已完成产品/技术交叉审查，待人工评审，未开始开发。
- 日期：2026-07-13。
- 适用项目：Aida 项目管理平台。
- 依据：`doc/v2/会议纪要.md`、当前 Token 页面能力、生产数据形态，以及只读参考项目 `ai_gateway_platform`。
- 本文是页面、权限、交互和产品口径的唯一产品依据；技术实现必须遵循 `doc/v2/Token成本统计与价格管理方案.md`，技术文档不得自行改变本文定义的产品形态。

## 1. 背景

平台已经采集用户上传的 session、按日活动切片、模型和 Token 数据，但目前 Token 页面主要面向个人明细查看，管理者无法快速回答以下问题：

- 各小组、部门和人员在选定时间内使用了多少 Token。
- 哪些人员使用最多，哪些人员长期使用不足。
- Token 主要消耗在哪些模型上。
- 按统一价格口径估算，相当于多少 API 使用成本。
- 哪些人员长期没有上传、没有活动或使用量明显偏低。
- 某个异常统计数值由哪些 session 构成。

本次迭代的重点是补齐管理分析能力，不将 Aida 改造成完整的 AI 网关运营平台。

### 1.1 术语与统计对象

为避免开发时混用数据库字段和页面概念，本文统一使用以下定义：

| 术语 | 唯一定义 |
| --- | --- |
| Session ID | 用户本地工具产生并由 Aida CLI 上传的 `session_ref`，即页面需要展示和搜索的真实 Session ID |
| 内部记录 ID | Aida 数据库 `sessions.id`，只用于内部关联，不在页面展示，也不作为用户搜索字段 |
| Session 概览 | 优先使用所选活动范围内最新的非空 activity summary；没有时依次回退 activity excerpt、session summary |
| Activity slice | 一个 Session 在一个业务自然日内的活动切片；同一 Session 跨天会有多个 slice |
| Session 数 | 选定范围内去重后的内部 Session 记录数，不是 activity slice 行数 |
| 活跃天数 | 选定范围内 Token 大于 0 的不同 `activity_date`数量 |
| API 等价成本 | 使用平台已审核的官方 USD API 价格计算，并按对应日期的平台核算汇率折算为人民币的估算金额；不是订阅消耗、Credits 消耗或实际账单 |
| 部门管理范围 | 当前总监负责的全部小组集合，即 `teams.director_user_id = 当前总监`；V1 不新增独立部门实体 |
| 统计成员 | 当前已启用且属于角色授权范围的用户；停用、归档账号不进入当前排名和人数分母 |

页面统一显示“Session ID”，其值必须是 `session_ref`。禁止把数据库内部 UUID 当作“真实 Session ID”展示给用户。

## 2. 产品目标

### 2.1 核心目标

1. 让总监能够从自己的部门管理范围、小组、人员、模型四个维度查看 Token 使用情况。
2. 让总监和小组长能够识别高用量与低用量人员，而不只看到汇总总量。
3. 在统一、可解释的价格口径下提供 API 等价成本估算，并与订阅套餐口径严格分开。
4. 保留从汇总数据下钻到 session 明细的路径，保证统计结果可核查。
5. 复用现有 session 与 Token 数据，不要求用户增加新的上报操作。

### 2.2 非目标

- 不建设模型网关的路由、限流、可用率、请求耗时和安全监控能力。
- 不建设或接入新的模型网关、第三方计价工具和定时价格自动同步服务；管理员主动触发的 AI 辅助查询只回填候选值，不能自动发布。
- 不核算自部署模型的 GPU、机器、人力等真实运营成本。
- 不将 API 等价成本描述成实际账单或真实订阅消耗。
- 不根据本地 Token 推算 Plus、Pro 等订阅套餐的剩余额度或利用率。
- 首期不拆分独立的模型分析、用户分析、部门分析等多个复杂子系统。
- 首期不提供小时级筛选、多模型复杂折线对比和多模态价格管理。

## 3. 目标用户与权限

| 角色 | 默认范围 | 可查看内容 |
| --- | --- | --- |
| 工程师 / PM | 个人 | 个人指标、API 等价成本、趋势、模型构成、session 明细 |
| 小组长 | 个人 + 本小组 | 个人概览；小组汇总、成员前后排名、每人成本、模型构成及 session 下钻 |
| 总监 | 个人 + 管理范围内全部数据 | 个人概览；部门与小组汇总、小组排名、全量人员前后排名、每人成本及逐级下钻 |
| 系统管理员 | 个人 + 全平台 | 个人概览；与总监相同的分析能力，以及价格维护能力 |

统计权限沿用现有组织和角色权限，不因新增图表扩大用户的数据可见范围。

## 4. 核心使用场景

### 4.1 总监查看整体使用情况

总监进入“Token 使用分析”后，默认查看最近 7 天的全部管理范围，快速了解总 Token、活跃人数、无数据人数和 API 等价成本，并查看小组及人员的高低用量排名。

### 4.2 总监定位低使用人员

总监选择本月，查看人员后 5 名及完整排名，区分“没有上传数据”“有上传但用量低”“存在未计价模型”等情况，再决定是否需要推动使用或排查上传问题。

### 4.3 小组长查看组内差异

小组长查看本小组成员排名和模型使用结构，点击成员后查看该成员的每日趋势及 session 明细，核对低用量是否来自休假、工作类型差异或上传遗漏。

### 4.4 个人核对自身数据

用户查看个人 Token 趋势、模型构成及 session 明细，确认本地使用记录是否已经上传并被正确统计。

### 4.5 管理员处理未计价模型

管理员查看未计价模型及其影响 Token，录入或审核价格。价格缺失只影响成本估算，不影响 Token 数据和 session 上传。

### 5.3 成本价格管理

价格管理是统计分析的支撑能力，仅管理员可编辑，不作为普通用户的主要入口。首期包含：

- 当前生效价格。
- 未计价模型。
- 历史价格记录。
- 人工新增、核对和发布价格。

## 6. 两个 Token 页面的公共规则与交互

### 6.1 筛选区

| 筛选项 | 产品规则 |
| --- | --- |
| 时间范围 | 默认最近 7 个 Asia/Shanghai 自然日，即今天及前 6 天；支持自定义自然日范围；不可清空 |
| 统计范围 | “我的 Token”固定为自己；“Token 使用分析”按角色固定可见范围 |
| 管理范围 / 小组 | 小组长固定为本小组；总监固定为自己的部门管理范围并可筛选其中小组；管理员可查看全平台并筛选总监管理范围或小组 |
| 人员 | 仅管理分析页展示，并限制在当前可见组织范围内 |
| 模型 | 各角色均支持单选或全部模型，默认全部 |

所有模块必须使用同一筛选条件。修改时间、组织、人员或模型后，指标、趋势、排名、模型明细和 session 明细同步刷新。

### 6.2 核心指标

不同角色展示不同的四项主指标：

| 角色 | 主指标 |
| --- | --- |
| 所有角色的“我的 Token” | 总 Token、API 等价成本、活跃天数、session 数 |
| 小组长 | 小组总 Token、活跃成员、无数据成员、API 等价成本 |
| 总监 | 管理范围总 Token、活跃人数、无数据人数、API 等价成本 |

输入、输出、缓存读取和缓存写入作为辅助信息，不与主指标竞争视觉优先级。最近活动时间显示在个人页摘要或 session 区域。

成本指标旁固定说明：

> 按平台已审核价格估算，不代表实际订阅或企业合同账单；未计价 Token 不计入成本总额。

成本展示规则：全部已计价时显示金额；部分可计价时显示“金额（部分未计价）”；全部无法计价时显示“未计价”。禁止把未计价部分当作 0，也禁止只显示一个看似完整但实际缺失部分模型的金额。

### 6.3 趋势

- 个人页和管理分析页均可通过 `Token` 和 `API 等价成本`切换趋势。
- 默认按日展示；范围较长时可按周或月聚合。
- 当前筛选为某个小组或人员时，趋势同步切换到对应对象。
- 首期不提供任意多个模型的复杂多折线组合。

### 6.4 排名

排名仅面向小组长、总监和管理员。工程师和 PM 的个人视图不展示任何组织或人员排名。

#### 小组排名

总监可查看所有可见小组，至少展示：

- 排名和小组名称。
- 总 Token。
- API 等价成本。
- 活跃人数 / 小组总人数。
- 人均 Token。

点击小组后，页面进入该小组范围，并同步刷新成员排名、模型和 session 明细。

#### 人员排名

按照会议确定的规则：

- 默认同时展示前 5 名和后 5 名。
- 可在 `Token`、`API 等价成本`、`活跃天数`之间切换排名指标。
- 当前范围不足 10 人时展示全部人员，不重复展示同一人员。
- 提供“查看完整排名”，展示当前筛选范围内的全部人员。
- 排名必须包含零数据人员，才能识别所选范围内没有可统计活动的人员。
- 无数据、有活动、计价异常和数据异常必须分别展示，不能都显示为 `0`，也不能直接得出“未上传”或“使用不充分”的结论。
- Token 和活跃天数并列时，先按最近活动时间排序，再按人员显示名称排序，保证结果稳定。
- API 等价成本排名只对 `已计价`数据进行金额排序；`部分未计价`和`未计价`人员单独列在“成本不可完整排名”区域，但仍出现在完整人员表中。

完整排名至少展示：人员、所属小组、Token、API 等价成本、活跃天数、session 数、最近活动时间和数据状态。

### 6.5 使用活跃度

会议中提出通过用量判断工具使用是否充分。平台只能基于已经上传的数据展示可验证的使用事实，不合成一个缺少依据的“套餐利用率”。

使用活跃度由以下独立指标共同呈现：

- Token 总量。
- 活跃天数。
- session 数量。
- 最近活动时间。
- Token 日趋势。

产品规则：

- 默认按 Token 排名前 5 和后 5，同时展示活跃天数、session 数和最近活动时间作为判断依据。
- 不把多个维度加权成无法解释的综合分数。
- 低 Token 只能作为管理线索，页面不能直接给人员标记“使用不充分”。
- 组织成员在所选范围内没有可统计 activity slice 时显示“无数据”。该状态不能用来判断用户是否执行过 `aida upload`。

### 6.6 订阅套餐与 API 成本的边界

外网用户使用的是 ChatGPT Plus、Pro 等订阅套餐，而不是由 Aida 持有 API Key 按 Token 结算。订阅月费、套餐内 Codex allowance 和超限购买的 credits 是不同概念。

- Aida 上传的 Token 可以用于工作量分析和 API 等价成本估算。
- Aida 无法仅凭这些 Token 得知用户订阅套餐的已用额度、剩余额度或重置周期。
- `API 等价成本 / Pro 月费`没有业务含义，禁止作为套餐利用率。
- 如果未来能够获得供应商提供的账号级官方 usage / credits 数据，应作为独立数据源展示，不能由 API 单价反推。
- 如需统计公司固定订阅支出，可另行维护套餐席位和月费；该金额只能用于预算统计，不能分摊成本地 Token 的实际消费。

### 6.7 模型使用明细

模型模块优先使用可比较的表格。所有角色展示：

- 标准模型名称。
- Token 总量及占比。
- 输入、输出和缓存 Token。
- 计价状态。

所有角色都展示自己可见范围内的 API 等价成本及占比。小组长、总监和管理员在管理分析页额外展示活跃人数；个人页面不展示其他人员信息。

模型名称无法归一化或没有价格时，进入“未识别 / 未计价”状态，不得按零成本处理。

### 6.8 Session 明细

Session 明细以“一个 Session 一行”展示，并与上方筛选联动。同一 Session 在所选范围内存在多个 activity slice 时，先按 Session 聚合 Token 和成本，不能重复显示成多个 Session。点击行后可查看该 Session 的逐日 activity slice。

至少展示：

- 真实 Session ID，即 `session_ref`。
- Session 概览。
- 用户和所属小组（仅有权限的角色可见）。
- 最近活动时间。
- 涉及模型。
- Token 分类及总量。
- API 等价成本或未计价状态（所有角色均可查看自己有权访问的记录）。

点击汇总指标、排名人员或模型后，可以通过筛选后的 session 明细解释统计来源。

### 6.9 Session 搜索

“我的 Token”和“Token 使用分析”都提供 Session 搜索，支持：

- 按真实 Session ID（`session_ref`）搜索，支持完整 ID 和连续片段。
- 按 session 概览内容关键词搜索。
- 结果以一个 Session 一行，展示真实 Session ID、概览、所属用户、最近活动时间、模型、Token 和 API 等价成本。

搜索规则：

- 搜索必须在服务端执行并支持分页，不能只筛选当前已经加载的一页。
- 搜索始终受角色数据权限约束，不能通过 Session ID（`session_ref`）越权读取其他人的记录。
- 服务端先在用户权限范围内判断输入值是否与 `session_ref`完全一致。完全一致时进入定位模式：忽略当前日期、组织、人员和模型筛选；页面显示“已按 Session ID 跨筛选定位”，并展示该 Session 全部已上传活动的日期范围、Token 和 API 等价成本。同一 `session_ref`在不同用户下有多条授权记录时分别展示，不能合并或随机取一条。
- 没有完全一致的 Session ID 时，按 Session ID 片段或概览关键词进行不区分大小写的包含搜索，并遵循当前时间、组织、人员和模型筛选条件。
- 搜索无结果时，页面应区分“不存在或无权限”与“当前筛选范围内无匹配结果”，但不能泄露无权限 session 是否真实存在。

## 7. 数据状态与提示

为避免错误管理判断，产品必须分别展示“活动状态”和“计价状态”，两者不得合并成一个模糊状态：

| 状态维度 | 状态 | 唯一判断依据 | 页面处理 |
| --- | --- | --- | --- |
| 活动状态 | 有活动 | 所选范围内至少一个 activity slice 的 Token 大于 0 | 展示 Token、活跃天数和 Session 数 |
| 活动状态 | 无数据 | 所选范围内没有可统计 activity slice | 标识无数据；不能推断为未上传或未使用工具 |
| 计价状态 | 已计价 | 范围内全部计费 Token 均匹配有效价格和汇率 | 展示完整的人民币 API 等价成本 |
| 计价状态 | 部分未计价 | 仅部分模型或 Token 匹配价格和汇率 | 展示已计价人民币金额，并标注“部分未计价” |
| 计价状态 | 未计价 | 有 Token，但全部无法同时匹配有效价格和汇率 | 成本显示“未计价”，不显示为 0 |
| 数据状态 | 数据异常 | Token 字段冲突、模型无法拆分等 | 不强行估算成本，提供异常提示 |

平台要求用户必须上传 session，目标完成率始终是 100%，因此页面不展示“上传覆盖率”或“未上传人数”。仅凭某段时间没有 Token 或 activity slice，无法判断用户是否执行过上传；页面统一使用事实口径“无数据”。

用户页面同样不展示“价格覆盖率”。出现新模型没有价格或目标日期缺少有效汇率时，在对应成本字段显示“未计价”，并由管理员在成本管理页集中处理。

## 8. 成本价格管理页

### 8.1 生效价格

展示标准模型、USD 输入价格、USD 输出价格、USD 缓存价格、生效日期、来源和审核人。单价单位固定为 USD/百万 Token，避免在价格配置中混入展示汇率。

### 8.2 待发布价格

管理员依据供应商官方价格页面人工录入价格，填写来源、计费变体和生效日期，核对后发布。可点击“AI 辅助查询”获取带官方来源链接的表单候选值；AI 不能直接保存或发布价格。未发布价格不能参与成本计算。

### 8.3 未计价模型

按未计价 Token 影响量排序，展示原始模型名称、首次和最近出现时间、影响用户及小组，帮助管理员优先处理。

### 8.4 价格历史

保留每次生效价格及其适用时间，确保历史成本能够解释。修改当前价格不能静默重写过去的成本结果。

### 8.5 美元汇率

平台维护统一的 USD/CNY 核算汇率，页面表达为“1 USD = N CNY”。管理员设置汇率、生效日期、来源和备注，也可使用 AI 辅助查询后人工确认。汇率不是浏览器实时汇率；新汇率只影响其生效日期之后的成本，历史人民币成本继续使用原汇率快照。

普通用户页面只显示人民币。成本详情和管理端可展示 USD 原值、使用的汇率及折算结果，便于核对。

## 9. 与参考项目的取舍

### 9.1 首期吸收

- 统一时间和组织筛选。
- 总量指标与趋势。
- 小组、人员排名。
- 模型使用及成本结构。
- 从汇总到明细的下钻。
- USD 原始单价、汇率快照和人民币成本的可追溯关系。

### 9.2 首期不吸收

- 模型、用户、部门各自独立的大型分析页面。
- 外部 API 与自部署模型的成本拆分。
- 网关请求数、请求耗时、缓存命中率运营分析。
- 小时级分析和复杂多模型曲线选择器。
- 音频、图片、视频、搜索等多模态计费字段。
- 每个模型价格版本重复保存汇率，以及面向多币种网关的复杂币种切换；Aida 使用独立的全局 USD/CNY 汇率版本。
- CSV 导出和定时报表导出。

## 10. 首期范围

### P0：必须完成

- 统一时间、组织、人员、模型筛选。
- 所有角色均有独立的“我的 Token”页面，并展示个人 API 等价成本。
- 小组长、总监和管理员拥有独立的“Token 使用分析”页面。
- 总 Token、API 等价成本、活跃人数和无数据人数。
- Token / 成本日趋势。
- 小组排名。
- 人员前 5、后 5及完整排名。
- 活跃天数、session 数和最近活动时间等使用活跃度信息。
- 模型使用明细。
- 按去重 Session 聚合、与筛选联动的 Session 明细及逐日 slice 下钻。
- 按真实 Session ID（`session_ref`）和概览内容进行服务端搜索。
- 生效价格、未计价模型和人工价格维护。
- USD/CNY 核算汇率维护，以及管理员主动触发、人工确认的 AI 辅助查询。

## 11. 产品验收标准

1. 工程师、PM、小组长、总监和管理员都能进入“我的 Token”，查看个人 Token、API 等价成本、趋势、模型和 session。
2. 小组长、总监和管理员能进入独立的“Token 使用分析”；工程师和 PM 不显示该菜单。
3. 总监可以按时间、自己的部门管理范围、小组、人员和模型查看统计数据及每个人的 API 等价成本。
4. 总监可以同时看到所选范围的前 5 名、后 5 名，并查看完整人员排名。
5. 人员排名包含组织内零数据人员，并能分别展示活动状态和计价状态；无数据不能被解释成未上传。
6. 小组长只能查看本小组，总监和管理员只能查看授权管理范围。
7. 任一排名对象都能下钻到对应趋势、模型和 session 明细。
8. 页面明确区分 API 等价成本、订阅月费、套餐额度和实际账单，不能产生误导或展示推算的套餐利用率。
9. 价格或汇率缺失不按零成本处理，并在相关成本字段显示“未计价”；缺失不影响 session 上传和 Token 总量统计。
10. 用户可以按真实 Session ID（`session_ref`）或概览内容搜索其有权查看的历史记录；搜索不能被当前分页限制，也不能越权。
11. Session 数按去重后的 Session 计算；跨天 Session 不得因多个 activity slice 被重复计数或重复展示。
12. 修改任一筛选条件后，当前页面所有统计模块使用完全相同的范围。
13. 默认最近 7 天的数据能够在合理等待时间内完成展示，不需要管理者手工拼接多个页面。
14. 个人、团队、部门的成本总额、趋势、排名和 Session 明细统一显示人民币；任一金额可追溯到 USD 单价版本、汇率版本和折算结果。

## 12. 已确认产品决策

1. V1 不新增独立部门实体。总监的“部门”就是其负责的全部小组集合；管理员可按总监管理范围或小组筛选。
2. 前 5、后 5首期不自动排除新入职、休假等人员，因为当前没有权威 HR 状态数据。页面只展示事实指标，不自动评价人员使用是否充分。
3. 完整排名首期只需页面查看，下载和导出属于 P1。
4. Plus、Pro 等订阅席位、固定月费和套餐剩余额度不在 V1 范围，也不参与个人 Token 利用率计算。
5. V1 官方 API 单价固定使用 USD，用户页面统一显示按平台核算汇率折算的人民币，成本名称仍为“API 等价成本”。
