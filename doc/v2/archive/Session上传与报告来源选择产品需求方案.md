# Session 上传与报告来源选择产品需求方案

## 文档状态

- 状态：待产品评审定稿
- 日期：2026-07-14
- 适用产品：Aida 项目管理平台、Aida CLI
- 产品范围：Session 浏览与上传、跨设备衔接、Session 内容管理、个人报告来源选择
- 文档定位：本文只定义用户可见的产品形态、交互规则、权限和验收口径，不定义接口、数据表、同步协议或代码实现

本文是本期 Session 产品形态的唯一产品依据。技术方案必须满足本文，不得在开发过程中自行增加用户操作、改变删除含义或扩大报告的数据范围。

## 1. 背景

当前 Session 使用流程存在以下用户问题：

1. CLI 一次展示过多 Session，用户难以找到最近实际使用的记录。
2. 长期 Session 每次上传看起来都像重新上传完整记录，用户无法判断本次新增内容是否已同步。
3. CLI 升级、重新安装或更换电脑后，用户担心登录失效、历史 Session 重复上传或无法继续同步。
4. 部分 macOS 终端看不到 Session summary，用户只能依靠 Session ID 判断内容。
5. 个人日报和周报只能按报告当天的 Session 切片选择，无法覆盖跨天任务和历史 Session。
6. 用户需要自主清理敏感或不再需要的 Session 内容，但管理统计又不能被随意抹除。
7. Session 上传、Token 日统计和报告来源选择在产品表达上混在一起，用户无法理解选择一个日期究竟代表什么。

本期目标是先把 Session 的上传、浏览、清理和报告来源选择做清楚。报告内容压缩、Token 成本分析和价格管理分别独立开发，不混入本期。

## 2. 产品目标

### 2.1 核心目标

1. 用户能够快速找到最近使用过的 Session，并通过 summary 判断其内容。
2. 用户重复执行上传时，只同步尚未同步的新活动，不产生重复记录和重复 Token。
3. CLI 升级、重新安装或更换电脑后，可以继续使用同一账号和已有同步进度。
4. 用户可以自主清除自己的 Session 内容，同时不破坏平台的组织统计真实性。
5. 用户生成个人日报或周报时，可以自由选择跨天、跨周期的多个 Session 来源。
6. 小组和部门报告继续基于下级已保存报告汇总，不默认读取所有成员的原始 Session。

### 2.2 用户价值

- 上传行为可预期：重复执行不会重复计算。
- 历史数据连续：换电脑或升级 CLI 不需要重新整理平台数据。
- Session 可辨识：summary、项目和最近活动时间足以支持选择。
- 报告来源灵活：任务跨天时不再受日报日期限制。
- 内容可管理：用户可以清除原始工作内容，平台统计仍保持稳定。

## 3. 本期范围

### 3.1 本期包含

- CLI 专用登录凭证长期有效。
- CLI 升级、重新安装和换电脑后的连续使用。
- Session 按最近活动排序。
- CLI Session 列表分页。
- CLI 上传选择分页。
- 只上传新增活动，并提供清晰结果状态。
- macOS、Linux 一致展示 Session summary。
- 用户清除自己的 Session 内容。
- 用户显式恢复并重新上传已清除的 Session。
- 管理员彻底删除错误或测试数据。
- 个人日报、个人周报跨天、多 Session 来源选择。
- 已选报告来源在一次生成过程中保持稳定。

### 3.2 本期不包含

- 报告内容压缩、去重、长文本截断或二次总结。
- 首尾各取若干条等临时压缩策略。
- Token 成本分析页面和模型价格管理。
- Plus、Pro、Credits 或订阅利用率计算。
- 自动后台上传和强制常驻客户端。
- 删除用户电脑上的 Claude Code 或 Codex 原始文件。
- 用户逐条选择底层上传片段。
- 小组和部门报告批量读取所有成员的原始 Session。
- 修改或扩展用户自定义 Agent 的产品能力。

## 4. 用户与权限

| 用户角色 | 浏览 Session | 清除内容 | 恢复上传 | 彻底删除 | 个人报告选择来源 |
| --- | --- | --- | --- | --- | --- |
| 工程师 | 自己 | 自己 | 自己 | 否 | 自己 |
| PM | 自己 | 自己 | 自己 | 否 | 自己 |
| 小组长 | 自己；管理分析中可查看授权统计 | 仅自己 | 仅自己 | 否 | 仅自己 |
| 总监 | 自己；管理分析中可查看授权统计 | 仅自己 | 仅自己 | 否 | 仅自己 |
| 管理员 | 自己及管理范围 | 仅自己的普通入口 | 自己 | 是 | 自己 |

权限规则：

1. 管理角色能查看成员统计，不代表可以清除成员的 Session 内容。
2. 用户不能通过 Session ID 查看无权限用户的 summary 或原始内容。
3. 个人报告只能选择当前登录用户自己的 Session。
4. 管理员彻底删除必须是独立管理操作，不能复用普通用户的“清除内容”。

## 5. CLI 登录产品规则

### 5.1 长期有效

Aida CLI 使用现有 CLI 专用凭证。该凭证不会因为时间经过而自动失效。

以下情况仍会导致无法使用：

- 凭证本身无效；
- 用户账号被停用；
- 用户的 Aida 使用权限被关闭；
- 管理员主动使该凭证失效。

页面登录状态和其他业务登录凭证不属于本规则。

### 5.2 CLI 升级

- 正常升级不得删除现有登录信息。
- 升级完成后用户不需要重新登录。
- 升级不得丢失本机已经确认的上传进度。
- 如果新版必须重新读取历史记录，平台不得因此重复生成 Session 或重复 Token。

### 5.3 更换电脑

用户在新电脑安装 Aida 后，通过现有方式输入同一个 CLI 专用凭证即可继续使用。

产品表现：

- 平台已有 Session 和统计继续存在；
- 新电脑上传相同 Session 时能够识别平台已接收的部分；
- 已完整迁移到新电脑的长期 Session 可以从已有进度继续同步；
- 新电脑没有对应本地日志时，不影响平台已有数据，但无法凭空恢复本地原始内容；
- 检测到本地记录与平台历史明显不一致时，停止自动续传并提示用户重新完整同步，不能静默重复计算。

本期不增加设备列表、设备绑定或多设备管理页面。

## 6. CLI Session 浏览

### 6.1 默认排序

`aida sessions` 默认按“最近活动时间”倒序，而不是按 Session 启动时间排序。

长期 Session 只要最近仍有活动，就应出现在列表前面。

### 6.2 分页

- 默认每页 20 条。
- 支持上一页、下一页和跳转页码。
- 支持调整为每页 10、20、50或100条。
- 页面显示当前页、总页数和 Session 总数。
- 翻页不改变当前列表的排序。

示意：

```text
Session 列表                                      第 1 / 8 页，共 153 条
────────────────────────────────────────────────────────────────────────
1   Codex   今天 10:42   019f...   修复需求看板弹窗显示异常
    project_manager · GPT-5.4 · 28.6M Token

2   Claude  今天 09:18   019e...   梳理 Session 上传与日报来源选择
    project_manager · Claude 4.7 · 17.2M Token

[上一页] [下一页] [跳转页码]                      每页 [20 ▼]
```

### 6.3 Summary 展示

- summary 必须在 macOS 和 Linux 终端中可见。
- 宽终端可以单行展示。
- 窄终端必须自动换为两行布局，不能把 summary 挤出可视范围。
- 中文、英文、emoji 和多行首条消息均应正常显示。
- 没有可用 summary 时明确显示“暂无摘要”，不能留空造成误解。
- summary 过长时可以在列表中省略，但必须保留可识别的开头内容。

### 6.4 Session 行展示内容

至少展示：

- 序号；
- Agent 类型；
- 最近活动时间；
- 真实 Session ID；
- summary；
- 项目或工作目录名称；
- 主要模型；
- Token 总量或数据状态。

## 7. CLI 上传

### 7.1 选择方式

`aida upload` 使用与 Session 列表一致的排序和分页。

- 用户可以跨页选择多个 Session。
- 翻页后已选择项继续保留。
- 确认上传前展示已选数量、Session ID 和 summary。
- 用户选择的是 Session，不需要理解或选择底层上传片段。
- 支持按真实 Session ID直接选择，避免自动化脚本依赖列表序号。

示意：

```text
选择要上传的 Session                            已选择 3 条
────────────────────────────────────────────────────────────────────────
[x] 1  019f...  修复需求看板弹窗显示异常
[ ] 2  019e...  梳理 Session 上传与日报来源选择
[x] 3  019d...  排查生产日报回写失败

[上一页] [下一页] [跳转] [选择全部待上传] [确认上传]
```

### 7.2 重复上传

用户可以放心重复执行上传：

- 没有新活动的 Session 不重复上传；
- 有新活动的 Session 只同步新增部分；
- 网络超时后再次执行不会重复计算；
- 同一 Session 在平台主列表中仍然只显示一条；
- 以前日期的数据不会因为后续上传而减少或移动到其他日期。

### 7.3 `upload --all`

“全部上传”表示检查全部本地 Session，并同步其中尚未同步的新活动。

它不表示每次重新发送全部历史内容。

### 7.4 上传结果

每个 Session 应显示用户可理解的结果：

| 状态 | 用户文案 | 含义 |
| --- | --- | --- |
| 已上传 | 已同步新增内容 | 本次存在新活动并已同步 |
| 无变化 | 已是最新 | 没有需要同步的新活动 |
| 已存在 | 平台已接收，无需重复上传 | 重试内容已经成功处理 |
| 内容已清除 | 已跳过，请显式恢复后上传 | 用户此前清除了平台内容 |
| 失败 | 显示明确原因和重试建议 | 本次没有完成同步 |

一次上传中部分 Session 失败时，已成功的 Session 不回退；失败项应单独列出，用户可以再次执行。

## 8. Session 内容管理

### 8.1 用户操作名称

普通用户操作统一命名为：

```text
清除内容
```

不使用“永久删除 Session”或“撤回 Session”，避免让用户误以为所有统计都会消失。

### 8.2 清除内容的影响

用户确认后清除：

- 平台保存的原始 Session 日志；
- Session summary 和 excerpt；
- 报告生成可读取的 Session 内容；
- 原始日志下载能力。

继续保留：

- Session ID；
- 活动日期和最近活动时间；
- 模型信息；
- Token 和 API 等价成本统计；
- 已保存报告正文；
- “内容已清除”状态。

确认文案：

> 清除后，平台将不再保存或展示该 Session 的原始内容，也不能再将其选择为报告来源。Token、模型、活动时间和成本统计仍会保留。此操作不会删除你电脑上的原始文件。

### 8.3 清除后的展示

Session 管理中保留一条轻量记录：

```text
019f...   内容已清除   最近活动 07-14 10:42   28.6M Token
```

- 不显示旧 summary；
- 不提供日志下载；
- 不允许选为报告来源；
- 管理统计中正常计入 Token、模型、活动日和成本。

### 8.4 恢复并重新上传

用户本机仍有原始日志时，可以显式选择“恢复并重新上传”。

- 普通 `upload --all` 不自动恢复已清除内容；
- 恢复前再次确认将重新向平台提供原始内容；
- 恢复后生成新的可用内容版本；
- 以前已经保存的报告不自动替换来源或重写正文；
- 本机日志已不存在时，页面应说明无法恢复原始内容。

### 8.5 管理员彻底删除

管理员可以对误传、测试数据和确认错误的统计执行“彻底删除数据”。

彻底删除包括内容、Token、成本和活动统计。操作前必须展示：

- 用户；
- Session ID；
- 影响日期；
- Token 和成本影响量；
- 已关联报告或任务提示。

管理员必须填写删除原因并二次确认。普通用户、小组长和总监没有该能力。

## 9. 个人报告来源选择

### 9.1 适用范围

Session 来源选择只用于：

- 个人日报；
- 个人周报。

小组日报、小组周报、部门日报和部门周报不展示 Session 选择入口。

### 9.2 默认行为

- 用户不选择 Session 时，报告生成继续使用报告周期内的现有个人数据来源。
- 用户显式选择 Session 后，选中来源是本次个人报告的优先来源。
- 报告日期决定报告保存在哪一天或哪一周，不限制用户可以选择哪些历史 Session。

### 9.3 Session 选择弹窗

弹窗一行展示一个 Session，不按自然日重复显示同一 Session。

支持：

- 默认查看报告周期附近的 Session；
- 查看更早历史；
- 按真实 Session ID 搜索；
- 按 summary 关键词搜索；
- 分页；
- 多选 Session；
- 选择完整 Session；
- 展开后选择连续活动范围；
- 同一 Session 选择多个不同活动范围。

示意：

```text
选择本次 AI 生成使用的 Session                         已选 2 项
──────────────────────────────────────────────────────────────────────
[搜索 Session ID 或摘要________________]  [日期不限 ▼]

[x] 019f...  修复需求看板弹窗显示异常
    最近活动：07-14 10:42  ·  活动范围：07-12 至 07-14
    来源范围：[07-12 09:30 至 07-14 10:42 ▼]

[x] 019e...  排查日报回写失败
    最近活动：07-11 18:20  ·  已选完整 Session

[取消]                                            [应用选择]
```

### 9.4 选择规则

1. 选择结果必须明确显示 Session 和活动时间范围。
2. 允许选择报告周期以外的历史 Session。
3. 已清除内容的 Session 不可选择。
4. 无权访问的 Session 不出现在搜索结果中。
5. 用户点击生成后，本次使用的来源固定；生成过程中继续上传同一 Session，不改变本次来源。
6. 生成完成后继续上传同一 Session，不自动重写已生成或已保存的报告。
7. 用户重新点击生成时，可以继续沿用当前选择，也可以重新调整。

### 9.5 AI 生成结果

- AI 生成仍是初稿，用户可以编辑和保存。
- 页面应保留本次选中的 Session 数量和范围，方便用户核对来源。
- 本期不承诺新增的内容压缩、长文本总结或更高报告准确率。
- 本期不得把完整原始 Session 无限制传入模型。
- 当前报告使用的信息范围保持现有能力，只解决“选哪些 Session”的产品问题。

## 10. 小组与部门报告

本期继续沿用以下产品路径：

- 小组日报和周报以成员已保存的个人日报、周报为主要来源；
- 部门日报和周报以已保存的小组报告及必要的下级报告为主要来源；
- 不要求小组长或总监逐个选择成员 Session；
- 不默认读取全小组、全部门所有原始 Session；
- 成员是否存在原始 Session 不能替代个人报告覆盖情况。

此规则用于控制权限、内容成本和报告可解释性，不因个人报告支持跨天选择而改变。

## 11. Token 与活动数据的产品口径

### 11.1 Session 与每日统计

- Session 是一条持续会话，同一 Session 跨天时主列表只显示一条。
- Token 页面可以按自然日展示该 Session 的活动统计。
- 报告来源选择不等于 Token 日统计选择，两者在产品上必须分开表达。

### 11.2 活跃状态

是否活跃根据有效 Session 活动判断，不以 Token 是否大于 0作为唯一条件。

页面应区分：

- 有活动且 Token 完整；
- 有活动但 Token 不完整；
- Token 数据异常；
- 所选范围内无活动数据。

### 11.3 后续上传

- 新增活动可以增加对应日期的数据；
- 普通重复上传不得降低既有日期数据；
- 晚上传的历史活动可以补充历史日期，但不能把其他日期数据移走；
- 用户清除内容后，Token 和活动统计继续保留；
- 只有管理员彻底删除或纠错才允许减少统计。

## 12. 异常状态与提示

| 场景 | 用户提示 |
| --- | --- |
| CLI 凭证无效 | 登录凭证无效，请重新获取 |
| 账号已停用 | 当前账号未启用 Aida 使用权限 |
| 网络超时 | 上传未完成，可直接重试；已成功内容不会重复计算 |
| 本地与平台历史不一致 | 检测到 Session 历史不一致，请重新完整同步 |
| 本地日志不完整 | 当前电脑缺少该 Session 的完整本地记录，无法继续同步 |
| Session 内容已清除 | 平台内容已清除；需要显式恢复后才能重新上传 |
| Summary 无法提取 | 暂无摘要 |
| 报告来源已清除 | 该 Session 内容已清除，请重新选择来源 |
| 部分 Session 上传失败 | 显示成功数、失败数及逐项原因 |

错误提示必须说明用户下一步能做什么，不能只显示内部错误码。

## 13. 页面和命令一致性

以下概念在 CLI 和页面中使用统一文案：

| 统一文案 | 禁止混用的文案 |
| --- | --- |
| 最近活动 | 结束时间、最后启动时间 |
| Session ID | 数据库 ID、记录 UUID |
| Summary / 摘要 | 标题、任务名称 |
| 清除内容 | 撤回、永久删除 Session |
| 恢复并重新上传 | 取消删除、自动恢复 |
| 已同步新增内容 | 更新整包、覆盖上传 |
| 内容已清除 | Session 不存在 |

## 14. 产品验收场景

### 14.1 CLI 登录与升级

1. 用户已登录 CLI，升级后无需再次输入凭证。
2. 用户一个月后继续上传，不因凭证时间过期失败。
3. 用户换电脑后输入同一 CLI 凭证，可以访问自己的平台 Session。
4. 用户账号被停用后，即使保留旧凭证也无法上传。

### 14.2 Session 浏览与上传

1. 500 条 Session 可以分页浏览，不一次性铺满终端。
2. 最近仍活跃的长期 Session 排在前面。
3. macOS 80列终端中 summary 仍然可见。
4. 用户跨页选择多个 Session 后，选择状态不丢失。
5. 同一 Session 连续三天上传，平台主列表始终只有一条。
6. 第二天、第三天只同步新增活动，第一天数据不减少。
7. 网络超时后重试，不产生重复 Token。
8. 换电脑并迁移完整日志后，可以继续已有 Session 的同步进度。

### 14.3 内容清除

1. 用户清除自己的 Session 内容后，summary 和日志下载立即不可用。
2. Token、模型、活动时间和成本统计仍保留。
3. 普通 `upload --all` 不会自动恢复内容。
4. 用户显式恢复并重新上传后，该 Session 内容重新可用。
5. 小组长和总监不能清除成员内容。
6. 管理员彻底删除测试 Session 后，内容和统计均消失并留有操作记录。

### 14.4 个人报告来源

1. 个人日报可以选择前一天开始、当天结束的 Session。
2. 个人周报可以同时选择多个历史 Session。
3. 同一 Session 在选择列表中只显示一行。
4. 用户可以选择完整 Session 或连续活动范围。
5. 报告周期外的显式来源可以正常用于本次生成。
6. 已清除内容的 Session 不可选择。
7. 生成开始后继续上传同一 Session，不改变本次报告来源。
8. 小组和部门报告页面不出现成员 Session 选择器。

## 15. 发布边界

本期产品完成的标志是：

1. 用户能够稳定登录、分页浏览、选择并增量上传 Session。
2. CLI 升级和换电脑不会让平台历史数据重复或断裂。
3. macOS 和 Linux 都能通过 summary 识别 Session。
4. 用户可以清除和显式恢复 Session 内容，管理统计保持可信。
5. 个人报告来源选择支持跨天、多 Session 和历史范围。
6. 小组、部门报告的数据来源路径不被改变。

报告内容压缩和 Token 成本分析分别进入独立产品和开发方案，不作为本期完成条件。

## 16. 已确认产品决策

1. CLI 专用凭证不会因时间自动过期，本期不增加设备管理、动态刷新或新的 Token 管理产品。
2. 用户换电脑后使用同一凭证继续使用，平台同步进度不能只依赖原电脑。
3. 普通用户可以清除 Session 内容，但不能通过该操作抹掉 Token、成本和活动统计。
4. 管理员拥有带原因和二次确认的彻底删除能力。
5. 上传选择面向 Session，不向普通用户暴露底层上传片段。
6. 个人报告支持跨天、多 Session 和历史 Session 来源选择。
7. 报告日期只决定报告保存周期，不限制显式选择的 Session 日期。
8. 小组和部门报告继续汇总下级已保存报告，不默认读取成员原始 Session。
9. 报告内容压缩是独立刚需，不混入本期，也不采用临时首尾截取方案。
10. Token 成本和价格管理继续由独立产品方案定义。
