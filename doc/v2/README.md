# Aida V2 文档索引

## 1. 目录用途

本目录只保存 Aida V2 当前生效的产品基线、共享技术契约和可直接驱动开发的专题方案。

开发、测试和评审必须先确认文档状态。`archive/` 中的会议记录、旧方案和评审稿仅用于追溯，不得作为实现依据。

## 2. 规范优先级

文档发生冲突时按以下顺序处理：

1. `V2产品需求总稿.md`：产品行为和范围的唯一来源；
2. `V2核心数据契约.md`：跨专题身份、状态、时间、Token 和删除语义的唯一技术来源；
3. 对应专题开发方案：该专题的数据结构、接口、迁移和测试；
4. `V2开发实施总览.md`：依赖顺序、任务边界和发布门槛；
5. 当前代码和测试结果。

当前代码与产品或技术契约不一致时，不能默认代码正确。应先判断是待实现能力、历史逻辑还是代码缺陷。

## 4. 专题依赖

```text
V2产品需求总稿
       |
V2核心数据契约
       |
Session增量上传与内容管理
       |-- Content Projection --> 个人报告来源选择/MCP
       |
       `-- Immutable Chunk ------> Token统计与成本管理
                         |
                         v
              回填 + 跨专题回归 + 联合切换
```

个人报告来源选择和 Token 统计彼此不读取对方的派生表；前者消费 Content Projection，后者消费不可变 Chunk/Metering Envelope。新版 CLI、Token 查询和 Report MCP 必须联合生产切换，不能独立发布形成数据空窗。

## 5. 文档编写规则

1. 产品决策只写入 `V2产品需求总稿.md`。
2. 跨专题规则只写入 `V2核心数据契约.md`，专题文档引用但不得复制改写。
3. 每个表、接口和状态必须只有一个所有者文档。
4. 专题文档固定写明“负责、不负责、上游输入、下游输出、允许修改模块、禁止修改模块”。
5. 验收项使用 `CORE-*`、`SES-*`、`RPT-*`、`TOK-*`、`CROSS-*` 编号。
6. 只有状态为“可开发”的专题文档可以直接交给 Codex 实施。
7. 旧合并方案退出生效目录，不允许新代码或测试引用旧文件名。
8. 不修改 `/home/intellif/dev/sandboxed-agent-platform` 源码；它只作为外部接口和行为参考。
9. 未明确要求兼容的开发期测试数据，不应反向限制当前正确设计。

## 6. 独立后续专题

报告内容压缩不属于上述三个专题。开始开发前必须单独完成产品需求和开发方案；当前版本继续使用已有 summary、excerpt 和结构化统计能力。

## 7. 归档规则

`archive/` 内文档应在标题后明确标注“已归档，不作为实现依据”。需要复用其中结论时，必须先核对并写回当前生效文档。
