# Session 增量上传与报告来源产品需求

> 文档状态：本文是 Session 增量上传、切片和六类报告来源的产品基准。实现和测试不得改变本文口径。

## 1. 文档目的

本文只定义以下产品行为：

- 用户多次上传同一个本地 Session 时，如何形成可选择的内容切片；
- 手动个人报告如何使用切片；
- 小组和部门报告如何获取下级内容；
- 报告切片与 Token 统计之间的边界；
- 最终如何进行真实验收。

本文不定义技术实现。

## 2. Session 上传与切片

### 2.1 首次上传

用户首次上传某个本地 Session 时：

1. 上传该 Session 当前已有的内容；
2. 上传成功后形成一个切片。

### 2.2 后续上传

用户以后再次上传同一个本地 Session 时：

1. 只处理上次成功上传结束后新增的内容；
2. 上传成功后形成一个新切片。

### 2.3 固定规则

1. 用户一次成功上传，只形成一个切片。
2. 同一个本地 Session 可以经过多次上传形成多个切片。
3. 切片不按自然日拆分。
4. 一次上传的新增内容即使横跨多天，仍然只形成一个切片。
5. 没有新增内容时，不形成切片。
6. 上传失败时，不形成可选择的切片。
7. 同一段新增内容被重复操作时，不能形成重复切片。
8. 产品界面不显示“第几次上传”。

## 3. 切片展示

同一个本地 Session 形成的多个切片，在个人报告的 Session 选择弹窗中显示为多条可独立选择的记录。

每条记录继续使用已经确定的现有展示内容：

- 日期；
- Session ID 与该切片的 Summary；
- Token。

展示规则：

1. Summary 只描述当前切片包含的内容，不能复用整个 Session 的 Summary。
2. 不新增展示字段。
3. 不增加展开行。
4. 不允许用户再次选择或修改切片内部的时间范围。
5. 列表保持活动时间、Session ID/切片 Summary、Token 三类核心信息；具体布局和交互以当前站内用户指南为准。
6. 日期筛选范围与切片活动日期相交时，显示完整切片，不裁剪切片内容。
7. Token 只用于帮助用户识别切片，不代表 Token 统计页面的统计结果。

## 4. 手动个人报告

### 4.1 用户明确选择切片

手动生成个人日报或个人周报时，用户可以选择一个或多个切片作为本次报告的 Session 来源。

生成规则：

1. 报告使用用户选中的切片内容。
2. 未选中的 Session 切片不能混入本次手动选择的 Session 来源。
3. 报告生成期间，同一个 Session 后续新增的内容不能进入本次已经选择的切片。

### 4.2 用户未选择切片

用户未选择切片时，由 Aida 后端在 Agent 启动前自动冻结本次报告的 Session 来源：

1. 个人日报使用报告日期，个人周报使用报告周起止日期，日期边界统一按 `Asia/Shanghai` 计算。
2. 切片活动结束时间不早于报告开始时间，并且切片活动开始时间不晚于报告结束时间时，判定为相交。
3. 相交后纳入整个上传切片，不按事件日期再次裁剪切片。
4. 同一个 Session 的多个上传切片分别保留，不合并成新的 cursor 范围。
5. 来源快照冻结后，同一个 Session 后续上传形成的新切片不能进入本次报告。
6. 没有相交切片时，Session 来源为空，不读取报告周期外的其他切片。
7. Agent 不自行按日期选择或裁剪 Session；Agent 只读取 Aida 已冻结的完整切片快照。

## 5. 定时个人报告

定时个人报告不提供人工切片选择。后端推导出报告周期后，使用第 4.2 节相同的完整切片自动选择规则。

本需求只统一定时个人报告的 Session 来源口径，不修改定时任务配置、触发时间、报告周期推导、并发和重试逻辑。

## 6. 小组和部门报告

- 小组日报和小组周报汇总成员已经生成并保存的个人报告；
- 部门日报和部门周报汇总所管小组已经生成并保存的小组报告；
- 小组和部门报告默认不逐个读取成员的原始 Session。

固定取数范围：

- 小组报告必须读取目标小组范围，不能降级为当前用户 `self` 范围；
- 部门报告必须读取目标部门范围，不能降级为当前用户 `self` 或全平台 `all` 范围；
- 下级报告缺失时必须明确列出缺失情况，不能改用错误范围的数据替代。

## 7. 报告来源一致性

1. MCP 读取个人报告来源快照时，只返回快照内的完整上传切片，不再按日期切割。
2. 用户明确选择的切片是本次个人报告必须使用的 Session 证据，已有报告内容不能替代或覆盖这些事实。
3. 已有报告只用于编辑参考；新一轮生成必须以本次报告周期和本次来源快照重新生成。
4. 小组和部门报告的已提交数、缺失数必须依据正确层级的结构化报告数据计算，不能根据正文关键词猜测。
5. “部分成员或小组缺失”不等于“全部报告为 0 份”。

## 8. Token 统计边界

报告切片和 Token 统计是两种不同用途、不同口径的数据：

- 报告切片用于选择报告所需的工作内容；
- Token 页面按照实际使用时间统计 Token 和成本。

报告 Agent 不得把 Session 原始事件中的累计 Token 数值相加后作为报告 Token 总量。报告正文如需展示 Token，只能使用后端已经归一化的统计结果。

修改 Session 上传和报告切片功能时，不能改变既有 Token、成本和日期归属结果。

## 9. 真实验收要求

最终验收必须执行完整真实流程：

1. 构建并发布 14.157 测试环境安装包；
2. 从测试环境提供的地址重新下载安装 AIDA；
3. 使用本机真实 Codex Session；
4. 使用 6 个真实测试账号，覆盖四类角色，并分布在至少 2 个小组；
5. 多次上传同一个 Session，核对首次切片和后续新增切片；
6. 核对显式选择、未选择自动取数、跨日相交完整切片和重复上传结果；
7. 核对 Token、成本和日期归属没有受到影响；
8. 将本次修改后的 MCP 和默认 Skill 真实更新到 14.157 测试环境；
9. 使用测试环境实际生效的 MCP 和 Skill，通过真实 Agent 分别生成个人日报、个人周报、小组日报、小组周报、部门日报和部门周报；
10. 使用测试环境实际生效的 MCP 独立执行直接调用，核对实际返回的报告来源和内容；
11. 核对真实 Agent 和直接 MCP 调用的权限范围、运行记录和最终保存内容。

定时任务只做不受影响的回归检查，不作为本次功能改造对象。

前端应在 14.157 开发环境使用真实测试角色执行浏览器回归，并保留关键页面截图；接口测试不能代替浏览器交互。涉及视觉判断的内容仍需人工确认，未实际执行的测试不得宣称通过。

本地 MCP/Skill 文件、Mock、临时提示词或未更新到测试环境的资源，不能作为真实 MCP/Skill 验收结果。

单元测试、模拟数据、伪造接口响应或接口只返回成功，均不能代替完整真实验收。

## 10. 验收结论

只有上述产品行为和真实流程全部通过，才能认定本需求完成。测试环境验收完成前不得发布生产环境。
