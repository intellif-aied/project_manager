# Session 增量上传与报告来源开发方案

## 1. 开发目标

依据同目录 `产品需求.md`，完整替换错误的“完整 Session + 人工时间范围”报告来源链路，实现：

```text
AIDA 增量上传
-> 一次成功上传形成一个固定切片
-> 手动个人报告选择切片
-> 定时个人报告按报告周期自动取数
-> MCP 读取固定来源
-> Agent 生成并保存报告
```

旧来源逻辑直接删除，不保留新旧双轨。

## 2. 开发前处理

1. 审查并单独处理当前未提交的报告/MCP 修改，不与本需求混合提交。
2. 保存改造前 Token、成本和日期归属对账基线。
3. 只使用 `产品需求.md` 作为本功能产品依据，旧 V2 文档不得引用。

## 3. 上传与切片

### 3.1 AIDA CLI

- 每次用户确认上传一个 Session 时生成唯一上传标识。
- 首次上传发送当前全部内容；后续从服务端确认位置发送新增内容。
- 全部内容上传成功后完成本次上传；重复请求返回同一结果。
- 失败后只续传未成功内容，不重复发送已确认内容。
- 换电脑后以服务端状态继续，不依赖原电脑缓存。
- CLI 列表、分页和现有交互保持不变。

### 3.2 后端

- 增加上传记录，保存本次上传的开始位置、结束位置和最终结果。
- 增加固定切片记录；一次有新增内容的成功上传只能对应一个切片。
- 切片保存 Session、内容版本、内容边界、活动日期、Summary 和展示 Token。
- 无新增、失败、重复请求不产生新切片。
- 并发上传必须串行确认，切片连续、不重叠、不丢失。
- 文件重建或内容恢复时只记录新出现的有效内容，不重建历史切片，不重复 Token。
- 切片 Summary 只读取本切片内容；切片内容可读后才进入报告来源列表。

## 4. 报告来源

### 4.1 API

- 候选列表改为一行一个固定切片。
- 返回现有 UI 所需的日期、Session ID、切片 Summary、Token 和内部选择键。
- 日期筛选与切片活动日期相交即返回完整切片，不裁剪内容。
- 手动个人报告只提交选择键，不再提交人工开始/结束时间。
- 创建报告时冻结所选切片内容，后续上传不影响本次报告。
- 删除旧的完整 Session 候选、人工时间范围选择和自然日切片来源路径。

### 4.2 手动与定时流程

- 手动个人日报、周报：读取用户选择的切片，未选切片不得混入。
- 定时个人日报、周报：不接收切片选择，按本次报告周期自动建立固定来源。
- 小组报告：汇总已保存个人报告。
- 部门报告：汇总所管小组已保存报告。
- 小组和部门默认流程不读取成员原始 Session。

## 5. 前端

- 列表行改为固定切片，选择值改为切片选择键。
- 保留现有“日期 / Session ID 与 Summary / Token”展示。
- 保留分页、跨页选择、日期筛选、搜索和已选数量。
- 删除人工范围参数和相关残留代码。
- 不增加字段、展开行、范围选择器或状态展示。
- 不改变现有列顺序、布局、图标、滚动和响应式样式。

## 6. MCP 与默认 Skill

- 手动个人报告通过固定来源读取全部已选切片内容。
- 定时个人报告按报告周期读取自动固定的来源。
- 来源分页必须全部读取后才允许回写报告。
- 删除托管报告中的旧自然日切片、人工范围和迁移期双路径。
- 通用 Session 查询继续供自定义 Skill 使用，不作为手动选择切片。
- 默认 Skill 按新口径重写六类报告取数说明。
- 更新现有 `aida-report@1.0.0` 内容，不创建新版本。
- 不修改 `sandboxed-agent-platform` 源码。

## 7. Token 与成本

- 报告切片不作为 Token 账本。
- Token 和成本继续按原始使用时间归属。
- 切片 Token 只做只读展示汇总，不回写统计。
- 首次、增量、重复、失败恢复、跨天、换电脑、并发和内容恢复均必须对账。
- 同一批原始数据改造前后的 Token、模型、日期和成本结果必须一致。

## 8. 删除与数据处理

- 删除旧 API 入参、前端类型、旧分支、旧 Skill 指令和对应错误测试。
- 旧测试报告来源数据不兼容，按测试脏数据清理。
- 保留已有 Session 原始内容、Token、价格、用户和组织数据。
- 现有自然日统计只用于 Token 和通用日期查询，不再作为手动报告切片。

## 9. 开发提交顺序

1. 上传记录、固定切片和后端测试。
2. AIDA CLI 增量上传与恢复测试。
3. 报告来源 API 和数据清理。
4. 前端切片列表与提交契约。
5. MCP 与默认 Skill。
6. Token、成本和六类报告完整回归。

每个阶段独立提交、独立验证；上一阶段未通过时停止，不继续后续阶段。

## 10. 完整验收

```text
单元测试与集成测试通过
-> 构建并发布 14.157 测试环境安装包
-> 从测试地址重新下载安装 AIDA
-> 使用本机真实 Codex Session
-> 使用真实测试账号依次验证四类角色
-> 多次上传同一个 Session
-> 核对切片、日期筛选、Token、成本和权限
-> 运行个人、小组、部门六类真实 Agent 报告
-> 核对实际来源、Agent 运行记录和最终保存内容
```

模拟测试、伪造响应或仅返回 HTTP 200 不能作为最终验收。14.157 完整验收通过前不得发布生产。
