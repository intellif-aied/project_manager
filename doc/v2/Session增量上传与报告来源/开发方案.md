# Session 增量上传与报告来源开发方案

> 文档状态：本文是 Session 增量上传与报告来源的实现基线。前端交互由用户人工验收，自动化测试只使用单元测试、集成测试和真实接口模拟，不执行前端 E2E。

## 1. 依据与目标

本方案只依据同目录 `产品需求.md`，不增加产品行为，不保留旧错误来源逻辑。

目标链路：

```text
AIDA 上传 Session
-> 成功上传形成切片
-> 个人报告显式选择切片，或按报告周期自动选择相交切片
-> 冻结完整切片来源快照
-> Agent 生成并保存报告
```

## 2. 开发范围

### 2.1 AIDA CLI

- 首次上传某个 Session 时上传当前已有内容。
- 后续上传同一个 Session 时只处理上次成功上传后的新增内容。
- 一次成功上传只形成一个切片。
- 无新增或上传失败时不形成切片。
- 同一段新增内容重复操作时不形成重复切片。
- 保持现有 Session 列表、分页和选择交互。

### 2.2 后端 Session 切片

- 支持首次上传形成初始切片。
- 支持后续每次成功上传新增内容形成一个新切片。
- 切片不按自然日拆分。
- 一次上传横跨多天时仍只形成一个切片。
- 每个切片只根据自身内容生成 Summary。
- 保存报告选择和展示所需的切片信息。
- 删除与上述产品规则冲突的旧切片实现。

### 2.3 报告来源

- 个人报告来源列表按切片返回。
- 每条保持现有日期、Session ID、切片 Summary 和 Token 展示。
- 日期筛选与切片活动日期相交时返回完整切片，不裁剪内容。
- 手动个人日报、周报使用用户选中的切片。
- 未选中的 Session 切片不能混入本次手动选择的 Session 来源。
- 报告生成期间，后续新增内容不能进入本次已选择切片。
- 未选择切片时，按报告周期与切片活动区间求交集，自动冻结所有相交的完整切片。
- 自动来源直接使用 `session_content_slices` 的原始起止 cursor，每个上传切片保存为独立来源项。
- 删除按事件日期筛选后重新计算最小/最大 cursor 的默认来源逻辑。
- MCP 按来源快照的精确 cursor 范围读取，不增加日期过滤，不合并或二次裁剪切片。
- 删除完整 Session 加人工时间范围的旧选择方式。

### 2.4 组织报告

- 小组日报、周报汇总成员已生成并保存的个人报告。
- 部门日报、周报汇总所管小组已生成并保存的小组报告。
- 小组和部门默认不逐个读取成员原始 Session。
- 小组报告固定使用 `team` 范围读取个人报告；部门报告固定使用 `department` 范围读取小组报告。
- 修正部门日报、周报写入校验的数据层级，分别校验目标部门内的小组日报、小组周报。
- 下级报告缺失名单和已提交数量使用结构化数据校验，不使用正文中的“暂无”“未提交”等局部文字推断总数。

### 2.5 前端

- 同一个 Session 的多个切片显示为多条可独立选择记录。
- 保持活动时间、Session ID/切片 Summary、Token 三类核心信息。
- 候选列表默认不限制日期、每页 5 条，支持跨页选择和可选日期筛选。
- 日期范围只筛选候选切片；关闭抽屉即保留选择，无需额外确认。
- 不增加字段、展开行或范围编辑。
- 删除人工时间范围相关的前端参数和代码。
- 前端交互由用户在 14.157 开发环境人工确认，本次开发不执行前端 E2E。

### 2.6 MCP 与默认 Skill

- 个人报告读取后端冻结的完整切片快照；显式选择和自动选择使用同一读取协议。
- 显式切片内容必须进入最终报告，`get_existing_report` 只能作为编辑参考，不能替代本次来源。
- 小组和部门报告按照已确认的下级报告层级取数。
- 默认 Skill 为六类报告写明固定的 `scope` 与下级 `report_scope` 组合，禁止回退到 `self` 或 `all`。
- 修正写入一致性校验，允许“已提交 N 份，同时缺失 M 个成员/小组”的正常表述。
- Session 原始累计 Token 事件不作为报告 Token 总量来源；默认 Skill 禁止自行累加原始计数。
- 删除旧自然日切片、人工时间范围和新旧双轨说明。
- 保留自定义 Skill 使用的通用 Session 查询能力。
- 按新口径更新现有默认 Skill，不修改 `sandboxed-agent-platform` 源码。

固定调用矩阵：

| 报告类型 | `scope` | 主要报告来源 |
|---|---|---|
| 个人日报 | `self` | 完整 Session 来源快照 |
| 个人周报 | `self` | 已保存个人日报 + 完整 Session 来源快照 |
| 小组日报 | `team` | 目标小组的个人日报 |
| 小组周报 | `team` | 目标小组的个人周报 |
| 部门日报 | `department` | 目标部门的小组日报 |
| 部门周报 | `department` | 目标部门的小组周报 |

### 2.7 Token 与成本

- 报告切片只用于报告内容选择。
- Token 页面继续按实际使用时间统计 Token 和成本。
- 切片展示 Token 不作为 Token 页面统计结果。
- 本功能改造前后，既有 Token、成本和日期归属结果不能改变。

## 3. 本轮已确认问题与修改

| 问题 | 当前原因 | 修改结果 |
|---|---|---|
| 未选择 Session 时切片被裁断或合并 | 默认来源按事件日期筛选，再按 Session 计算 cursor 范围 | 改为按活动区间选择 `session_content_slices`，完整、逐条冻结 |
| 显式切片已读取但最终正文未使用 | 只校验 MCP 已翻完页，没有明确限制已有报告覆盖本次来源 | 强化默认 Skill 的来源优先级，并用带唯一事实标记的真实 Agent 用例验收 |
| 部门周报错误使用 `self` 范围 | Agent 工具调用未遵循部门范围 | 固定六类报告 scope 矩阵，部门报告只能使用 `department` 范围读取小组报告 |
| 小组周报“已提交 2、缺失 2”被判定为 0 份 | 正则把单个成员“暂无周报”误判为整体无周报 | 删除该宽泛判断，只校验明确的整体 0 份声明与结构化数量 |
| 报告 Token 出现累计值相加 | 原始事件里的 Token 是累计值，Agent 将多次累计值求和 | 报告不从原始累计事件计算 Token，只接受后端归一化值 |
| 部门报告校验未阻止错误来源 | 写入校验查询个人日报/周报，而不是小组日报/周报 | 改为按产品层级查询 `team_reports`、`team_weekly_reports` |

## 4. 删除范围

- 删除完整 Session 加人工时间范围的报告来源逻辑。
- 删除手动报告使用自然日切片的逻辑。
- 删除默认来源按事件日期重新生成 cursor 范围的逻辑。
- 删除对应旧前端参数、旧 MCP/Skill 指令、错误测试和错误文档。
- 不删除已有 Session 原始内容、Token、价格、用户和组织数据。

## 5. 冻结范围

- 不修改定时任务代码、配置和触发逻辑。
- 不修改定时任务的报告周期推导、并发和重试；定时个人报告只改为统一的完整切片自动来源规则。
- 前端继续保留活动时间、Session ID/切片 Summary、Token 三类核心信息，不恢复旧的人工切片范围编辑。
- 不在生产环境执行破坏性浏览器测试；浏览器回归使用 14.157 测试账号和脱敏数据。
- 不修改 MCP 授权、凭证、工具名称、工具列表、owner、slug 和 Agent 绑定方式；默认 Skill 内容更新时仅提升补丁版本，测试服本轮使用 `aida-report@1.0.5`。
- 不修改系统 MCP/Skill 资源管理方式，不修改 `sandboxed-agent-platform` 源码。
- 不改变 Token、成本和日期归属统计口径。

## 6. 开发顺序

1. 修改默认来源解析，验证手动和定时个人报告都冻结相交的完整切片。
2. 修正组织报告 scope、写入校验层级和局部缺失误判。
3. 更新 MCP 与默认 Skill，修复显式来源优先级和 Token 累计值使用问题。
4. 运行后端单元测试和接口测试，覆盖跨日切片、同 Session 多切片、空来源和写入校验。
5. 更新并发布 14.157 实际 MCP、默认 Skill 和 AIDA 安装包。
6. 使用六个测试账号完成四角色、六类报告真实回归，并执行 Token/成本对账。

每个阶段独立提交和验证；上一阶段未通过时停止。

## 7. 真实验收

```text
构建并发布 14.157 测试包
-> 从测试地址重新下载安装 AIDA
-> 使用本机真实 Codex Session
-> 使用 6 个真实测试账号覆盖四类角色和至少 2 个小组
-> 多次上传同一个 Session
-> 通过接口模拟显式选择、未选择、跨日相交、同 Session 多切片和空来源
-> 将修改后的 MCP 和默认 Skill 真实更新到 14.157 测试环境
-> 真实 Agent 生成个人/小组/部门日报和周报共六类报告
-> 使用测试环境实际生效的 MCP 独立执行直接调用
-> 核对来源范围、切片完整性、缺失数量、Token、权限、运行记录和最终保存内容
```

单元测试和接口测试只是开发检查。模拟数据、伪造响应或仅返回 HTTP 200 不能作为最终验收。

前端交互由用户在 14.157 人工验收，不执行前端 E2E；自动化结果与人工确认应分别记录。

不得使用本地 MCP/Skill 文件、Mock、临时提示词或未更新到测试环境的资源冒充真实 MCP/Skill 测试。

定时任务验证触发和周期推导未受影响，并验证个人定时报告使用统一的完整切片来源。

14.157 完整验收通过前不得发布生产。
