# Aida 客户端自动 Session 同步产品需求

> 文档状态：已定稿
> 日期：2026-07-21
> 适用范围：Aida CLI 自动 Session 同步的产品行为
> 关联基线：`doc/v2/Aida客户端重构/README.md`

## 0. 文档边界

本文只定义产品要解决的问题、用户可观察行为和验收口径，不设计守护进程、操作系统任务、接口、数据表、状态机、更新协议或监控页面。

本文中的规则只来自已经确认的产品要求。

平台客户端监控与用户自动 Session 同步是两个独立产品范围。平台客户端监控暂缓，不进入本期产品范围，也不阻塞自动 Session 同步。

## 1. 背景

用户每天需要主动执行 Session 上传，重复操作负担明显。用户希望 Aida 可以在本人指定的时间自动上传本地 Session，使当天 Session 能及时进入 Aida，供后续查看和生成报告使用。

当前需求不是增加复杂的定时策略，而是让用户在明确授权后，选择每天一个具体时间，由 Aida 自动完成一次现有的全部 Session 上传。

## 2. 产品目标

1. 用户无需每天手动执行全部 Session 上传。
2. 自动同步只在用户主动开启后生效，不默认开启。
3. 用户开启时选择每天一个具体执行时间。
4. 每次自动上传前先检查 Aida 版本，并在需要时先完成更新。
5. 自动同步能力在异常中断或设备重启后能够恢复，不要求用户重复开启。
6. 保留现有手动 Session 上传能力。
7. 首期以 Linux 为核心平台，优先保证 Linux 用户完整可用。

## 3. 名词

- **自动 Session 同步**：用户主动开启后，Aida 每天在用户选择的具体时间自动执行一次全部 Session 上传。
- **自动上传时间**：用户为自动 Session 同步选择的每日具体执行时间。
- **手动上传**：用户主动执行现有 Aida Session 上传操作。
- **平台客户端监控**：平台管理侧了解 Aida 客户端运行与使用情况的独立能力，不是用户自动同步功能。

“自动 Session 同步”“客户端在线”和“平台客户端监控”不得混用。

## 4. 产品规则

### AS-PRD-001：用户主动开启

- 适用对象：使用 Aida CLI 上传 Session 的用户。
- 触发条件一：用户登录成功，且尚未开启自动 Session 同步。
- 触发条件二：用户主动执行 `aida auto-sync enable`。
- 产品行为：Aida 进入完整开启引导，向用户说明作用并询问是否开启；用户确认后，再要求用户选择自动上传时间。
- 未开启时行为：Aida 不得自动上传 Session。

自动 Session 同步不得因安装、升级、登录或执行其他命令而被默认开启。
`aida auto-sync enable` 是完整引导流程，不是要求用户直接填写配置的单独设置项。

### AS-PRD-002：选择每日具体时间

- 适用对象：准备开启自动 Session 同步的用户。
- 触发条件：用户选择开启自动 Session 同步。
- 产品行为：用户选择每天一个具体时间；选择完成后，自动同步才可生效。
- 过去时间行为：如果所选时间在今天已经过去，用户继续明确选择今天立即同步一次或从明天开始；产品不替用户默认选择。
- 缺少时间时行为：不得开启自动 Session 同步。

本需求不增加时间段、时间段内频率、多时间点或其他定时策略。

### AS-PRD-003：自动执行全部 Session 上传

- 适用对象：已经开启自动 Session 同步并完成时间选择的用户。
- 触发条件：到达用户选择的每日具体时间。
- 产品行为：Aida 自动执行一次与现有全部 Session 上传一致的操作。
- 无新增 Session 时行为：沿用现有全部 Session 上传的结果语义，不因自动执行改变上传口径。

自动执行不得改变现有 Session 发现、分组、增量上传、重复上传或服务端处理口径。

### AS-PRD-004：上传前检查并更新 Aida

- 适用对象：即将执行自动 Session 上传的客户端。
- 触发条件：每次自动 Session 上传开始前。
- 产品行为：Aida 先检查客户端版本；需要更新时，先完成更新，再执行全部 Session 上传。
- 更新异常时行为：本次自动上传继续执行，不因版本检查或更新失败而停止。

### AS-PRD-005：中断后的自动恢复

- 适用对象：已经开启自动 Session 同步的用户。
- 触发条件：自动同步能力因进程退出、连接中断或设备重启而停止。
- 产品行为：自动同步能力恢复后继续保持已开启状态，用户不需要重新开启。
- 恢复后的执行行为：如果已经错过当日的自动上传时间，恢复后第一时间补执行当日上传。

本文只确认用户可观察的恢复结果，不指定由何种操作系统能力或进程形态实现。

### AS-PRD-006：保留手动上传

- 适用对象：全部 Aida CLI 用户。
- 触发条件：用户主动执行 Session 上传。
- 产品行为：无论是否开启自动 Session 同步，用户都可以继续手动上传。
- 自动同步异常时行为：不得阻止用户使用现有手动上传能力。

### AS-PRD-007：允许修改和关闭

- 适用对象：已经开启自动 Session 同步的用户。
- 修改时间：用户可以修改每日自动上传时间，修改后按新的时间执行。
- 关闭能力：用户可以主动关闭自动 Session 同步。
- 关闭后行为：Aida 不再自动上传 Session，手动上传能力不受影响。

### AS-PRD-008：首期以 Linux 为核心平台

- 首期范围：Linux。
- 产品要求：首期支持具备 systemd user manager 的 Linux。
- 开启检测：进入开启流程时检测 systemd user manager；不满足时明确提示当前环境暂不支持，且不得保存为已开启。
- 其他平台：macOS 和 Windows 不纳入本期承诺范围。

### AS-PRD-009：平台客户端监控暂缓

- 适用对象：平台管理者。
- 产品目标：了解 Aida 客户端运行与使用情况。
- 与自动同步的关系：不是用户自动同步功能，也不是自动同步上线的前置条件。
- 当前结论：暂缓建设，不进入本期产品范围。

平台客户端监控不得被描述为验证用户是否需要自动 Session 同步。

## 5. 产品交互

### 5.1 交互入口

| 用户场景 | 交互入口 | 产品行为 |
|---|---|---|
| 首次登录或重新登录后尚未开启 | `aida login` 登录成功 | 登录结果展示完成后，直接进入开启引导 |
| 用户后续主动开启 | `aida auto-sync enable` | 进入与登录后相同的完整开启引导 |
| 查看自动同步状态 | `aida auto-sync status` | 展示开启状态；已开启时同时展示每日同步时间 |
| 查看 Aida 状态 | `aida status` | 在现有登录状态中同时展示自动同步状态和每日同步时间 |
| 修改每日同步时间 | `aida auto-sync set-time` | 展示当前时间，引导用户输入新的每日具体时间 |
| 关闭自动同步 | `aida auto-sync disable` | 关闭自动同步并明确告知手动上传不受影响 |

本期不提供多个交互入口表达同一操作，不增加 `cron`、`timer`、`schedule` 或 `daemon` 等面向用户的同义命令。

### 5.2 登录后的开启引导

登录成功且自动 Session 同步尚未开启时，Aida 直接询问：

```text
是否开启每天自动同步全部 Session？[y/N]
```

- 用户输入 `y`：继续选择每日同步时间。
- 用户输入 `N` 或直接回车：保持未开启，不执行自动上传，并提示以后可以运行 `aida auto-sync enable` 开启。
- 用户取消引导：保持未开启，不影响本次登录结果。

如果登录时自动 Session 同步已经开启，不重复询问，直接展示当前每日同步时间。

### 5.3 `enable` 开启引导

用户执行 `aida auto-sync enable` 后，Aida 先说明：

```text
开启后，Aida 将在你选择的每日时间自动上传全部 Session。
如果错过该时间，将在 Aida 恢复运行后第一时间补传。
是否继续？[y/N]
```

- 用户确认继续：进入时间选择。
- 用户拒绝或取消：保持当前状态，不修改任何自动同步设置。
- 已经开启时再次执行：不重复开启，展示当前每日同步时间，并提示可使用 `aida auto-sync set-time` 修改或 `aida auto-sync disable` 关闭。

### 5.4 选择每日同步时间

登录后开启和 `aida auto-sync enable` 使用同一时间选择交互：

```text
请选择每天同步时间（HH:MM，按本机时间）：
```

- 时间采用 24 小时制，用户必须输入一个有效的 `HH:MM` 具体时间。
- 输入无效时，明确提示格式错误并重新等待输入，不保存无效时间。
- 用户在完成时间选择前取消，自动同步保持未开启。

如果用户选择的时间在今天已经过去，继续询问：

```text
你选择的 18:00 今天已经过去
请选择首次同步时间

  今天立即同步一次
  从明天 18:00 开始

↑/↓ 选择 · Enter 下一步 · q 取消
```

- 选择“今天立即同步一次”：完成开启后立即执行一次自动同步；后续每天按所选时间执行。
- 选择“从明天开始”：今天不执行，自动同步从明天的所选时间开始。
- 该步骤使用与 Aida 现有终端交互一致的可移动选项列表，不要求用户输入选项编号。
- 用户取消时不完成开启，也不保存本次设置。

开启成功后固定展示：

```text
自动 Session 同步已开启
每天 18:00（本机时间）自动上传全部 Session
如果错过该时间，将在 Aida 恢复运行后第一时间补传
```

如果用户刚才选择今天立即同步一次，追加展示：

```text
今天将立即同步一次
```

如果用户选择从明天开始，追加展示：

```text
首次自动同步：明天 18:00（本机时间）
```

### 5.5 查看状态

已开启时，`aida auto-sync status` 和 `aida status` 中的自动同步部分展示：

```text
自动 Session 同步：已开启
每日同步时间：18:00（本机时间）
```

未开启时展示：

```text
自动 Session 同步：未开启
开启方式：aida auto-sync enable
```

状态展示不要求用户理解后台进程、操作系统任务或其他实现概念。

### 5.6 修改时间

用户执行 `aida auto-sync set-time` 时：

```text
当前每日同步时间：18:00（本机时间）
请输入新的每日同步时间（HH:MM，按本机时间）：
```

修改成功后展示：

```text
每日同步时间已更新为 19:00（本机时间）
```

当新时间今天已经过去时，在上述结果后追加展示用户刚才选择的首次执行结果：“今天将立即同步一次”或“首次自动同步：明天 19:00（本机时间）”。

- 输入无效时不修改原时间，并重新等待输入。
- 用户取消时保留原时间。
- 尚未开启时不单独设置时间，提示通过 `aida auto-sync enable` 完成开启引导。
- 如果新时间在今天已经过去，使用 5.4 相同的二次选择：用户明确选择今天立即同步一次或从明天开始；取消时保留原时间。

### 5.7 关闭自动同步

用户执行 `aida auto-sync disable` 后展示：

```text
自动 Session 同步已关闭
你仍可使用 aida upload 或 aida upload --all 手动上传 Session
```

关闭后不再自动上传，已保存的登录状态和手动上传能力不受影响。重复关闭时只告知当前已经处于未开启状态。

### 5.8 自动执行时的用户行为

- 到达每日同步时间后自动执行，不再次要求用户确认。
- 版本检查或更新失败时，继续自动上传全部 Session。
- 错过当日同步时间时，恢复后第一时间补传，不要求用户操作。
- 自动同步不得弹出 Session 选择器，也不得要求用户选择待上传 Session。

## 6. 用户流程

1. 用户登录成功后看到自动 Session 同步开启引导，或后续主动执行 `aida auto-sync enable` 进入同一引导。
2. 用户明确选择开启。
3. 用户选择每天一个具体的自动上传时间；如果该时间今天已经过去，用户继续明确选择今天立即同步一次或从明天开始。
4. Aida 告知用户自动 Session 同步已开启、每日执行时间、首次执行选择以及错过后的补传行为。
5. 每天到达所选时间时，Aida 先检查并更新客户端；检查或更新失败时，仍继续自动执行全部 Session 上传。
6. 如果当日执行时间因设备或自动同步能力未运行而错过，恢复后第一时间补传。
7. 用户可以查看状态、修改每日执行时间或主动关闭自动 Session 同步。
8. 用户仍可随时使用现有手动上传能力。
9. 自动同步能力发生中断并恢复后，用户不需要重新开启。

## 8. 非目标

- 不默认开启自动 Session 同步。
- 不提供时间段、时间段内频率、多时间点或复杂定时策略。
- 不改变现有 Session 上传、增量、重复判断和服务端处理口径。
- 不取消或替代手动上传。
- 不承诺本期支持 macOS 和 Windows。
- 不在本文设计守护进程、操作系统任务或重启机制。
- 不在本文设计自动更新的技术实现。
- 不复用已经退役且职责不同的 `consume` 产品入口。
- 本期不建设平台客户端监控，也不设计其字段、页面、权限或统计口径。
- 不通过平台客户端监控验证自动 Session 同步是否为用户刚需。
