## 3. 设计分层

### A. 本期必须完成

- 登录成功后的 opt-in 引导；
- `aida auto-sync enable|status|set-time|disable`；
- 本机时间每日一次、错过后恢复补传；
- 自动执行前更新，失败继续 `upload --all`；
- Linux 后台监督，具体支持范围按 A-02 最终结论执行；
- 安装、普通命令和更新后的自检恢复；
- 现有手动上传与跨平台构建回归。

### B. 代码事实触发的必要保障

- 独立 AutoSync 本地目录和原子 JSON，避免与 `.aida.yaml` 的登录/更新写入冲突；
- `start.lock`、`daemon.lock` 和 `run.lock`，避免并发启动、重复实例和重叠上传；
- PID 的 UID/命令行校验，避免关闭或更新时误杀无关进程；
- health 中保存 daemon version，支持新二进制对旧后台的修复；
- 隐藏 execute 隔离自动路径更新 fail-open；
- 自动 execute 不写 `.aida.yaml` 更新缓存，避免后台和登录并发覆盖 Token/服务地址；
- Linux/非 Linux 分文件，保证现有 darwin/windows release build 不被破坏；
- 非 TTY 登录不进入阻塞问答，非 TTY enable 明确失败。

### C. 后续增强

- 平台客户端监控；
- macOS/Windows 自动同步；
- 自动上传失败后的重试策略；
- 日志轮转和最近一次执行结果的用户界面。

C 类不得进入本期实现任务。

## 7. 任务实施细节

### 7.1 D-01：本地状态和时间计算

1. 建立可注入 `now` 的时间计算函数，测试不依赖真实等待。
2. `config.json` 与 `schedule.json` 分离：用户变更只写配置，daemon 每日写只改执行记录。
3. 所有写入使用同目录临时文件、`Sync`、`Chmod`、`Rename`。
4. enable/set-time/disable/ensure 在 `start.lock` 下读取最新值后再写，避免旧快照覆盖。
5. 执行前写 `last_attempt_at`，成功后才写 `last_success_date`；任一写入失败都不得伪造成功。
6. `run.lock` 防止重叠执行；非零退出后保持当天到期，至少一分钟后再尝试，以满足离线恢复补传。
7. 不增加可配置退避、最大次数或复杂失败状态机；现有增量和去重负责重复尝试安全。

### 7.2 D-02：CLI 交互

1. login 必须先完成 `/auth/me` 验证和 `.aida.yaml` 保存，再进入引导。
2. 引导取消只影响 AutoSync，不回滚登录。
3. login 与 enable 调用同一个引导函数和时间解析函数。
4. `aida status` 先读取并打印本地 AutoSync，再进行或完成远程身份检查；断网时仍保留本地输出。
5. set-time 只在 enabled 时生效；disable 幂等。
6. 非 TTY login 跳过问答并打印后续 enable 命令，不读取无限 stdin。
7. 非 TTY enable 直接返回明确提示，不写配置、不增加绕过引导的参数。

### 7.3 D-03：后台监督

1. enabled 配置是唯一产品状态，不额外引入完整运行状态机。
2. health/PID 只是内部运行证据。
3. systemd unit 中只包含解析后的 executable 和固定 argv，不包含 Token、时间或服务地址。
4. systemd 不可用时严格执行 A-02 的最终结论，不得静默降级后仍宣称完整重启恢复。
5. 每次启动持有 `daemon.lock`；自检启动过程持有 `start.lock`。
6. stop 只对当前 UID 且命令行为 `aida auto-sync daemon-run` 的 PID 发信号。

### 7.4 D-04：更新和上传

1. 公开 upload 路径不增加任何 AutoSync 参数分支。
2. 隐藏 execute 在完整生命周期持有 `run.lock`，调用可复用的更新核心，但关闭更新状态缓存写回和当前进程重启；更新错误只记录。
3. 更新尝试结束后重新解析磁盘上的 executable，启动隐藏 `auto-sync upload-all`；更新成功时自然使用新版本。
4. 更新检查、下载、校验、替换继续复用 `self_update.go`，不新建 updater。
5. upload-all 调用 `cmdUpload([]string{"--all"})`，不再执行更新、自检或选择器，不 shell out 到字符串命令，不复制扫描代码。
6. upload-all 返回 `0` 后由 execute 写当天成功；非零只写错误并保留补传条件。
7. daemon 启动 execute 时 stdin 连接 `/dev/null`，stdout/stderr 追加到 AutoSync 日志；disable/SIGTERM 必须取消并等待当前子进程。

### 7.5 D-05：生命周期对齐

1. 普通命令自检必须有界且 best-effort；失败不得改变原业务命令的退出结果。内部 daemon/execute 命令必须排除，避免递归。
2. login 未完成或 enabled=false 时自检不创建后台进程。
3. installer 的 ensure 不改变 disabled，不把失败当安装失败，只提示下一次命令会重试。
4. 显式 update 完成后重启已开启 daemon；未开启时不创建。
5. 新版本普通命令发现 health 中 daemon version 旧时，停止已验证 PID 后按首选 adapter 恢复。

## 8. 开发顺序

```text
D-01 状态/时间
  ├─→ D-02 交互
  └─→ D-03 后台监督
          └─→ D-04 更新与上传执行
D-02 + D-03 + D-04
          └─→ D-05 安装/命令/更新生命周期
                  └─→ D-06 全量测试
                          └─→ D-07 文案与帮助核对
```

优先以测试驱动完成 D-01、D-03 的时间、锁和进程边界；真实上传测试必须使用测试服务或 fake server，不得写生产数据。

## 9. 停止条件

出现以下任一情况立即停止实现并返回相应文档评审：

- 需要改变产品交互、默认选择、每日一次或失败行为；
- 需要新增服务端接口、数据库、凭据或监控；
- 现有 `upload --all` 无法在非 TTY 中保持相同上传语义；
- A-02 批准的后台机制无法在目标 Linux 环境满足恢复验收，且需要引入未批准的新启动机制；
- 自动更新必须削弱所有手动命令的更新门禁才能实现；
- 为 macOS/Windows 增加实现才能让 Linux 构建通过。

A-02 未确认前不得开始 D-03；其他任务可按已确认产品和架构决策开发。

局部测试失败只阻塞依赖该决策的任务，不自动扩大为整体重构。
