## 1. 评审结论

方案范围与已定稿产品需求一致，没有新增平台监控、时间段、同步频率、服务端接口或非 Linux 首期能力。A-08 已由产品确认采用用户二次选择；当前仅 A-02 需要确认，Linux 后台任务暂不开发。

| 结论 | 范围 |
|---|---|
| 可进入开发 | AutoSync 模块、独立状态、交互骨架、两段式自动更新与上传、状态展示、锁和测试基础设施 |
| 暂停开发 | Linux 后台安装与恢复 |
| 不进入本期 | 平台监控、macOS/Windows 自动同步、可配置重试、日志轮转 |

## 2. 阻塞风险

### P0-01 Linux 重启恢复范围未定

- 事实：目标测试环境已验证 systemd user manager 可用；脱离终端运行的普通进程只能维持当前开机会话，设备重启后不能自行恢复。
- 风险：如果把有限后台进程写成 Linux 完整支持，AS-AC-008 的“设备重启后无需重新 enable”会形成虚假验收。
- 建议决策：首期 Linux 完整支持以 systemd user manager 可用为前提；不满足时 enable 明确失败，不保存 `enabled=true`。这不扩大产品能力，也能给出可证明的恢复承诺。
- 所需确认：是否接受上述 Linux 首期支持边界。

### 已关闭：首次选择已过去时间的行为

- 产品结论：enable 或 set-time 选择的时间今天已经过去时，通过终端可移动选项列表引导用户选择“今天立即同步一次”或“从明天开始”。
- 约束：使用 ↑/↓ 选择并 Enter 下一步，不输入 `1/2`；取消时不保存本次设置。
- 状态：已写入产品需求、架构决策 A-08、开发任务 D-01 和验收用例 T-20/U-04/U-08。

## 3. 已收敛的高风险

| 风险 | 原问题 | 方案中的约束 | 必须保留的验收证据 |
|---|---|---|---|
| 后台更新覆盖登录配置 | 现有更新缓存会整份保存 `.aida.yaml`，可能覆盖并发登录写入的 Token/服务地址 | 自动 execute 不持久化更新缓存 | 自动执行与 login 并发后，配置仍是 login 的最终值 |
| 更新后仍由旧版本上传 | 在持锁进程内直接自重启会造成锁继承、重复执行或旧版本继续运行 | execute 只安装更新，再从磁盘启动新版本隐藏 `upload-all` | fake vNext 记录自身收到 `upload-all --all` 语义 |
| status 被更新门禁吞掉 | 当前命令入口先更新检查，失败时可能看不到本地 AutoSync 状态 | 本地 enabled/time 先输出，远程身份与更新错误分开呈现 | 断网及更新失败时仍先看见本地状态 |
| 非交互 enable 挂起 | enable 必须完成确认和时间选择，管道或 CI 无法回答 | 非 TTY 明确失败并提示在交互终端执行，不写配置 | closed stdin、pipe、EOF 均有界返回 |
| disable 后仍继续上传 | 只停 daemon 不等于停止其正在运行的子进程 | disable 取消并等待 execute/upload-all；已被服务端接受的数据不回滚 | disable 返回后无新请求、无自动进程复活 |
| 并发重复上传 | daemon 重启、分钟 tick 和 ensure 可能重叠 | daemon 单实例锁、执行锁、成功日期共同约束 | 并发触发只有一个 executor，当天成功后不再执行 |

## 4. 残余风险

### P1-01 永久性失败会重复扫描

当前方案在当天未成功时每分钟重新尝试。网络短暂断开时能较快补传，但认证失败、坏 Session 或稳定服务端错误也会造成每分钟重新扫描。

本期不增加用户可配置重试或复杂错误分类。开发时必须保证同一时刻只有一次执行、每次失败至少间隔一分钟，并在真实测试数据规模下记录扫描耗时和请求量；若压测达到发布环境不可接受的负载，则回到 A-05 调整固定技术参数，不能直接发布。

### P1-02 systemd 用户会话差异

不同 Linux 发行版和用户会话配置可能影响 user unit 在注销、重启后的启动行为。仅在当前测试机通过不等于 Linux 范围已通过。发布证据必须明确发行版、systemd 版本、linger/登录会话条件和重启方式，支持范围以实测结果为准。

### P2-01 日志持续增长

本期日志为本地单文件追加，长期失败可能持续增长。该问题不影响首期核心流程，但验收必须确认日志不包含 Token 和 Session 正文；日志轮转作为后续增强，不在本次擅自加入产品范围。

## 5. 文档一致性检查

- 产品需求是用户行为唯一基线，架构和开发方案没有新增时间段、频率、多时间点或默认开启。
- 自动上传固定复用现有全部上传语义，不复制 Session 扫描和上传实现。
- 自动更新失败继续上传，只作用于隐藏自动路径；手动命令仍保留现有更新门禁。
- 用户关闭优先于安装、自检、更新和恢复，任何入口不得重新开启。
- Linux 是首期核心平台；macOS/Windows 仅保持现有手动命令和构建回归，不宣称自动同步可用。
- 平台监控已明确排除，不新增 API、数据库、Web 页面或采集行为。
