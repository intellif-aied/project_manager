# Aida 客户端自动 Session 同步架构设计

> 文档状态：待决策

## 1. 设计边界

- 本文只解释如何满足定稿需求，不增加产品规则。
- 首期只保证 Linux；macOS、Windows 和平台客户端监控不进入本期。
- 不新增服务端接口、数据库表、独立服务或远程控制能力。
- 现有 `aida upload --all` 是自动同步唯一的上传语义来源，自动同步不得复制 Session 扫描和上传实现。
- 逻辑职责不等于必须创建同名包或公开接口；首期继续位于 `daemon/` 的同一个 CLI 二进制内。

## 5. 最小目标架构

```text
用户入口
  aida login
  aida auto-sync enable|status|set-time|disable
  aida status
          │
          ▼
┌────────────────────────────────────────────┐
│ AutoSync 模块                              │
│ 外部接口：引导、管理、状态、自检、更新重启 │
│                                            │
│  本地配置 ── 每日到期判断 ── 尝试/成功记录  │
│       │              │                     │
│       ▼              ▼                     │
│  后台监督 seam     隐藏执行入口             │
│  └─ A-02 批准的 adapter                    │
│                    aida auto-sync execute   │
└────────────────────────────┼───────────────┘
                             ▼
                    现有 maybeAutoUpdate
                    更新失败只记录并继续
                             │
                             ▼
                    现有 cmdUpload(--all)
                             │
                             ▼
                    现有 Session Sync API
```

### 5.1 模块外部接口

AutoSync 模块只向 CLI 编排层暴露以下能力：

1. 登录成功后的开启引导；
2. `auto-sync` 子命令统一处理；
3. 普通命令启动时的 best-effort 自检；
4. 显式更新成功后的 best-effort 后台重启；
5. 向 `aida status` 追加本地自动同步状态。

调度、文件格式、后台 adapter、PID、健康和锁全部隐藏在模块内部。隐藏的 `daemon-run`、`execute`、`upload-all`、`ensure` 只供 Aida 自身和安装脚本调用，不出现在帮助文档中。

### 5.2 本地资源

运行目录固定为 `~/.aida/auto-sync/`，目录权限 `0700`：

| 文件 | 最小内容 | 作用 | 权限 |
|---|---|---|---|
| `config.json` | `schema_version`、`enabled`、`daily_time`、`schedule_effective_at`、`updated_at` | 保存用户明确选择和当前时间 | `0600` |
| `schedule.json` | `schema_version`、`last_success_date`、`last_attempt_at` | 判断当天是否已经成功完成；失败时等待下一次检查补传 | `0600` |
| `health.json` | `pid`、`daemon_version`、`started_at`、`updated_at` | 自检后台是否存活以及是否仍是旧版本 | `0600` |
| `daemon.pid` | 当前 PID | 停止和重启目标 | `0600` |
| `daemon.log` | 内部执行和错误摘要，不写 Token | 后台不可见时保留诊断证据 | `0600` |
| `start.lock` | 文件锁 | 串行化 enable/disable/ensure/restart | `0600` |
| `daemon.lock` | 文件锁 | 保证同一 OS 用户只有一个后台调度实例 | `0600` |
| `run.lock` | 文件锁 | 保证同一时间只有一个自动上传执行 | `0600` |

不把运行状态写入 `~/.aida.yaml`：该文件同时由登录和自更新缓存写入，当前 `saveConfig` 不是原子合并写；分离后可避免后台每日写入与登录/更新互相覆盖。AutoSync 文件使用临时文件加同目录 rename 原子替换。

### 5.3 每日时间与补传

- 时间格式严格为本机时区下的 `HH:MM`，24 小时制。
- daemon 启动后立即判定一次，之后每分钟判定。
- 当 `enabled=true`、当前时间已经到达当天目标时间、当天目标时间不早于 `schedule_effective_at` 且 `last_success_date` 不是今天时，判定为应执行。
- 首次开启或修改时间时，如果当天所选时间已经过去，保存前通过终端可移动选项列表让用户选择“今天立即同步一次”或“从明天开始”，不要求输入编号。前者把本次调度标记为立即到期，后者将 `schedule_effective_at` 设为次日所选时间；取消时不写入本次设置。
- 已经启用后因进程、连接或设备中断而错过时间，daemon 恢复时立即满足到期条件并补传。
- daemon 触发前写入 `last_attempt_at`；隐藏 execute 在更新和上传的整个生命周期持有 `run.lock`。daemon 重启或并发自检不能同时启动第二个自动上传。
- 隐藏执行入口返回 `0` 后才写入当天 `last_success_date`。无新增 Session、全部 unchanged 或上传已正常接受均沿用现有 `upload --all` 的 `0` 退出码，视为当天完成。
- 更新失败但后续上传成功时，仍写入当天成功；上传返回非零时不写成功日期。
- 到点时网络离线或上传失败必须在连接恢复后补传，因此失败后保持当天到期状态。daemon 每分钟检查一次，并以 `last_attempt_at` 保证两次尝试至少间隔一分钟；下一次检查重新执行，直到当天一次上传成功或用户关闭自动同步。
- 重试仍调用现有增量上传和服务端去重，不创建补偿事务或第二套 checkpoint。

### 5.4 后台监督与恢复

推荐的 Linux systemd user service：

- unit 固定执行当前解析后的 Aida 二进制：`aida auto-sync daemon-run`；
- `Restart=on-failure`，`RestartSec=10s`，`WantedBy=default.target`；
- enable 时写入或更新 unit，执行 `daemon-reload` 和 `enable --now`；
- disable 时先写入 `enabled=false`，再 `disable --now` 并停止已验证 PID；
- systemd user manager 随用户环境恢复后自动恢复服务。

若 A-02 最终批准 detached process 作为有限 fallback，必须同时满足以下约束：

- systemd 不存在、user manager 不可用或 unit 写入失败时，使用 `Setsid` 启动同一隐藏入口；
- stdout/stderr 写入 `daemon.log`，stdin 使用 `/dev/null`；
- detached process 退出后，安装、显式 enable 和后续普通 Aida 命令可以通过自检恢复；
- detached process 无法在设备重启后自行启动，必须等用户再次执行 Aida 命令，因此不能单独满足 AS-AC-008 的完整重启恢复；
- 在 Linux 支持边界确认前，detached fallback 不得作为“完整支持 Linux”的验收依据。

无论哪个 adapter，`enabled=false` 都是最高优先级，自检、安装和更新不得重新开启。

### 5.5 自动执行与更新

后台不直接实现上传，而是执行隐藏入口：

```text
aida auto-sync execute
```

该入口按固定顺序执行：

1. 获取 `run.lock`，读取现有 Aida 登录和发布配置；
2. 调用现有更新核心完成检查、下载、校验和原子替换，但自动路径不写更新缓存、不重启当前 execute 进程、也不触发后台重启；
3. 更新检查或安装失败时记录错误，但继续下一步；
4. 重新解析当前 Aida 可执行文件，从磁盘启动隐藏的 `aida auto-sync upload-all`；更新成功时该进程天然使用新版本，更新失败时使用当前可用版本；
5. `upload-all` 只调用现有 `cmdUpload([]string{"--all"})`，不再执行更新、自检或 Session 选择；
6. `upload-all` 返回 `0` 时由 execute 写入当天 `last_success_date`；非零时只记录错误；
7. 释放 `run.lock` 并将摘要写入后台日志。

普通 `login/upload/status` 的更新失败门禁保持现状。只有隐藏自动执行入口采用 fail-open，避免扩大行为变化。隐藏自动执行入口不得把 `LastKnownVersion`、`LastUpdateCheck` 写回 `.aida.yaml`，避免后台和登录流程并发覆盖用户配置；版本检查、下载、校验和替换仍复用现有实现。

显式 `aida update` 成功后，如果自动同步已开启，则 best-effort 重启后台进程，使 daemon 版本与新二进制对齐；失败只写日志，不把已经成功的客户端更新改判为失败。自动执行过程中发生更新时，当前执行使用新二进制完成上传；后台旧版本由下一次普通命令自检或显式更新重启修复，不中断当前自动上传。

### 5.6 登录和非交互输入

- 交互式登录成功后，按产品文案直接进入开启引导。
- `aida auto-sync enable` 使用同一引导函数，不允许通过裸字段写配置绕过说明和确认。
- 当前 CLI 支持 `--token` 和非 TTY 输入。非 TTY 无法可靠完成问答，因此登录必须保持成功、不得阻塞；输出 `aida auto-sync enable` 提示，自动同步保持未开启。
- `aida auto-sync enable` 本身也是引导流程；在非 TTY 下必须明确失败并提示在交互终端执行，不得等待无限输入，也不得增加绕过引导的参数。
- 取消、EOF 或直接回车均不改变已有选择。

这是保持现有自动化登录可用的必要兼容结果，不新增另一套非交互启用参数。

## 7. 数据流与失败边界

### 7.1 开启

```text
登录成功或 auto-sync enable
→ 展示说明并确认
→ 校验 HH:MM
→ start.lock 下原子写 config.json
→ 按 A-02 最终结论启动 Linux 后台
→ 启动成功后展示产品确认文案
```

后台启动失败时，必须在同一启动锁内回写 `enabled=false`。不得显示“已开启成功”；可以保留用户输入的时间用于诊断，但后续再次执行 enable 仍进入完整引导。

### 7.2 每日执行

```text
daemon 启动/分钟 tick
→ 读取 enabled 和 daily_time
→ 判断今天是否到期且未成功
→ 写 last_attempt_at 并执行隐藏 execute
→ execute 获取 run.lock
→ 更新成功：磁盘安装新版本
→ 更新失败：写日志并继续
→ 从当前磁盘二进制启动隐藏 upload-all
→ upload-all 调用现有 cmdUpload(--all)
→ 退出码 0：写 last_success_date
→ 非零：写日志，释放锁，下一分钟继续检查
```

上传和服务端处理失败沿用现有退出码与服务端语义；AutoSync 不回滚已接受的 Session，不实现补偿事务。

### 7.3 修改时间

修改在 `start.lock` 下原子替换 `daily_time` 和 `schedule_effective_at`。daemon 每分钟重新读取配置，不需要为了改时间重启。无效输入或取消不写文件。

### 7.4 关闭

```text
写 enabled=false
→ 禁用 systemd user unit
→ 校验 PID 属于当前用户且命令行为 aida auto-sync daemon-run
→ 发送 SIGTERM
→ 清理当前 PID/health
```

先写关闭选择，再停止进程，保证并发自检看见关闭状态后不会重新拉起。

如果关闭时自动 execute/upload-all 正在运行，daemon 必须取消当前子进程并等待其退出；已经被服务端接受的数据不回滚。关闭成功后不得再启动新的自动上传。

## 8. 安全、容量与兼容性

### 8.1 安全

- 不复制 Token；隐藏执行入口仍从现有 `~/.aida.yaml` 读取。
- 本地目录 `0700`、文件 `0600`；systemd unit `0644` 且不包含 Token。
- 不通过 shell 拼接执行命令，直接传固定 argv。
- 停止进程前校验 PID 的 UID 和命令行，避免 PID 复用误杀其他进程。
- 日志截断单条错误，不记录 Token、Authorization 或完整 Session 内容。

### 8.2 容量

- 每分钟只读取小型本地 JSON 并做时间比较；不会每分钟扫描 Session。
- 正常情况下每日只执行一次现有全部上传；网络或上传失败时按每分钟最多一次重新尝试，成功后当天停止。Session 扫描、增量跳过和上传容量继续由现有实现承担。
- 日志采用单文件追加。本期不新增轮转策略；验收只要求错误不泄露敏感信息。日志治理不是本期准入项。

### 8.3 兼容性

- Linux/amd64 是本期发布与真实验收平台。
- 未开启用户没有后台进程，现有命令行为除登录后的 opt-in 引导和 status 展示外保持不变。
- 旧版本没有 AutoSync 文件时视为未开启，不做迁移。
- macOS/Windows 执行 `auto-sync enable` 时明确提示首期仅支持 Linux；现有手动上传和更新保持不变。
- 历史 `consume`、`daemon` 命令不恢复，不读取其环境变量或状态。

## 10. 设计分层

### A. 本期必须完成

- 产品定稿的登录引导和四个 `auto-sync` 管理交互；
- 一个每日本机时间、每日一次、错过后恢复补传；
- 自动执行前更新，更新失败仍继续全部上传；
- Linux 后台监督；具体完整支持边界由 A-02 确认；
- 显式关闭、修改时间、本地状态展示；
- 现有手动上传、增量上传和更新行为回归。

### B. 代码事实触发的必要保障

- 独立 AutoSync 目录，并禁止自动执行路径写 `.aida.yaml` 更新缓存，避免后台与登录互相覆盖；
- 原子文件、启动锁、daemon 单实例锁和自动执行锁，避免并发拉起和重叠上传；
- 健康、PID 身份和版本校验，支持恢复、关闭和更新对齐；
- 非 TTY 登录跳过问答，避免现有自动化登录阻塞；
- 隐藏执行入口隔离自动路径 fail-open，避免改变手动更新门禁。

### C. 后续增强

- 平台客户端监控；
- macOS/Windows 后台能力；
- 自动上传失败后的可配置重试；
- 本地日志轮转与用户可见的最近执行结果。
