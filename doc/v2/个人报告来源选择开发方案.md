## 2. 最终产品行为

1. 只有个人日报和个人周报显示 Session 来源选择。
2. 用户不选择时，服务端在报告 run 创建时按报告周期解析当前个人数据来源并建立 default selection；浏览器不需要伪造选择明细。
3. 用户显式选择后，本次运行优先使用选中的 Session 内容范围。
4. 报告日期决定保存周期，不限制用户选择更早的历史 Session。
5. 同一 Session 可以选择完整内容或多个互不重叠的连续活动范围。
6. 报告运行创建成功后输入固定，后续上传不改变本次输入。
7. Agent 生成结果回写为已保存报告，用户仍可继续编辑并保存。
8. 小组、部门报告继续读取已保存的下级报告，不逐个读取成员 Session。

## 3. 来源身份

客户端选择项不是 Token slice key，也不是数据库内部 Session UUID。稳定选择输入：

```text
session_ref
agent_type
activity_start_at
activity_end_at
```

服务端创建报告运行时，将其解析为不可变快照：

```text
session_id
source_generation_id
source_id
content_projection_revision_id
start_cursor
end_cursor
activity_start_at
activity_end_at
```

客户端不能直接指定 generation UUID 或 cursor 绕过权限和内容状态校验。

## 4. 数据模型

### 4.1 `report_source_selections`

一次报告运行对应一条选择头：

```text
id
user_id
report_type (personal_daily|personal_weekly)
period_start
period_end
selection_mode (default|explicit)
status (prepared|attached|expired)
created_at
attached_run_id
```

### 4.2 `report_source_selection_items`

```text
id
selection_id
session_id
session_ref_snapshot
agent_type
source_id
source_generation_id
content_projection_revision_id
start_cursor
end_cursor
activity_start_at
activity_end_at
summary_snapshot
content_status_snapshot
content_epoch_snapshot
created_at
```

约束：

- item 必须属于 selection 的同一用户；
- `start_cursor < end_cursor`；
- 范围必须落在 Content Projection Revision 所属 generation 的连续已确认 Chunk 内；
- 范围必须落在 selection 创建时 active Content Projection Revision 的 `content_indexed_cursor` 内；
- 同一 source 的重叠范围在创建快照时合并，避免 Agent 重复读取；
- item 创建后不可修改；再次生成创建新 selection；
- `content_epoch_snapshot` 必须与 Session 当前 epoch 一致；清除或恢复后旧 selection 永久失效；
- `summary_snapshot` 只用于页面核对，不代替实际内容读取。
- explicit selection 至少包含一个 item；default selection 允许零 item，并由 MCP 返回 `completeness=complete`、`returned_item_count=0`，报告仍可使用任务/需求等其他来源。

### 4.3 生命周期

```text
前端候选选择
   -> API 校验并创建 prepared selection
   -> 数据库事务创建 Aida 本地 run(preparing)并绑定 selection(attached)
   -> 事务提交后调用 managed Agent 平台并记录 platform task id
   -> MCP 按 selection_id 读取固定内容范围
```

managed Agent 平台调用失败时，本地 run 标记 failed，selection 保持绑定用于审计/幂等重试。禁止先启动远端任务再绑定 selection，不能产生 Agent 已运行但 MCP 尚无来源快照的竞态。

default 模式不经过前端候选选择：run 服务在同一数据库事务中按 period 解析当时已完成内容索引的范围，创建 `selection_mode=default` 的 selection/items、本地 run 并完成绑定。个人报告远端任务不允许在没有 attached selection 的情况下启动。

- `selection_id` 使用不可预测的服务端标识，不包含用户、Session 或 cursor 信息。
- selection 从 prepared 变为 attached 时，`user_id + attached_run_id + report_type + period` 一次性绑定，之后不可改绑。
- prepared selection 可以超时清理；attached selection 及其引用的 Content Projection Revision 至少保留到运行结束和审计保留期届满。

## 5. 候选 Session API

```http
GET /api/v1/report-source-sessions
```

参数：

```text
report_type
period_start
period_end
q
activity_from
activity_to
page
page_size
```

规则：

- 只返回当前登录用户自己的 Session；
- 只返回 `content_status=available` 且 Source 存在 active Content Projection Revision 指针的 Session；
- 只返回 `end_cursor <= content_indexed_cursor` 的可读范围；上传已 ack 但内容索引未完成的范围标记 pending，不允许被选择；
- 默认优先展示报告周期附近有活动的 Session，但允许清除日期筛选查看更早历史；
- `q` 服务端搜索真实 `session_ref` 和当前 summary，不只搜索当前页；
- 排序为 `last_activity_at DESC, session_ref ASC`；
- 一行一个 Session，不按自然日重复；
- 返回可选活动范围边界，但不暴露内部 generation、source UUID 和 cursor。

响应至少包含：

```json
{
  "session_ref": "019f...",
  "agent_type": "codex",
  "summary": "修复需求看板弹窗显示异常",
  "last_activity_at": "...",
  "activity_start_at": "...",
  "activity_end_at": "...",
  "cwd": "...",
  "models": ["gpt-5.4"],
  "content_status": "available",
  "content_index_status": "ready",
  "available_through_at": "..."
}
```

Token 可作为辅助展示，但不是候选身份，也不能因为 Token 为零排除有效 Session。

## 6. 创建来源快照 API

```http
POST /api/v1/report-source-selections
```

该接口只创建 `selection_mode=explicit`。default selection 由个人报告 run 服务端创建，前端不得提交空数组伪造 default。

请求：

```json
{
  "report_type": "personal_weekly",
  "period": {
    "week_start": "2026-07-13",
    "week_end": "2026-07-19"
  },
  "selected_session_sources": [
    {
      "session_ref": "019f...",
      "agent_type": "codex",
      "activity_start_at": "2026-07-12T09:30:00+08:00",
      "activity_end_at": "2026-07-14T10:42:00+08:00"
    }
  ]
}
```

服务端在一个事务中：

1. 校验 report type 仅为个人日报/周报；
2. 校验 Session 所有权和内容状态；
3. 将活动时间范围解析成 active Content Projection Revision 的完整事件/cursor 边界；
4. 合并重叠范围；
5. 保存不可变 selection 和 items；
6. 返回 `selection_id`、数量、实际固化范围和 `content_snapshot_at`。

报告运行接口只接收服务端签发的 `selection_id`，不能让浏览器直接把内部 cursor 传给 Agent 平台。

## 7. 前端交互

沿用现有“AI 生成”旁可展开的紧凑 Session 面板，不新增第二层嵌套大弹窗。

- 支持 Session ID/summary 搜索；
- 支持日期筛选并允许清空日期限制；
- 支持分页、多选和跨页保留；
- 支持完整 Session 和连续活动范围；
- 同一 Session 可添加多个不重叠范围；
- 展示已选数量、Session ID、summary 和时间范围；
- 页面不展示数据库 UUID、generation、cursor 和 Token slice key；
- 内容已清除、无权限或没有 active Content Projection Revision 的项不可选择；
- 内容索引 pending/error 的新增范围不可选择，页面显示“内容处理中”或明确错误，不回退到 Token slice；
- 清空选择恢复 default 模式。

生成按钮行为：

1. explicit 模式先创建 selection；
2. 数据库事务创建本地 run 并绑定 selection，提交后再启动 managed Agent 平台任务；
3. 远端任务创建成功后页面展示实际固化来源数量和范围，失败则展示本地 run 的明确失败状态；
4. default 模式由 run 服务端按 period 创建 default selection；浏览器不提交伪造明细，但本次运行仍使用固定快照。

## 8. Managed Agent 参数

个人报告 run 无论 default/explicit 都传递：

```json
{
  "report_type": "personal_daily",
  "period": {"date": "2026-07-14"},
  "target": {"type": "self"},
  "run_id": "...",
  "report_source_selection_id": "..."
}
```

`report_source_selection_id` 对个人日报/周报必填，所指 selection 可以是 default 或 explicit。兼容字段 `selected_session_slice_keys` 不再使用；迁移期如果旧字段和新 selection 同时出现，API 返回 400，不做隐式优先级。

小组、部门报告不得携带 `report_source_selection_id`。服务端发现非个人 report type 使用该字段时返回 400。

## 9. Aida Report MCP

### 9.1 `get_sessions` 两种互斥调用模式

Managed report 快照模式用于所有 default/explicit 个人报告：

```json
{
  "scope": {"type": "self"},
  "target": {"type": "self"},
  "report_type": "personal_daily",
  "period": {"date": "2026-07-14"},
  "run_id": "...",
  "report_source_selection_id": "...",
  "include_summary": true,
  "page_cursor": null
}
```

Ad-hoc 日期查询模式只供经过认证的自定义 Skill/诊断调用，不属于 managed report 固定输入：

```json
{
  "scope": {"type": "self"},
  "target": {"type": "self"},
  "date_range": {"start": "2026-07-14", "end": "2026-07-14"},
  "include_summary": true,
  "page_cursor": null
}
```

规则：

1. 快照模式禁止同时传 `date_range`、`week_range` 或旧 `selected_session_slice_keys`，否则返回 `AMBIGUOUS_REPORT_SOURCE`。
2. MCP 校验认证用户与 selection.user_id 一致，selection 已 attached，且 `run_id`、`report_type`、`period` 与绑定记录完全一致；任一不符返回 `REPORT_SOURCE_MISMATCH`。
3. selection 只允许个人日报/周报和 `scope/target=self` 使用；组织报告使用时返回 400。
4. 快照模式只读取 default/explicit selection 固化的 Content Projection Revision 和 Source/cursor 范围，不按当前报告日期再次裁剪，不读取后续新增 Chunk，也不受 Metrics Revision/Token 修正影响。
5. Ad-hoc 模式首调用时建立短期只读 query snapshot，后续 `next_cursor` 固定该 snapshot；不得在分页过程中重新解析 active projection。
6. Managed report 缺少 selection 时返回 `REPORT_SOURCE_MISMATCH`，MCP 不自行回退到实时日期查询。
7. MCP 不自行猜测 selection，不把 Token slice、Daily Usage 或 Session 总 Token 当作内容范围。

### 9.2 返回契约

```json
{
  "source_mode": "explicit",
  "selection_id": "...",
  "content_snapshot_at": "...",
  "completeness": "complete",
  "returned_item_count": 2,
  "has_more": false,
  "next_cursor": null,
  "items": [
    {
      "session_ref": "019f...",
      "agent_type": "codex",
      "activity_start_at": "...",
      "activity_end_at": "...",
      "summary": "...",
      "excerpt": "...",
      "messages": [],
      "tools": [],
      "commits": [],
      "content_quality": "exact"
    }
  ]
}
```

`source_mode` 枚举为 `default|explicit|ad_hoc`。

- 不向模型暴露数据库用户 ID、内部 Session UUID、generation ID、projection revision ID 和 cursor。
- 分页必须在完整内容事件边界切分，`next_cursor` 是绑定用户、selection/revision/query 的服务端随机句柄或带完整性保护的不透明稳定游标，不能接受客户端自报内部 cursor。
- 达到响应体限制时必须返回 `has_more=true` 和 `next_cursor`，禁止静默截断、静默丢 Session 或把 `completeness` 标为 complete。
- 默认 Report Skill 必须持续调用至 `has_more=false`；中途失败必须调用 `write_report_failure` 或明确生成不完整，不能写回“完整报告”。
- 返回 item 数、范围数和内容事件数必须与 selection 审计可对账；default/explicit/ad_hoc 均返回实际覆盖范围和内容水位。
- 单个内容事件超过响应限制时返回明确 `CONTENT_ITEM_TOO_LARGE`，不得截断后伪装完整。本期不在 MCP 内实现内容压缩。

### 9.3 MCP 读取工具共同契约

本节适用于 `get_sessions`、`get_tasks`、`get_requirements`、`get_daily_reports`、`get_weekly_reports` 和 `get_report_inventory`：

1. Managed report 调用必须携带或由 MCP 上下文解析 `run_id`。服务端以本地 run 保存的 `report_type + period + target` 为权威，模型传入的 scope/target/date 与 run 不一致时返回 `REPORT_CONTEXT_MISMATCH`，不能按模型参数扩大范围。
2. 响应统一包含 `data_as_of`、`scope_context`、`completeness`、`returned_count`、`has_more` 和 `next_cursor`。不需要分页时也明确返回 `has_more=false`。
3. 达到条数或响应体上限必须显式分页或失败，禁止返回 HTTP 200 的半份数据并标记 complete。
4. `scope_context` 返回模型写报告需要的显示名称、角色、应覆盖人数/报告数和缺失情况，不暴露数据库 user/team/department UUID。确需跨页关联时使用仅在该 run/query snapshot 内有效的 opaque subject key。
5. 小组/部门报告的 `get_daily_reports/get_weekly_reports/get_report_inventory` 必须使用相同 run scope 和 period 口径；库存 expected/available/missing 与报告列表逐项可对账。
6. 默认组织报告 Skill 先读取 inventory/scope_context，再分页读取全部已保存下级报告；不得用 Session 数、Token 数或仅第一页内容代替工作内容汇总。
7. 各工具返回的 Token 如存在，只是辅助字段，不决定内容是否存在、报告是否已保存或成员是否已覆盖。
8. 本期不要求对任务/需求/已保存报告建立新的内容版本系统；因此除 Session selection 外，`data_as_of` 表示该次工具查询快照。跨工具发生业务数据更新时必须分别返回实际 `data_as_of`，不能伪称整个 run 是单一不可变业务快照。
9. 部门报告创建本地 run 时，服务端根据当前 `departments.director_user_id` 完成授权并把规范的部门 UUID 和 `scope_as_of` 保存在 run 内；后续 MCP 只复用该范围。`department_id` 不能继续兼作总监用户 ID，`teams.director_user_id` 不参与 V2 部门授权。

## 10. 内容变化规则

### 后续上传

selection 创建后的新增 Chunk不进入本次运行。再次生成时用户可以沿用界面选择或重新选择，新运行创建新快照。

### 用户清除内容

- `clearing`、`clearing_failed` 和 `cleared` 均优先于尚未发生的 MCP 读取；新读取返回 `CONTENT_CLEARED`，不能因为原始对象尚未物理删除而继续暴露内容；
- 已经发送给 Agent 平台的输入无法撤回，但平台不得继续提供后续内容读取；运行因此失败时显示“来源内容已清除”；
- 清除后不能创建新的 selection；
- prepared 但尚未绑定 run 的 selection 在绑定时重新校验，已清除则失败；
- 已保存报告正文和来源数量/范围审计保留，但不继续暴露已清除 summary 或原始内容。

### Source Generation 切换

旧 selection 继续指向创建时 generation 和 Content Projection Revision，不自动漂移。新运行只能选择 Source 当前 active Content Projection Revision。

### 管理员彻底删除

彻底删除预览必须列出关联 selection 和运行。执行后未开始运行不可再读取；已保存报告正文按产品确认的影响预览处理。

## 11. 小组和部门报告边界

- 小组日报/周报主要读取成员已保存个人报告；
- 部门日报/周报主要读取已保存小组报告及必要下级报告；
- 组织报告按唯一归属日解析来源：日报使用 `report_date`，周报使用 `week_end`。小组成员读取 `user_team_memberships`；部门下小组读取 `team_department_memberships`；直属 PM/总监读取 `user_department_memberships`。无法确认的历史归属不使用当前字段倒填。
- 当前总监权限与报告周期来源范围分开校验：当前权限来自 `departments.director_user_id`，报告来源按运行时固化的部门和周期组织范围读取。
- 同一 run 的 inventory、下级报告列表和 `scope_context` 必须复用相同的组织范围，部门调整不能造成跨工具人数和报告集合不一致。
- 小组长和总监不逐个选择成员 Session；
- 默认流程不遍历全部成员原始 Session；
- `get_sessions` 仍可作为自定义 Skill 的能力入口，但默认组织报告 Skill 不调用它遍历所有成员；
- 自定义 Skill 调用 `get_sessions` 仍受现有 scope 权限和内容水位限制；本方案不扩大到任意成员原始内容读取权限；
- Session 数、Token 数不能代替报告覆盖人数和工作内容汇总。

## 12. 迁移与发布

1. 先完成 Content Projection、索引水位和 selection 服务端契约；旧 Report MCP 继续线上服务。
2. 新增 selection 表、候选 API 和 MCP 双模式实现，先使用测试账号验证，不建立用户级功能开关，也不提前切默认 Skill。
3. Aida API、Report MCP、默认 Skill 和 managed Agent 参数模板在同一提交批次支持 `report_source_selection_id + run_id`。
4. 完成个人日报、周报跨天、多页、清除竞态和越权 E2E，并完成六类报告回归。
5. 与 Token 查询、Chunk CLI 的生产切换在同一发布窗口完成，避免新上传内容只在部分消费者可见。
6. 切换后删除 `selected_session_slice_keys` 前后端和 Skill/MCP 契约；迁移期新旧字段同时出现始终返回 400，不做隐式优先级。
7. 切换发布同步更新当前用户文档 `doc/Aida Report MCP 使用说明.md`；实现前不得提前把线上仍不存在的新参数写成当前可用能力。
8. 不修改 managed Agent 平台源码，只使用其现有 Agent 参数和运行接口。

## 13. 测试与验收

- `RPT-001`：个人日报不手动选择来源时，run 服务创建 default selection 并固定当时已索引的周期来源。
- `RPT-002`：个人周报显式选择跨周期历史 Session 后可以生成。
- `RPT-003`：同一 Session 选择两个不重叠范围时均被读取。
- `RPT-004`：重叠范围在服务端合并，Agent 不重复读取。
- `RPT-005`：分页和搜索后跨页选择不丢失。
- `RPT-006`：default/explicit 生成开始后继续上传，当前 selection 均不变化。
- `RPT-007`：页面不暴露内部 UUID、generation 和 cursor。
- `RPT-008`：内容已清除或无权限 Session 不能创建 selection。
- `RPT-009`：prepared selection 绑定前内容被清除时 run 创建失败并给出明确提示。
- `RPT-010`：Token 为零但存在有效内容和活动的 Session 可以选择。
- `RPT-011`：个人报告参数不能用于小组或部门报告。
- `RPT-012`：小组/部门默认报告不遍历所有成员 Session。
- `RPT-013`：旧 `selected_session_slice_keys` 与新字段同时提交返回 400。
- `RPT-014`：六类报告回归通过，个人来源改造不影响组织报告保存和读取。
- `RPT-015`：selection 与其他用户、其他 run、不同 report type 或不同 period 组合时均返回 `REPORT_SOURCE_MISMATCH`，不泄露来源是否存在。
- `RPT-016`：快照模式 selection 与 date/week range 或旧 slice key 同传时返回 `AMBIGUOUS_REPORT_SOURCE`。
- `RPT-017`：显式选择报告周期外来源时完整返回，不被 period 二次裁剪。
- `RPT-018`：内容索引水位落后上传水位时，未索引范围不进入候选且 MCP 不读取。
- `RPT-019`：Content Parser 修正并切换新 revision 后，已 attached selection 仍读取原 projection，新的 selection 读取新 projection。
- `RPT-020`：MCP 多页返回与 selection 中 Session、范围和内容事件计数一致，Skill 调用至 `has_more=false`。
- `RPT-021`：模拟第二页超时后重试稳定游标，不重复或跳过内容事件。
- `RPT-022`：响应体达到限制时 `has_more=true`；单事件超限返回明确错误，不静默截断。
- `RPT-023`：selection 创建后进入 clearing，绑定或 MCP 读取失败且不暴露尚未物理删除的内容。
- `RPT-024`：默认模式与显式模式的响应均包含实际范围、completeness 和内容水位，字段口径一致。
- `RPT-025`：小组/部门六类报告默认 Skill 不携带 selection、不调用 `get_sessions` 遍历成员，继续以已保存下级报告为主。
- `RPT-026`：managed personal report 缺少 attached selection 时确定失败，不回退到实时日期查询。
- `RPT-027`：Ad-hoc 多页查询首调用后上传新 Chunk 或切换 projection，后续页仍读取首调用快照且不重不漏。
- `RPT-028`：远端 Agent 提交前 selection 已绑定本地 run；模拟远端立即调用 MCP、提交超时和失败重试，不出现未绑定窗口或重复 run。
- `RPT-029`：六个 MCP 读取工具的 scope/target/period 与 run 不一致时返回 `REPORT_CONTEXT_MISMATCH`，无越权结果和存在性泄露。
- `RPT-030`：所有 MCP 读取工具达到条数/体积上限时显式返回分页或错误，不存在 HTTP 200 静默截断。
- `RPT-031`：小组/部门 inventory 的 expected/available/missing 与分页读取的下级报告集合逐项一致。
- `RPT-032`：MCP 模型可见结果不包含数据库 user/team/department/session/projection UUID，opaque subject key 不能跨 run 使用。
- `RPT-033`：默认组织报告 Skill 消费全部分页下级报告，正文包含实际工作内容，不以 Session/Token 统计替代。
- `RPT-034`：default selection 零 Session 时 MCP 返回完整空集，个人报告仍可使用任务/需求；explicit 空选择被拒绝。
- `RPT-035`：部门 report target 在 run 创建时解析为规范部门 UUID，模型传总监用户 ID 或其他部门 ID 均不能扩大权限。
- `RPT-036`：小组在周中调整部门时，日报按报告日期、周报按周结束日确定唯一部门；inventory 和下级报告逐项一致，不重复进入两个部门，也不使用当前 `teams.department_id` 改写历史。
- `RPT-037`：直属 PM/总监和经小组归属的成员都能进入本部门正确 inventory，冲突或 unknown 关系不会被静默归入部门。
- `RPT-038`：总监变更后旧总监不能新建或继续发起该部门报告，新总监可用；已保存报告正文和已启动 run 的来源审计不被改写。

上述用例和核心契约 `CORE-016`、`CORE-017`、`CORE-018`、`CORE-019`、`CORE-025`、`CORE-029`、`CORE-031` 通过后，本专题才可标记为“可开发”；六类真实 Agent E2E 通过后才能切换生产 MCP。
