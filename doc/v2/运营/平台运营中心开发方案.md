# 平台运营中心开发方案

> 版本：V1.0  
> 状态：三轮评审通过，等待 `OPS-000` 预检  
> 需求源：`平台运营中心需求文档.md`  
> 架构源：`平台运营中心架构设计.md`  
> 主方案：`平台运营中心方案.md`  
> 适用分支：`fea.0.0.1`，每次任务开始时以远程当前 HEAD 重新确认

## 1. 目的

本文把运营中心拆成可独立评审、可回退、低冲突的开发任务。开发只交付两个产品模块：

1. 用户使用统计；
2. 运维生产异常监控。

实施优先级固定为“保护现有平台 > 数据正确 > 产品完整”。任何运营能力失败都只能降低运营数据完整性，不能改变业务请求、页面保存、后台任务或现有部署行为。

### 2.2 并行会话防冲突

每个 Task 开始前必须执行只读预检：

```bash

find api/db/migrations -maxdepth 1 -type f -printf '%f\n' | sort
```

### 2.3 单任务规则

- 一轮开发只执行一个 `OPS-*` Task；
- 完成测试、变更清单和停止点汇报后等待 review；
- 不自动开始下一 Task；
- 发现需要修改白名单外文件时先停止；
- 不做全仓格式化、依赖升级或无关重构；
- commit、push、rebuild、deploy 和开关启用均需要当轮明确授权。

## 3. 固定产品与技术边界

### 3.1 产品边界

```text
一个侧边栏入口：运营中心
一个路由：/operations
两个固定页签：usage / production
一个只读简报抽屉
```

两个页签均不可用时隐藏入口；入口一旦显示，两个页签始终存在，未生效页签显示“未启用”。不新增第三个模块、日志检索、Bug/反馈/工单、人工运营记录或个人行为时间线。

### 3.2 代码边界

新增模块统一使用：

```text
api/internal/operations/
api/handler/operations_*.go
api/cmd/ops-probe/
web/src/features/aidashboard/operations/
```

数据表使用 `platform_*` 或 `ops_*` 前缀，不复用现有 `api/internal/usage` 的含义。

允许按任务小范围接线的现有文件：

- `api/config/config.go`；
- `api/main.go`；
- `docker-compose.yml`、`deploy/docker-compose.single-port.yml`；现有 `docker-compose.override.yml` 默认不改；
- `web/docker/nginx.conf`、`deploy/nginx.conf`；
- 前端路由、权限、菜单以及任务卡明确列出的业务动作入口；
- `web/src/shared/request/types.ts`、`web/src/shared/auth/authApi.ts` 仅限 `OPS-204` 所需的 request id/错误信息接入。

禁止修改：

- 已有 migration 和业务表；
- `api/internal/usage/**` 计算语义；
- `session_processing_jobs` 状态机；
- 现有 worker 的 claim、lease、retry、返回值和循环顺序；
- 业务数据库连接池参数；
- Session、日报、Token、Prompt、命令或用户输入内容。

## 4. 功能开关

### 4.1 开关清单

全部默认 `false`：

| 环境变量 | 控制能力 |
| --- | --- |
| `OPERATIONS_ENABLED` | 总开关 |
| `OPERATIONS_METRICS_ENABLED` | Request ID 以外的 HTTP 指标和生产快照 |
| `OPERATIONS_PERSIST_ENABLED` | 独立运营连接、writer 和聚合持久化 |
| `OPERATIONS_UI_ENABLED` | 管理端查询和前端入口 |
| `OPERATIONS_INTERACTIONS_ENABLED` | 页面、动作和前端异常事件接收 |
| `OPERATIONS_ALERTS_ENABLED` | incident 计算，初期只静默记录 |
| `OPERATIONS_WEBHOOK_ENABLED` | API 内 notifier transport |
| `OPERATIONS_PROBE_ENABLED` | 独立 probe 与 heartbeat 接收 |
| `OPERATIONS_PROBE_NOTIFY_ENABLED` | API 不可用时 probe 独立通知 |

### 4.2 生效值

```text
production_enabled = admin && UI && METRICS && PERSIST
usage_enabled      = admin && UI && INTERACTIONS && PERSIST
can_view           = admin && UI && (production_enabled || usage_enabled)
events_accepting   = ENABLED && INTERACTIONS && PERSIST
brief_enabled      = usage_enabled && production_enabled && brief provider ready
```

以上 `UI/METRICS/PERSIST/INTERACTIONS` 均指生效值。brief provider 不增加环境变量；OPS-303 前或任一页签未生效时 brief=false，不生成部分简报。普通角色始终 can_view=false。非法组合只记录一次告警并降级。

允许文件：


实现要求：

验证：空库升级、真实历史 001~025 schema fixture 升级、重复/并发迁移、失败回滚、业务表结构和样例数据不变。

停止点：只提交 migration 变更供 review；不得 rebuild 157 API，因为启动会自动迁移共享库。

### OPS-101：Request ID 和 HTTP 内存指标

允许文件：新建 `api/internal/operations/httpmetrics/**`、operations middleware/测试，以及 `api/main.go` 最小接线。

实现要求：

- `X-Request-ID` 每请求生成并响应，CORS 暴露；
- 指标中间件位于 recoverer 外层，panic 也产生 5xx 指标；
- 使用 Chi route template，404 归为 `unmatched`，绝不使用原始 URL；
- traffic class 固定：`web_api`、`cli_session_sync`、`mcp`、`health_probe`、`operations`、`unmatched`；
- 固定直方图桶保存可合并的 total/状态/bytes/sum/max/buckets；
- 同步更新有界 5xx 指纹累加器，指纹仅由 method/route template/status/固定类别组成，保存次数和一个 sample request id，不含用户或错误全文；
- 请求路径零运营 SQL；
- ResponseWriter 完整兼容 JSON、下载、流式和可选接口；
- 运营、health、probe 流量不进入业务 API 成功率和告警。
- 业务 API 成功率分母只含 `web_api/cli_session_sync/mcp`；`health_probe/operations/unmatched` 明确排除。

后端 5xx 不能可靠取得认证中间件下游替换后的用户 Context，因此 `affected_users` 允许为空，不为此改认证链。

### OPS-102：有界队列、repository 和单 writer

允许文件：`api/internal/operations/queue/**`、`writer/**`、`repository/**`、`api/db/operations_connect.go` 和 `api/main.go` 最小接线。

实现要求：

- 本 Task 只建立稳定 writer envelope，并批写 HTTP 分钟快照、5xx 脱敏样本/分组和组件快照；交互事件 DTO/repository 到 OPS-201 再扩展；
- HTTP 每分钟原子交换完整快照，同一 `snapshot_id` 重试不得重复累计；
- 将 OPS-101 的 5xx 分钟累加异步写入 `ops_error_events/ops_error_groups`，OPS-104 不负责生产这些数据；
- 高优先级容量 1000，低优先级 5000，容量配置有硬上限；
- writer 连接不超过 2；
- 聚合任务使用 PostgreSQL advisory lock；
- DB 失败时有限重试/丢弃并更新采集自监控，不阻塞业务。

允许文件：新建 health handler/测试、`api/main.go`、`web/docker/nginx.conf`、`deploy/nginx.conf`。

实现要求：

### OPS-104：生产事实、队列推断状态与查询 API

允许文件：operations `facts/health/aggregate/query`、生产 handler/测试、`api/main.go` 最小接线，以及 `scripts/operations_loadtest.go`、`scripts/testdata/operations_load_scenario.json`。

实现要求：

- `session_processing_jobs` 使用现有 status 前导索引读取 pending/leased/retry_wait/dead；
- V1 不扫描全部 completed 计算吞吐；
- `ai_runs` 只允许低频、限定窗口、短 `statement_timeout` 查询；超时返回 `partial`；
- migration 026 不给业务表加索引；
- 只展示队列推断状态：
  - `idle`：没有待处理任务；
  - `degraded`：到期 backlog、重试堆积或过期租约；
  - `error`：存在 dead；
  - `unknown`：快照查询超时；

可选 `OPS-107` 才能增加 worker 循环观察器；它不属于 V1，需并行业务结束并单独授权修改 worker。

### OPS-201：事件批量接收

允许文件：operations interactions handler/schema/queue/repository/测试及 `api/main.go` 最小接线。

固定契约：

| 场景 | 状态码 | 行为 |
| --- | --- | --- |
| 未认证 | `401` | 零入队 |
| 非法 schema/枚举/时间/身份字段/混合优先级 | `400` | 整批拒绝 |
| 请求体超过 32 KB | `413` | 不解析 |
| `events_accepting=false` | `204` | 静默关闭 |
| 整批容量不足 | `429` | 整批拒绝 |
| 合法或幂等重试 | `202` | 返回 `received/accepted/duplicates`；duplicates 仅统计同批相同载荷重复 |

每批 1~50 条；用户、角色、团队、部门只由服务端补充，客户端携带身份字段一律 400；不允许部分成功。

同批相同 id 但载荷不同返回 400。接收路径不查询数据库；跨请求历史重复可能计入 accepted，writer 通过唯一约束 `ON CONFLICT DO NOTHING` 丢弃并增加 `persisted_duplicates`，最终聚合不得重复。

### OPS-202：前端 transport 与 page view

允许文件：operations telemetry、路由元数据、`PermissionGuard` 和必要 Provider。

实现要求：Bearer Header、keepalive fetch、并发 1、每 10 秒或 20 条 flush、内存最多 500；不使用 sendBeacon/LocalStorage；401/429/5xx 静默失败；StrictMode 幂等；登录、403、404、operations 页面和动态 URL 不采集。

### OPS-203A~E：白名单动作

每个子任务单独 review：

| Task | 范围 | 特别约束 |
| --- | --- | --- |
| `OPS-203A` | 登录、退出 | 登录保存 Token 后以同一 id 入队 started+success；退出在清 Token 前构造认证 keepalive 的 started+success；不采集未认证登录失败 |
| `OPS-203B` | 需求、任务、我的工作 | 只统计创建、编辑、状态变更、添加文档 |
| `OPS-203C` | 日报、周报 | 不采集正文、AI 输入输出 |
| `OPS-203D` | AI 资产 | 不采集 Prompt、配置正文和运行输出 |
| `OPS-203E` | 组织管理 | 不采集成员字段值 |

每次 Mutation 新建 action id；自动重试沿用；每个 id 一个 started 和至多一个 success/failure 终态。

### OPS-204：前端异常

允许文件：operations telemetry、root Error Boundary、router、统一请求层、`web/src/shared/request/types.ts`、`web/src/shared/auth/authApi.ts` 及明确列出的原生 fetch。

只采集 error name、受控类别、稳定指纹、request id、page key 和时间；禁止 message、stack、原始 URL、表单值、请求/响应体。普通 HTTP 5xx 不由前端重复上报。

本 Task 只产生并持久化 `platform_interaction_events(kind=frontend_error)`，不在请求路径同步维护 error group。

### OPS-205：使用聚合、API 与 usage 页面

除 operations 业务文件外，允许新增/修改 `web/e2e/operations-usage.spec.ts` 和 `web/e2e/operations-telemetry.spec.ts`，完成 UI-010~016；不得改其他 E2E。

### OPS-301：静默告警

- 只基于已持久化且完整的时间窗创建 incident；

- 只记录不通知，至少观察 7 天。

### OPS-302：Webhook 与 probe 通知

- 只启用一个飞书或企微通道；
- API notifier 有界队列、有限重试；
- probe 在 API 不可用时独立通知，恢复后补报完整区间；
- 通知尝试写 `ops_alert_deliveries`；
- 通过 heartbeat 的 `deliveries` 最多补报 20 条，并以 delivery_id 幂等；不得上传远端响应正文或 Webhook 地址；

### OPS-303：每日简报与保留期清理

- 不支持编辑、补录、模板设计或运营记录；

## 10. 回退方案

| 故障 | 回退动作 |
| --- | --- |
| HTTP 指标增加延迟 | 关闭 `OPERATIONS_METRICS_ENABLED` |
| writer/数据库异常 | 关闭 `OPERATIONS_PERSIST_ENABLED`，保留业务服务 |
| 事件拒绝/前端异常 | 关闭 `OPERATIONS_INTERACTIONS_ENABLED` |
| 页面查询异常 | 关闭 `OPERATIONS_UI_ENABLED`，后端采集可继续 |
| incident 噪音 | 关闭 `OPERATIONS_ALERTS_ENABLED` |
| Webhook 刷屏 | 关闭 WEBHOOK/PROBE_NOTIFY |
| probe 异常 | 停止独立 profile，不影响 API |

不删除 026 表，不修改业务表，不清理历史运行数据。代码回退与 schema 保留兼容；后续修正使用 027+。

## 11. Definition of Done

每个 Task 必须同时满足：

1. 只修改白名单文件，`git diff --check` 通过；
2. 对应自动化用例通过，Skip 和未运行项明确列出；
3. 不新增敏感字段、高基数维度、同步运营 SQL或无界队列；
4. 不改变业务状态码、响应体、worker 行为或现有权限；
5. 文档中的 API、状态码、表名、开关、Task、Gate 与代码一致；
6. 浏览器/集成/性能验证如未实际执行必须写 `not-run`；
7. 不擅自 commit、push、rebuild、deploy、迁移共享库或开启开关；
8. 按固定交付格式汇报并停在对应 Gate。

固定交付格式：

```text
Task ID：OPS-xxx
基线：HEAD / branch / migration / working tree
范围：本次完成什么
修改文件：逐项列出
未修改：业务模块、运行数据、开关状态
验证：命令、结果、Skip、interaction
性能：请求路径、连接池、轮询影响

风险与回退：当前剩余风险
下一停止门：Gx，等待 review
```
