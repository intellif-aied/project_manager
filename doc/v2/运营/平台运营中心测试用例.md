# 平台运营中心测试用例

> 版本：V1.0  
> 状态：三轮评审通过，等待 `OPS-000` 预检  
> 需求源：`平台运营中心需求文档.md`  
> 架构源：`平台运营中心架构设计.md`  
> 开发源：`平台运营中心开发方案.md`  
> 原则：隔离测试、可复现数据、逐 Gate 放行、共享环境只读

## 1. 测试目标

测试必须同时证明：

1. 指标口径、权限、隐私和页面交互符合需求；
2. migration 能兼容空库与真实历史 001~025 schema；
3. 运营采集不会改变业务状态码、响应体、页面操作和 worker；
4. 队列、数据库、probe、Webhook 故障被限制在运营失败域；
5. 开关默认关闭且可按 Gate 安全灰度；
6. “构建通过、静态检查、单测通过、集成测试、浏览器交互、压测、已上线”严格区分。

## 2. 当前测试基础与缺口

- 后端已有 Go 单测、`sqlmock`、`httptest`；
- 集成测试依赖 `AIDA_TEST_DATABASE_URL`、`AIDA_TEST_MINIO_*`；未配置时会 Skip；
- `go test ./...` 成功不代表 PostgreSQL/MinIO 集成通过；
- 前端已有 Node 源码契约脚本；
- Playwright 和 Chromium 已有依赖，但当前没有运营专用配置和 spec；
- 当前没有固定运营压测驱动；
- 共享 157 工作树、数据库、MinIO 和运行容器不能作为破坏性测试环境。

建议新增：

```text
api/db/operations_migration_test.go
api/db/testdata/operations/history_001_025.sql
api/internal/operations/**/*_test.go
api/handler/operations_*_test.go
api/cmd/ops-probe/**/*_test.go

deploy/operations-test/nginx.conf.template
scripts/operations-test-preflight.sh
scripts/test-operations-integration.sh
web/scripts/operations_workflow_test.mjs
web/e2e/operations-production.spec.ts
web/e2e/operations-usage.spec.ts
web/e2e/operations-telemetry.spec.ts
web/e2e/operations-brief.spec.ts
web/playwright.operations.config.ts

```

不新增前端测试框架，直接复用 Playwright、TypeScript 和现有构建链。

当前仓库基线命令固定为：`api: go test ./...`、`daemon: go test ./...`、`web: pnpm test && pnpm lint && pnpm typecheck && pnpm build`。不存在的 `test:routes` 或 `test:report-source` 不得写入验收报告。

## 3. 测试环境

| 标识 | 环境 | 允许范围 |
| --- | --- | --- |
| `UT` | 本地纯单元 | fake clock、sqlmock、httptest、内存队列 |
| `ISO-DB` | 独立临时 PostgreSQL/MinIO bucket | migration、repository、聚合、清理、隐私扫描 |
| `ISO-STACK` | 独立 compose project/name/volume | API、Web、PostgreSQL、MinIO、ops-probe 集成 |
| `MOCK-BROWSER` | 独立 Vite + Playwright mock API | 权限、页面状态、轮询、筛选、异常 transport |
| `ISO-PERF` | 独立且数据固定的压测环境 | 性能、断依赖、容量、延迟和进程故障 |
| `CANARY` | 获明确授权的灰度环境 | 分开关观察，不做故障注入 |
| `PROD-RO` | 生产只读 smoke | health、菜单、只读查询、指标观察 |

硬规则：

- `ISO-DB/STACK/PERF` 不得连接 157 共享数据库或共享 MinIO bucket；
- migration 测试使用专用数据库，测试后只删除测试资源；
- 禁止在 157 执行 `docker stop` 依赖、网络延迟、磁盘填满、连接耗尽、队列灌满或敏感哨兵注入；
- PROD-RO 不写事件、不触发告警、不修改开关；
- 所有测试报告保存环境标识、HEAD、配置、数据集版本和实际执行命令。

### 3.1 隔离环境硬保护

仓库必须提供 `deploy/docker-compose.operations-test.yml`、`scripts/operations-test-preflight.sh` 和 `scripts/test-operations-integration.sh`。专用 compose 只绑定 loopback 的可配置端口，PostgreSQL/MinIO 使用 tmpfs，不复用任何命名 volume。

每次生成唯一 `COMPOSE_PROJECT_NAME=aida-ops-test-<run-id>`；数据库名必须以 `aida_operations_test` 开头，bucket 必须以 `aida-operations-test-` 开头。preflight 同时检查：

- project 前缀正确；
- PostgreSQL/MinIO endpoint 为 127.0.0.1/localhost；
- `current_database()` 与允许前缀一致；
- bucket 前缀正确；
- `AIDA_TEST_DESTRUCTIVE_OK=1` 明确设置；
- 未继承 157 的 `DATABASE_URL`、MinIO endpoint 或共享 bucket。
- ISO-PERF base URL 只允许 loopback，test-only proxy 必须返回与 project 相同的 `X-Aida-Test-Environment`；压测驱动在 guard 通过前零请求。

标准命令以《开发方案》9.1 为准。运营集成门禁固定运行 `go test -json -count=1 ./... -run '^TestOperations'`，必须至少执行一个匹配测试且 `skip=0`；环境缺失导致的 Skip 等于未通过，不是通过。结束只对已验证前缀的 test project 执行不带 `-v` 的 `docker compose down --remove-orphans`。

## 4. 测试数据

### 4.1 固定组织数据

至少包含：

- 2 个部门、每部门 2 个团队；
- admin、director、team_leader、employee；
- 跨团队、无团队、组织变更用户；
- 一个从未活跃用户和一个首次活跃用户。

### 4.2 固定时间数据

- Asia/Shanghai 零点前后；
- 7 日、30 日滚动边界；
- 月末、年末、闰日；
- 延迟到达、重复到达、未来时间和超窗事件；
- 30 分钟无动作终态。

### 4.3 敏感哨兵

使用明显但虚构的哨兵值注入测试输入：正文、Prompt、Token、Authorization、原始 URL query、error message/stack、用户名、表单值。测试后扫描全部运营表、CSV、简报和日志，哨兵不得出现。

| `SEC-003` | 客户端提交 user_id、用户名、角色、团队、部门 | 400，整批拒绝；不能静默忽略 | UT |
| `SEC-004` | 提交原始 URL/query、message、stack、正文、Session、Token 等字段 | 400，零入队 | UT |
| `SEC-005` | 检查 telemetry 网络请求和存储 | Token 只在 Authorization Header；不进 URL/body/新增 LocalStorage/log | MOCK-BROWSER |
| `SEC-006` | telemetry 返回 401/429/5xx/超时 | 不 Toast、不退出、不跳转、不递归上报、不影响业务操作 | MOCK-BROWSER |
| `SEC-007` | 向所有入口注入敏感哨兵并扫描运营表 | 全部运营表不得出现哨兵 | ISO-DB |
| `SEC-008` | 导出 CSV/复制简报 | 不含 user id、用户名、原始事件、正文、Session、Token 数值 | ISO-DB/MOCK-BROWSER |
| `SEC-009` | 枚举 admin API | 不存在 raw event、个人行为时间线、人工关闭或删除接口 | UT |
| `SEC-010` | 高频随机 URL/error/user 值 | 不成为指标维度；内存 key 数有硬上限 | UT/ISO-PERF |
| `SEC-011` | 访问/轮询运营页和探针 | 不计入产品使用、业务 API 成功率或业务告警 | ISO-STACK |

## 8. Migration 用例

全部只允许 `ISO-DB`。

| ID | 步骤 | 预期 |
| --- | --- | --- |
| `MIG-001` | 空库执行当前源码 migrations，再执行 026 | 11 张表、索引、约束正确 |
| `MIG-002` | 从真实历史 001~025 脱敏 schema fixture 执行 026 | 成功升级，不依赖合并后文件假象 |
| `MIG-003` | 重复执行迁移流程 | 不重复建表、不丢数据 |
| `MIG-004` | 两个 API 并发启动 | advisory lock 确保 migration 只执行一次 |
| `MIG-005` | 在 026 中间制造失败 | 事务回滚，schema_migrations 不记录 026 |
| `MIG-006` | 比较迁移前后业务 schema/行数/样例 | 业务表完全不变，无 trigger/回填/新索引 |
| `MIG-007` | 放入另一份 026 或检测编号已占用 | 预检/测试直接失败并停止开发 |
| `MIG-008` | 模拟 026 已进入共享环境后修改需求 | 026 冻结，后续必须新增 027+，无逆向清库脚本 |

历史 fixture 必须源自真实 001~025 schema，不能只插入 `schema_migrations=25` 冒充历史库。

## 9. 性能与资源隔离用例

全部只允许 `ISO-PERF`；相同数据、请求组合、并发和持续时间各跑至少 3 轮，比较中位数。

| ID | 验证内容 | 门槛 |
| --- | --- | --- |
| `PERF-001` | 先用缺失flag/错误header/157地址验证guard，再比较全关闭vs仅METRICS | 非隔离目标零请求退出；合法test header后固定负载和JSON可复现 |
| `PERF-002` | 吞吐、P95、P99 | 吞吐回归≤2%；P95 回归≤2%且绝对≤2ms；P99 无持续异常 |
| `PERF-003` | 请求路径 SQL spy | 业务请求零运营 SQL |
| `PERF-004` | 运营连接池采样 | Open≤2，Idle≤1；不改业务池 |
| `PERF-005` | 队列满、运营 DB 断开 | 业务 status/body hash 不变，性能仍在门槛内 |
| `PERF-006` | 随机路径/错误高压 | map/内存维度有界，无持续泄漏 |
| `PERF-007` | 分钟快照、事实查询、日聚合、清理 | 无高频轮询、长事务或业务锁等待 |
| `PERF-008` | 大数据下≤30天精确UV/动作人数及>30天查询 | 前者EXPLAIN命中运营事件复合索引并在2秒内完成或partial；后者绝不扫描原始事件且唯一人数为null |
| `PERF-009` | 开启 INTERACTIONS 后重跑 PERF-001~005 | 仍满足 G3 门槛，队列丢弃可观测 |
| `PERF-010` | 前端 bundle/网络 | 非运营页面不加载图表 chunk、不请求运营 API；hidden 停止轮询 |

压测驱动使用 Go 标准库固定实现，写出 baseline/candidate 的 commit、参数、每轮原始结果和中位数。固定命令以《开发方案》9.2为准：ISO-PERF、同一场景、120秒、并发32、三轮，认证只从 `AIDA_LOADTEST_TOKEN` 读取且不记录。

## 15. 发布阻断条件

出现以下任一项立即阻断：

- migration 编号冲突或历史升级失败；
- 客户端身份/敏感字段被接受或持久化；
- 业务请求路径出现运营 SQL或等待队列；
- ResponseWriter 行为变化；
- 连接数、吞吐或 P95 超门槛；
- 运营 DB/Webhook/probe 故障改变业务结果；
- AdminOnly 可绕过；
- 页面伪造零值、个人名单或 raw event；
- `partial/delayed` 窗口产生告警；
- 浏览器用例未运行却准备开放 UI；
- 共享工作树出现其他会话重叠修改。
