# 平台运营中心架构设计

> 版本：V1.0  
> 状态：三轮评审通过，等待 `OPS-000` 预检  
> 需求源：`平台运营中心需求文档.md`  
> 主方案：`平台运营中心方案.md`

## 1. 设计目标

本设计在当前单 Go API、PostgreSQL、MinIO、React 前端和多个同进程 worker 的基础上，增加轻量运营能力，并满足：

- 正常业务请求路径零运营 SQL；
- 采集、落库、查询、告警与业务失败域隔离；
- 不改变现有 Session、Token、报告和 Managed Agent 业务语义；
- 可通过默认关闭的功能开关逐层启用；
- API/Web 进程不可用时仍有独立探针通知；
- 所有指标维度有限，避免高基数和敏感数据进入系统。

## 2. 当前系统基线

当前关键事实：

- 后端：Go + Chi，单 API 进程；
- 前端：React、React Router、React Query、Axios、Ant Design、ECharts；
- 数据：业务 PostgreSQL；API 启动自动执行 migration；
- 对象存储：MinIO，已是 Session 内容/用量处理核心依赖；
- 后台：Managed Agent 调度和状态同步、Session 内容投影、Session 用量投影、计量生命周期 worker；
- Session 任务事实：`session_processing_jobs`；
- Agent 任务事实：`ai_runs`、`managed_agent_schedules`；
- 当前只有固定 200 的 `/health`，没有 request id、运营指标和前端全局异常采集；
- 现有 `api/internal/usage` 表示 AI Session Token usage，运营模块不得复用该名称。

## 3. 架构原则

1. **旁路**：业务请求只更新内存计数或尝试入队，不等待数据库和 Webhook。
2. **隔离**：运营使用独立 `*sql.DB` handle，最大 1 至 2 个连接，单 writer。
3. **有界**：内存队列、批次、维度、错误字段、查询周期和分页全部有上限。
4. **复用事实**：只读聚合现有任务表，不复制每条业务失败，不把运营任务写入 Session 队列。
5. **默认关闭**：非法开关组合只降级运营能力，不能导致业务 API 启动失败。
6. **最小数据**：只收集回答产品问题所需字段，不收正文、原始 URL、message/stack 或凭证。
7. **可解释**：所有页面返回数据时间和完整性，best-effort 数据不伪装成审计数据。

## 5. 组件设计

### 5.1 前端运营页面

目录：`web/src/features/aidashboard/operations/`。

职责：

- 一个 `/operations` 路由和 `usage/production` 两个页签；
- 两个能力都未生效时隐藏入口；入口显示后固定展示两个页签，未生效页签显示“未启用”；
- 只调用运营预聚合 API；
- URL Query 保存页签和筛选；
- 复用 Ant Design 和现有 ECharts；
- 模块懒加载；
- production 每 60 秒刷新，`document.hidden` 时暂停；
- 保留最近一次成功响应并显示完整性状态；
- 仅 `brief_enabled=true` 时渲染简报按钮；
- 不把运营查询放进全局 Provider 或 MainLayout 常驻轮询。

### 5.2 前端 telemetry transport

独立实现，不复用会处理 Toast、401 跳转的普通 `api.request`。

```text
track page/action/error
       │ 同步入队
       ▼
浏览器内存队列（最多 500）
       │ 10 秒或 20 条
       ▼
按优先级分批（每批 1-50，<=32 KB，并发 1）
       │ Bearer fetch
       ▼
POST /api/v1/operations/events/batch
```

规则：

- `page_view` 低优先级；`action/frontend_error` 高优先级；
- 高低优先级不能混批，高优先级先发送；
- 页面卸载使用带 Authorization 的 `fetch(..., {keepalive:true})`；
- 不使用 `sendBeacon`，不把 Token 放 URL/body；
- 不使用 LocalStorage 持久化，不弹 Toast，不自动跳登录，不递归上报自身错误；
- 满队列先丢低优先级，并增加本地 dropped counter。
- 客户端不得发送用户、用户名、角色、团队或部门字段；出现这些字段时服务端整批返回 400，不能静默忽略。

### 5.3 路由和动作采集

- `AppRoute` 增加 `telemetryPageKey`、`telemetryDisabled`；
- tracker 位于 `PermissionGuard` 内，未授权路由不采集；
- 详情、创建路由归一到所属 page key；
- 每次 Mutation 调用由显式 `trackAction` 生成 action id；
- 自动重试沿用 action id，用户再次操作生成新 id；
- 不修改全局 MutationCache；
- started 和终态分别使用唯一约束；30 分钟无终态仅标记 incomplete，不进入成功率。

### 5.4 Request ID 与 HTTP 指标中间件

建议顺序：

```text
Request ID
→ HTTP metrics（位于 Recoverer 外层）
→ Logger
→ Recoverer
→ CORS
→ route-specific Auth
```

设计约束：

- 服务端生成 `X-Request-ID` 并通过 CORS expose；
- 请求结束后读取 `chi.RouteContext(...).RoutePattern()`；
- 404 统一为 `unmatched`，不使用原始 path；
- 记录 method、route template、traffic class、status class、response bytes、duration；
- traffic class 固定为 `web_api`、`cli_session_sync`、`mcp`、`health_probe`、`operations`、`unmatched`；
- ResponseWriter 不缓存响应体；
- 使用 Chi 兼容包装或完整保留 Flusher、Hijacker、Pusher、ReaderFrom；
- 请求路径只更新固定大小内存结构，不执行运营 SQL。

同一中间件还维护有界 5xx 指纹累加器：指纹只由 `method + route_template + status + 固定 error_category` 计算，保存次数、首次/最近时间和一个 sample request id，不含用户、message 或 stack。每分钟随 HTTP snapshot 交换；OPS-102 异步写 `ops_error_events/ops_error_groups`，OPS-104 只查询。`unmatched/health_probe/operations` 的 5xx 可做自监控，但不进入业务告警。

### 5.5 固定延迟直方图

V1 固定桶：

```text
5, 10, 25, 50, 100, 250, 500,
1000, 2000, 3000, 5000, 10000, +Inf ms
```

聚合键：`minute + method + route_template + traffic_class + instance_id`。

每分钟持久化：

- total、2xx、3xx、4xx、5xx；
- `sum_ms`、`max_ms`、response bytes；
- `bucket_schema_version`；
- `bucket_counts BIGINT[]`。

跨时间窗口先逐桶相加，再计算 P50/P95/P99。低于配置样本量返回 `sample_sufficient=false`。

### 5.6 后端优先级队列与 writer

默认容量：

- 低优先级 5000 个事件；
- 高优先级 1000 个事件；
- 一个 writer；
- 每分钟或达到批量阈值 flush；
- 运营连接池 `MaxOpenConns=1~2`、`MaxIdleConns=1`；
- 每次事务和查询使用短 context timeout。

批量接口语义：

- 未认证：401，零入队；
- schema、枚举、时间、客户端身份字段或混合优先级非法：400，整批拒绝；
- 请求体超过 32 KB：413，不解析、不入队；
- 采集未生效：204，不入队；
- 整批容量不足：429，整批不入队；
- 合法或幂等重试：202，固定返回 `received/accepted/duplicates`；duplicates 只表示同批相同载荷重复；
- 每批 1 至 50 条，同批只允许同一优先级，任何事件无法接收时均不得部分成功；
- 202 不代表持久化，API 非正常退出可能丢失未 flush 事件。

接收路径不查询数据库：同批先按 client_event_id 去重，同 id 不同载荷返回 400；received 为输入条数，accepted 为进入队列的唯一事件数。跨批/重启历史重复可能再次入队，writer 使用数据库唯一约束和 `ON CONFLICT DO NOTHING` 消除，并增加 `persisted_duplicates` 自监控。这样既保证最终不重复计数，也不把同步 SQL 引入采集接收路径。

writer 失败不能阻塞入队方；队列达到上限后按优先级拒绝/丢弃并更新完整性状态。

### 5.7 业务事实 collector

每 60 秒用短超时只读聚合：

- `ai_runs.status/error_message`；
- `managed_agent_schedules.last_error`；
- `session_processing_jobs` 全部 job type 的 pending、leased、retry_wait、dead、最老等待和租约状态。

查询限制：

- `session_processing_jobs` 只利用现有 status 前导索引查询未完成/异常状态；V1 不扫描全部 completed 计算吞吐；
- `ai_runs` 只允许低频、限定窗口、短 `statement_timeout` 查询；超时返回 `partial`；
- 026 不给现有事实表新增索引；需要新业务索引时另立 migration 和评审。

禁止：

- 修改上述表；
- 把行复制成第二套业务任务；
- 使用 2 秒轮询；
- 改 worker claim、heartbeat、lease、retry 或返回值。

V1 展示的是“队列推断状态”，不是 worker 进程健康：

- `idle`：没有待处理任务；
- `degraded`：存在到期 backlog、重试堆积或过期租约；
- `error`：存在 dead；
- `unknown`：快照查询超时。

V1 不展示无法可靠获得的“最后循环成功时间”，也不修改现有 worker。真正的循环观察器作为可选 `OPS-107`，不进入 V1。

### 5.8 健康检查

- `/health`：保持当前兼容行为；
- `/health/live`：只检查 API 进程，不访问依赖；
- `/health/ready`：短超时检查 PostgreSQL 和 MinIO；
- Managed Agent：`not_configured/normal/degraded/unknown`，不阻断 ready；
- worker lag：管理员状态，不阻断 ready；
- 依赖结果缓存 10 至 30 秒；
- Nginx 同时代理 `/health` 和 `/health/*`。

### 5.9 独立 ops-probe

独立 Go 二进制和 compose profile，默认不启动。

职责：

- 检查 Web、live、ready；
- 保存连续失败、恢复和冷却；
- 使用小数据卷原子保存当前 incident；
- API 可用时用共享密钥上报 heartbeat；
- API 不可用时仍可直接发送 Webhook；
- 恢复后补报完整故障区间。

数据映射固定为：

- heartbeat 和组件状态写 `ops_component_metric_minutes`；
- 故障区间写 `ops_alert_incidents`，用 `source_external_id` 幂等；
- 通知尝试写 `ops_alert_deliveries`。

同机 probe 只能发现容器/API/Web 故障；要覆盖整机掉电，需在另一台机器部署同一二进制。

### 5.10 告警 evaluator 与 notifier

- evaluator 只读取预聚合运营数据；
- evaluator 只基于已经持久化且完整的时间窗；`partial/delayed` 窗口不创建新 incident；
- 同一 rule + target + fingerprint 维护一个 incident；
- 触发同时考虑数量、比率、最小样本和连续窗口；
- 恢复自动关闭；
- notifier 是独立有限队列，默认一个 Webhook；
- evaluator 先静默运行至少 7 天；
- notifier 失败不影响 API，也不递归创建业务告警。

### 5.11 后端模块边界

`api/internal/operations` 内部按职责拆分，禁止形成新的巨型 service：

| 模块 | 单一职责 |
| --- | --- |
| `config/runtime` | 配置值、生效值、生命周期和关闭态 |
| `httpmetrics` | request id、流量分类、固定直方图、分钟交换 |
| `interactions` | 事件协议、校验和高低优先级队列 |
| `writer/repository` | 单 writer、批写、幂等和采集自监控 |
| `facts` | 受限只读查询现有业务事实表 |
| `health` | PostgreSQL、MinIO 和缓存探测 |
| `aggregate/query` | 日/分钟聚合、查询水位和完整性 |
| `errors` | OPS-102 持久化后端5xx组；OPS-205按30天窗聚合浏览器错误并计算affected_users |
| `alerts/notifier` | incident 收敛、静默期、通知和恢复 |
| `retention` | 聚合成功后的分批清理 |
| `probe` | 独立探针状态、故障区间和恢复补报 |

模块之间只通过小接口和不可变 DTO 连接。HTTP handler 不直接扫描业务事实表，业务 handler 不依赖 operations 模块。

## 6. 数据模型

### 6.1 迁移原则

- 首个文件为 `026_operations_center.sql`；
- 不修改合并后的 017；
- 026 只新建运营表/索引，不给业务表加 trigger，不回填业务数据；
- 新表中的 user/team/department 快照不建立级联业务 FK，避免业务删除和运营保留期互相耦合；
- 026 一旦在共享环境执行即冻结，后续变化用 027+。

### 6.2 表职责

| 表 | 主键/唯一性 | 关键内容 | 默认保留 |
| --- | --- | --- | --- |
| `platform_interaction_events` | id；`client_event_id` unique；用户+action id 的 started/终态部分唯一 | 所有浏览器 page/action/frontend_error、组织快照、request id | 30 天 |
| `platform_user_first_seen` | user id unique | 首次有效 page view/action 日期；frontend_error 不写入 | 用户存在期间 |
| `platform_user_active_days` | activity date + user id unique | role、team/department 快照 | 400 天 |
| `platform_daily_usage_metrics` | date + dimension unique | DAU/WAU/MAU、PV、动作聚合；page/action 维度互斥 | 长期 |
| `ops_http_metric_minutes` | minute + route dimensions + instance unique；snapshot id 幂等 | 状态计数、sum/max、直方图桶 | 90 天 |
| `ops_component_metric_minutes` | minute + source + component/target + instance unique；snapshot 幂等 | health、queue 推断、collector 自监控 | 90 天 |
| `ops_error_events` | id | 后端 5xx 的受控 route/status/category/fingerprint；不重复存浏览器错误 | 30 天 |
| `ops_error_groups` | source + fingerprint unique | first/last/count/affected/recovery | 30 天滚动状态 |
| `ops_daily_metrics` | date + dimension unique | 每日可用性、错误、性能 | 长期 |
| `ops_alert_incidents` | id；open dedupe key；`source_external_id` 可空 unique | rule、target、status、first/last/recovered | 至少 1 年 |
| `ops_alert_deliveries` | id | channel、attempt、status、error category | 至少 1 年 |

### 6.3 字段级数据字典

本节是 `026_operations_center.sql` 的唯一 DDL 契约。除这里列出的字段、约束和索引外，OPS-001 不得自行增加业务 FK、自由 JSON、原文或高基数维度。所有时间列使用 `TIMESTAMPTZ`，日期使用 `DATE`，计数使用非负 `BIGINT`；`user_id BIGINT`、`team_id/department_id UUID` 只保存快照，不建立业务 FK。

#### 6.3.1 `platform_interaction_events`

| 字段 | 类型/空值 | 约束与说明 |
| --- | --- | --- |
| `id` | BIGSERIAL PK | 内部顺序键 |
| `client_event_id` | UUID NOT NULL | UNIQUE，覆盖三种浏览器事件 |
| `schema_version` | SMALLINT NOT NULL | CHECK = 1 |
| `kind` | TEXT NOT NULL | CHECK `page_view/action/frontend_error` |
| `occurred_at/received_at` | TIMESTAMPTZ NOT NULL | occurred 只接受 -24h 至 +5min |
| `user_id` | BIGINT NOT NULL | 服务端身份快照 |
| `role` | TEXT NOT NULL | 当前角色有限枚举 |
| `team_id/department_id` | UUID NULL | 服务端组织快照 |
| `page_key` | TEXT NULL | 需求文档 page registry |
| `action_key/action_id/phase` | TEXT/UUID/TEXT NULL | phase CHECK `started/success/failure` |
| `duration_ms` | BIGINT NULL | CHECK 0~86400000 |
| `error_category/error_name/fingerprint` | TEXT NULL | 受控枚举；name≤64；fingerprint 为 64 位小写 hex |
| `request_id` | TEXT NULL | ≤128，不存 URL |

行级 CHECK 固定三种 shape：page view 必须有 page_key 且无 action/error 字段；action 必须有 action_key/action_id/phase；frontend error 必须有 page_key/error_category/fingerprint 且无 action 字段。同一 `(user_id, action_id)` 分别建立 `phase='started'` 和 `phase IN ('success','failure')` 的部分唯一索引。

#### 6.3.2 `platform_user_first_seen`

| 字段 | 类型/空值 | 约束与说明 |
| --- | --- | --- |
| `user_id` | BIGINT PK | 无业务 FK |
| `first_activity_date` | DATE NOT NULL | Asia/Shanghai |
| `first_occurred_at/first_received_at` | TIMESTAMPTZ NOT NULL | 只由有效 page/action 写入 |
| `role/team_id/department_id` | TEXT/UUID/UUID NULL | 首次活跃快照，role NOT NULL |

frontend_error 不得创建或更新本表。

#### 6.3.3 `platform_user_active_days`

| 字段 | 类型/空值 | 约束与说明 |
| --- | --- | --- |
| `activity_date/user_id` | DATE/BIGINT NOT NULL | 复合 PK，每日每用户一条 |
| `first_occurred_at` | TIMESTAMPTZ NOT NULL | 当日首次有效 page/action |
| `role/team_id/department_id` | TEXT/UUID/UUID NULL | 当日首次有效事件快照，role NOT NULL |
| `has_page_view/has_action` | BOOLEAN NOT NULL | 默认 false，至少一个必须 true |

本表不保存 page_key/action_key，不能用于长期个人页面轨迹；精确跨日页面 UV/动作人数限制为 30 天。

#### 6.3.4 `platform_daily_usage_metrics`

| 字段组 | 类型/空值 | 约束与说明 |
| --- | --- | --- |
| `metric_date` | DATE NOT NULL | 聚合日期 |
| `organization_type/key/label` | TEXT/TEXT/TEXT | type CHECK `all/role/team/department`；all 的 key 固定空串 |
| `content_type/key` | TEXT/TEXT | type CHECK `all/page/action`；page/action 互斥，all key 固定空串 |
| `dau/wau/mau/pv/new_active_users` | BIGINT NOT NULL DEFAULT 0 | 仅适用维度写非零 |
| `active_teams/active_departments` | BIGINT NOT NULL DEFAULT 0 | 非负 |
| `daily_unique_users` | BIGINT NOT NULL DEFAULT 0 | 仅表示单日精确人数，不可跨日相加 |
| `action_started/success/failure/incomplete` | BIGINT NOT NULL DEFAULT 0 | content_type=action 时使用 |
| `generated_at/data_through` | TIMESTAMPTZ NOT NULL | 聚合水位 |
| `completeness/note_category` | TEXT/TEXT NULL | completeness 四态；note 只能有限类别 |

UNIQUE `(metric_date, organization_type, organization_key, content_type, content_key)`；只生成“一个组织维度 × all/page/action”，不生成 role×team×department 的笛卡尔积。

#### 6.3.5 `ops_http_metric_minutes`

| 字段组 | 类型/空值 | 约束与说明 |
| --- | --- | --- |
| `id` | BIGSERIAL PK | - |
| `bucket_minute/observed_at` | TIMESTAMPTZ NOT NULL | minute 必须整分钟 |

### 6.4 必要索引

- 原始交互：清理索引 `(occurred_at,id)`；用户日聚合 `(user_id,occurred_at)`；精确去重部分索引 `(occurred_at,page_key,user_id) WHERE kind='page_view'`、`(occurred_at,action_key,user_id) WHERE kind='action'`；前端分组索引 `(occurred_at,fingerprint,user_id) WHERE kind='frontend_error'`；
- active days：`activity_date`、组织快照可查询字段；
- daily usage：`metric_date + organization_type/key + content_type/key`；
- HTTP 分钟指标：`bucket_minute + traffic_class`、`method + route_template + bucket_minute`；
- errors：`ops_error_events(fingerprint,first_seen_at)`、`ops_error_events(route_template,first_seen_at)`、`ops_error_groups(source,last_seen_at)`、`ops_error_groups(status,last_seen_at)`；
- incidents：`status + severity + last_seen_at`；
- 所有清理索引都以时间列为前缀，避免大批量全表扫描。

索引必须在独立测试库用预估数据量验证，不得因为查询方便给现有业务表随意加索引。

### 7.2 capability 生效值

```text
enabled             = ENABLED
production_enabled  = admin && UI effective && METRICS effective && PERSIST effective
usage_enabled       = admin && UI effective && INTERACTIONS effective && PERSIST effective
can_view            = admin && UI effective && (production_enabled || usage_enabled)
events_accepting    = ENABLED && INTERACTIONS effective && PERSIST effective
brief_enabled       = usage_enabled && production_enabled && brief provider ready
```

`brief provider ready` 是 `OPS-303` 注册的内部能力，不是环境变量；此前或任一页签未生效时返回 false，V1 不生成部分简报。

### 7.3 查询通用契约

所有管理员 JSON 查询使用顶层公共字段，不增加全局 `data` envelope：

```json
{
  "generated_at": "2026-07-15T08:30:00Z",
  "data_through": "2026-07-15T08:29:00Z",
  "completeness": "normal",
  "completeness_note": null
}
```

固定规则：

- 时间戳为 RFC3339 UTC，业务日期为 `YYYY-MM-DD`，日界按 `Asia/Shanghai`；
- `*_ms` 为非负整数毫秒；计数为非负整数；比率为 `0~1` 数值，分母为 0 时返回 `null`；
- 分位数样本不足时 `sample_sufficient=false` 且对应 `p50_ms/p95_ms/p99_ms=null`；
- `completeness` 仅为 `normal/delayed/partial/disabled`；
- 页码从 1 开始，默认 20，最大 100；分页响应固定包含 `page/page_size/total/items`；
- `completeness_note`、`affected_users`、`recovered_at`、`sample_request_id` 等不可可靠取得的字段返回 `null`，不能伪造 0 或空字符串；
- 正常但无数据返回 200 和空数组，不返回 404；
- 默认排序必须稳定，第二排序键固定使用业务 key 或 id，避免翻页漂移。

统一错误码：

| 状态码 | 场景 |
| --- | --- |
| `400` | 日期/窗口/枚举/分页/组合参数非法 |
| `401` | 未认证 |
| `403` | 已认证但非 admin |
| `404` | 对应 capability/brief provider 未生效，或指定 detail key 不存在 |
| `503` | capability 已生效但 provider 暂时不可用且没有可返回的旧数据 |

如果仍有上次成功数据，provider 暂时失败优先返回 200 + `partial/delayed`，让前端保留旧数据；只有完全没有可用数据才返回 503。

### 7.6 probe heartbeat 契约

请求使用 `Authorization: Bearer <OPERATIONS_PROBE_SHARED_SECRET>`，handler 以常量时间比较；不得接受 query/body 中的 secret，日志必须脱敏 Authorization。请求体上限 16 KB：

```json
{
  "schema_version": 1,
  "probe_id": "host-a",
  "heartbeat_id": "uuid",
  "observed_at": "RFC3339",
  "checks": [
    {
      "target": "web|api_live|api_ready",
      "status": "normal|degraded|error",
      "latency_ms": 12,
      "http_status": 200,
      "error_category": null
    }
  ],
  "transition": {
    "source_external_id": "uuid",
    "target": "api_ready",
    "phase": "started|recovered",
    "started_at": "RFC3339",
    "recovered_at": null
  },
  "deliveries": [
    {
      "delivery_id": "uuid",
      "source_external_id": "uuid",
      "event_type": "triggered|recovered",
      "attempt_no": 1,
      "attempted_at": "RFC3339",
      "status": "sent|failed",
      "error_category": null
    }
  ]
}
```

校验规则：

- `probe_id` 匹配 `[a-z0-9][a-z0-9._-]{0,63}`；heartbeat_id 为 UUID；
- checks 为 1~3 条，同一 target 只能一条；latency 0~600000 ms；http_status 可空或 100~599；
- error_category 仅 `timeout/dns/connection/http/unknown`，normal 时必须为空；
- transition 可省略；started 阶段 recovered_at 必须为空，recovered 阶段必须给出完整 `[started_at,recovered_at]`，且 started<=recovered<=observed_at；
- OPS-105 阶段 `deliveries` 必须为空或省略；OPS-302 后最多 20 条，只补报 probe 自己直接通知的脱敏尝试；
- 同一 source_external_id 的 started/recovered 更新同一 incident，同一 delivery_id 只写一次；
- 不接受 endpoint URL、响应正文、错误 message/stack 或 Webhook 地址。

响应：

| 场景 | 状态码 | 行为 |
| --- | --- | --- |
| secret 缺失或错误 | `401` | 空泛错误，不泄露配置 |
| schema/枚举/时间/组合非法 | `400` | 整请求拒绝 |
| 超过 16 KB | `413` | 不解析 |
| probe 或 persist 未生效 | `204` | probe 保留本地状态，稍后重试 |
| 内部高优先级队列满 | `429` | 不部分接收，probe 稍后重试 |
| 接受 heartbeat/transition/deliveries | `202` | `{"accepted":true}`；最终幂等由 snapshot/external/delivery id 保证 |

heartbeat checks 写 component minutes；transition 写 incidents；OPS-302 后 deliveries 写 alert deliveries。API 不可达时 probe 不调用其他 API，而是继续本地保存并按开关直接通知；恢复后通过同一契约补报。

直接访问 `/operations` 仍需前端 capability 校验；菜单隐藏不是权限控制，所有管理员查询接口继续由后端 `AdminOnly` 决定。

## 8. 开关状态机

环境变量固定为九个且默认 false：`OPERATIONS_ENABLED`、`OPERATIONS_METRICS_ENABLED`、`OPERATIONS_PERSIST_ENABLED`、`OPERATIONS_UI_ENABLED`、`OPERATIONS_INTERACTIONS_ENABLED`、`OPERATIONS_ALERTS_ENABLED`、`OPERATIONS_WEBHOOK_ENABLED`、`OPERATIONS_PROBE_ENABLED`、`OPERATIONS_PROBE_NOTIFY_ENABLED`。

| 条件 | 生效行为 |
| --- | --- |
| master false | 子能力全部 false，不创建运营连接或 goroutine |
| metrics true, persist false | 只做内存 shadow，不写库、不开放 production |
| interactions true, persist false | events 返回 204，不接受数据 |
| persist true，metrics/interactions 都 false | persist 降为 false |
| UI true | 只有 persist 生效后可生效；页签再由 metrics/interactions 决定 |
| alerts true | 需要 metrics + persist |
| webhook true | 只开放 transport；告警通知还需 alerts |
| probe true | master 开启后才启动；persist false 时 heartbeat 返回 204 |
| probe notify true | 需要 probe + webhook，不依赖 evaluator |

非法组合只记录一次告警并降级，不 `log.Fatal`。运营连接失败只降级 persist/UI/alerts，业务 API 继续启动。

## 9. 查询与聚合

- 可用率 = 成功探测次数 / 计划探测次数，缺失探测不从分母剔除；
- 业务 API 成功率 = 非 5xx 有效业务请求数 / 有效业务请求数；有效分母只含 `web_api/cli_session_sync/mcp`，排除 `health_probe/operations/unmatched`，4xx 单独展示；
- usage overview 默认查询 daily/active-day/first-seen；仅当范围≤30天时，为页面UV/人均访问和动作人数执行受限 `COUNT(DISTINCT user_id)` 查询 `platform_interaction_events`，使用独立运营连接、专用复合索引、2秒 statement timeout；
- production overview 只查询分钟/日聚合和 incident；
- 页面列表/动作/组织维度通过预聚合表返回；
- 生产 1h/6h/24h/7d 使用分钟指标，长期简报使用日聚合；
- 查询必须有最大时间范围、page size 和 context timeout；
- CSV 只读取聚合结果，限制 366 天，使用流式输出但保持 ResponseWriter 兼容；
- raw event 表没有管理员查询 API。
- 日聚合、告警、简报和清理任务使用 PostgreSQL advisory lock，避免未来多实例重复执行；
- 后端 5xx 的 `affected_users` 允许为空；只对前端异常计算受影响用户，不为此重构认证中间件。
- 每日简报只读取完成的日聚合，并在次日 02:00 前生成；失败时标记 delayed，不能用不完整数据覆盖前一次成功结果。

组件状态统一为：

| 状态 | 判定 |
| --- | --- |
| 正常 | 最近探测成功，且无达到阈值的依赖、性能或积压问题 |
| 降级 | 服务仍可用，但依赖、性能或积压达到警告阈值 |
| 异常 | 连续探测失败或达到严重阈值；队列存在 dead 时队列推断为 error |
| 未知 | 超过两个探测周期无有效数据，或受限事实快照超时 |
| 未配置 | API 值 `not_configured`，只用于未配置的可选 Managed Agent，不参与异常数量 |

## 10. 故障隔离

| 故障 | 运营行为 | 业务行为 |
| --- | --- | --- |
| 运营 DB handle 创建失败 | persist/UI/alerts 降级，完整性 disabled/partial | API 正常启动 |
| flush 失败 | 有限内存重试、计数、达到上限丢弃 | 请求不等待 |
| 队列满 | 低优先级先被拒绝；整批 429 | 业务请求不变 |
| aggregator 超时 | 保留旧聚合并标记 delayed | 业务不变 |
| Webhook 超时 | notifier 有限重试 | 业务不变 |
| probe 无心跳 | UI 显示 unknown | API readiness 不受影响 |
| PostgreSQL 不可用 | ready 失败，外部 probe 告警 | live 仍可响应 |
| MinIO 不可用 | ready 失败，外部 probe 告警 | live 仍可响应 |
| Managed Agent 不可用 | degraded | ready 不失败 |
| API 重启 | 未 flush telemetry 可丢失并标记 best-effort | 业务按现有启动流程恢复 |

## 11. 部署拓扑

V1 默认仍为单 API 实例：

```text
web ──> api ──> postgres/minio
          └── operations goroutines（flags 控制）

ops-probe（compose profile，默认关闭）
  ├──> web/api/ready
  └──> webhook
```

生产开启顺序固定为：

```text
METRICS → PERSIST → PROBE（仅记录）→ UI → INTERACTIONS
→ ALERTS（至少 7 天静默）→ WEBHOOK / PROBE_NOTIFY
```

多实例时：

- 每条分钟指标携带 instance id；
- 直方图桶可跨实例合并；
- 事件 id 保持全局唯一；
- alert evaluator 需要 leader/DB lock；
- 只有达到多实例需求时才实施，不属于 V1。

## 12. 架构决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 指标方案 | 内存固定桶 + PostgreSQL 批写 | 当前单实例轻量、无需新平台 |
| 交互可靠性 | best-effort 内存队列 | 优先保护业务延迟，不作为结算审计 |
| 错误详情 | 指纹、类别、request id | 避免敏感信息和日志平台范围膨胀 |
| worker 监控 | 只读现有事实表 | 不复制任务、不改状态机 |
| 可用性 | 独立 probe | API 宕机时仍可通知 |
| 前端埋点 | 显式 trackAction | 避免全局 MutationCache 横向影响 |
| UI | 一个路由两个页签 | 产品形态简单，符合现有路由体系 |
| 图表 | 复用 ECharts | 已有依赖，不新增技术栈 |

## 13. 架构验收

- 需求文档每项 P0 都能映射到组件、表、API 和测试；
- 所有开关组合有唯一生效语义；
- 没有同步运营 SQL、无界队列、高基数维度或 raw event 查询 API；
- 运营数据库、Webhook、probe 故障不改变业务结果；
- 迁移只新增独立表，未触碰 017 或业务表；
- 当前 worker 只读聚合，不改变其调度、重试、租约和返回值；
- V1 只承诺队列推断状态，不承诺 worker 循环心跳或最后循环成功时间；
- 两个页签默认只读预聚合数据；唯一原始查询例外是≤30天页面UV/动作人数，且只读运营事件表、走专用索引和2秒timeout；
- 所有隐私禁止字段在 API schema 和测试中都有拒绝用例。
