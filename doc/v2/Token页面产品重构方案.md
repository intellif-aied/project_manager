# Token 页面产品重构方案

## 1. 背景与目标

本方案根据 `archive/会议纪要.md` 重新定义 Token 页面。Token 不是管理目标本身，而是判断 AI 工具是否真正落地的辅助证据。

页面需要优先回答：

1. 当前范围内有多少成员实际使用 AI 工具；
2. 哪些成员使用充分，哪些成员低用量或零用量；
3. 使用量在人员、小组、模型和时间维度如何分布；
4. 管理者需要核实时，哪些 Session 可以作为明细证据。

## 2. 页面职责

### 2.1 我的 Token

面向所有角色，仅展示当前用户数据，用于了解个人使用趋势并定位高消耗 Session。

信息顺序：

1. 统计范围和日期；
2. 总 Token、活跃天数、Session 数、API 等价成本；
3. 输入、缓存、输出 Token 构成；
4. Token 趋势和模型构成；
5. Session 明细与搜索。

### 2.2 团队 AI 使用分析

面向小组长、总监和管理员，用于判断管理范围内的 AI 使用情况。

信息顺序：

1. 统计范围和日期；
2. 总 Token、有使用成员、零用量成员、人均 Token、API 等价成本；
3. 高用量 Top 5、低用量与零用量成员；
4. 趋势和小组／人员／模型对比；
5. 当前维度完整排名；
6. 成员 Session 明细。

## 3. 关键交互

- 日期、部门和小组属于整页统计范围筛选。
- Session 关键词只筛选明细，不重算顶部概览、趋势和排名。
- 点击成员只筛选下方 Session，顶部分析保持不变。
- 被选成员在 Session 标题旁持续显示姓名，并提供清除入口。
- 小组／人员／模型切换同时更新分布图和完整排名，页面结构不发生跳变。
- 排名操作使用明确的“查看 Session”，不再把整行做成无提示点击区域。

## 4. 指标说明

- API 等价成本是按已发布模型价格和汇率计算的估算值，不代表订阅账单。
- 人均 Token 使用当前管理范围内的当前成员人数计算，包含零用量成员。
- 零用量表示成员在所选日期范围内没有已统计 Token，不直接等同于没有工作。
- 数据尚未追平或未完全计价时，页面必须展示影响数量，不能把缺失金额显示为 0。

## 5. 接口使用

本轮不调整后台，继续使用现有接口：

- `/token-analytics/summary`
- `/token-analytics/trends`
- `/token-analytics/rankings`
- `/token-analytics/sessions`

概览、趋势和排名复用概览快照。成员下钻或 Session 搜索通过独立 summary 请求建立绑定筛选条件的明细快照，避免改变上层分析状态。

## 6. 后续边界

当前接口可以完成前 5、低用量、零用量和组织维度对比。以下能力需要后续产品确认或后台支持，不在本轮伪造：

- 与每人每月订阅额度的真实利用率；
- 环比、同比和连续低活跃判断；
- 低用量阈值配置；
- 组织使用目标和自动提醒。
