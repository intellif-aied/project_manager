## 3. 设计分层

### A. 本期必须完成

- 配置、状态迁移与运行时管理接口；
- ready 来源发现、2 分钟防抖、单飞领取和 Run 终态衔接；
- 系统默认 Report Agent 的自动个人日报提交 Adapter；
- 已有日报判断和自动写回乐观保护；
- 多主机、团队 owner、开关、重复、刷新与竞态测试。

### B. 代码事实触发的必要保障

- 自动触发必须晚于 Catalog ready，否则默认来源会漏掉刚上传切片（F-02）；
- 自动写回必须区分 absent/replace 前置状态，否则当前 upsert 会覆盖用户日报（F-06）；
- 动态开关必须带 `enabled_since`，否则重新开启会补跑当天历史 ready 来源（F-03/F-08）。

### C. 后续增强

- 用户级开关、静默时间自定义和前端管理页；本期不实施、不阻塞。

## 4. 变更边界

## 9. 运行时配置接口

- 查询：`GET /api/v1/admin/runtime-config/auto-daily-report`
- 修改：`PUT /api/v1/admin/runtime-config/auto-daily-report`，JSON 为 `{"enabled": true}` 或 `{"enabled": false}`。
- 鉴权：沿用现有登录 Token 与 `AdminOnly`。
- 返回：当前开关、`enabled_since`、最近操作人/时间，以及固定静默时间 `quiet_period_seconds=120`。
- 每次 PUT 同时写入 `auto_daily_report_config_events`，供测试和生产审计。
