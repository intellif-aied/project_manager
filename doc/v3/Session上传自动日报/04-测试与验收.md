## 1. 测试原则

- 自动化先验证模块接口、数据库约束和写回原子门禁；
- 真实链路只在测试服启用功能并使用真实 Aida 客户端、真实 Session 和测试账号；
- 不启动或复用独立 worktree 的共享 Docker、端口和数据库；
- 构建或 HTTP 成功不能代替最终日报来源、owner 和内容验收。

## 4. 回归范围

- Session prepare/chunk/finalize、无新增和重复上传；
- `--team` 目录映射与 Session owner；
- 手工个人日报、定时个人日报、个人周报及组织报告；
- Report Source、Digest、Context、Report Run、MCP 写回；
- Token、成本和日期归属；
- 功能关闭时的全部现有行为。

## 5. 真实链路验收

测试服启用配置后，由用户在一台测试机器执行真实 `aida upload`：

1. 准备当天没有日报的测试账号；
2. 记录上传前日报、Run 和来源状态；
3. 上传一个具有新增内容的真实 Session；
4. 确认最后来源 ready 后 2 分钟内没有提前生成，静默到期后出现一条自动 Run；
5. 等待 Run 成功，确认日报 owner、日期、来源和正文；
6. 继续新增并上传，确认未编辑自动日报刷新；
7. 手工编辑并保存，再次上传新增内容，确认不再自动刷新；
8. 关闭开关后上传，确认不生成；重新开启后确认关闭期间来源不补跑；
9. 如需 `--team` 验收，使用至少两个映射成员，确认分别生成且上传者不串入。

保存：账号、Session/Generation/Slice ID、Catalog ready 时间、自动状态、Run ID、来源快照、日报 ID、开关审计与结果时间线。不得记录用户 Token。

启用前由管理员调用：

```http
PUT /api/v1/admin/runtime-config/auto-daily-report
Authorization: Bearer <admin-token>
Content-Type: application/json

{"enabled":true}
```

验收结束可用同一接口传 `{"enabled":false}` 关闭。不要将 Token 写入验收记录。
