# Session 上传自动日报需求文档

> 文档状态：已定稿
> 日期：2026-07-31
> 产品负责人：用户确认
> 适用范围：测试服先行，个人 Session 上传与 `--team` Session 上传

## 1. 背景

当前用户上传 Session 后，仍需进入日报页面手动启动个人日报。用户可能从多台主机上传，同一轮上传中的 Session 完成时间也不一致；`--team` 上传时，上传者还可能不是 Session 的实际所属成员。因此不能以单个 Session 完成或单台主机上传结束作为“当天来源完整”的判断。

## 2. 产品目标

1. 当用户当天的可用 Session 来源在一段时间内不再变化时，自动生成个人日报。
2. 多主机和 `--team` 上传按 Session 实际所属用户汇总，不重复、不串人。
3. 后续新增来源可自动刷新尚未被用户接管的自动日报。
4. 任何已有手写、手工生成、已编辑或已提交日报都不得被自动流程覆盖。
5. 生产运维可以不重启服务动态开启或关闭本功能。

## 3. 产品规则

### 3.1 来源变化与静默窗口

- 适用对象：`Asia/Shanghai` 当日具有可用个人报告 Session 来源的用户。
- 触发条件：当日来源集合新增或替换，并且已经可被报告来源选择。
- 产品行为：从最后一次来源变化起等待 2 分钟；期间再次变化则重新计时。静默到期后，只为该用户和当日创建一条自动个人日报 Run。
- 异常或缺失时行为：来源为空、来源仍不可用或来源集合未变化时不创建 Run。

### 3.2 多主机与团队上传

- 多台主机上传的数据按 `用户 + 报告日期` 聚合，主机和单次上传命令不形成日报边界。
- `--team` 模式按 Session 在服务端解析后的实际 `owner_user_id` 归组，不按上传操作者归组。
- 同一用户同一天同时只能有一条本功能创建的活动 Run。

### 3.3 已有日报与自动刷新

- 当天没有日报时，允许自动生成。
- 当天日报由本功能自动生成、尚未被用户编辑且尚未提交时，后续新增来源允许自动刷新。
- 当天存在手写日报、手工生成日报、其他触发方式生成的日报、已编辑日报或已提交日报时，不执行本功能且不覆盖原内容。
- 自动 Run 执行期间用户保存、编辑或提交了日报时，本次自动写回必须取消。
- 自动 Run 执行期间又出现新来源时，当前 Run 使用已冻结来源完成；完成后静默窗口满足时最多补一轮刷新。

### 3.4 运行时开关

- 配置项：`auto_daily_report_after_upload_enabled`。
- 默认值：关闭。
- 开启后只处理开启时间之后发生的新来源变化，不补跑关闭期间或开启前的历史来源。
- 关闭后不再领取新的自动生成任务；已经创建的 Report Run 继续按现有链路完成。
- 关闭期间积累的来源在重新开启后不补跑；重新开启后只处理新的来源变化。
- 开关变更必须记录操作人、变更时间和当前值，并在运行中生效，无需重启服务。

### 3.5 失败行为

- 自动生成失败不得改变 Session 上传结果，也不得回退或删除 Session 来源。
- 同一来源集合失败后不自动无限重试；新的来源变化可以再次触发。
- Digest 等待、Report Context 构建、Agent 提交和写回继续使用现有 Report Run 的状态、重试和完整性门禁。

## 4. 用户流程

```text
用户在一台或多台主机上传 Session
  -> 服务端来源陆续可用
  -> 最后一次来源变化后静默 2 分钟
  -> 当天无受保护日报时自动生成
  -> 用户可在现有日报页面查看、编辑或提交
  -> 用户一旦编辑或提交，后续自动刷新停止
```

功能关闭时，上传与现有手工/定时报告行为保持不变。

## 5. 验收标准

| 编号 | 产品规则 | 可观察结果 |
|---|---|---|
| R-01 | 3.1 | 连续上传多个 Session 时只在最后一次来源变化 2 分钟后创建一条自动 Run |
| R-02 | 3.2 | 两台主机为同一用户上传后生成一份汇总日报 |
| R-03 | 3.2 | `--team` 上传分别为实际成员生成个人日报，不为上传者生成混合日报 |
| R-04 | 3.3 | 自动生成且未编辑的日报可随新来源刷新 |
| R-05 | 3.3 | 手写、手工生成、已编辑或已提交日报均不被启动或覆盖 |
| R-06 | 3.3 | 自动 Run 期间发生用户写入时，自动写回被拒绝 |
| R-07 | 3.4 | 开关运行时开启/关闭生效，关闭与重新开启均不补跑历史来源 |
| R-08 | 3.5 | 自动生成失败不影响 Session 上传成功状态和现有来源 |

## 6. 非目标

- 不修改 Aida 客户端或 Session 上传协议。
- 不根据单个 Session `done` 时间判断整批完成。
- 不新增用户级开关、静默时间自定义或前端管理页面。
- 不自动生成个人周报、小组报告或部门报告。
- 不修改手工报告、既有定时报告、Digest、Token 和成本统计口径。
- 不在本阶段自动发布生产。
