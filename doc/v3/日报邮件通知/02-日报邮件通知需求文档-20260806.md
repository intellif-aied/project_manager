# 日报邮件通知需求文档：每日个人日报与 TL 小组汇总

> 文档状态：已定稿
> 日期：2026-08-06
> 产品负责人：待补充
> 适用范围：Aida 日报邮件通知第一期

## 1. 背景

公司已申请群发邮箱。当前 Aida 已保存个人日报，但没有每天通过企业邮箱主动送达日报的能力，TL 也不能通过邮件一次查看本组成员的日报汇总。

## 2. 产品目标

1. 每天北京时间 08:00，将前一自然日的个人日报发送给对应成员。
2. 每天北京时间 08:00，将前一自然日本组每位成员的日报汇总表发送给 TL。
3. 单个收件人缺少邮箱、缺少日报或发送失败时，不阻断其他收件人的邮件，并保留可核对结果。

## 3. 产品规则

### 3.1 个人日报邮件

- **产品规则**：适用对象为状态正常、已配置可信企业收件邮箱的 Aida 用户。
- **产品规则**：每天 08:00（Asia/Shanghai）发送前一自然日的个人日报。
- **产品规则**：邮件正文使用该日期日报的当前正文；没有日报时不发送个人邮件，并记录“缺少日报”。
- **产品规则**：TL 作为普通用户时，也接收自己的个人日报邮件。

### 3.2 TL 小组汇总邮件

- **产品规则**：适用对象为状态正常、已配置可信企业收件邮箱且角色为 TL 的用户。
- **产品规则**：TL 接收其所属小组前一自然日的成员日报汇总表。
- **产品规则**：汇总表列出成员姓名、日报状态和日报正文；缺少日报的成员仍保留一行并标记“缺少日报”。
- **必要推导**：同一 TL 同时收到自己的个人日报和一封小组汇总邮件，否则无法同时满足“所有人个人日报”和“TL 小组汇总”。

### 3.3 收件人与失败处理

- **产品规则**：仅使用经过企业通讯录匹配确认的邮箱，不把 AIHub 注册邮箱自动视为可信收件邮箱。
- **产品规则**：同一“日期 + 邮件类型 + 收件人”成功投递后不得重复发送。
- **产品规则**：失败邮件最多自动重试 3 次；其他邮件继续发送。
- **产品规则**：本期每天都执行，包括周末。

## 4. 用户流程

1. 管理员先通过企业通讯录匹配流程维护可信收件邮箱。
2. 系统每天 08:00 自动读取前一自然日的日报。
3. 系统分别发送个人日报邮件和 TL 小组汇总邮件。
4. 管理员通过投递记录核对成功、失败、缺少邮箱和缺少日报结果。

## 5. 验收标准

| 编号 | 产品规则 | 可观察结果 |
|---|---|---|
| R-01 | 3.1 | 08:00 后，符合条件的成员收到自己前一日的日报 |
| R-02 | 3.2 | TL 收到本组所有正常成员的一张日报汇总表 |
| R-03 | 3.2 | 没有日报的成员在 TL 汇总表中显示为“缺少日报” |
| R-04 | 3.3 | 一个收件人失败不影响其他收件人，且结果可追踪 |
| R-05 | 3.3 | 已成功投递的同一封业务邮件不会重复发送 |
| R-06 | 3.3 | 未经企业通讯录确认的邮箱不会收到邮件 |

## 6. 非目标

- 本期不发送部门日报、个人周报或团队周报。
- 本期不提供用户自定义发送时间、邮件模板或退订设置。
- 本期不导入生产通讯录、不配置生产 SMTP、不执行生产发布。
- 本期不新增前端管理页面。
