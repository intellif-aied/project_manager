## 1. 测试原则

- 必须使用真实测试账号和测试服默认 Report Agent 验证两种身份；
- 模型额度归属和 MCP 数据归属分别取证；
- 构建成功不能代替真实报告链路验收；
- 仅验证本方案范围，不扩展为全量平台审计。

## 3. 架构风险验证

| 用例 | 架构决策 | 风险 | 验证方法 | 通过条件 |
|---|---|---|---|---|
| AR-01 | A-01 | 用户额度被误用 | 核对平台 Session 和模型用量归属 | owner 为 `100866`，无用户模型 override |
| AR-01A | A-01A | 默认模型被用户覆盖 | 核对请求和平台 Session | 模型固定为 `deepseek-v4-flash` |
| AR-02 | A-02 | 系统 Token 进入 MCP | 核对 Credential audit、Aida run user 和 MCP 结果 | Credential 对应实际 AIDA 用户 |
| AR-03 | A-02 | 跨用户数据泄露 | 两用户交叉生成与读取 | 任一用户不能读取或写入另一用户报告 |
| AR-04 | A-03 | 仅隐藏菜单但直达页仍开放 | 访问所有旧前端路由 | 前端不可进入个人 Skill/MCP 管理功能 |

## 4. 回归范围

- 个人、小组、部门日报与周报生成；
- Session 来源选择、默认来源冻结和 Digest/Context；
- 报告写回、失败写回和通知跳转；
- 组织角色权限；
- 普通 Agent、手动运行、定时任务；
- 已有个人 Skill/MCP 数据和后端接口保持存在。

## 5. 真实链路验收

测试服使用系统 owner `100866`。至少选择两个具有不同业务数据的 AIDA 用户，各生成一次个人报告；再使用一个 TL 或总监账号生成一次汇总报告。保存以下证据：Aida run ID、平台 Session ID、Agent owner、模型额度归属用户、MCP Credential 对应的 Aida user ID、最终报告 ID。证据不得包含明文 Token。

生产发布只验证 owner 切换为 `10086`，不得复用测试 owner 或测试资产版本。

## 6. 发布门禁

- T-01～T-07 和 AR-01～AR-04 全部通过；
- 未出现跨用户数据访问；
- 模型额度未落到个人用户；
- 默认报告模型均为 `deepseek-v4-flash`；
- 无报告链路和其他 Agent 回归；
- 无方案外代码、migration、服务或协议变更。
