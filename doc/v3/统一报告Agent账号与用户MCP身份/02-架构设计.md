## 4. 最小目标架构

```text
环境专用账号（测试 100866 / 生产 10086）
  ├─ 持有默认 Report Agent、系统 Report Skill、系统 Report MCP
  └─ 创建报告 Credential 与 Session，默认模型 deepseek-v4-flash

当前 AIDA 用户
  ├─ 创建属于自己的 Aida Report Run
  └─ 用户 Token 仅作为 AIDA_REPORT_MCP_AUTH Credential 的值
       └─ Report MCP 按现有权限读取来源并写回报告
```

复用当前 `ReportRunSubmitter` 作为身份编排入口：平台资产、Credential 容器和 Session 均由专用账号客户端创建；Credential 内保存的 Report MCP 授权值仍由每次 run 的当前 AIDA 用户签发。`share_model_access` 继续开启作为 Agent 资产声明，但正确性不依赖共享 Token 的降级行为。

## 6. 数据流与失败边界

1. Aida 以当前用户创建 Report Run；
2. Aida 使用专用平台账号创建包含当前用户 Token 值的 Report MCP Credential；
3. Aida 使用同一专用平台账号创建 Session，并固定请求 `deepseek-v4-flash`；
4. Agent 调 MCP 时使用用户 Credential；
5. MCP 按现有 run/user 校验读取和写回；
6. 模型额度失败属于 Agent 平台执行失败；MCP 身份或权限失败属于现有 MCP/报告运行失败，不相互降级。

## 7. 安全、容量与兼容性

- 系统账号 Token 只用于平台模型额度和系统资产管理；
- 用户 Token 只通过现有 write-only Credential 流程进入 MCP 槽；
- 禁止在日志、运行输入和错误正文中输出任一 Token；
- 不允许模型失败时回退到用户额度；
- 不允许 MCP 失败时改用系统账号；
- 旧报告、旧 run、已有个人资产和其他 Agent 行为保持兼容。
