# V3 需求文档：统一报告 Agent 账号与用户 MCP 身份

> 文档状态：已定稿
> 日期：2026-07-27
> 适用范围：默认 Report Agent 生成的个人、小组、部门日报与周报

## 1. 背景

当前报告生成同时涉及模型额度和业务数据访问。两者必须使用不同身份：模型额度由统一账号承担，报告数据仍按实际 AIDA 用户权限读取和写回。与此同时，个人 Skill/MCP 管理暂不面向 Aida 用户开放。

## 2. 产品目标

1. 所有默认报告 Agent 的模型调用统一计入环境专用账号；
2. Report MCP 只能以当前 AIDA 用户身份访问业务数据；
3. 前端不再向用户展示“我的 Skill”“我的 MCP”功能；
4. 除上述三项外，其他业务行为保持不变。

## 3. 产品规则

### 3.1 模型额度统一

- 适用对象：Aida 默认 Report Agent 的所有运行用户；
- 触发条件：用户生成个人、小组或部门日报/周报；
- 产品行为：模型调用使用环境专用账号额度；测试服账号为 `100866`，生产服账号为 `10086`；
- 默认模型：默认 Report Agent 固定使用 `deepseek-v4-flash`，运行用户不得覆盖为个人模型；
- 异常行为：专用账号模型访问不可用时，本次报告生成失败并返回现有 Agent 平台错误，不自动改用用户个人额度。

### 3.2 MCP 使用当前用户身份

- 适用对象：所有 Report MCP 读取和写回操作；
- 触发条件：默认 Report Agent 调用 Report MCP；
- 产品行为：`AIDA_REPORT_MCP_AUTH` 绑定发起本次报告运行的当前 AIDA 用户 Token；
- 权限行为：个人、小组、部门数据范围继续由现有 Aida 权限规则决定；
- 禁止行为：系统账号 Token 不得用于读取或写入用户报告数据。

### 3.3 系统资产账号

- 默认 Report Agent、系统 Report Skill 和系统 Report MCP 使用同一环境专用账号维护；
- 测试服 owner 为 `100866`，生产服 owner 为 `10086`；
- “系统资产归属”不等于“MCP 数据访问身份”。

### 3.4 前端屏蔽个人 Skill/MCP

- Aida 前端隐藏个人 Skill/MCP 的列表、创建和管理入口；
- 旧前端直达地址不得继续展示对应管理页面；
- 后端接口、平台资产和历史数据暂时保留，不删除、不迁移；
- 其他 AI 资产能力不因本规则改变。

## 4. 用户流程

1. 用户在原有报告入口选择生成日报或周报；
2. Aida 创建属于该用户的报告运行；
3. 默认 Report Agent 使用专用账号的模型额度执行；
4. Agent 调用 Report MCP 时使用当前 AIDA 用户 Token；
5. MCP 按原权限读取来源并写回该用户对应的报告；
6. 用户在原页面查看生成结果。

## 5. 验收标准

| 编号 | 产品规则 | 可观察结果 |
|---|---|---|
| R-01 | 3.1 | 不同用户生成报告时，模型用量均归属对应环境专用账号 |
| R-01A | 3.1 | 默认 Report Agent 的实际运行模型为 `deepseek-v4-flash` |
| R-02 | 3.2 | MCP 读取和写回仍归属于实际发起报告的 AIDA 用户 |
| R-03 | 3.2 | 两个用户生成报告时互不可见、不可写入对方数据 |
| R-04 | 3.4 | 前端看不到且不能通过旧直达地址进入个人 Skill/MCP 管理页 |
| R-05 | 2.4 | 日报、周报、Session 来源、Digest、组织权限及其他 Agent 业务无行为回归 |

## 6. 非目标

- 不修改日报、周报数据结构和业务规则；
- 不修改 Session 选择、来源冻结、Digest、Report Context 和报告写回协议；
- 不修改组织、角色和报告权限；
- 不删除或迁移个人 Skill/MCP 数据；
- 不改变普通 Agent、手动运行、定时任务和其他 AI 业务的模型身份；
- 不允许用户选择改用个人模型额度；
- 不调整其他 Agent 的默认模型；
- 不进行无关数据库迁移、模块重构或 UI 改版。

## 7. 产品待确认

无。三个核心目标和严格非目标已确认。
