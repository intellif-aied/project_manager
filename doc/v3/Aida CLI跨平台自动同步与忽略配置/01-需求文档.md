# Aida CLI 跨平台自动同步与忽略配置需求文档

> 文档状态：已定稿
> 日期：2026-08-04  
> 产品负责人：待指定  
> 适用范围：Aida CLI（`daemon/`）的本地 Session 上传

## 1. 背景

【已验证代码事实】当前 `aida auto-sync` 的调度判断、失败退避和上传入口位于 CLI；Linux 有后台运行实现，而 macOS 和 Windows 构建会返回“不支持自动同步”。证据：`daemon/auto_sync.go:351`、`daemon/auto_sync_supervisor_linux.go:27`、`daemon/auto_sync_supervisor_unsupported.go:11`。

【产品规则】用户需要在 Windows、Intel Mac 和 Apple Silicon Mac 上获得与 Linux 同等的自动定时上传能力；并能在本机选择 Session 或工作文件夹，将其排除在后续上传之外。

【产品反馈，待复现】有 Apple Silicon（M5）Mac 用户反馈执行 `aida update` 后被提示需要新开会话。该反馈的原始终端输出、安装路径和更新前后版本尚未取得，不能据此判定根因。

## 2. 产品目标

1. 【产品规则】已登录用户可在 Linux、Windows、Intel Mac、Apple Silicon Mac 开启、查询、修改时间和关闭每日自动 Session 上传。
2. 【产品规则】用户可通过 CLI 的交互式列表选择一个或多个 Session 加入忽略列表。
3. 【产品规则】用户可通过 CLI 的交互式列表选择一个或多个工作文件夹加入忽略列表。
4. 【必要推导】忽略规则若仅在手动选择时生效，`upload --all` 和自动同步仍会上传用户明确排除的内容，无法满足目标 2、3；因此所有本地上传入口都必须应用忽略规则。
5. 【产品规则】在受支持的 macOS 架构上，`aida update` 成功后不得要求用户新开终端会话或新建 AI Session 才能继续使用已更新的 Aida。

## 3. 产品规则

### 3.1 跨平台自动定时上传

- 适用对象：已完成 Aida 登录的本机用户。
- 触发条件：用户执行 `aida auto-sync enable`，并完成现有时间选择。
- 产品行为：CLI 在当前操作系统注册可持续运行的用户级调度；到达已设置的每日时间时，自动上传该用户未忽略的本地 Session。
- 一致性：自动同步继续使用当前的北京时间显示和每日成功、失败重试语义；具体的系统调度器实现不是产品规则。
- 异常或缺失时行为：平台调度不可注册、不可启动或已失效时，`enable`/`status` 必须给出可理解的失败或异常状态，不能显示“已开启”。

### 3.2 忽略单个 Session

- 适用对象：CLI 当前可发现并展示的本地 Session。
- 触发条件：用户在 `aida ignore` 的 Session 选择列表中确认选择。
- 产品行为：所选 Session 不出现在后续可上传列表中，且不会由 `upload --all`、手动上传或自动同步上传。
- 异常或缺失时行为：本地已不存在的 Session 忽略项保留，不影响其他 Session；用户可以在忽略列表中移除它。

### 3.3 忽略工作文件夹

- 适用对象：可从本地 Session 解析出的工作目录。
- 触发条件：用户在 `aida ignore` 的文件夹选择列表中确认选择。
- 产品行为：该目录及其子目录中产生的 Session 不出现在后续可上传列表中，且不会由任何上传入口上传。
- 异常或缺失时行为：目录移动、删除或不可访问时，规则仍保留；不会因路径解析失败误匹配其他目录。

### 3.4 忽略规则的本地边界

- 【产品规则】忽略配置仅控制未来的本机上传选择；不删除本地 Session 文件，不删除或修改服务端既有上传数据。
- 【产品规则】忽略配置与登录凭据分离保存，且不包含用户令牌。

### 3.5 macOS 手动更新连续性

- 适用对象：Intel Mac 和 Apple Silicon Mac 的已安装 Aida CLI。
- 触发条件：用户执行 `aida update`。
- 产品行为：更新成功后，CLI 明确显示更新后的版本或可验证的完成结果；用户可在同一终端直接运行下一条 Aida 命令。
- 异常或缺失时行为：更新失败、当前 shell 指向非更新文件或存在多个 Aida 二进制时，CLI 必须给出可执行的诊断，不能用“新开会话”掩盖问题。

## 4. 用户流程

1. 用户执行 `aida auto-sync enable`，选择每日时间；CLI 注册当前系统的用户级后台调度并显示启用结果。
2. 用户执行 `aida ignore`，选择“忽略 Session”或“忽略文件夹”；在与 Session 列表相同的交互方式中勾选并确认。
3. 用户执行 `aida upload`、`aida upload --all` 或等待自动同步；CLI 先发现本地 Session，再去除符合忽略规则的内容，随后保持现有上传流程。
4. 用户执行 `aida ignore list` 查看规则，或通过对应交互入口移除规则。

## 5. 验收标准

| 编号 | 产品规则 | 可观察结果 |
|---|---|---|
| R-01 | 3.1 | Windows、Intel Mac、Apple Silicon Mac 可启用、查看、改时、关闭自动同步；到时只执行一次成功上传。 |
| R-02 | 3.1 | 自动上传失败后遵循当前退避上限；平台调度不可用时不误报已开启。 |
| R-03 | 3.2 | 从交互列表选择 Session 后，该 Session 在手动全量上传和自动上传中均不再上传。 |
| R-04 | 3.3 | 选择工作目录后，该目录及其子目录的 Session 均不再上传，其他目录仍可上传。 |
| R-05 | 3.4 | 新增忽略规则不删除本地文件和服务端历史数据，且配置文件不包含令牌。 |
| R-06 | 3.5 | Intel/Apple Silicon Mac 上，`aida update` 后在同一终端执行 `aida version` 和后续 Aida 命令均使用新版本，不需要新开会话。 |

## 6. 非目标

- 不修改 Session 上传 HTTP 协议、服务端 API、数据库表或迁移。
- 不提供图形化文件浏览器；“选择文件夹”仅从已发现 Session 的工作目录中选择。
- 不改变现有 Session 内容解析、切片、Token 和成本口径。
- 不清理或重写历史上传数据。

## 7. 产品待确认

无。`aida ignore` 的内部子命令命名不改变产品行为，按现有 CLI 风格在开发时确定。
