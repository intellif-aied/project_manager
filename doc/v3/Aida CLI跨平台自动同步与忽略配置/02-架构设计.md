## 4. 最小目标架构

【建议方案】保持 `autoSyncDue`、`runAutoSyncOnce` 和 `executeAutoSync` 作为唯一的业务规则入口，新增一个无交互的内部 tick：每次由平台调度唤起时，只运行一次“是否到期 + 上传 + 状态写入”。

【必要推导】需求 R-01 要求各平台保留当前每日成功和失败退避行为；F-01 表明这些状态仅在现有自动同步逻辑中维护。因此平台调度必须触发同一套单次判定逻辑，而不是直接定时执行 `upload --all`。

【建议方案】Linux 保持现有服务/守护方式；macOS 用用户级 LaunchAgent，Windows 用当前用户的 Task Scheduler，每分钟调用 tick。频率不表示每分钟上传，实际是否上传仍由既有每日时间和退避状态决定。

【建议方案】新增独立 ignore 存储，读取后在 `scanLocalSessions` 的归组结果上统一过滤，并在 `cmdUpload` 取到 Session 列表前执行。目录规则使用清理后的绝对路径及“目录自身或子路径”关系匹配，不用字符串前缀匹配。

## 6. 数据流与失败边界

```text
平台调度器
  -> aida auto-sync tick
  -> 读取 auto-sync 配置和当日状态
  -> 到期判断/退避
  -> 读取 ignore 配置
  -> 发现、索引、归组本地 Session
  -> ignore 过滤
  -> 现有增量上传
  -> 写入成功或失败状态
```

- ignore 配置读取或格式无效：建议阻止本次自动上传并明确报错，避免在用户以为已忽略内容时发生意外上传。
- 调度注册失败：不能把 `Enabled` 配置持久化为成功状态；若注册后启动校验失败，应回滚注册和启用状态。
- 上传锁已被手动上传占用：沿用当前“跳过本次、按退避后重试”的自动同步语义。
- 已忽略的 Session：不改变上传 checkpoint、源 Session 文件和服务端数据。

## 7. 安全、容量与兼容性

- 【已验证代码事实】现有配置与 Session 索引都在用户目录，配置写入已有 `0600` 和临时文件 rename 的模式。证据：`daemon/main.go:94`、`daemon/session_index.go:55`。
- 【建议方案】ignore 文件采用相同的用户目录、`0600`、原子写方式；禁止写入 Token。
- 【必要推导】路径匹配若用字符串前缀，会把 `/work/a` 错判为 `/work/another`，不能满足 R-04；必须基于清理后路径边界判断。
- 【已验证代码事实】Windows 更新已有延迟替换路径；macOS/Windows 调度记录的可执行文件路径必须在升级后仍有效。证据：`daemon/self_update.go:173`。
