## 3. 设计分层

### A. 本期必须完成

- Evidence Facts稳定引用；
- Report Brief Schema、校验、规范化、持久化和幂等；
- `write_report_brief` MCP工具；
- 个人日报最终写回Brief门禁；
- 系统Report Skill两阶段流程；
- 测试服功能开关和真实链路验证。

### B. 代码事实触发的必要保障

- Brief必须绑定当前用户、run和immutable Context hash；
- 写回门禁不能削弱现有来源冻结、编辑冲突和结果幂等；
- 其他五类报告和普通Agent不进入Brief流程；
- API与Skill版本必须配套发布。

### C. 后续增强

- 周报、小组和部门报告是否启用Brief，待独立样本和验收后再决定；本期不实现。

## 4. 变更边界

- 修改范围：`reportcontext` Facts、`reportbrief`模块、Report MCP、个人日报写回、配置、系统Report Skill、migration和定向测试；
- 不修改范围：Digest、Projection语义、Session选择、权限、统一账号身份、前端、其他Agent和其他五类报告；
- 新增资源：migration`028`与`report_run_briefs`、migration`029`与`report_run_generation_attempts`、`REPORT_TWO_PASS_ENABLED`。
