# Project 关联评测数据集正规化方案

## 结论

Project Memory 不整体降级。`Workspace + 语义锚点`继续作为父项目强参考，但必须区分：

- `semantic_fact_refs`：当天明确命中项目名称或别名的强锚点；
- `workspace_fact_refs`：与锚点同 Workspace 的候选事实，只在当天目标兼容且没有其他项目冲突时归入。

这样保留困难样本恢复父项目的能力，同时避免一个语义命中把整个目录的新工作强制并入旧项目。

## 两层数据集

### 1. Project Association Regression Dataset

小型、可版本化、无需 Agent 的回归层。保存匿名 Case、Source Set Hash、期望父项目、可接受别名和禁止合并关系。它回答：

- 是否召回正确父项目；
- 连续多日是否保持稳定项目名；
- 新 Workspace 或冲突目标是否被错误合并；
- Project Memory 是否仍只是辅助信息，没有带入历史成果。

### 2. Controlled Source Archive

大体量、受控访问的重放层。保存真实 Session/Slice、冻结 Context、Memory Snapshot、A/B Artifact 及运行映射。只在候选发布前执行完整 Agent 回归，不进入 Git。

## V1 样本

| 匿名组 | 用户日 | 核心边界 |
| --- | ---: | --- |
| `pa-001` | 1 | 模块名无法直接给出父项目，必须恢复“芯片验证平台” |
| `pa-101`～`pa-103` | 3 | 多模型训练、评测与数据管线连续归入“AI Coding 提效支撑” |
| `pa-201`～`pa-203` | 3 | OSCAR 归入“KV Cache 压缩算法研发”，独立 v5 套件不得误并 |

员工姓名仅保存在 Controlled Source Archive 的访问映射中，不属于数据集领域语言。

连续样本的第一天是 Memory Seed：当日之前没有可用 Snapshot，只观察 Facts 自身的归并效果，不作为历史项目召回硬门禁；从第二个用户日起才要求 Project Memory 稳定恢复父项目。

## 门禁

每次改动必须先通过确定性校验；准备发布时再重放 7 个 Case。上线至少满足：

1. 必须项目召回率 `100%`；
2. 禁止合并违规数 `0`；
3. 历史成果泄漏数 `0`；
4. 7 个 Case 全部生成成功；
5. 人工只复核文案自然度和信息密度，不重新定义项目归属。

数据集发布后不可原地修改。新的真实失败样本经人工确认后进入下一版本，避免为单个异常临时改 Prompt 或规则。
