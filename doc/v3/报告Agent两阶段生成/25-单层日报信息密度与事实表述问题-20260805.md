# 单层日报信息密度与事实表述问题

> 日期：2026-08-05
> 状态：问题留存，未进入本次运行逻辑修改

## 1. 现象

个人日报改为单层编号列表后，系统日报只复制每个 Workstream 的 `title`。这消除了“工作概览 / 工作详情”的重复，但没有带出 Brief 中已筛选的 `deliverables`，使内容被压缩为事项标题。

量化适配、问题定位、模型评估这类工作，日报只保留主题和一句主结果，读者看不到当日关键推进、已定位问题或仍在分析的范围。用户手工修改后的日报通常会在同一主题下保留这些信息，说明单层结构本身不是问题，问题在于信息密度被过度压缩。

## 2. 根因

当前系统 Report Skill 第二阶段要求：逐条复制已接受 Brief 的 `workstreams[].title`，禁止从 `deliverables` 展开，并用同一份标题列表写入 `summary` 和 `content`。因此 Brief 中的成果信息不是没有生成，而是在最终写回前被主动丢弃。

## 3. 不可接受的表述

Session、Digest 和 Evidence Facts 只能证明用户进行了相关工作，通常不能可靠证明外部状态。因此日报不得仅凭这些证据生成以下断言：

- 测试通过、完整后端测试通过；
- 验收通过、端到端验证完成；
- 已发布、已上线、生产可用；
- 因未观察到后续动作而推导未完成、未发布或不建议上线。

即使 Facts 中含有 Agent 叙述，也必须把这类外部状态视为不可靠，不能因展开 `deliverables` 而重新带回日报。

## 4. 后续调整方向

保持单层正文，不恢复“工作概览 / 工作详情”。每个 Workstream 仍是一条一级编号，但正文应由“主题 + 已筛选的关键推进”构成：

```md
1. nnp412 量化适配：处理 GTCRN 的 conv2d_transpose 转换问题，并完善相关量化适配。
2. 模型量化评估：补充 v69 portable ONNX 的量化验证；分析 DeepFilterNet 与 Conformer encoder 的相似度波动及输入数据影响。
```

约束如下：

- 每条只使用同一 Workstream 内一至三个已接受 Deliverable；
- 使用自然句或分号连接，不增加标题、详情段或嵌套列表；
- 保留工作推进、明确定位和用户实际处理的事项；
- 对测试、验证、发布、验收等内容，只能描述用户做了相关工作，不能下外部结果结论；
- 简单事项仍可只有一句，不能为了变长补充无价值细节。

## 5. 影响范围（后续实施时）

仅涉及系统默认 Report Skill 的个人日报第二阶段和相应格式/事实表述测试；不修改 Brief、Report MCP、数据库、个人 Agent、周报或团队报告。
