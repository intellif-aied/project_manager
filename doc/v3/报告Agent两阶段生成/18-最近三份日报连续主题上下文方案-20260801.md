# 最近三份日报连续主题上下文方案

> 日期：2026-08-01
> 范围：系统默认个人日报 `personal_daily`
> 目标：改善跨 Session、跨日期的项目归并，不改变当日事实边界

## 1. 已确认需求

生成个人日报时，为 Report Agent 提供当前报告日期之前最近三份有效日报的主题层级：

- 按日报日期倒序取最近三份，不按最近三个自然日取数；
- 没有日报的日期自然跳过；
- 不区分工作日、周末或节假日，周六、周日的加班日报正常参与；
- 当前实现设置 14 天最大回溯窗口，窗口内不足三份时按实际数量提供；
- 只读取用户已保存或已提交的日报；未经过用户保存的 Generated Draft 不参与；
- 兼容历史数据：`edited=true` 的已保存日报视为用户最终稿；新数据以保存/提交结果事件为准。

## 2. Context 契约

`continuity_context` 与 `work_evidence` 分离：

```json
{
  "continuity_context": {
    "purpose": "识别跨日报持续工作的稳定项目名称、父子归属和常用别名。",
    "evidence_rule": "仅用于归类当前 work_evidence；历史日报中的成果、状态、数据和结论不得写入当前日报，除非当前 Fact 独立支持。",
    "grouping_rule": "提交 Brief 前，将匹配历史子主题的 Subject 映射到父主题，并合并所有映射到同一父主题的 Workstream；子主题只在 Deliverable 中表达，无关 Fact 不得强行归入。",
    "recent_reports": [
      {
        "date": "2026-07-30",
        "themes": [
          {
            "title": "KV Cache 压缩算法研发",
            "children": ["GLM-5.2 模型在苹果 800 的 OSCAR 算法适配任务"]
          }
        ]
      }
    ]
  }
}
```

主题提取是确定性的，不调用 LLM：

1. 优先读取系统日报的“工作概览”列表；
2. 对人工 Markdown 日报保留一级列表和直接子列表；
3. 更深层的成果、指标和过程不进入连续性主题；
4. 无列表时使用三级标题，纯文本日报至少保留首个非空主题。

## 3. Agent 使用边界

- 仅当当前 Fact 与历史主题匹配时，使用历史稳定名称或父子归属；
- 提交 Brief 前，把匹配历史子主题的 Subject 映射到父主题，并合并所有映射到同一父主题的 Workstream；
- 当前 Fact 与历史主题无关时建立新 Workstream，不强行合并；
- Deliverable 仍必须引用当前 `fact_ref`；历史日报不能证明当天完成、发布、验证、状态或指标。

## 4. 前置 A/B 结论

测试服使用相同 Session 证据完成三组对照：

- 无历史上下文：OSCAR 与 KV Cache 被拆为两个一级事项；
- 直接提供前三份日报摘要：项目名称更准确，但仍拆为两个一级事项；
- 提供“一级主题—子主题”结构：成功归并为一个 `KV Cache 压缩算法研发` Workstream，且未抄入历史成果。

因此正式方案不直接拼接历史正文，而是提供结构化、非证据的连续主题提示。

正式实现后的生产样本 A/B：

| 样本 | 控制组 | 连续性组 | 结果 |
| --- | --- | --- | --- |
| 生产用户 62 → 测试用户 314，93 Facts | `68deda91…`，OSCAR 与 KV Cache 拆成 2 项 | `65c53d62…`、`d2cb4c0c…`，均归并为 1 项 | 两次重复均使用父主题 `KV Cache 压缩算法研发`，无 Brief 降级 |
| 生产用户 24 → 测试用户 313，68 Facts | `6799f72b…`，3 项 | `a7c2f146…`，仍为 3 项 | 保持 GLM、Qwen、CUDA/NCCL 三个独立成果，没有被宽泛的 `Ai coding 提效支撑` 强行合并 |

同一用户 A/B 的 `work_evidence` 去除 Run 身份与 `continuity_context` 后哈希一致，证明 Session 证据没有变化。候选结果均未出现只存在于历史日报的 `RocketKV`、`1-bit KV Cache`、`MiniMax-M2.5` 或 `KIMI-k3` 内容。

## 5. 验收重点

- A/B 两组必须使用相同 Session 切片、模型和 Skill，仅控制 `continuity_context` 是否存在；
- 正向样本观察同一持续项目是否减少不合理拆分；
- 负向样本观察无关工作是否被错误合并；
- 检查最终正文是否出现只存在于历史日报、当前 Fact 不支持的成果或状态；
- 所有生产数据只读获取，生成与写回限定在测试服测试账号。
