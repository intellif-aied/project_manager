# V3 测试与验收：Report Agent 两阶段生成

> 文档状态：测试服验收通过
> 日期：2026-07-27
> 需求基线：[01-需求文档](01-需求文档.md)
> 架构基线：[02-架构设计](02-架构设计.md)

## 1. 测试原则

- 先证明工具顺序、事实覆盖、状态门禁和幂等，再评价文字质量；
- 通过模块公开接口和真实报告入口测试，不绑定内部拆分；
- 同一冻结 Context 必须可重复回放；
- 构建成功不能替代测试账号真实链路；
- 首期只验收默认个人日报。

## 2. 需求追溯矩阵

| 用例 | 需求引用 | 场景 | 输入 | 可观察结果 | 层级 |
|---|---|---|---|---|---|
| T-01 | R-01 | 正常个人日报 | 有效run和45 Facts Context | 同一Session按Context→Brief→Result执行 | 真实链路 |
| T-02 | R-02 | Facts含同项多轮进展 | 代表性Context | 归并为少量Workstreams，全部Facts被引用或排除 | 模块/真实链路 |
| T-03 | R-03 | 测试和生产状态混合 | released/validated/completed Deliverables | 最终日报不提升状态 | 模块/人工 |
| T-04 | R-04 | Context含技术词和内部标识 | 深链、错误码、组件名、地址等 | Brief和日报不含禁用内容 | 模块/人工 |
| T-05 | R-05 | 未提交Brief直接写结果 | 缺失brief_hash | `REPORT_BRIEF_REQUIRED`且报告未写入 | MCP |
| T-06 | R-05 | 错hash、跨run、跨用户 | 无效brief_hash | mismatch且报告未写入 | MCP |
| T-07 | R-07 | 相同Brief重复/并发提交 | 同一run同一payload | 幂等返回同一hash，仅一条记录 | 集成 |
| T-08 | R-07 | 同一run不同Brief | 冲突payload | conflict且首份不覆盖 | 集成 |
| T-09 | R-06 | 最终写作 | 已接受Brief | 按主题组织、无过程复述、表达自然 | 真实链路/人工 |

## 3. 架构风险验证

| 用例 | 架构决策 | 风险 | 验证方法 | 通过条件 |
|---|---|---|---|---|
| AR-01 | A-01 | 实际仍是一轮语义处理 | Agent平台事件审计 | Brief工具响应后存在新的模型推理 |
| AR-02 | A-02 | Facts遗漏或被同时排除和引用 | Brief模块覆盖校验 | 无遗漏、引用和排除互斥 |
| AR-03 | A-03 | Brief跨Context复用 | 修改hash/run/user测试 | 全部拒绝 |
| AR-04 | A-04 | 开关误影响其他业务 | tools/list和六类报告回归 | 仅默认个人日报进入门禁 |
| AR-05 | A-05 | Flash忽略术语和工具协议 | 真实Session审计 | 最终日报达标；MCP强门禁不可绕过 |
| AR-06 | A-06 | 并发或重复提交绕过纠错上限 | run级计数并发测试 | 原子计数且超过上限不可继续 |

## 4. 回归范围

- Session选择、Digest构建、Report Projection和Context冻结；
- 个人日报来源校验、编辑冲突、最终写回和通知；
- 个人周报、小组/部门日报与周报；
- 专用模型账号与当前用户Report MCP身份；
- 普通Agent、手动运行和定时任务；
- 功能开关关闭后的原个人日报协议。

## 5. 质量门槛

| 指标 | 门槛 |
|---|---|
| Context无支持的结果、状态、环境、原因或计划 | 0 |
| 测试状态误写为生产发布 | 0 |
| Token、私网地址、绝对路径、UUID、提交哈希、账号标识 | 0 |
| “报表、通知深链、报告Agent、报告MCP” | 0 |
| 准备、讨论、纯轨迹成为独立主题 | 0 |
| 同一事实重复表达 | 0 |
| 主题数量 | 通常2～4，按事实复杂度允许变化 |
| 人工评分 | 事实和状态5分；覆盖、简洁、自然平均≥4分 |

## 6. 真实链路验收

1. 测试服发布匹配版本API、Report MCP和系统Report Skill；
2. 使用测试账号选择2026-07-27本机代表性Session；
3. 从报告页面生成个人日报；
4. 核对Agent平台只有一个Session，工具顺序正确；
5. 核对`report_run_briefs`的Context hash、Brief hash和Facts覆盖；
6. 对照冻结Context人工Review Brief和最终日报；
7. 验证模型仍为`deepseek-v4-flash`、执行账号为测试专用账号、Report MCP身份为测试用户；
8. 定向验证其他报告和开关关闭回退。

## 7. 发布门禁

- T-01～T-13和AR-01～AR-06通过；
- 代表性Session最终日报通过人工Review；
- 无跨用户、跨run、跨Context Brief复用；
- 其他报告、普通Agent和身份链路无回归；
- API、MCP工具和系统Skill版本作为同一发布单元。
