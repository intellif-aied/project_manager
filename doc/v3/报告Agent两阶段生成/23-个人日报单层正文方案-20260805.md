# 个人日报单层正文方案

> 日期：2026-08-05  
> 范围：系统默认 Agent 生成的个人日报 `personal_daily`

## 1. 问题

现有 AI 日报把同一批工作重复展示为“工作概览”和“工作详情”。真实手写日报通常只有一层 `1. ... / 2. ...`，两层结构增加阅读和编辑成本；用户编辑正文后，生成时保存的 Summary 还可能与最终正文不一致。

近期两个完整生产日共 50 份日报，其中 21 份手写日报基本均为单层列表；29 份 AI 日报的 Summary 约占正文字符数 13%，且 13 份被编辑的 AI 日报中仅 2 份最终正文仍保留原 Summary。该数据只用于确认重复结构问题，不作为日报内容质量结论。

## 2. 产品口径

- 用户只看到一份日报正文，不再显示“工作概览”和“工作详情”。
- 正文使用 Markdown 有序列表，一条对应一个稳定工作主题，通常 1～3 条，最多 5 条。
- 每条直接表达“项目或主题 + 当日主要成果”，不为简单工作强行补充细节。
- Git、测试、构建、合并和部署只帮助归并主题，不作为日报结论。
- 不推导发布状态、完成状态、建议或下一步；明日计划仍使用既有独立字段。
- 专业名称保留原文，普通操作使用自然中文。

## 3. 实现

1. Report Brief 的 `workstream.title` 继续承担用户可读的完整条目。
2. 系统 Skill 第二阶段按 Brief 顺序复制标题，生成一份有序列表；`summary` 与 `content` 传入同一内容。
3. 服务端以校验后的 Brief Reader Summary 为准，并把它直接保存为个人日报正文；Summary 字段仅为快照、评测和兼容用途保留，不再拼接进正文。
4. Brief 结果校验由“正文三级标题数等于 Workstream 数”改为“正文有序列表项数等于 Workstream 数”。

## 4. 兼容边界

- 只改变系统默认 Agent 的个人日报；个人自定义 Agent 的 Markdown 不重写。
- 周报、团队报告和部门报告维持原格式。
- 历史日报不迁移、不重写。
- Project Memory 和最近日报连续性读取已具备无标题列表回退，本期不调整其生成、权重或关联机制。
- 前端沿用现有 Markdown 渲染，无需新增页面逻辑。

## 5. 验收

- 系统个人日报最终正文只有连续编号列表，不含重复标题或详情段。
- Brief 有几个 Workstream，正文就有几个顶层条目。
- 个人 Agent 和周报格式回归不变。
- 新单层日报可被 Project Memory 与连续性上下文提取为主题。
- 代表性真实 Session 在测试服完成生成，并由人工确认可读性后再决定生产发布。
