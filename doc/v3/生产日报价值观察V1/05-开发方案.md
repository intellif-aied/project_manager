# 生产日报价值观察 V1：开发方案

> 文档状态：可开发
> 日期：2026-07-28

## 1. 实现任务

| 编号 | 需求 | 架构 | 任务 | 完成条件 |
|---|---|---|---|---|
| D-01 | R-01～R-03 | A-01/A-02 | 增加 Generation Snapshot 和 User Outcome Event 存储 | Snapshot 一对一；Outcome 只追加；删除不级联丢证据 |
| D-02 | R-01/R-03 | A-01 | 个人日报成功写回时保存 Draft、Summary、Variant 和 Hash | 新成功 Run 均有快照；失败 Run 不产生伪 Draft |
| D-03 | R-02/R-03/R-07 | A-02/A-03 | 保存、提交、删除时追加 Outcome 并绑定当时 Run | G1→Save U1→G2 后 G1/U1 仍可还原，当前结果只按 G2 分类 |
| D-04 | R-05～R-07 | A-03 | 实现 Markdown 规范化、全文差异、Summary 和主题差异 | 符合统计口径，中文和空值有单测 |
| D-05 | R-04/R-08～R-10 | A-03～A-05 | 增加管理员按日汇总、明细、实时趋势和文件导出 API | 仅 admin；返回完整分母、缺失状态和 observed_at |
| D-06 | R-08～R-11 | A-05 | 增加“生产日报价值观察”页面 | 日期、卡片、分布、趋势、筛选、Diff、摘要和导出可用 |

## 2. 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/admin/daily-report-value` | 按日汇总、分布、趋势和分页用户日明细 |
| `GET` | `/api/v1/admin/daily-report-value/users/{user_id}` | 指定用户日 Run、Draft、Outcome 和 Diff |
| `GET` | `/api/v1/admin/daily-report-value/export` | 下载带 `observed_at`、筛选条件和 Hash 的冻结文件 |

查询响应顶层包含 `report_date`、`observed_at`、`data_completeness` 和缺失计数。每个比例包含 `numerator`、`denominator`、`value`。

## 3. 开发顺序

1. D-01～D-03：先保证新生产数据不再丢失；
2. D-04～D-05：完成确定性统计和只读 API；
3. D-06：完成管理员页面和导出；
4. 测试服验证后再按独立发布流程上线。

## 4. 不改范围

- 不修改 Digest、Context、Brief、Final 生成逻辑；
- 不修改普通用户页面操作；
- 不同步调用 Codex；
- 不实现测试数据集和 Variant 配对执行器。
