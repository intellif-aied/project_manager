# 生产日报价值观察 V1：产品方案

> 文档状态：已确认
> 日期：2026-07-28
> 用户：管理员
> 数据范围：生产环境 `personal_daily`

## 1. 页面目的

管理员按指定日期查看 AI 生成日报在生产环境中的实际使用结果，回答：

1. 当天有多少个人日报使用 AI 生成；
2. AI 是否稳定完成生成；
3. 用户最终保留了多少 AI 内容；
4. 用户是否需要大幅修改、删除工作总结或调整主题；
5. 哪些用户日需要进一步查看 Draft 与用户稿差异；
6. 当前证据能否支持“AI 已显著减少日报撰写工作”的内部汇报。

页面不评价测试服 Variant，不决定上线，不向普通用户展示。

## 2. 页面结构

```text
生产日报价值观察
[报告日期] [部门/小组] [Variant] [导出]
数据截止：observed_at    数据完整性：完整 / 有缺失

AI 日报覆盖 | 生成成功 | 确认直接使用 | 轻度及以下修改
Draft 保留  | 显著修改 | 总结删除     | 重新生成

修改程度分布 | 工作总结结果 | 近 14/30 日趋势

用户日明细
用户 | 生成次数 | Variant | 用户结果 | 修改比例 | Draft 保留 | 总结结果 | 主题变化 | 操作
                                                                    [查看对比]
```

默认打开昨天，可选择今天或历史日期。选择日期后只查询该 `report_date`，不按 Run 创建时间替代报告日期。

## 3. 核心卡片

每张卡片同时显示百分比、分子、分母；分母为零时显示“暂无可计算数据”。

新采集上线之前的历史日期只能展示总日报、AI/手写覆盖和 Run 成功失败等现有事实。无法恢复的历史 Draft、用户事件、全文差异和 Summary Outcome 显示为“历史未采集”，不得使用当前 `edited` 状态补算。

| 卡片 | 口径 | 说明 |
|---|---|---|
| AI 日报覆盖 | AI 生成个人日报 / 当天已有个人日报 | 表示已有日报中的 AI 使用覆盖，不代表全部员工完成率 |
| 生成成功 | 成功 Report Run / 当天全部 Report Run | 同时显示失败阶段和失败数 |
| 确认直接使用 | 明确保存或提交且全文未改 / Comparable User Outcome | 最强用户使用证据 |
| 轻度及以下修改 | `unchanged + light` / Comparable User Outcome | 表示用户撰写工作量较低，不自动表示内容完全正确 |
| Draft 保留 | Draft Retention P50 | 表示 AI 文字最终保留程度，同时展示 P25/P95 |
| 显著修改 | `medium + heavy` / Comparable User Outcome | 用于定位仍需较多人工改写的用户日 |
| 总结删除 | `summary_removed` / 可比较且生成稿含总结 | 直接观察“工作总结”区域是否被用户删除 |
| 重新生成 | 多次生成用户日 / AI 生成用户日 | 表示用户重新请求 AI 结果，不自动等同模型失败 |
| 下游采用 | 被小组或部门报告明确引用的 AI 日报 / 可被下游采用的 AI 日报 | 表示 AI 日报进入后续汇总链路，不代表内容完全正确 |

Observed Unchanged 作为独立补充卡片或卡片附注展示，不能并入“确认直接使用”。

## 4. 分布与趋势

### 4.1 修改程度分布

展示 `unchanged / light / medium / heavy / not_comparable` 的用户日数量。点击区间后过滤下方明细。

### 4.2 工作总结结果

展示：

- 保持不变；
- 被修改；
- 被删除；
- 缩短至少 30%；
- 无可比较用户稿。

“被删除”只判断 Generated Draft 中的 `## 工作总结` 区域在用户稿中不存在或为空，不使用日报列表的摘要预览字段。

### 4.3 趋势

支持最近 14 日和 30 日查看：

- AI 日报覆盖；
- 生成成功率；
- 确认直接使用率；
- 轻度及以下修改率；
- Draft Retention P50；
- 显著修改率；
- 总结删除率；
- 重新生成率。
- Downstream Reuse Rate 和生成后删除率。

趋势按查询时点从不可变 Draft、Outcome 和 Run 事实实时计算，每个点共享页面 `observed_at`。新采集上线前无法恢复的历史差异显示缺口；用于正式汇报时通过导出冻结本次结果。

## 5. 用户日明细

一个明细行对应“用户 + `report_date`”，保留该用户日全部 Run。

字段包括：

- 用户、部门、小组；
- Report Run 数、成功数和最后失败阶段；
- 实际 Variant；
- 最近成功 Generated Draft；
- 用户结果状态：确认直接使用、已修改、Observed Unchanged、无明确结果、已删除；
- 全文 `text_diff_ratio`、Draft Retention、User Addition；
- Summary Outcome 和总结长度变化；
- 主题标题删除、新增数量；
- 是否重新生成；
- 是否被小组或部门报告采用；
- 数据缺失原因。

筛选包括 Variant、部门/小组、生成状态、修改区间、Summary Outcome、是否重新生成和是否缺数据。

## 6. Draft 与用户稿对比

管理员点击“查看对比”后查看：

- 左侧 Generated Draft，右侧对应保存或提交稿；
- 行内增加、删除和修改高亮；
- 单独展示“工作总结”差异；
- 展示该用户日全部 Run 时间线，明确当前用户稿对应哪个 Run；
- 展示 Source Session 数量和 Source Coverage 结论，不默认展示 Session 正文。

没有 Comparable User Outcome 时，可以展示当前内容与最近 Draft 的 Observed Difference，但必须标记“未确认用户结果”。

## 7. 汇报摘要

页面根据确定性数据生成可复制的内部汇报摘要，不调用模型。格式固定为：

```text
<日期>共有 <总日报数> 份个人日报，其中 <AI日报数> 份由 AI 生成，覆盖率 <比例>。
AI Report Run 成功 <成功数>/<总Run数>。
在 <可比较数> 份有明确用户结果的日报中，<直接使用数> 份未修改直接使用，
<轻度及以下数> 份修改不超过轻度；Draft 内容中位保留率为 <比例>。
有 <显著修改数> 份发生显著修改，<总结删除数> 份删除“工作总结”，
<重新生成数> 个用户日发生重新生成。另有 <不可比较数> 份缺少明确用户结果。
```

摘要必须保留分子和分母，不输出“全部员工已使用”“用户完全接受”或“AI 内容完全正确”等超出证据的结论。

## 8. 导出

导出内容包括：

- 日期、`observed_at`、筛选条件和数据完整性；
- 核心指标及分子分母；
- 用户日明细；
- Generated Draft、对应用户稿和确定性差异；
- Run、Variant 和 Hash。

每次导出形成包含 `report_date`、`observed_at`、筛选条件和 Hash 的 Production Observation Snapshot 文件。V1 不在服务端建设 Snapshot 管理库；文件仅供授权内部观察与汇报使用。

## 9. 权限与边界

- 页面、聚合接口、明细和导出仅允许 `admin`；
- 生产请求链路不调用 Codex 或其他 Reviewer；
- 页面只使用实际生产 Variant，不生成候选日报；
- 测试服数据不进入页面；
- 不根据行为指标自动评价个人或团队绩效；
- 不把用户修改自动视为 AI 失败，也不把未修改自动视为内容正确。
