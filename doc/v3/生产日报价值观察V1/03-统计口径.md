# 生产日报价值观察 V1：统计口径

> 文档状态：已确认
> 日期：2026-07-28

## 1. 基础分母

```text
ai_report_coverage_rate = AI 生成个人日报数 / 当天已有个人日报总数
generation_success_rate = 成功 Report Run 数 / 当天全部 Report Run 数
regeneration_rate = 多次生成用户日数 / AI 生成用户日数
downstream_reuse_rate = 被小组或部门报告明确引用的 AI 日报数 / 可被下游采用的 AI 日报数
```

页面同时显示原始数量。当天已有日报不等于应填日报员工范围。

## 2. 用户结果

每个用户日只按 `observed_at` 前最后一个成功 Run 分类。分母中的 Comparable User Outcome 必须绑定该 Run；更早 Run 的保存/提交只用于时间线和历史行为统计，不重复进入当日当前结果分母。

```text
confirmed_direct_use_rate = 明确保存或提交且全文未改的用户日数 / Comparable User Outcome 数
observed_unchanged_rate = 无明确结果但观察时全文未变的用户日数 / 无明确结果的 AI 用户日数
```

Confirmed Direct Use 与 Observed Unchanged 不合并。删除、无 Outcome、缺 Draft 分别统计。

## 3. 文本规范化与差异

统一换行符、移除行尾空白、去除首尾空白，保留 Markdown 结构；以 Unicode 字符比较。

```text
matched_chars = Generated Draft 与用户稿的最长公共子序列字符数
text_diff_ratio = 1 - (2 × matched_chars / (generated_chars + user_chars))
draft_retention_rate = matched_chars / generated_chars
user_addition_rate = (user_chars - matched_chars) / user_chars
```

空分母为 `not_applicable`。修改区间：

- `unchanged`：`text_diff_ratio = 0`；
- `light`：`0 < ratio <= 0.10`；
- `medium`：`0.10 < ratio <= 0.30`；
- `heavy`：`ratio > 0.30`。

修改区间只表示文本工作量。小范围事实或状态纠错仍可能是实质问题。

## 4. Summary Outcome

Generated Draft 的 `## 工作概览` 到下一个同级标题之间为 Summary Region；历史报告仍兼容识别 `## 工作总结`。两者同时存在时以文档中先出现的标题为准。

- `summary_unchanged`：两侧规范化后相同；
- `summary_modified`：两侧均存在但内容不同；
- `summary_removed`：生成稿存在，用户稿不存在或为空；
- `summary_reduced_30`：用户总结字符数至少减少 30%。

同时返回总结 Diff 和长度变化。列表摘要预览不参与计算。

## 5. 主题变化

按除“工作总结”外的同级 Markdown 标题计算删除、新增和标题变化信号。确定性比较不判断语义重命名，不将其自动标为归并错误。

## 6. 管理汇报核心指标

1. AI Report Coverage；
2. Generation Success Rate；
3. Comparable Outcome Coverage；
4. Confirmed Direct Use Rate；
5. `unchanged + light` 比例；
6. Draft Retention P50/P25/P95；
7. `medium + heavy` 比例；
8. Summary Removed 和 Summary Reduced 30%；
9. Regeneration、删除和 Downstream Reuse。

V1 不将指标加权为总分。
