# 生产日报价值观察 V1：需求文档

> 文档状态：已确认
> 日期：2026-07-28

## 1. 背景

生产日报生成成功后会自动覆盖同一用户同一日期的当前日报。现有数据不能完整保留每次 Generated Draft，也不能还原用户保存后再次生成的历史，因此无法可靠回答 AI 内容被保留、修改或删除了多少。

## 2. 产品目标

1. 按指定日期展示生产个人日报的 AI 覆盖和生成稳定性；
2. 可靠对比 Generated Draft 与用户明确保存或提交内容；
3. 展示全文修改、Draft Retention、Summary Outcome、主题变化和重新生成；
4. 形成可复制、可导出的内部汇报证据；
5. 为后续 Report 链路优化提供生产信号，但不自动决定优化或发布。

## 3. 产品规则

### 3.1 观察单位

- 汇总单位：`report_date`；
- 明细单位：用户 + `report_date`；
- 同一用户日的全部 Report Run 必须保留；
- 每个成功 Run 必须对应唯一 Generated Draft 和 Generation Variant。

### 3.2 用户结果

- 用户明确保存或提交形成 Comparable User Outcome；
- 系统自动 `saved` 不形成用户接受证据；
- 无明确事件但当前内容未变只记为 Observed Unchanged；
- 用户保存后再次生成，不得覆盖此前 Draft 和 Outcome；
- 删除个人日报必须保留删除事件和此前证据。

用户日汇总始终以 `observed_at` 前最后一个成功 Generated Draft 为当前 Draft。只有绑定该 Run 的最新明确保存或提交才形成当前 Comparable User Outcome；更早 Run 的 Outcome 只保留在时间线，不进入当前用户日指标。最后成功 Run 之后没有明确 Outcome 时，当前用户日只能是 Observed Unchanged、已删除或无明确结果。

### 3.3 生产页面

管理员选择日期后查看核心指标、分布、趋势和用户日明细；点击明细可查看 Draft、用户稿、Run 时间线和确定性 Diff。

所有百分比同时展示分子、分母和 `observed_at`。缺失 Draft 或 Outcome 的记录单列，不从分母静默删除。

### 3.4 汇报边界

- AI 日报覆盖率的分母是当天已有个人日报，不代表全部员工日报完成率；
- 修改行为是工作量和产品信号，不自动代表 AI 失败；
- 未修改不自动代表内容正确；
- 页面不生成单一“AI 可行分数”；
- 只有存在明确应填人员范围时，才计算组织日报完成率。

## 4. 验收标准

| 编号 | 可观察结果 |
|---|---|
| R-01 | 每个新成功 Run 有唯一、不可变的 Draft 和 Variant 快照 |
| R-02 | 用户保存、提交、删除形成追加式 Outcome，并绑定当时 Run |
| R-03 | 同一用户日多次生成和此前用户结果均可还原 |
| R-04 | 管理员可按日期查看 AI/手写覆盖、成功失败和耗时 |
| R-05 | 可计算全文修改区间、Draft Retention 和 User Addition |
| R-06 | 可计算 Summary Outcome、总结长度变化和主题变化信号 |
| R-07 | Confirmed Direct Use 与 Observed Unchanged 分开统计 |
| R-08 | 支持组织、Variant、状态、修改区间、总结结果和重新生成筛选 |
| R-09 | 支持用户级并排 Diff、Run 时间线和下游采用信息 |
| R-10 | 支持 14/30 日实时趋势、确定性汇报摘要和带 `observed_at` 的冻结文件导出 |
| R-11 | 页面与接口仅允许管理员，普通用户流程和其他报告不变 |

## 5. 非目标

- 测试服固定数据集和候选 Variant 配对；
- 在线 Codex 或 LLM Judge；
- 内容事实正确性的自动判定；
- 模型排行榜、员工排名、自动发布或切流；
- 其他五类报告和普通 Agent；
- 历史 Draft 与 Outcome 回填。
