# 生产日报价值观察 V1：前置验证记录

> 日期：2026-07-28
> 操作边界：代码和数据库只读；未读取生产 Session 正文

## 1. 现有结构验证

- Report Run 成功终态后 `output_ref_json` 不再被状态同步覆盖，但通用 Run API 会直接返回该字段；
- 当前只保存 Result Hash，不保存 Generated Draft；
- AI 生成按 `(user_id, report_date)` 覆盖当前 `daily_reports`，重新生成会替换 `managed_agent_run_id` 并重置 `edited=false`；
- 用户保存会覆盖当前内容并设置 `edited=true`，再次生成会丢失该保存历史；
- Submit 写路径保存 `submitted_content`，但生产尚无 Submitted 样本。

## 2. 历史丢失规模

| 环境 | 成功个人日报 Run | 当前日报仍关联 | 原 Draft 已无法找回 |
|---|---:|---:|---:|
| 测试服 | 68 | 23 | 45 |
| 生产 | 173 | 103 | 70 |

验证结论：现有最终态不能支撑生产价值观察，必须新增不可变 Snapshot 和追加式 Outcome。

## 3. 生产基础分母

生产最近 13 个有数据的报告日包含：

- 189 份个人日报；
- 63 份 `managed_agent` 日报；
- 126 份手写日报；
- 179 个个人日报 Run，其中 119 个成功、60 个失败。

按日 AI/手写覆盖和 Run 成功失败可由现有数据取得。历史 `edited` 不能还原修改过程；历史 Summary Outcome、Draft Retention 和 Confirmed Direct Use 必须显示“历史未采集”。

## 4. 结论

- V1 数据基础与页面方向可行；
- 只对新 Run 开始可信采集；
- 未修改代码、数据库或服务；
