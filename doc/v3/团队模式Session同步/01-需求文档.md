# V3 需求文档：团队模式 Session 同步

> 文档状态：已定稿
> 日期：2026-07-28
> 适用范围：共享开发机上的 Aida CLI 手动与自动 Session 同步，以及“我的 Token”页面的低频目录配置。

## 1. 背景

当前 Aida CLI 登录后只保存一个账号的 Token；`aida upload --all` 和自动同步会扫描当前系统账号下全部 Claude Code 与 Codex Session。共享开发机没有独立系统用户时，多人产生的 Session 会被上传到同一个 Aida 个人账号，既不符合实际归属，也使其他成员的个人 Token 统计和日报缺少数据。

让用户每天逐条选择本人 Session 成本过高。团队已确认接受共享开发机使用团队模式同步，并以工作目录作为 Session 的个人归属依据。

## 2. 产品目标

1. 共享开发机可由任一团队成员使用现有 `aida login` 登录后，显式开启团队模式手动上传或自动同步；不新增团队账号、团队 Token 或多团队选择。
2. 成员可在“我的 Token”页面自行维护自己的同步目录；不要求管理员日常登记新目录。
3. 团队模式上传时，既有 Session 延续原个人归属，新 Session 按命中的成员目录确定个人归属，使其进入对应成员现有的个人 Token 统计和日报来源。
4. 未配置目录的 Session 不上传、不误归属，并能在 CLI 本地日志中被发现和处理。
5. 既有普通个人上传与个人自动同步行为保持不变。

## 3. 名词

- **团队模式**：登录账号所属团队的共享开发机上传方式。登录账号只用于获得该团队的上传权限，不决定每条 Session 的最终归属。
- **个人同步目录**：成员在“我的 Token”页面为自己配置的绝对目录路径；其下工作目录产生的 Session 在团队模式上传时归属该成员。
- **未配置目录**：Session 的工作目录未命中任何成员个人同步目录的目录。
- **团队模式手动上传**：用户显式执行的团队模式全部 Session 上传。
- **团队模式自动同步**：用户主动开启后，在已设置的每日时间自动执行的团队模式全部 Session 上传。
- **既有 Session**：团队模式上传前，当前团队成员名下已存在相同 `agent_type + session_ref` 的 Session。
- **历史归属拆分**：针对曾由一个个人账号代传全组 Session 的存量数据，按已确认目录配置执行的一次性受控归属校正。

## 4. 产品规则

### TS-PRD-001：团队资格与开启方式

- 适用对象：登录账号属于一个团队的 Aida CLI 用户。
- 前提：一个 Aida 账号只属于一个团队；本期不支持一个账号选择或切换多个团队。
- 手动上传：用户可显式执行 `aida upload --team`，以团队模式上传全部本地 Session。
- 自动同步：用户可显式执行 `aida auto-sync enable --team` 开启团队模式自动同步；每日时间、自动恢复、更新失败后继续上传等已确认自动同步行为沿用现有产品规则。
- 身份行为：团队模式继续使用现有 `aida login` 保存的个人 Token。不得要求用户创建、保管、复制或轮换额外的团队账号或团队 Token。
- 团队归属：Aida 不在本地保存或由 CLI 上送 `team_id`；服务端在每次团队模式上传请求中按当前登录用户的最新组织关系取得唯一团队。用户组织迁移后，下一次请求立即使用新团队。
- Token 有效期：团队模式相关 CLI 上传请求与现有个人上传一致，不因 Token 的过期时间停止；Token 签名、尚未生效、用户不存在或 Aida 已禁用仍按现有 CLI 鉴权规则拒绝。
- 不具备团队资格时行为：团队模式命令明确提示当前登录账号不属于团队，且不得上传或开启团队模式自动同步。
- 显式开启：普通个人模式不得因登录、升级或执行其他命令自动变为团队模式。

### TS-PRD-002：个人同步目录配置

- 适用对象：团队成员。
- 配置入口：在 Web 端“我的 Token”页面提供低频、默认收起的“团队设备同步目录（高级）”配置区。
- 配置内容：成员可新增、查看、修改、删除多个属于自己的绝对目录路径；不得配置文件系统根目录 `/`。
- 配置说明：页面明确说明，目录用于共享开发机团队模式的同步准入，并决定新 Session 的个人归属；既有 Session 延续原归属；不配置不影响普通个人上传。
- 宽目录约定：除 `/` 外，平台不判断一个绝对目录是否过宽；成员按小组约定配置本人工作目录，并对该目录覆盖范围负责。
- 冲突行为：不同成员不得保存重叠目录路径；保存失败时，页面明确提示该目录已被其他成员占用。相同成员的嵌套目录不产生额外归属。
- 生效行为：配置成功后，后续团队模式上传按最新目录配置判断归属；已上传的历史 Session 不因目录配置变更而自动改归属。
- 删除行为：成员删除目录后，该目录下新旧 Session 均停止后续团队同步；已经上传的历史内容保留，不撤回、不迁移。

### TS-PRD-003：目录命中后的直接个人归属

- 适用对象：团队模式发现的 Claude Code 与 Codex Session。
- 触发条件：Session 的工作目录命中当前团队某成员的个人同步目录。
- 新 Session：当前团队内不存在相同 `agent_type + session_ref` 时，Session 直接归属目录命中的成员，而不是归属登录者。
- 既有 Session：当前团队内只存在一条相同 `agent_type + session_ref` 时，继续使用该 Session 及其原个人归属；目录命中只决定本次团队同步是否被允许，不改变原 owner。
- 重复身份：当前团队多个成员名下存在相同 `agent_type + session_ref` 时，返回 Session 身份冲突，不上传新 Chunk，也不自动合并记录。
- 匹配行为：目录及其子目录均可命中；当同一成员配置了嵌套目录时，结果仍归属该成员。
- 统计行为：团队模式上传的已归属 Session 按其归属成员参与现有个人 Token、成本、Session 和日报统计，不另设“团队账号”统计口径。
- 审计行为：系统需保留该 Session 由团队模式上传并按目录归属的可追溯记录，但该记录不改变成员可见的个人统计口径。
- 固定归属：同一 Session 建立后不得因登录账号或目录配置变化而中途换人。目录仍存在但改由其他成员配置时，既有 Session 继续归原 owner；该目录下新 Session 归新的目录 owner。
- 团队边界：既有 Session 的原 owner 不再属于当前团队时，返回团队上下文冲突，不上传新 Chunk。

### TS-PRD-004：未配置目录拒绝上传与本地日志

- 适用对象：团队模式发现的工作目录未命中个人同步目录的 Session。
- 产品行为：Aida 不上传该 Session 的内容，也不将其归属给登录者、团队或其他成员。
- 批次行为：同一次团队模式上传中，已命中目录的 Session 继续上传；未配置目录只导致对应 Session 被拒绝，整体结果明确显示存在未处理项。
- 本地日志：用户可通过 `aida log` 查看当前未配置目录及受影响 Session 数量，并看到“请在我的 Token 页面配置团队设备同步目录”的处理提示。
- 去重行为：同一未配置目录持续存在时，日志应以当前未处理项汇总展示，不每天重复制造大量相同失败记录。
- 自动同步结果：未配置目录属于已处理的待配置项，不触发当日每分钟重复自动同步；真实上传或网络失败继续沿用现有自动同步重试行为。
- 后续行为：成员补充目录配置后，该目录下未上传 Session 在下一次团队模式手动上传或自动同步时重新尝试。

### TS-PRD-005：个人模式保持不变

- 适用对象：未使用团队模式的 Aida CLI 用户。
- 产品行为：现有 `aida upload`、`aida upload --all` 与 `aida auto-sync enable` 继续按当前登录账号的个人模式运行。
- 隔离行为：个人模式不读取团队个人同步目录配置，也不改变既有 Session 的归属、统计或日报来源。

### TS-PRD-006：历史归属拆分

- 适用对象：切换团队模式前，曾由一个个人账号代传全组 Session，且可通过已配置目录明确识别实际成员归属的存量数据。
- 执行方式：由平台运维按当前团队已确认的个人同步目录执行一次性数据库归属拆分，不作为日常 Team 上传的自动行为。
- 拆分粒度：按完整 Session 调整个人归属；Session ID、`agent_type + session_ref`、Chunk、内容、增量位置和处理结果保持在同一 Session，不拆分单条 Session 的 Chunk。
- 数据一致性：同步校正以 Session owner 为来源的个人统计和日报来源数据，使迁移后历史数据与后续新增 Chunk 归属于同一成员。
- 执行校验：仅处理唯一目录命中、目标成员仍属于当前团队且目标成员名下不存在相同 `agent_type + session_ref` 的 Session；未命中、多重命中和身份重复记录不变并进入执行结果清单。
- 执行窗口：拆分期间暂停目标团队上传；归属校正以单次事务执行，完成核对后恢复团队模式上传。
- 后续行为：拆分完成后，团队模式将其识别为目标成员的既有 Session，并在原 Session 上继续增量上传。

## 5. 用户流程

1. 团队成员在 Web 端进入“我的 Token”，按需在默认收起的“团队设备同步目录（高级）”中维护自己的绝对工作目录。
2. 共享开发机上的任一团队成员完成普通 `aida login`。
3. 用户执行 `aida upload --team` 立即进行团队模式上传，或执行 `aida auto-sync enable --team` 后设置每日自动同步时间。
4. Aida 扫描本地 Session：命中目录的既有 Session 延续原 owner，新 Session 进入目录对应成员的个人数据；未命中目录的 Session 不上传。
5. 用户可在现有个人 Token 页面和个人日报中看到归属给自己的 Session；如有未配置目录，可执行 `aida log` 查看并由对应成员自行补充目录。

## 7. 非目标

- 不新增团队账号、团队密码、团队 Token、设备 Token 或独立的团队账号管理页面。
- 不支持一个账号属于多个团队，也不提供 CLI 团队选择或切换。
- 不要求管理员维护成员的日常工作目录。
- 不自动推断、提示或替用户登记工作目录。
- 不上传、暂存或转交未配置目录下的 Session。
- 不在日常团队上传中自动批量重算历史归属；历史拆分仅按 TS-PRD-006 的一次性受控操作执行。
- 不拆分一条 Session 内的 Chunk，不将一条 Session 分配给多个成员，也不改变协作 Session 的现有统计口径。
- 不改变已有个人模式、Session 解析、增量上传、日报生成和组织权限的其他产品规则。

## 8. 产品待确认

无。本需求以“一个账号只属于一个团队”为已确认前提；若该前提变化，需先修订本需求，再进入架构和开发方案。
