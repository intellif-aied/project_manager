## 1. 测试原则

- 产品验收从 TS-AC-001 至 TS-AC-017 派生；
- 架构验证从 A-01 至 A-08 派生；
- 通过 Prepare/Chunk/Finalize 公开入口和真实 CLI/Web 链路验证，不依赖内部函数名；
- 未配置目录验证必须证明原始 Session 内容未发送；
- 个人统计和日报来源以最终目标成员可见数据为准，构建成功不能代替业务验收。

## 3. 架构决策验证

| 用例 | 架构决策 | 验证内容 | 验证方法 | 通过条件 |

| A-T02 | A-02 | 路径规范化和并发唯一归属 | 数据库并发提交绝对路径及其子路径 | 只有一个成员获得路径，事务结束后无重叠记录 |
| A-T03 | A-03 | 内容上传前路由 | 记录 Prepare 后所有 HTTP/对象存储调用 | 未命中时无 Chunk 和对象写入；命中时 owner 正确 |

## 4. 数据库与接口测试

- fresh PostgreSQL 从 migration 001 执行到 030；
- 从当前最高 migration 029 升级到 030，核对既有 Session 与 Generation 新字段均为 NULL；
- 目录记录的用户必须是保存时当前团队成员；用户迁组后旧团队目录不参与新请求匹配；
- 路径匹配验证 `/home/a` 不命中 `/home/alice`，尾部 `/` 规范化一致；
- Prepare 重复、并发、父子 Session、已有 active/staging Generation 继续符合现有唯一约束；
- 团队与个人 Generation 的 Chunk cursor、hash、Finalize 幂等、Status readiness 和 Abort 清理均通过；
- 当前团队范围内同 `agent_type + session_ref` 的零条、一条和多条查询分别走新建、复用和拒绝分支；
- 两个成员并发 Prepare 同一新 Session 时，团队 Session 身份锁保证只创建一条 Session；
- 历史拆分验证 `sessions` 及直接保存用户归属的 usage、catalog、contribution 和 rollup 数据一致，临时查询快照失效；
- 所有新增错误码具有稳定 HTTP/Prepare 结果映射，不返回数据库错误文本。

## 5. CLI 与 Web 测试

- `aida upload --team` 强制全部扫描，不出现 Session 选择器；不允许与编号选择组合；
- 团队模式只走增量 Prepare/Chunk/Finalize，不调用 legacy batch；
- 个人和团队上传共用现有上传锁；并发执行仍只有一个上传进程；
- `aida auto-sync enable --team` 复用现有时间选择、首次执行和后台恢复；状态输出显示团队模式；
- 旧自动同步配置迁移后仍运行个人 `upload --all`；
- `aida log` 在文件不存在、空快照、多个目录和损坏快照时返回明确结果且不泄露 Session 内容；
- 我的 Token 页面默认不展开目录配置；展开后支持加载、新增、修改、删除和冲突反馈；
- Token 汇总、趋势、Session 表格和筛选不因新增面板发生回归。

## 7. 真实链路验收

测试服准备同一团队的 Alice、Bob 两个有效用户，以及一个未归属目录：

1. Alice、Bob 分别在“我的 Token”配置不同绝对目录；
2. 共享测试机使用 Alice 的个人 Token 登录并开启团队模式；
3. 分别在 Alice、Bob 和未配置目录产生可识别且不含敏感信息的 Codex Session；
4. 执行 `aida upload --team`，保存命令输出、Prepare/Generation ID 和数据库归属证据；
5. 核对 Alice/Bob 各自“我的 Token”、Session 明细和个人日报来源；
6. 核对未配置 Session 无服务端记录和对象内容，并通过 `aida log` 可见；
7. 为未配置目录补充 owner，再次上传并核对成功与日志清除；
8. 使用 Bob 个人模式先上传一个 Session，再由 Alice 登录 Team 模式续传，核对仍归 Bob 且新增 Chunk 接入原 Session；
9. 删除一个已归属 Session 的目录配置，追加本地内容并核对后续内容停止上传、历史内容保留；
10. 将该目录配置给另一成员，核对旧 Session 仍归原 owner，并核对该目录中新 Session 归新 owner；
11. 准备代传账号测试数据，执行历史拆分预检和事务迁移，核对成功、未匹配、冲突清单及迁移后续传；
12. 使用签名有效的过期 Token 复验一次团队上传；
13. 在测试数据上变更登录用户团队后再次 Prepare，核对使用最新团队且无需重新登录；
14. 恢复测试用户组织数据并保存恢复结果。

证据不得包含明文 Token、真实对话内容或完整原始 Session 文件。
