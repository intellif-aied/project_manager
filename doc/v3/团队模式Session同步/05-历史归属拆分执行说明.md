# 历史归属拆分执行说明

> 日期：2026-07-28
> 状态：待测试服执行验收

## 1. 适用范围

用于将曾由一个个人账号代传的全组 Session，按照团队成员已经配置的同步目录，一次性调整到实际成员名下。工具按完整 Session 处理，不拆分 Chunk，不更换 Session ID。

## 2. 执行前提

- 目标团队成员已经在“我的 Token”配置同步目录；
- 已确定目标 `team_id` 和历史代传账号 `source_user_id`；
- 目标团队的个人上传、Team 手动上传和 Team 自动同步均已停止；
- 当前代码 migration 030 已完成。

## 3. 预检

在 `api` 目录执行：

```bash
go run ./cmd/team-session-reassign \
  -database-url "$DATABASE_URL" \
  -team-id "<team_id>" \
  -source-user-id "<source_user_id>"
```

命令只读取数据库并输出 JSON 清单，不修改数据。状态含义：

| 状态 | 含义 | 执行阶段行为 |
|---|---|---|
| `ready` | 唯一命中目标成员且不存在目标身份重复 | 可执行迁移 |
| `unchanged` | 当前 owner 已是目录对应成员 | 保持不变 |
| `unmapped` | CWD 未命中同步目录 | 保持不变 |
| `identity_conflict` | 目标成员已有相同 `agent_type + session_ref` | 保持不变 |
| `family_conflict` | 同一 Session 家族无法整体归属同一成员 | 保持不变 |

## 4. 执行

预检清单确认后增加 `-apply`：

```bash
go run ./cmd/team-session-reassign \
  -database-url "$DATABASE_URL" \
  -team-id "<team_id>" \
  -source-user-id "<source_user_id>" \
  -apply
```

工具重新生成预检计划，只处理执行时仍为 `ready` 的 Session，并在单个数据库事务中：

1. 锁定目标团队的历史拆分操作；
2. 锁定待迁移 Session，并确认不存在 staging Generation；
3. 更新 Session owner；
4. 同步校正 Token、usage、报告来源和 family rollup 的个人归属；
5. 清理受影响用户的临时 Token 查询快照；
6. 提交后将成功项状态输出为 `migrated`。

任一步骤失败时整个事务回滚，不产生部分迁移。

## 5. 执行后核对

- 输出清单中的 `migrated` 数量与预检 `ready` 数量一致；
- 目标成员可查看迁移后的 Session、Token 统计和日报来源；
- 执行 `aida upload --team` 后，新增 Chunk 进入原 Session ID；
- `unmapped`、`identity_conflict` 和 `family_conflict` 对应记录保持原 owner。
