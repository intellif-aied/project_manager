# V3 架构设计：团队模式 Session 同步

> 文档状态：已确认
> 日期：2026-07-28
> 唯一需求基线：[01-需求文档.md](01-需求文档.md)

## 1. 设计边界

- 本文只实现需求基线中的团队模式、个人目录配置、直接个人归属和本地未配置目录日志；
- 复用现有 Session 扫描、Prepare/Chunk/Finalize、内容处理、Token 汇总和日报来源链路；
- 不新增团队账号、团队 Token、设备凭据、独立服务或通用上传框架；
- 文中的职责名称不要求创建公开抽象，内部逻辑通过现有上传入口测试。

## 4. 最小目标架构

### 4.1 目录配置

新增 `team_sync_paths` 保存当前用户在当前团队下配置的规范化绝对目录。Web 请求使用现有普通登录鉴权；服务端从当前用户取得 `team_id`，不接收客户端指定的用户或团队。

新增接口：

```text
GET    /api/v1/me/team-sync-paths
POST   /api/v1/me/team-sync-paths
PUT    /api/v1/me/team-sync-paths/{id}
DELETE /api/v1/me/team-sync-paths/{id}
```

目录写入在团队级事务锁内完成。文件系统根目录 `/` 返回 `400 INVALID_TEAM_DIRECTORY`；不同成员存在相同、祖先或子目录关系时返回 `409 TEAM_DIRECTORY_CONFLICT`；查询和修改只允许当前用户在当前团队下的记录。除 `/` 外，服务端不增加目录层级或宽度判断。

### 4.2 上传路由

`PrepareBatchRequest` 增加可选 `upload_mode`，缺省值为 `personal`。团队 CLI 只发送 `upload_mode=team`，不发送 `team_id`。

现有 `SyncService.Prepare` 内部增加团队路由实现，输入保持为认证 actor、Prepare 元数据和上传模式，输出仍为现有 Prepare 结果。团队路由在同一数据库事务内完成：

1. 按 actor ID 读取当前 `users.team_id`；
2. 规范化 `request.cwd`；
3. 在当前团队目录中按路径边界匹配目录 owner，未命中时返回 `action=rejected`、`error_code=TEAM_DIRECTORY_UNMAPPED`，不创建 Session、Source 或 Generation；
4. 对当前团队和 `agent_type + session_ref` 获取事务级身份锁，再在当前团队全部成员名下查询相同身份；
5. 查询到一条既有 Session 时复用其原 owner；查询到多条时返回 `TEAM_SESSION_IDENTITY_CONFLICT`，不创建 Generation；
6. 未查询到既有 Session 时，以目录 owner 创建新 Session 并固化首次团队归属；
7. 创建 Generation 时记录当前团队、Prepare actor 和本次命中的目录记录。

团队路由是现有 Prepare 模块的内部实现，不为单一调用方增加公开 Provider 或 Adapter。

### 4.3 数据变化

migration 030 新增：

```text
team_sync_paths
  id UUID PK
  team_id UUID NOT NULL FK teams ON DELETE CASCADE
  user_id BIGINT NOT NULL FK users ON DELETE CASCADE
  normalized_path TEXT NOT NULL
  created_at / updated_at
  UNIQUE(team_id, normalized_path)

sessions
  team_upload_team_id UUID NULL FK teams ON DELETE SET NULL
  team_sync_path_id UUID NULL FK team_sync_paths ON DELETE SET NULL
  team_uploaded_by_user_id BIGINT NULL FK users ON DELETE SET NULL
  partial UNIQUE(team_upload_team_id, agent_type, session_ref)

session_source_generations
  upload_team_id UUID NULL FK teams ON DELETE SET NULL
  prepared_by_user_id BIGINT NULL FK users ON DELETE SET NULL
  team_sync_path_id UUID NULL FK team_sync_paths ON DELETE SET NULL
```

`upload_team_id IS NULL` 表示个人 Generation；非空表示团队 Generation。现有数据和个人上传默认保持 NULL。

团队 Prepare 先按当前目录配置确认同步资格，再按当前团队成员范围查询 `agent_type + session_ref`。没有既有 Session 时按目录 owner 创建；只有一条时复用原 Session 和原 owner；存在多条时返回 `TEAM_SESSION_IDENTITY_CONFLICT`。目录被删除或未配置时返回 `TEAM_DIRECTORY_UNMAPPED`，新旧 Session 都不再上传。目录改为其他 owner 后，既有 Session 仍归原 owner，新 Session 归新的目录 owner。原 owner 已不属于当前团队时返回 `TEAM_CONTEXT_CHANGED`，历史数据保留在原 owner。

### 4.4 历史归属拆分

提供一次性受控拆分工具，输入目标 `team_id`，读取该团队已经保存的 `team_sync_paths`，按 `sessions.cwd` 的规范化目录边界生成 Session 级变更清单。工具分为预检和执行两个阶段：

1. 预检只输出唯一命中、未命中、多重命中、目标成员离队和目标身份重复五类结果，不写数据库；
2. 执行只接收预检中的唯一命中记录，并校验受影响 Session 当前无 staging Generation；
3. 单次事务内更新 Session owner，并校正所有按受影响 Session ID 保存个人归属的现行投影，包括 `token_usage`、`session_activity_slices`、`session_usage_components`、`session_daily_usage`、`report_source_slice_catalog`、`session_usage_contributions` 及 token family rollup；
4. Session ID、Source、Generation、Chunk、内容切片、cursor、checkpoint 和对象存储对象均保持原记录；
5. 清理受影响的临时查询快照，使后续查询按校正后的归属重新生成；
6. 提交后输出成功、未处理和冲突清单，按 Session ID 可核对事务结果。

拆分期间目标团队上传保持停止。事务完成并核对后，团队 Prepare 将迁移记录作为目标成员的唯一既有 Session 继续增量同步。该工具不进入每日上传调用链。

### 4.5 Generation 写入权限

Chunk、Finalize、Status、Abort 和 Abort 对象清理统一采用以下规则：

```text
个人 Generation：session.user_id = 当前 actor.id
团队 Generation：generation.upload_team_id = 当前 actor 最新 users.team_id
               且 session owner 最新 users.team_id = generation.upload_team_id
```

认证用户由现有 `CLIAuthMiddleware` 每次请求重新加载。Token 过期继续允许；签名、`nbf`、Aida 用户和启用状态继续使用现有门禁。Prepare actor 或 Session owner 在 Prepare 后迁移团队时，旧 Generation 的后续请求返回 `TEAM_CONTEXT_CHANGED`，不得继续写入旧团队。

Session Clear/Restore 等 owner 操作不使用团队 Generation 权限，继续只允许 `sessions.user_id` 对应用户。

### 4.6 CLI 本地状态和日志

自动同步配置 schema 升级并增加：

```json
{"mode":"personal|team"}
```

缺少 `mode` 的旧配置迁移为 `personal`。登录配置和 Prepare 请求都不持久化或上送 `team_id`。

上传状态 schema 升级，状态键增加 `personal|team` 前缀；旧状态原子迁移到 `personal` 命名空间。

团队运行把 `TEAM_DIRECTORY_UNMAPPED` 按规范化目录聚合，原子覆盖 `~/.aida/team-sync-unresolved.json`。该文件只保存目录、数量和首次/最近发现时间，不保存 Session 内容、摘要或 Token。`aida log` 读取该快照；一次完整团队扫描后已不再未配置的目录从快照移除，网络或真实上传失败时不清空已有快照。

### 4.7 自动同步结果

团队自动同步复用现有时间、更新、锁和恢复流程，只按 `mode` 选择个人全部上传或团队全部上传。

团队运行结果分为：

- 成功或未变化；
- 待配置：仅包含 `TEAM_DIRECTORY_UNMAPPED`，记录日志但退出成功，使当天调度完成；
- 失败：网络、鉴权、团队变化、归属冲突、Chunk、Finalize 或处理失败，保持非零退出码并沿用现有重试。

## 6. 数据流与失败边界

```text
aida upload --team
  -> 扫描 Claude Code/Codex Session
  -> Prepare(upload_mode=team, cwd, metadata, checkpoint)
  -> CLIAuth 加载 actor 最新 team_id
  -> 当前团队目录匹配
       -> 未命中：rejected/TEAM_DIRECTORY_UNMAPPED，不上传内容
       -> 命中：查询当前团队同 agent_type + session_ref
            -> 0 条：按目录 owner 创建 Session
            -> 1 条：复用既有 Session 和原 owner
            -> 多条：rejected/TEAM_SESSION_IDENTITY_CONFLICT
       -> 创建团队 Generation
  -> Chunk：按 Generation 团队和 actor 最新团队授权
  -> Finalize：激活 Generation，创建既有切片和处理任务
  -> 内容、Token、报告来源继续按 sessions.user_id 处理
  -> CLI 汇总未配置目录并更新 aida log 快照
```

Prepare 事务提交前不产生对象存储写入。Chunk/Finalize 继续沿用现有原子 cursor、checkpoint、Generation 和处理任务语义，不增加跨系统事务或补偿流程。

## 7. 权限、容量与兼容性

- Web 目录配置使用现有 Web 鉴权；用户只能管理本人当前团队的目录记录；
- CLI 团队上传全部使用现有允许过期 Token 的 CLI 鉴权；
- 服务端路径匹配使用规范化绝对 Unix 路径和目录边界，不使用简单字符串前缀；
- 每个 Prepare 只查询当前团队目录，增加 `(team_id, normalized_path)` 索引；
- 既有 Personal Prepare 未提供 `upload_mode` 时保持原路径；
- migration 030 对既有行使用 NULL 默认值，不自动回填或改 owner；历史归属只由 A-08 的受控工具处理；
- 团队模式不调用已禁用的 legacy batch fallback；
- 首期客户端范围继续是现有 `upload --all` 支持的 Claude Code 与 Codex。
