# 报告 Agent 语义审核与有界纠错架构设计

> 文档状态：已确认
> 日期：2026-08-07
> 唯一需求基线：[需求文档](02-需求文档-20260807.md)

## 1. 设计边界

- 只覆盖系统默认个人日报；
- 保留现有 Report Context、Report Brief、Report MCP 和 Report Run；
- 逻辑职责优先收敛到现有模块，不为每个概念新建包；
- 本期只新增 Reviewer 必需的一个持久化 Job 和一套系统资产。

| 明确不做 | 不改 Digest、Memory 的归并决策、个人 Agent、非个人日报和前端；Memory 读取端仅兼容 Reviewer 最终 Brief |

## 4. 最小目标架构

```text
Report Agent
  → write_report_result(candidate workstreams)
  → Report Brief Compile（仅结构修复，不使用 Memory 改写）
  → report_review_jobs + parent stage=review_pending
  → Review Worker 提交系统 Reviewer Agent
  → Review MCP 读取冻结 Review Context
  → Reviewer 写 accept / patches / conservative
  → Report Finalizer 应用白名单 Patch 并复用原写回保护
  → daily_reports + snapshot + parent run succeeded
```

`reportbrief.Service` 继续作为深模块：负责候选 Brief 的结构校验、白名单 Patch 应用、确定性渲染和保守降级。Project Memory 只在 Report Context 中提供候选，不进入 Finalizer。

## 6. 数据流与失败边界

1. 原 Report Agent 提交候选后不直接写日报；
2. 候选 Brief 和 Review Context Hash 冻结，Job 幂等创建；
3. 原 Run 切到 `review_pending`，旧 Agent session 完成不会触发 missing-writeback fallback；
4. Review Worker 提交后切 `review_running`；
5. Review MCP 回写时校验用户、Job、Brief Hash、Context Hash 和 Fact 引用；
6. Finalizer 是唯一最终写入口；重复回调返回已完成；
7. Reviewer 不可用：保存候选；Reviewer 已报风险但 Patch 无效：先删目标成果，再保守渲染；
8. Reviewer 未回写而外部任务结束：Review Worker 执行相同降级；
9. 用户在运行期间编辑日报：沿用现有编辑冲突保护，取消 AI 写回。
10. Project Memory 夜间任务优先读取 `report_review_jobs.final_brief_json`，禁止把审核前候选重新写入记忆。

Project Memory 的 `canonical_name` 是用户建立的业务标签，Reviewer 不按字面翻译或重新解释其业务范围。只有关联 Facts 能覆盖多个当天子主题、且当天事实没有明确冲突项目时，Reviewer 才把相关 Workstream 的 `subject` 统一为该项目名；各 Workstream 的 `title` 继续保留具体子主题。仅当子主题确实重复且不超过结构容量时才合并，避免为项目关联丢失日报内容。

项目关联采用 propose-then-verify：Resolver 根据当前 Workstream 文本与已确认 `workstream_cues` 产生 `proposed_targets`；Reviewer 的 `accept` 表示未发现冲突，服务端校验候选项目、目标和 `related_fact_refs` 后确定性应用。Reviewer 发现项目误绑时必须返回 `unsupported_project` 风险而不是接受。模型负责语义判断，服务端负责机械改字段，避免模型判断正确却漏写 Patch。

Review Pack 只向 Agent 暴露候选稿、候选稿已引用 Facts、Project Memory 关联 Facts 和少量高价值遗漏候选。单 Fact 最多保留 800 字符的头尾信息，最多 36 条；Compiler 的 `excluded_facts` 审计清单保留在 Job 中但不发送给 Reviewer，防止 MCP 大输出落盘后诱发 Agent 自行调用文件工具。

`major_omission` 第一阶段允许通过 `add_deliverable` 修复，但只能引用 Review Pack 已冻结的 `review_candidates`，且每次最多新增一个成果；否则只记录观察，不扩展 Context。

## 7. 安全、容量与兼容性

- Review Token 绑定 `review_job_ref + user_id + parent_run_id`；
- Reviewer Context 最多 60 Facts，输入估算不超过约 16k tokens；估算仅作预算，不声称精确模型 Token；
- Reviewer 不能访问 Report MCP、Project Memory 写工具和原始 Session；
- 用户不可见 Reviewer 系统资产；
- Reviewer 默认模型独立配置；配置缺失时降级候选，不阻断 API 启动；
- 非 system personal_daily 不创建 Job。
