## 3. 设计分层

### A. 本期必须完成

- 移除 Compiler Memory 强制归并；
- 候选 Brief 入队、一次 Reviewer、白名单 Patch、最终写回；
- Reviewer 不可用与已识别风险的两类降级；
- 系统资产、配置、迁移和真实测试服链路。

### B. 代码事实触发的必要保障

- 原 Run stage 门禁，避免 status syncer 竞争；
- 幂等回调、Context/Brief Hash 校验和用户编辑冲突；
- Review Agent 系统资产不可见且 Token 绑定当前用户。

### C. 后续增强

- 根据生产编辑数据优化 Review Pack 抽样；
- Reviewer 模型 A/B；
- 管理侧审核命中率展示。

C 类不进入本期实现。

## 9. 系统资产与配置

先使用与 Project Memory 相同的系统资产账号执行 dry-run，再显式 apply：

```bash
cd api
go run ./cmd/report-review-assets
go run ./cmd/report-review-assets -apply
```

所需环境变量：

- `MANAGED_AGENT_URL`、`MANAGED_AGENT_TOKEN`；
- `REPORT_REVIEW_AGENT_ID`；
- `REPORT_REVIEW_MODEL_ID`，默认 `MiniMax-M2.5`；
- `REPORT_REVIEW_SKILL_OWNER`；
- `REPORT_REVIEW_SKILL_VERSION=report-review-v8`；
- `REPORT_REVIEW_MCP_URL`，指向 `/api/v1/mcp/report-review`；
- 资产创建并核验后设置 `REPORT_REVIEW_ENABLED=true`。

Reviewer Agent 由系统账号持有，仅由后端按 Job ID 调用，不加入用户的默认 Agent 列表。

测试服系统资产：`aida-report-review-system-test-v1`，模型 `MiniMax-M2.5`，Skill `aida-report-review@report-review-v8`，MCP `aida-report-review-mcp@report-review-v2`。
