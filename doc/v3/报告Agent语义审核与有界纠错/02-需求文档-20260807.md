# 报告 Agent 语义审核与有界纠错需求文档

> 文档状态：已定稿
> 日期：2026-08-07
> 产品负责人：用户确认
> 适用范围：系统默认个人日报

## 1. 背景

Project Memory 当前既提供历史项目参考，又会在 Report Agent 产出后参与标题替换和 Workstream 合并，造成历史工作项进入当天标题、测试结论被写成确定成果等问题。继续调整 Memory 强弱或增加提示词 case 不能稳定解决职责冲突。

## 2. 产品目标

1. 保留 Project Memory 对跨 Session 项目关联的辅助价值；
2. 防止历史 Memory 改写当天事实、完成状态和工作标题；
3. 由模型对候选日报做一次独立语义审核和必要纠错；
4. 审核链路异常时用户仍能获得一份保守日报。

## 3. 产品规则

### 3.1 REQ-01：当天事实权威

- 适用对象：系统默认个人日报；
- 触发条件：生成候选日报；
- 产品行为：只有冻结的当天 Facts 可以决定成果内容和完成程度；
- 异常行为：历史 Memory 与当天 Facts 冲突时忽略 Memory。

### 3.2 REQ-02：Project Memory 只作候选

- Project Memory 只提供稳定项目身份及相关 Fact；
- Report Agent 可以采用或拒绝候选；
- Compiler 不得根据 Memory 改写标题、补充成果或强制合并 Workstream。

### 3.3 REQ-03：一次独立语义审核

- 系统默认个人日报候选稿写回前，执行一次系统 Reviewer；
- Reviewer 检查事实拔高、限定词丢失、项目误绑、错误合并和明显主要成果遗漏；
- Reviewer 只能引用冻结 Review Context 中的 Facts；
- Reviewer 最多执行一次，不形成开放循环。

### 3.4 REQ-04：审核不阻断日报

- Reviewer 不可用或超时时，保存合法候选稿；
- Reviewer 已明确识别风险但修复无效时，先删除风险项或生成保守稿，不能保存已知错误原稿；
- 内部 Agent、MCP、Schema 和超时错误不得直接展示给用户。

### 3.5 REQ-05：业务隔离

- 个人自定义 Agent、个人 Skill/MCP、周报、团队报告和其他业务维持原流程；
- Reviewer 使用当前报告用户的受限身份读取冻结 Review Context；
- Reviewer 不更新 Project Memory，不读取原始 Session，不影响夜间 Memory 任务。

## 4. 用户流程

用户仍从原入口生成日报并看到统一“正在生成”。系统内部完成候选生成和一次审核后保存日报；不向用户增加 Reviewer 配置或技术状态。

## 5. 验收标准

| 编号 | 产品规则 | 可观察结果 |
|---|---|---|
| R-01 | REQ-01/02 | 当天无 CLI 事实时，历史 Memory 不能把 CLI 写入标题 |
| R-02 | REQ-01/03 | “尚未证明”不能变为确定完成结论 |
| R-03 | REQ-03 | 每份系统默认个人日报最多一个 Reviewer Run |
| R-04 | REQ-04 | Reviewer 失败或超时后报告仍成功生成 |
| R-05 | REQ-04 | Reviewer 已识别风险但 Patch 无效时不保存原风险项 |
| R-06 | REQ-05 | 个人自定义 Agent 与非个人日报行为不变 |

## 6. 非目标

- 不重做 Session Digest、Fact Projection 和 Project Memory 夜间整理；
- 不用 Reviewer 评价发布价值或给出工作建议；
- 不建立无限 Reflection/ReAct 循环；
- 不增加前端配置入口。
