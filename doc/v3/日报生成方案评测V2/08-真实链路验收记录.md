## 3. 首轮回归发现并修复的契约缺陷

1. 15 MB Source Freeze 超过通用 HTTP 30 秒超时：冻结命令增加独立、可配置的 5 分钟默认超时，不放宽普通 API 请求。
2. 一个 Variant Token 无法代表多个用户：Plan 支持按 `case_id` 精确映射凭证。执行前能预检映射完整性、Token 非空/可认证和 Runtime Attestation，但不提前证明 Source 所有权；错账号 Token 会在对应 Case 读取用户隔离 Source 时失败，Bundle 不会完成。
3. StaffDeck Case 把 7 月 28 日成果标在 7 月 29 日：Dataset Loader 与 Bundle Verifier 增加上海自然日约束；跨日事实仅允许 `exclude`。
4. Plan 标记 `MiniMax-M3`，系统默认 Agent 实际仍运行 `deepseek-v4-flash`：Exporter 与 Verifier 增加实际模型一致性校验，旧 Bundle 被准确判为无效。

这些问题均由真实数据暴露，并已增加自动化回归用例；未通过修改样本或放宽校验掩盖。

## 6. 匿名评审闭环

- 在打开 Pairing Map 前完成 10 份匿名单结果 Review；
- AI Review 单独聚合时，因缺少必需 Gold，结论正确保持 `evidence_insufficient`；
- 早期曾用明确标记 `codex-functional-gold-smoke-not-human` 的非人工文件做聚合函数烟测，由此暴露“任意格式正确文件可充当 Gold”的契约缺口；
- 最终契约要求 Gold 声明匿名人工 Reviewer 且 `human_confirmed=true`，非人工烟测文件现在会被拒绝。没有人工 Gold 时结论必须保持 `evidence_insufficient`。

历史重复运行 Bundle 的盲审暴露出当前系统默认流程的真实质量问题，包括环境误标、必需限制遗漏、内部默认凭据进入 Final、产品定位幻觉和超长会话下的随机遗漏。最终独立 Variant Bundle 尚未完成人工 Gold，因此不产生模型质量结论；评测工具没有把 10/10 运行成功误报为质量改善。
