# Project Memory Production Sample V1

该数据集保存真实生产日报的匿名索引，用于检验 Project Memory 历史输入、日报项目归并和最终内容可用性。它不是单一 Gold Baseline，也不能仅凭一项分数判断版本可以发布。

## 数据范围

- 生产只读快照：2026-07-29 至 2026-08-07，共 203 个用户日、27 名用户。
- 分层评测子集：2026-08-03 至 2026-08-07，共 48 个用户日、10 名用户。
- 子集构成：39 份 AI 日报、9 份手写日报、25 份有修改结果、14 份未修改结果、13 份重复生成记录。
- 每个 Case 只注入目标日期之前最多 10 份已有日报；跳过没有日报的日期，不跳过周末。
- 子集累计包含 271 条历史日报引用。

## 分层原则

样本覆盖以下行为，避免只挑容易生成或单一项目的用户：

1. AI 原稿直接保留或未修改。
2. AI 原稿经过明显修改。
3. 同一用户日重复生成。
4. 同一用户同时存在 AI 和手写日报。
5. 历史日报以手写为主。
6. 已知的跨日项目关联典型样本。

## 保存位置与边界

Git 仅保存本 README 和匿名 `manifest.json`。受控原文位于：

    /home/intellif/evaluation/project-memory-production-sample-v1

受控目录包含：

- `raw/exports/`：生产管理接口的每日只读快照与 SHA-256。
- `sample/cases/`：每个匿名 Case 的目标用户日和严格早于目标日的历史日报。
- `sample/mapping.controlled.json`：匿名编号与生产用户映射。
- `sample/targets.controlled.json`：48 个目标用户日的完整内容。
- `sample/SHA256SUMS.txt`：Case 完整性校验。

禁止把员工姓名、生产用户 ID、Token、完整生产日报或 Session 正文提交到 Git。

## 使用方式

1. 先核对 Git `manifest.json` 的 Case 数量和受控文件 SHA-256。
2. Project Memory 测试只读取每个 Case 的 `prior_report_history`，不得读取目标日最终稿作为输入。
3. 日报生成或人工 Review 可对照 `target_user_day` 中的 AI 原稿与最终稿，但最终稿只表示员工实际留存结果，不自动等于 Gold Truth。
4. Project Memory 只能作为弱参考：不得因为历史项目相似而强制覆盖当天 Source。
5. 原始 Session 不在本数据集中；需要端到端重放时，与现有受控 Session 数据集组合使用，不能声称本数据集单独完成了 Session 回放。
6. 所有模型调用只在测试服执行，结果另存候选文件，不覆盖 V1 快照。

## 验收维度

- 项目关联：历史是否帮助恢复稳定父项目，同时避免把新项目误并入旧项目。
- 内容真实性：不得把历史日报内容当成当天已完成事实。
- 归并质量：同一项目的工作是否合理合并，是否出现无意义拆项。
- 内容长度：日报不能退化为过短标题，也不能展开成执行日志。
- 可读性：保留必要专业术语，避免生造技术化表达和无依据结论。
- 稳定性：同一版本重复运行时，核心项目归属和事实范围不应大幅漂移。
