# 日报生成方案评测 V2：评测依据与评分规则

> 文档状态：已确认
> 日期：2026-07-28

## 1. 质量等级

- `pass`：无质量问题；
- `minor`：只有不影响使用的轻微风格、格式或重复问题；
- `unacceptable`：存在需要用户实质修改的问题。

```text
directly_usable_rate = (pass + minor) / reviewed_completed_cases
clean_pass_rate = pass / reviewed_completed_cases
```

## 2. 错误类型

| 类型 | 定义 |
|---|---|
| `FACT_OMISSION` | 重要事实遗漏 |
| `FACT_HALLUCINATION` | 新增无依据事实 |
| `STATUS_UPGRADE` | 错误提升交付状态 |
| `ENVIRONMENT_MIX` | 测试与生产环境混写 |
| `WRONG_GROUPING` | 错误归并改变事实含义 |
| `OVER_COMPRESSION` | 压缩导致有价值信息丢失 |
| `NOISE_RETENTION` | 保留无价值过程或技术噪声 |
| `INTERNAL_LEAKAGE` | 输出内部标识或敏感信息 |
| `REPETITION` | 内容重复 |
| `POOR_READABILITY` | 表达不自然或影响理解 |

事实、状态、环境、归并、过度压缩和泄漏默认为 unacceptable。噪声、重复和可读性按是否影响使用判 minor 或 unacceptable。

### 2.1 评测证据层级

1. 事实是否成立、状态是否准确，只由 Source Evidence Snapshot 和 Evidence Baseline 判定；
2. 日报常见的主题数量、层级、篇幅、合并颗粒度和表达方式，以多用户、多日期的 Production Report Pattern Baseline 为主要参考；
3. 单个 Employee Final Reference 只说明该用户当次的主观取舍，不能作为期望答案，也不能据此判定 Session 中其他真实主题必须删除；
4. AI 草稿与员工修改稿的差异用于发现候选问题，不直接生成排除规则；
5. 任何方案改进必须在多用户、多用户日的配对 Case 上成立，禁止为单个员工或单份日报定制规则。
6. `required` 和 `optional` Evidence 必须发生在该 Case 的上海自然日；相邻日期 Evidence 只能以 `exclude` 记录，不能作为当日应生成事实。

## 3. First Bad Stage

按 Variant 实际阶段顺序对照 Artifact：问题在哪个阶段首次出现，就记录该阶段；后续级联不重复计数。Issue 只允许填写该 Run Manifest 实际存在的阶段或 `unresolved`；缺失阶段只在阶段指标中记为 `not_applicable`，不能作为 Issue 的 First Bad Stage。

## 4. Scorecard

每个 Variant 输出：

- pass/minor/unacceptable 分布；
- Directly Usable 与 clean pass；
- 错误类型和每 Case 错误数；
- First Bad Stage 分布；
- fixed/regressed Case；
- 配对 win/tie/loss；
- 相对 Production Report Pattern Baseline 的主题数量、结构和篇幅分布偏差；
- 成功率、平均/P95 耗时、Token 和成本。

不加权为单一总分。

## 5. AI 与 Gold Review

AI Review 必须输出 grade、issues、error_type、severity、first_bad_stage、evidence_refs、affected_final_refs、confidence 和 `needs_human_review`。每个 `evidence_refs` 必须精确引用该 Case 冻结 Source 的 `evidence_ref` 或 Evidence Baseline 的 `evidence_id`，聚合器拒绝无法回放的引用。

匿名配对不暴露 Variant、模型和方案名称。所有 unacceptable、低置信度、回归和每个 Variant 的抽样 Case 进入 Gold Review。AI Review 必须声明 `reviewer_kind=model` 并记录模型与 Prompt/Skill Hash；Gold Review 必须由人工独立确认，声明 `reviewer_kind=human`、匿名 `reviewer_id` 和 `human_confirmed=true`。AI 结果不能通过改标签充当 Gold，两类结果分开聚合。

Candidate 只有在 Directly Usable 提升，或持平但 clean pass 提升，并且不存在 Gold 确认的新增 unacceptable 回归时，才可得出 `improvement_supported`。`pass → minor` 仍记录为配对 loss，但不单独触发阻断。
