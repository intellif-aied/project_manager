# 日报生成方案评测 V2：架构设计

> 文档状态：已确认
> 日期：2026-07-28

## 1. 依赖边界

V2 复用“生产日报价值观察 V1”建立的 Generation Snapshot、Variant Manifest 和确定性文本差异能力，在测试服运行。V2 不依赖生产页面，也不读取生产数据库。

## 2. 目标架构

```text
Draft Dataset
  → 已证明的 Evaluation Runtime 冻结 Digest 前 Source Evidence
  → Frozen Dataset（Source + Evidence Baseline + Pattern Baseline + Hash）

Frozen Dataset + 基线/候选 Variant
  → 对每个 Case × Variant 预检凭证存在性和独立 Runtime Attestation
  → 在对应 Runtime 顺序运行现有 Report 链路
  → 通过受控接口保存实际 Digest / Context / Brief / Final / Metrics
  → 导出 Evaluation Bundle
  → 确定性检查
  → Codex + gpt-5.6-sol 单结果与匿名配对 Review
  → Gold Review
  → Scorecard + fixed/regressed + First Bad Stage
  → Evaluation Conclusion
```

CLI 不连接 PostgreSQL 或 MinIO。服务端 Evidence/Artifact Adapter 在鉴权、`environment=test` 且评测开关开启后，隐藏 Selection 查询、规范事件读取、脱敏和 Artifact 查询实现。

## 3. 公平比较

端到端共同边界始终是 Source Evidence Snapshot 到 Final。Variant 内阶段可以不同：

- 无 Brief Variant 的 Brief 指标为 `not_applicable`；
- 不同 Digest 实现分别保存实际 Artifact；
- 只有契约可比的同名阶段并列比较；
- 阶段不同不改变 Final 的统一 Rubric；
- Source Evidence 文件在任何 Variant 运行前冻结，Digest 不属于 Source 文件；
- Variant 可运行于不同隔离 Runtime，但 Source 文件 Hash 和报告任务必须一致；
- Plan 显式填写 `model_id` 时，实际 Variant Manifest 的 `model_id` 必须完全一致；系统默认 Agent 忽略单次模型覆盖时，评测立即失败，禁止用错误标签形成伪 A/B；
- 同一 `variant_version` 在全部 Case 和重复中只允许一个实际 Manifest Hash；不同 Variant 不得共享同一实际 Manifest Hash；
- 同时改变多个变量时只评价整体 Variant。

## 4. 可选阶段评测

- Digest：Evidence 覆盖、状态/环境保真、噪声、确定性结构和耗时；
- Brief：Fact 引用/排除守恒、Deliverable `fact_refs`、归并、状态/环境和校验重试；
- Final：事实、状态、环境、归并、压缩、泄漏、重复、可读性和 Directly Usable；
- 不存在或不可比阶段明确为 `not_applicable`。

## 5. Evaluation Bundle

Bundle 绑定 Dataset、Variant、Rubric、Case 清单和所有输入 Hash。每个 Run 包含实际 Variant Manifest、Source Evidence、存在的阶段 Artifact、Generated Draft 和运行指标。

任一回归 Case 缺失、Hash 不一致或必需 Artifact 不完整时，不生成版本优劣结论。

## 6. 关键架构决策

### A-01：Source 与 Digest 分离

对应需求：R-02、R-04、R-09。当前代码事实：旧 Exporter 将 `selection_digest_payload` 放入 Source Evidence。待解决问题：无法定位 Digest 遗漏，也无法比较不同 Digest。候选方案：继续使用 Digest；或读取规范事件并在运行前冻结。选择方案：由 Evidence Adapter 读取固定 Slice 的 Digest 前规范事件，写入带 Hash 的 Source 文件，Digest 只作为 Variant Artifact。验证证据：Source 文件 Hash 跨 Variant 一致且 Digest 可不同。是否已确认：是。

### A-02：服务端受控 Adapter

对应需求：R-09、R-10。当前代码事实：服务端已拥有 DB、MinIO、用户身份和内容读取器，旧 CLI 直接连接数据库且仅凭参数声明测试环境。待解决问题：CLI 可能连错库并复制底层查询。候选方案：强化 CLI 数据库校验；或由服务端提供测试专用 Adapter。选择方案：服务端在双重开关和用户鉴权后提供 Runtime Attestation、Source Freeze 与 Run Artifact 读取；CLI 不持有数据库连接。验证证据：生产默认关闭、测试端到端和拒绝用例。是否已确认：是。

### A-03：每 Variant 独立 Runtime

对应需求：R-02、R-10。当前代码事实：旧 Runner 只有一个 Base URL 和一个账号 Token，只能切换 Agent 和模型。待解决问题：无法比较不同代码、Digest 或 Projection，也无法执行多个真实用户日。候选方案：单 Runtime 动态切配置；或 Plan 为每个 Variant 指定 Runtime，并按 Case 声明凭证环境变量。选择方案：每个 Variant 指定 Runtime URL；单账号计划可使用一个 Token 环境变量，多账号计划必须按 `case_id` 完整映射 Token 环境变量。首个 Run 前预检 Token 非空、可认证且 Runtime Attestation 有效；该预检不宣称证明 Token 的 Source 所有权，错账号 Token 会在对应 Case 读取用户隔离 Source 时被服务端拒绝，因此不产生有效 Bundle。实际 Manifest 在 Run Artifact 返回后校验。验证证据：两个不同 Runtime Adapter 的配对测试及五账号真实 Dataset。是否已确认：是。

### A-04：约束式 Baseline 与形态 Baseline 分层

对应需求：R-03、R-09、R-11。当前代码事实：旧 Evidence Baseline 为任意 JSON，生产手写日报尚未进入 Scorecard。待解决问题：空 Baseline 可评审，跨日事实可能被错误标成当日必需项，手写稿又不能当事实 GT。候选方案：标准全文；或结构化 Evidence Baseline 加聚合 Pattern Baseline。选择方案：事实采用结构化 Evidence Item/关系/禁止断言，`required/optional` 引用受上海自然日约束，形态只报告聚合分布偏差。验证证据：Schema 拒绝空 Baseline、未知引用和跨日可报告引用，Scorecard 输出分布且不改变事实等级。是否已确认：是。

### A-05：计划身份必须与实际 Variant 一致

对应需求：R-02、R-04、R-10。当前代码事实：系统默认 Agent 会使用服务端配置模型，可能忽略请求中的模型覆盖。待解决问题：Plan 标签和实际运行模型不一致时会形成不可复现的伪比较。选择方案：Exporter 与独立 Bundle Verifier 都校验 Plan 的显式 `model_id` 与实际 Variant Manifest；不一致时拒绝 Bundle。验证证据：真实链路成功拦截了标记为 MiniMax-M3、实际为 deepseek-v4-flash 的五个 Run。是否已确认：是。

### A-06：Variant 标签绑定唯一实际身份

对应需求：R-02、R-04、R-10。当前代码事实：只校验单个 Run 的 Manifest Hash 时，同一标签仍可能跨 Case 漂移，两个标签也可能实际执行完全相同方案。待解决问题：伪 A/B 可通过完整性校验。选择方案：Exporter 在落盘最终 Manifest 前、独立 Verifier 在复核 Bundle 时，都强制同一 `variant_version` 只映射一个实际 Manifest Hash，且不同 Variant 的实际 Hash 必须不同。验证证据：标签漂移、共享实际 Manifest 的单元测试和旧重复运行 Bundle 拒绝记录。是否已确认：是。

## 7. 执行边界

- 内部脚本运行现有 Report 链路，不建设通用 DAG；
- Codex Skill 只读冻结 Bundle，不连接数据库；
- Reviewer 不进入生成请求；
- AI 与 Gold Review 分开保存；
- 结论不触发发布、切流或代码修改。
- 生产默认不暴露 Source/Artifact，评测开关与环境证明任一不满足即拒绝；
- Variant Manifest 的不可变记录属于运行身份，不代表生产开启评测。
