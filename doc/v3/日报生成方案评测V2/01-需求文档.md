# 日报生成方案评测 V2：需求文档

> 文档状态：已确认
> 日期：2026-07-28
> 范围：测试服默认 Report Agent `personal_daily`

## 1. 产品目标

1. 对每个候选 Generation Variant 执行一次可重复的标准评测；
2. 在相同 Source Evidence 上比较基线和候选方案；
3. 输出 Directly Usable、修复 Case、回归 Case和错误类型变化；
4. 在实际存在的阶段中定位 First Bad Stage；
5. 给出“改善证据成立 / 改善证据不成立 / 证据不足”结论。

评测结果只交还生成链路开发会话，不决定发布。

## 2. 产品规则

### 2.1 Variant

任何影响结果的 Digest、Context、阶段结构、模型、Prompt、Skill、契约、校验规则或代码变化都形成新 `variant_version`。同时改变多个变量时，只评价完整 Variant，不单独归因某个模型。

Manifest 至少记录 `pipeline_profile`、代码 Revision、阶段顺序、各阶段实现/schema、模型、Prompt Hash、Skill Ref/Hash、校验规则和配置 Hash。不适用字段为 `not_applicable`。

### 2.2 公平比较

基线和候选必须使用相同 Dataset、Source Evidence、报告任务、Rubric、重复次数和超时口径。阶段可以不同；端到端统一比较 Source Evidence 到 Final 的结果。

有 Brief 和无 Brief、不同 Digest 或新增阶段都可比较。阶段指标只在双方存在且契约可比时并列；否则分别记录，不影响端到端公平比较。

### 2.3 评审

- 确定性代码检查覆盖 Hash、完整性、引用、禁止标识和结构契约；
- Codex + `gpt-5.6-sol` 执行单结果与匿名配对 AI Review；
- 所有 unacceptable、低置信度、回归和抽样 Case 进入 Gold Review；
- AI 与人工结果分开保存。

### 2.4 结论

- `改善证据成立`：Directly Usable 提升，或持平但 clean pass 提升，且无新增 Gold 确认的 unacceptable 回归；
- `改善证据不成立`：评测完整但无改善，或存在 unacceptable 回归；
- `证据不足`：Case、证据或必需 Gold Review 不完整。

## 3. 验收标准

| 编号 | 可观察结果 |
|---|---|
| R-01 | 每个 Run 可还原唯一 Variant Manifest |
| R-02 | 2～3 个 Variant 在同一固定 Dataset 上完成配对运行 |
| R-03 | 每个 Case 有 pass/minor/unacceptable 和 Directly Usable |
| R-04 | 每个实质问题有错误类型和 First Bad Stage 或 unresolved |
| R-05 | 输出 fixed/regressed Case 和三态 Evaluation Conclusion |
| R-06 | Digest、Brief、Final 阶段指标按实际阶段可选计算 |
| R-07 | 成功率、耗时、Token 和成本可比较 |
| R-08 | Codex Skill 可从完整 Bundle 生成结构化结果和 Markdown 报告 |

## 4. 非目标

- 生产日报价值页面和用户行为日常统计；
- 在线 Reviewer 或用户评分；
- 通用 DAG、任意阶段编排或通用评测平台；
- 自动模型排名、选择、切流或发布；
- Holdout、多人一致性和完整数据集治理平台；
- 其他报告和普通 Agent。
