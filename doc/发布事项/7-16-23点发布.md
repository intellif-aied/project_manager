# 7-16 23点发布

> 发布目标：API（Session Digest v2.8 + Session readiness）与 Aida CLI `0.1.14`
>
> 当前状态：已于 2026-07-17 完成生产发布，处于 48 小时兼容观察窗口。

## 1. 本次发布范围

### 1.1 API

- 新报告固定使用 `session-digest/v2.8.0`，读取策略由 `reportsource.ProductConfig()` 随 API 镜像发布；
- Digest v2 Reconciler/Worker 固定启动，首期 batch/并发为 1；
- 删除 Digest 模式、版本、容量、rollout/canary、Worker 开关/批量等 12 个部署配置项；
- Report Skill/MCP slug、MCP 协议版本、凭据槽、默认 Agent 文案和资产修复策略改为代码内部契约；
- 部署只保留 Managed Agent 地址/Token、默认引擎/模型、Skill owner/version、MCP URL 等环境绑定；
- 提供 `GET /api/v1/session-syncs/{generation_id}/status`，供 Aida CLI 查询服务端 readiness；
- 使用 migration `020_report_digest_v2.sql`，不新增本次配置收敛专用 migration；
- API 返回结构、Session 上传协议、Token 统计和 Web 交互不因配置收敛改变。

### 1.2 CLI `0.1.14`

不能用测试服现成产物覆盖生产。

主要改动：

- 每次执行业务命令检查最新版本，发现新版本后下载、校验、替换并重新执行当前命令；
- 安装脚本不再接收或写入 `AIDA_TOKEN`，用户统一执行 `aida login` 输入个人令牌；
- 登录时隐藏令牌输入；
- `aida upload` 使用 Bubble Tea Session 选择器，保留非 TTY 的传统交互兼容；
- Codex 主 Session 与 fork sub-agent 按父子关系分组，默认只展示根 Session，不显示无实际选择价值的 sub-agent 数量；
- 选择分组后逐个检查主 Session 和 sub-agent，按 Session ID 去重；
- Session 列表使用组内最后活动时间，显示到秒；
- Session 列表固定使用双行布局：第一行显示最后活动时间、工作目录和首条有效用户需求摘要，第二行显示客户端、完整 Session ID 和用户或 Agent 的最新消息；
- 首条摘要和最新消息按终端显示宽度严格水平对齐，中文宽字符也纳入宽度计算；
- Claude Code/Codex 的 IDE、环境、Skill、权限等结构化注入不会进入首条摘要，Codex `outcome` 等机器控制消息不会进入最新消息；
- sub-agent 的目录、Session ID 和 agent path 仍作为隐藏搜索字段，选择根 Session 后继续随根 Session 上传；
- 上传完成后轮询服务端权威 readiness，区分 `ready`、`processing`、`current snapshot` 和 `failed`；
- Session 索引升级到 v4，首次运行会重新扫描并生成新摘要，之后继续使用缓存。

以下逻辑与生产 `0.1.5` 保持一致：

- Prepare/Chunk/Finalize 增量上传协议；
- 服务端返回 `expected_cursor` 后从该位置继续读取；
- prefix checkpoint 校验；
- 每个 Session 独立维护 cursor 和上传状态；
- 单 chunk 最多 500 个事件、最大 500 MiB；
- 无新增内容时 `UploadedChunks=0`，不会重复全量上传；
- 只有服务端返回 `rebuild_required`、checkpoint 不一致或服务端历史状态丢失时才重建。

## 5. 不同版本用户行为

### 5.1 `0.1.4` 及更早版本

- 无法进入当前自动升级链路；
- 当前生产上传接口已不再兼容；
- 必须重新执行生产安装脚本：

```bash
curl -fsSL http://113.100.143.91:9180/statics-live/aida/install.sh | bash
aida login
```

### 5.2 `0.1.5`

- 可以继续正常使用，前提是生产 API 保持兼容；
- 每 24 小时最多检查一次新版本；
- 24 小时不是固定时间点，而是距离 `last_update_check` 满 24 小时后，用户下一次执行 `login/sessions/upload/status` 时检查；
- 检查到 `0.1.14` 后在后台替换二进制；
- 本次命令仍由 `0.1.5` 执行，下一条命令开始使用 `0.1.14`；
- 用户可执行 `aida update` 绕过 24 小时等待。

注意：`0.1.5` 在发起下载前会更新 `last_update_check`。若当时网络失败，用户需要执行 `aida update` 立即重试，或等待下一个周期。

### 5.3 `0.1.6` 至 `0.1.13`

- 每次业务命令都会检查更新；
- 检查到 `0.1.14` 后立即下载、校验、替换并重新执行原命令；
- 如果其 `release_url` 仍指向 14.157 测试源，不会发现生产版本，需要重新执行生产安装脚本。

### 5.4 `0.1.14`

- 检查到版本相同后直接正常执行；
- 不重复下载。
- 若测试期间以相同版本号覆盖发布物，安装脚本会因版本相同跳过下载；正式生产禁止同版本覆盖，修复包必须增加版本号。

## 6. 发布后验收

先使用生产测试账号，不使用个人账号做首轮验收。

### 6.1 安装与升级

- 空 HOME 执行生产 `install.sh`，版本为 `0.1.14`；
- 配置中的公网、内网和 release 地址正确；
- 原 Token 在覆盖安装后保留；
- 从 `0.1.5` 执行 `aida update`，下一条命令为 `0.1.14`；
- `aida status` 能根据网络选择 internal/public 路由。

### 6.2 Session 列表

- 普通 Claude Code、普通 Codex Session 正常展示；
- Codex fork Session 按根 Session 折叠；
- 默认列表不显示 sub-agent 数量和独立子 Session 行；
- 最后活动时间与组内最新事件一致；
- 第一行依次显示最后活动时间、工作目录和首条有效用户需求摘要；
- 第二行依次显示客户端、完整 Session ID 和“最新消息”，最新消息可以来自用户或 Agent；
- 两行摘要在 168 宽终端中严格水平对齐，长文本按显示宽度截断且不换乱布局；
- IDE/环境/Skill/权限注入、命令前缀和机器控制消息不进入摘要；
- 子 Agent 的摘要、目录、Session ID 和 agent path 可以搜索到所属根 Session；
- 首次索引 v4 重建允许等待，完成后第二次扫描应明显变快。

首次重建时间取决于本地历史日志大小。14.159 已使用 217 个原始 Session 完成真实扫描和 85 个根 Session 聚合回放；结构化注入、命令前缀和机器控制消息残留均为 0。后续缓存扫描应明显快于首次重建。

### 6.3 增量上传

选择一个包含 sub-agent 的根 Session，记录每个成员上传前后的 cursor：

- 主 Session 和 sub-agent 分别执行 prepare；
- 已上传且无新增内容的成员显示 `chunks=0`/`unchanged`；
- 有新增内容的成员只上传 `expected_cursor` 之后的数据；
- 不出现无原因的 `rebuild_required`；
- 上传完成后 readiness 最终为 `ready`，报告 Session 列表可见；
- Token 不因父子分组重复累计。

## 7. 观察与兼容窗口

发布后至少 48 小时继续接受 `0.1.5`，重点观察：

- `/session-syncs/prepare`、chunk、finalize、status、abort 的 4xx/5xx；
- `uploading`、`processing`、`upload_failed` 的数量和停留时间；
- `rebuild_required` 和 checkpoint mismatch 是否异常增长；
- `0.1.5` 用户是否能继续上传；
- 首次索引重建是否被用户误认为卡死；
- fork Session Token 是否出现重复。

不要在兼容窗口结束前把 API 最低版本直接提高到 `0.1.14`。

## 8. 回滚

客户端出现问题时：

1. 暂停切换或恢复生产 `aida-latest.txt` 为 `0.1.5`，阻止尚未升级用户继续升级；
2. 已升级到 `0.1.14` 的客户端不会自动降级；
3. 保留新版 API，不回滚增量上传协议和数据库结构；
4. 修复后发布更高版本，或让受影响用户重新执行指定版本安装；
5. 不直接复制测试服产物到生产。

回滚前必须保存生产 `0.1.14` 三平台产物及 `SHA256SUMS.txt`，便于复盘。
