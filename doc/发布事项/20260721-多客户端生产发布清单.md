## 5. API、migration 和 Web 发布清单

### 5.1 API

API 必须先于 CLI 版本发现文件发布。新 API 需要同时满足：

- 旧 `/session-syncs` 上传、parser、Token、成本和 digest worker 行为保留；
- `/canonical-session-syncs/prepare` 已注册并复用现有 CLI 鉴权；
- 生产 release policy 只放行 `client_version=0.1.17` 的 `opencode-v1`、`kimi-code-v1`、`openclaw-v1`；
- 三个 Adapter 最大 usage capability 均为 `unavailable`；
- WorkBuddy 不在 release policy 中；
- canonical 失败不得回退到 legacy 上传入口。

### 5.2 migration 026

API 启动自动执行 `026_canonical_session_sources.sql`。发布记录必须确认：

- `schema_migrations` 最高版本由 `025` 变为 `026`；
- 旧 source 默认 `source_format=legacy_native_v1`；
- canonical source 使用 `aida_event_v1`；
- 新增 metadata/owner 字段不会触发历史回填；
- migration 前后 users、sessions、active generation 等核心数量没有异常下降。

本迁移为前向兼容迁移，不执行反向 DROP。若上线失败，优先 forward fix；不得删除 migration 026 新增列或约束。

### 5.3 Web

Web 只有客户端显示映射变化，但生产需要发布，否则新增 Session 会退化为原始 agent_type 文案。Web 与 API 使用同一目标 Git SHA 的不可变镜像标签。

## 8. 停止与回退边界

### 8.1 立即停止

出现任一情况停止继续发布：

- Claude Code/Codex 扫描、上传、Token、成本或 auto-sync 回归；
- migration 026 失败或核心数据数量异常下降；
- API 持续 5xx、数据库锁等待异常、处理任务 dead 持续增长；
- CLI 正式包包含测试服地址、版本不是 `0.1.17` 或 SHA256 不一致。

单个新增 Adapter 失败不允许修改旧上传链路。当前独立关闭 Adapter 需要修改服务端 release policy 并发布新的 API 镜像，不存在可直接修改的生产环境变量开关。

### 8.2 回退

- CLI：在切换 `aida-latest.txt` 前可直接停止；切换后可恢复版本发现文件以阻止未升级用户，但已升级客户端不会自动降级，应发布更高修复版本。
- Web：恢复发布前不可变镜像标签。
- API：尚无 canonical 写入时可评估恢复旧镜像；已有 canonical 写入后优先 forward fix，旧 API 不应处理 canonical source。
- migration：保留 026，不反向删除字段或约束。
- 数据：本次没有回填、清理或删除任务，不应产生数据回退动作。
