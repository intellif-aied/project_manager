Review 范围：

- 前端：`web/`，重点包含工作台、AI Assets、登录与全局用户菜单

基础校验结果：

## 严重程度说明

- 高：可能导致越权、服务崩溃、数据不一致或重复执行，建议上线后优先处理。
- 中：影响安全边界、产品可信度或用户体验，建议近期修复。
- 低：维护性、性能或交付规范问题，可纳入后续优化。

## 遗留问题

### 1. 会话详情接口缺少权限范围校验

- 严重程度：高
- 位置：`api/handler/session.go:147-204`
- 现象：`Get` 通过 UUID 直接返回会话详情，没有像列表接口一样按角色、本人、团队做范围过滤。
- 影响：知道 session UUID 的登录用户可能读取其他人的会话元数据，包括 summary、tool calls、commit、需求/任务关联、日志对象名等。
- 建议：抽取统一的 `canViewSession` 权限判断，详情、下载、关联更新后的刷新逻辑都复用同一套规则。

### 2. MinIO 未配置时批量上传日志可能触发 API panic

- 严重程度：高
- 位置：`api/main.go:33-42`、`api/handler/session.go:289-307`
- 现象：`minioStore` 可以为空，但批量上传接口只要带了 `file_xxx` multipart 文件，就会直接调用 `h.store.Upload`。
- 影响：在 MinIO 未配置或初始化关闭的环境中，上传原始日志文件会触发空指针，导致 API 请求崩溃。
- 建议：上传前显式判断 `h.store != nil`；未配置存储时返回可控 warning 或忽略文件上传。

### 3. 需求创建不是事务，且忽略团队关联写入错误

- 严重程度：高
- 位置：`api/handler/requirement.go:174-188`
- 现象：先创建 requirement，再循环插入 `requirement_teams`，但未检查每次插入错误，也没有事务。
- 影响：无效 team、重复 team、FK 失败或部分写入失败时，接口仍可能返回 201，留下缺少目标团队或孤立的需求数据。
- 建议：创建需求、团队关联、自动关注逻辑放入同一事务；所有 team_id 先校验存在性和权限范围。

### 4. 定时任务执行缺少数据库级 claim，API 多实例可能重复触发

- 严重程度：高
- 位置：`api/main.go:77`、`api/handler/managed_agent.go:3672-3695`
- 现象：调度器查询 due schedule 后，普通更新 `next_run_at`，没有 `FOR UPDATE SKIP LOCKED`、旧 `next_run_at` 条件、advisory lock 或 rows affected 校验。
- 影响：多 API 实例或调度器重复启动时，同一个定时任务可能被多个实例同时执行。
- 建议：采用事务内 claim 机制，例如 `UPDATE ... WHERE id = ? AND next_run_at = ? RETURNING`，或 `SELECT ... FOR UPDATE SKIP LOCKED`。

### 5. Agent 运行详情只刷新 task 型运行，session 型运行容易展示旧状态

- 严重程度：中高
- 位置：`api/handler/managed_agent.go:2157-2183`
- 现象：运行详情接口只在 `external_task_id` 存在时主动刷新；部分 Agent 运行通过 managed session 创建，只写入 `external_session_id`。
- 影响：前端轮询运行详情时，session 型运行需要等待后台 syncer；syncer 延迟或异常时页面会长时间停留在 pending/running。
- 建议：运行详情刷新逻辑同时支持 `external_task_id` 和 `external_session_id`，或增加 session 型运行的即时刷新方法。

### 6. 任务创建依赖写入失败会留下半创建任务

- 严重程度：高
- 位置：`api/handler/task.go:223-240`
- 现象：先插入 task，再插入 dependencies；如果依赖写入失败，接口返回 500，但 task 已经创建。
- 影响：产生无依赖或依赖不完整的任务，需求进度和任务关系可能不一致。
- 建议：任务创建、依赖写入、需求进度更新、自动关注放入同一事务。

### 7. Dashboard 仍保留大量硬编码 demo 业务数据

- 严重程度：中
- 位置：`web/src/features/aidashboard/dashboard/DashboardPage.tsx:433-939`
- 现象：`ROLE_DATA` 中包含固定人员、需求、日期、风险、指标等 demo 数据；后续虽然合并 API 数据，但空数据或部分数据场景仍可能显示假业务内容。
- 影响：对外演示时容易被认为是 demo 页面，影响产品可信度。
- 建议：将静态业务数据替换为空态、骨架屏或真实接口数据；只保留纯文案配置。

### 8. dev secret 和默认 secret 仍可能进入真实环境

- 严重程度：中
- 位置：`docker-compose.yml:41-57`、`api/config/config.go`、`api/handler/auth.go`、`api/handler/managed_agent.go`
- 现象：compose 和代码默认值中仍有 `devpassword`、`dev-jwt-secret`、默认 MinIO 密钥等开发配置。
- 影响：如果真实环境缺少环境变量，可能使用弱 secret 或开发默认凭证启动。
- 建议：区分 dev compose 和上线 compose；非开发环境缺少关键 secret 时应 fail fast。

### 9. 接口大量直接返回内部错误文本

- 严重程度：中
- 位置：`api/handler/middleware.go:37-40`、`api/handler/requirement.go:63-81`、`api/handler/managed_agent.go:232-246`
- 现象：多处直接将 `err.Error()` 返回给客户端。
- 影响：可能暴露数据库表名、SQL 约束、上游服务地址、认证失败细节，前端 toast 也会显得不正式。
- 建议：服务端记录详细错误，客户端返回稳定错误码和正式文案。

### 10. 数据库迁移执行不是事务

- 严重程度：中
- 位置：`api/db/connect.go:29-88`
- 现象：每个 migration 直接执行 SQL，再单独写入 `schema_migrations`。
- 影响：如果 SQL 半执行失败，或执行成功但记录版本失败，数据库可能进入难以恢复的半迁移状态。
- 建议：每个 migration 尽量包裹在事务中，迁移 SQL 和版本记录在同一事务内提交。

### 11. 用户菜单暴露一键复制 Bearer Token

- 严重程度：中低
- 位置：`web/src/shared/auth/UserMenu.tsx:59-75`
- 现象：用户菜单提供“复制 Token”，失败文案还引导用户查看 localStorage。
- 影响：对正式环境不够安全，也会让普通用户接触不应感知的认证细节。
- 建议：移除该入口，或只在 debug 开关、管理员角色下展示。

### 12. Vite dev 服务配置暴露面偏大

- 严重程度：低
- 位置：`web/vite.config.ts:21-32`
- 现象：dev server 使用 `host: "0.0.0.0"` 和 `allowedHosts: true`，HMR host 存在硬编码默认值。
- 影响：作为内网开发环境可接受，但不适合作为对外或长期共享部署方式。
- 建议：限制 `allowedHosts`，通过环境变量显式配置暴露地址。

### 13. 存在未使用且行为不一致的旧调度 runner

- 严重程度：低
- 位置：`api/service/managed_agent_scheduler.go`
- 现象：service 层仍有一套 `ManagedAgentScheduleRunner`，但实际入口使用 handler 层 runner。
- 影响：两套逻辑字段和行为不同，后续维护容易误改或误用。
- 建议：确认无引用后删除旧实现，或迁移为唯一实现。

### 14. AI Assets 页面无论当前 tab 都请求运行历史

- 严重程度：低
- 位置：`web/src/features/aidashboard/ai-assets/pages/AIAssetsPage.tsx:285-289`
- 现象：页面初始化时总是请求 `agent-runs`，即使当前不在运行历史 tab。
- 影响：增加不必要接口请求，数据量变大后影响首屏性能。
- 建议：只在运行历史 tab 激活时启用该 query。

4. 清理产品化观感和安全边界：问题 7、8、9、11。
5. 后续维护优化：问题 10、12、13、14。
