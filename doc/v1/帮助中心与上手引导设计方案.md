# 帮助中心与上手引导设计方案

> 文档状态：发布版方案，暂不进入开发。
>
> 更新原因：早期方案编写时，工作台、需求任务、日报周报、AI 资产的交互还没有稳定。当前版本已经接近发布，页面能力和用户路径变化较大，因此需要按发布版真实交互重新梳理帮助中心与上手引导。

## 结论

发布版仍然不建议做传统的“首次登录强制弹窗 + 多步骤遮罩引导”。

当前平台已经是一个以工作台为入口、围绕需求任务推进、日报周报和 AI 生成辅助的企业级工作台。用户真正需要的不是被强制看完教程，而是在真实操作时快速知道：

- 我今天应该先看哪里。
- 这条事项为什么需要我处理。
- 这个风险到底是什么导致的。
- 我该点进需求还是任务。
- 我为什么没有权限操作。
- 日报/周报如何补写、如何 AI 生成。
- 什么时候需要配置默认报告 Agent。

因此，发布版更合适的形态是：

1. 帮助中心：Header 右侧入口，右侧 Drawer 打开，承载完整指南。
2. 当前页面帮助：根据路由展示当前页面的使用说明。
3. 角色化上手清单：在帮助中心内展示，不强制打断用户。
4. 上下文帮助：在禁用按钮、空状态、权限失败、复杂表单旁给出解释。

整体目标不是做一个文档站，而是让用户在工作流里少迷路、少问人、少误操作。

## 发布版产品现状

### 1. 工作台

当前工作台已经是发布版主入口，核心区域包括：

- 我的事项。
- 我的风险提示。
- 报告处理。
- Token 用量。

其中，“我的事项”和“我的风险提示”已经支持分页加载、展开全部、需求/任务弹窗下钻。

发布版帮助必须重点解释：

- 我的事项包含我创建、我关注、我负责、与我相关的需求和任务。
- 我的风险提示不是普通通知，而是风险诊断摘要。
- 需求和任务都可能出现在我的事项里，这是合理的，因为用户可能既关心整个需求，也单独关注某个关键任务。
- 风险里需要区分需求逾期、任务逾期、依赖阻塞、依赖冲突。
- 点击事项或风险后，优先在工作台内打开需求详情抽屉或任务详情弹窗，不再要求用户一定跳到需求看板。

### 2. 需求看板

当前需求看板已经从简单列表演进为完整的需求任务工作区：

- 顶部 scope：我的事项、关注、负责、创建、全部。
- 视图切换：阶段看板、需求列表。
- 阶段看板：待开始、评审、进行中、完成。
- 需求详情：右侧抽屉。
- 任务详情：居中 Modal。
- 任务拆解：在需求详情中创建、查看、编辑任务。
- 上游依赖：创建/编辑任务时选择依赖任务，支持分页加载。
- 风险追溯：任务详情里可看到依赖阻塞、上游依赖、风险说明。
- 操作记录：需求和任务都有动态记录。
- 关注度：按关注人的角色权重聚合，展示为普通关注、一般关注、重点关注、高关注。
- 多负责人：需求和任务负责人都支持多人。

发布版帮助必须把“需求、任务、依赖、风险、操作记录”作为一条连续流程解释，而不是分散说明。

### 3. 日报与周报

当前日报/周报已经支持：

- 个人日报、个人周报。
- 小组日报、小组周报。
- 部门日报、部门周报。
- 选择日期补写日报。
- 选择周期管理周报。
- AI 生成。
- 生成设置。
- 个人日报/个人周报选择 Session 切片。
- 小组/部门报告沿用范围内数据，不提供个人 Session 选择。
- 未配置默认报告 Agent 时提示去 AI 资产配置。

发布版帮助必须解释：

- “填写日报/周报”是主要入口，不要只理解为今日/本周。
- 历史日期可以补写。
- AI 生成会覆盖当前正文，需要先确认。
- 个人报告可以选择 Session 切片，小组/部门报告不选择个人 Session。
- 默认报告 Agent 是 AI 生成的前置条件。

### 4. AI 资产

当前 AI 资产包含：

- 我的 Agents。
- 我的 Skills。
- 我的 MCP。
- 定时任务。
- 运行历史。
- 默认报告 Agent。
- Agent 运行页。
- 报告 Agent 运行参数。
- Session 切片选择。
- MCP 凭证。
- 删除确认。

发布版帮助不应该把 AI 资产写成技术文档。对普通用户只需要解释：

- 默认报告 Agent 用于日报/周报 AI 生成。
- 如果未配置默认报告 Agent，AI 生成入口会提示去配置。
- 运行历史用于查看 Agent 执行结果。
- Skill/MCP 是 Agent 的能力来源，普通用户通常只需要知道“它们由平台或管理员维护”。
- 模型 ID 为空时，必须由 Agent 默认模型或本次运行手动填写。

### 5. Token 用量与 Session

当前 Token 页面和报告生成都围绕 Session 切片展开：

- Session ID 需要完整展示，便于用户和本机 Codex 会话对应。
- Session 按活动时间切片，不是按上传时间或 session 开始时间简单归类。
- Token 页面用于查看 Session、Token 消耗、活动时间。
- 报告生成时，个人报告可以选择 Session 切片，作为报告上下文过滤条件。

发布版帮助必须解释 Session 切片的业务含义，避免用户误解为“一个 Session 就是一整天内容”。

### 6. 组织与权限

当前角色包括：

- 管理员。
- 总监。
- PM。
- TL。
- 员工。

权限已经细化到页面可见、按钮可点、接口可操作。帮助内容应解释“为什么能看不能改”，但不要在帮助里堆复杂权限矩阵。

## 设计原则

### 不打断

首次登录不弹强制遮罩，不要求用户点完所有步骤。

上手清单放在帮助中心内，也可以在工作台轻量露出，但不应遮挡核心工作。

### 按工作流组织

帮助内容不按数据库对象组织，而按用户任务组织。

例如：

- 处理一个风险。
- 创建一个需求并拆任务。
- 补写一份日报。
- 用 AI 生成报告。

### 按角色推荐

不同角色的上手任务不同，但帮助中心的完整内容仍可访问。

角色化只用于推荐优先阅读内容，不用于隐藏用户需要的解释。

### 就地解释优先

按钮禁用、接口 403、空状态、复杂字段，应优先在当前页面解释。

帮助中心解决“想系统了解”的问题，上下文帮助解决“我现在为什么不能操作”的问题。

### 避免技术文档口吻

尤其是 AI 资产、MCP、Session 切片相关内容，应尽量用业务语言解释。

不建议在用户界面中出现：

- credential slot。
- MCP endpoint。
- token 注入。
- skill 快照。
- selected_session_slice_keys_json。

这些可以作为开发文档内容，不应作为业务帮助主文案。

## 帮助中心信息架构

### 入口

建议在 Header 右侧增加一个帮助入口。

- 图标：`QuestionCircleOutlined` 或同类帮助图标。
- Tooltip：帮助中心。
- 点击打开右侧 Drawer。

不建议第一期新增左侧菜单“帮助中心”，原因：

- 帮助是辅助能力，不应与工作台、需求看板、日报周报平级。
- Drawer 可以保留当前页面上下文。
- 用户看完后能直接回到原操作。

### Drawer 结构

帮助中心 Drawer 建议包含四块：

1. 当前页面帮助。
2. 角色上手清单。
3. 常用指南。
4. 常见问题。

桌面宽度建议 440px-520px。移动端全屏。

### 当前页面帮助

根据路由自动匹配内容。

| 路由 | 当前页面帮助重点 |

| `/dashboard` | 我的事项、我的风险提示、报告处理、Token 用量、如何下钻需求/任务 |

## 角色化上手清单

上手清单不做强制流程，建议作为帮助中心里的“推荐先完成”。

### 员工

1. 查看工作台里的我的事项。
2. 打开一个任务详情，确认负责人、截止日期、上游依赖。
3. 更新一次任务状态或进度。
4. 查看任务是否存在风险或阻塞来源。
5. 填写或补写一份日报。

### TL

1. 查看小组相关需求和风险。
2. 给成员创建或分配任务。
3. 为任务设置上游依赖。
4. 查看任务操作记录，确认关键变更。
5. 管理小组日报或小组周报。

### PM

1. 创建一个跨团队需求。
2. 指定需求负责人和参与团队。
3. 关注一个重点需求，观察关注度变化。
4. 查看我的风险提示，并下钻到风险任务。
5. 检查需求的任务拆解、验收标准和操作记录。

### 总监

1. 查看部门风险和高关注需求。
2. 下钻到需求详情，确认负责人和任务完成情况。
3. 查看小组/部门日报周报。
4. 关注重点需求。
5. 检查风险是否来自逾期、依赖阻塞或依赖冲突。

### 管理员

1. 检查组织成员、角色和小组。
2. 确认 PM、TL、员工的权限范围。
3. 查看 AI 资产中的默认报告 Agent。
4. 检查 Agent 运行历史。
5. 处理用户无法访问或无法操作的问题。

## 当前页面帮助内容草案

### 工作台

工作台用于快速查看今天最需要处理的事项。

- 我的事项：展示我创建、我关注、我负责或与我相关的需求和任务。
- 我的风险提示：展示逾期、依赖阻塞、依赖冲突等需要处理的风险。
- 点击事项或风险，可以在当前页面打开需求详情或任务详情。
- 如果一条需求和它下面的任务都出现在列表中，通常表示用户既需要关注整体需求，也需要关注某个关键任务。
- 报告处理可以填写或查看日报/周报。
- Token 用量展示近期 AI 工作记录和消耗趋势。

### 需求看板

需求看板用于推进需求和任务。

- 我的事项、关注、负责、创建、全部用于切换业务范围。
- 阶段看板按需求阶段展示，需求列表适合批量查看和筛选。
- 点击需求打开右侧需求详情抽屉。
- 需求详情中可以查看负责人、参与团队、任务拆解、验收标准、关联 Session、操作记录。
- 点击任务可以打开任务详情弹窗。
- 任务详情中可以修改状态、进度、负责人、上游依赖、验收标准，并查看风险和操作记录。

### 日报

日报支持查看记录、补写历史日期、直接填写和 AI 生成。

- 点击“填写日报”可以打开日报管理弹窗。
- 日期旁的日历用于切换目标日期。
- AI 生成会基于当前报告日期和默认报告 Agent 生成正文。
- 个人日报可以在生成设置中选择 Session 切片。
- 小组日报和部门日报按组织范围汇总，不选择个人 Session。
- 保存后可在记录中查看和继续编辑。

### 周报

周报支持个人、小组、部门三类范围。

- 个人周报可直接填写，也可以 AI 生成。
- 个人周报可以选择 Session 切片，用于限定生成上下文。
- 小组周报和部门周报更关注成员日报、需求进展、风险和下周计划。
- 历史周报可在记录中打开。

### AI 资产

AI 资产用于管理 Agent、Skill、MCP、定时任务和运行历史。

- 默认报告 Agent 用于日报/周报的 AI 生成。
- 如果未配置默认报告 Agent，报告弹窗会提示去 AI 资产配置。
- 运行历史用于查看 Agent 执行状态和结果。
- Skill 表示 Agent 的能力说明，MCP 表示 Agent 可调用的数据服务。
- 普通用户通常只需要关注默认报告 Agent 是否存在、运行是否成功。

### Token 用量

Token 用量用于查看 AI 工作记录和消耗。

- Session ID 是真实会话 ID，便于和本机记录对应。
- 同一个 Session 可能按日期或活动时间切成多个片段。
- 活动时间表示该切片实际覆盖的时间范围。
- 个人报告生成时可以选择这些切片作为上下文。

## 上下文帮助清单

### 禁用按钮

关键按钮 disabled 时应说明原因。

| 场景 | 建议提示 |
| --- | --- |
| AI 生成不可用 | 请先配置默认报告 Agent |
| Agent 运行按钮不可用 | 请填写模型 ID 或检查必填参数 |
| 无法编辑需求 | 当前账号没有编辑该需求的权限 |
| 无法修改任务状态 | 当前账号不是任务负责人，或没有状态更新权限 |
| 无法删除任务 | 只有具备任务管理权限的角色可以删除 |
| 无法选择 Session | 当前报告范围不支持手动选择个人 Session |

### 空状态

空状态不要只写“暂无数据”，要告诉用户下一步。

| 场景 | 建议文案 |
| --- | --- |
| 暂无我的事项 | 当前没有需要你处理或关注的事项，可前往需求看板查看全部需求 |
| 暂无风险提示 | 当前没有命中逾期、阻塞或依赖冲突的风险 |
| 暂无任务 | 可以在需求详情中创建任务并指定负责人 |
| 暂无日报 | 可以直接填写日报，或在配置默认报告 Agent 后使用 AI 生成 |
| 暂无运行历史 | 运行 Agent 后会在这里显示执行记录 |

### 权限失败

接口返回 403 时，不应跳转 403 页面。应停留在当前页面并提示：

- 当前账号没有修改负责人权限。
- 当前账号不能编辑该需求。
- 当前账号不能管理该任务。
- 当前账号不能访问该资源。

如果用户能访问页面，只是某个动作没有权限，应使用 toast 或表单错误提示。

## 技术实现建议

### 前端结构

建议新增轻量 feature：

```text
web/src/features/aidashboard/help/
  components/
    HelpDrawer.tsx
    HelpEntryButton.tsx
    OnboardingChecklist.tsx
    CurrentPageHelp.tsx
  data/
    helpArticles.ts
    onboardingChecklists.ts
    routeHelpMap.ts
  types.ts
```

`HelpEntryButton` 接入 Header 右侧。

`HelpDrawer` 可以先放在 Header 或 MainLayout 内部，避免新增全局状态。

### 数据结构

一期使用 TypeScript 静态配置，不引入后台配置。

```ts
type HelpArticle = {
  id: string;
  title: string;
  category: string;
  roles?: UserRole[];
  routes?: string[];
  summary: string;
  content: React.ReactNode | string;
};

type OnboardingItem = {
  id: string;
  title: string;
  description?: string;
  route?: string;
  roles: UserRole[];
};
```

### 状态存储

一期可以使用 localStorage：

```text
aida_help_drawer_seen
aida_onboarding_dismissed
aida_onboarding_completed_item_ids
```

后续如果需要跨设备同步，再考虑用户偏好接口。

### 路由匹配

规则：

1. 精确路径优先。
2. 动态路径按父级模块兜底。
3. 无匹配时展示通用帮助。

例如：

- `/ai-assets/agents/:id/run` 匹配 Agent 运行帮助。
- `/requirements/create` 匹配新建需求帮助。
- `/requirements` 匹配需求看板帮助。

### 暂不做

- 富文本编辑器。

## 验收标准

一期完成后应满足：

1. 用户可以从 Header 打开帮助中心。
2. 用户在不同页面看到不同的当前页面帮助。
3. 不同角色看到不同的上手清单。
4. 上手清单可以关闭，刷新后不反复打扰。
5. 工作台帮助能解释我的事项和我的风险提示。
6. 需求看板帮助能解释需求、任务、依赖、风险、操作记录。
7. 日报/周报帮助能解释日期补写、AI 生成、Session 切片。
8. AI 资产帮助能解释默认报告 Agent 和运行历史。
9. Token 帮助能解释 Session 切片和活动时间。
10. 关键禁用按钮能说明原因。
11. 403 操作失败停留当前页面并展示中文提示。
12. 帮助中心不影响现有菜单、权限和业务接口。

## 风险与取舍

### 风险 1：帮助内容过多，用户不看

处理方式：每篇指南控制在 300-800 字，当前页面帮助优先展示最关键 3-5 条。

### 风险 2：AI 资产解释太技术

处理方式：业务用户只解释默认报告 Agent、运行历史和模型 ID；Skill/MCP 放在“了解更多”里。

### 风险 3：上手清单打扰用户

处理方式：不强制弹窗，允许关闭和不再显示。

### 风险 4：页面变化导致帮助过期

处理方式：一期使用静态配置，但按模块集中维护。每次发布前把帮助内容加入回归检查。
