# 四角色流程与权限矩阵

## 1. 角色定义

| 角色 | 系统值 | 工作范围 | 报告范围 |
| --- | --- | --- | --- |
| 工程师 | `employee` | 本人创建、本人负责或本组参与的需求，以及本人有管理权限的任务 | 个人日报、个人周报 |
| 团队负责人 | `team_leader` | 本人创建、本人负责或所属团队参与的需求与任务 | 个人、小组成员、小组汇总日报周报 |
| 产品经理 | `pm` | 全部需求与任务，可跨团队推进 | 个人日报、个人周报 |
| 部门总监 | `director` | 全部需求与任务，可跨团队管理和审计 | 个人、部门成员、部门汇总日报周报 |

管理员不纳入用户指南，也不显示指南入口。

## 2. 快速开始

四个角色共享同一条首次成功路径：复制个人 Token → 安装 AIDA 客户端 → `aida login` → `aida status` → `aida upload` → 从工作台打开个人日报 → 选择日报归属日期 → AI 生成 → 检查结果。AI 生成完成后正文已经自动保存；人工修改正文或明日计划后再保存。日报弹窗顶部的日期决定报告归属；打开 Session 选择抽屉后，其中的开始日期和结束日期仅用于筛选候选 Session。

完成标准是目标日期的日报已经保存并出现在“我的日报记录”，不是只完成客户端安装或 Session 上传。未手动选择 Session 时，系统按目标日期冻结默认 Session 来源快照；选择后，勾选的切片成为唯一允许使用的 Session 证据，即使切片跨天或位于报告日期之外也不会被日期再次过滤。

## 3. AIDA 客户端与 Session 上传

四个角色流程相同：

1. 按操作系统安装 AIDA 客户端。
2. 从右上角个人菜单选择“复制 Token”。
3. 执行 `aida login`，按提示粘贴个人令牌；当前 AIDA 服务环境由安装脚本自动配置。
4. 执行 `aida status` 核对登录身份。
5. 执行 `aida upload` 进入全屏选择器，在其中检查项目、时间和摘要；使用方向键移动、Space 勾选、`/` 搜索，确认后按 Enter 上传。
6. 回到 Session 页面检查记录；日报与周报的 Session 选择器会读取已上传记录。

上传采用增量切片模型：首次成功上传形成一个切片；同一 Session 有新增内容后再次上传，只上传新增部分并形成新的独立切片；没有新增内容、上传失败或重复操作不产生新切片。一次上传的新增内容即使横跨多天，也仍是一个完整切片。`aida upload --all` 会处理全部本地可发现 Session，不只是最近记录，首次使用不建议执行。

安全边界：令牌不得出现在需求、日报、周报、聊天或截图中；Session 摘要可能包含终端命令、内部地址或凭据，上传前必须检查。

## 4. 工作台

### 通用流程

1. 查看“我的事项”，优先判断阶段、负责人、截止时间和风险。
2. 选择事项详情，下钻到需求抽屉或任务弹窗。
3. 查看“我的风险提示”，处理需求逾期、任务逾期、依赖阻塞和依赖冲突。
4. 在“报告处理”确认当天日报和本周周报状态。
5. 通过日报、周报入口进入完整历史记录。
6. 查看 Token 使用趋势；管理角色还可查看团队范围汇总。

### 角色差异

| 能力 | 工程师 | 团队负责人 | 产品经理 | 部门总监 |
| --- | :---: | :---: | :---: | :---: |
| 本人事项与风险 | 是 | 是 | 是 | 是 |
| 小组日报、周报处理 | 否 | 是 | 否 | 否 |
| 部门日报、周报处理 | 否 | 否 | 否 | 是 |
| 团队 Token 汇总 | 否 | 小组 | 否 | 部门 |

## 5. 需求看板

### 5.1 查找需求

1. 在“我的事项、关注、负责、创建、全部”之间切换范围；具体可见数据仍由后端权限决定。
2. 在阶段看板与需求列表之间切换。
3. 使用关键词、阶段、优先级和风险筛选。
4. 选择需求卡片打开需求详情。

### 5.2 创建需求

团队负责人、产品经理和部门总监可以看到“新建需求”；工程师不显示该入口。

创建时必填标题、需求描述、至少一名负责人和优先级；参与团队、截止日期、飞书文档和验收标准可按需补充。创建后继续拆分任务。

校验规则：标题最多 120 个字符且不能包含换行、制表符或不可见控制字符；描述最多 10000 个字符且不能包含不可见控制字符；飞书文档填写时必须是最长 2048 个字符的 `http` 或 `https` 链接；验收标准最多 50 条，每条最多 1000 个字符。

### 5.3 需求详情

详情抽屉保持单一滚动责任：抽屉外壳不滚动，任务、验收、动态在各自内容区滚动。

1. 顶部确认标题、阶段、优先级和主要操作。
2. 概览直接展示需求说明，不再把描述藏在独立标签中。
3. 有权限时快捷编辑截止时间、负责人和参与团队。
4. 在“任务”中拆分和推进执行项。
5. 在“验收”中核对完成条件。
6. 在“动态”中查看关键变更。
7. 标签栏右侧使用“关联 session”管理需求级工作记录。

### 5.4 任务与依赖

任务负责人更新状态与进度时，前端必须保持 `done`、`progress`、`completed_at` 一致；需求和任务更新携带 `base_version`，冲突时刷新后重新编辑。

依赖流程：选择当前任务 → 添加上游任务 → 核对阻塞关系与截止时间 → 上游完成后确认阻塞解除。依赖关系不是普通备注，错误依赖会直接进入风险统计。

任务创建必填标题、至少一名负责人和优先级；标题最多 120 个字符，上游依赖最多 50 项，验收标准最多 50 条且每条最多 1000 个字符。进度范围为 0% 至 100%；“阻塞”由依赖和时间关系推导，不作为可手动保存的任务状态。

### 5.5 权限边界

能打开需求不等于能修改全部字段。页面以接口返回的能力字段决定是否显示编辑、阶段修改、任务创建、依赖和验收操作；无权限时仍可阅读说明、任务、验收与动态。

| 能力 | 工程师 | 团队负责人 | 产品经理 | 部门总监 |
| --- | --- | --- | --- | --- |
| 查看需求 | 本人创建、本人负责或本组参与 | 本人创建、本人负责或本组参与 | 全部 | 全部 |
| 新建需求 | 否 | 是 | 是 | 是 |
| 编辑需求、阶段、依赖与验收 | 本人创建或本人负责的需求 | 本人创建、本人负责或本组参与的需求 | 全部 | 全部 |
| 新建任务 | 在可见且未取消的需求中，仅能指派给自己 | 在本人管理范围内，负责人仅限本组 | 任意未取消需求，可跨团队分配 | 任意未取消需求，可跨团队分配 |
| 编辑任务 | 本人创建、本人负责，或本人可管理需求下的任务；不能改派负责人 | 本人创建、本人负责、本组成员负责，或本人可管理需求下的任务 | 全部 | 全部 |
| 设置任务依赖 | 仅限本人有任务管理权限的任务 | 仅限本人有任务管理权限的任务 | 全部 | 全部 |
| 关联 Session | 可将本人的 Session 关联到本人可见需求 | 同左 | 同左 | 同左 |
| 查看动态、关注需求 | 本人可见需求 | 本人可见需求 | 全部需求 | 全部需求 |

“本组参与”指需求的参与团队包含当前用户所属小组，并不自动表示工程师可以编辑需求。工程师只有在自己是需求创建者或负责人时才具备需求管理权限。删除需求还要求当前用户具有需求管理权限，且需求不存在阻止删除的关联数据。

## 6. 日报

### 6.1 个人日报

所有角色均可：按日期范围查看记录、折叠预览、展开全文、复制 Markdown、编辑历史记录和填写任意日期日报。个人日报记录展开后，在完整正文下方继续显示明日计划；没有填写时显示“未填写”。

编辑流程：通过日历图标选择日期 → 填写正文 → 可选填写最多两行的明日计划 → 直接保存，或用 AI 生成 → 检查已经自动保存的正文 → 人工修改后再保存。明日计划仅由用户人工维护，AI 生成或重新生成不得填写、修改或清空。个人日报可按需选择 Session，但这不是 AI 生成的前置条件：未选择时系统按目标日期冻结默认 Session 来源快照；选择后，已勾选切片是唯一允许使用的 Session 证据。报告 Agent 仍可读取日期范围内的事项、需求和已有报告，这些非 Session 数据不会改变已选切片的来源优先级。

Session 选择只用于个人日报。候选列表默认不限制日期、每页 5 条，翻页保留已选记录；日期范围只筛选候选切片，清空选择后恢复按日报日期取数。摘要可能包含敏感上下文，选择前应检查。个人日报和部门汇总日报弹窗均可通过日期旁的日历图标切换目标日期。

### 6.2 成员与汇总

| 视图 | 工程师 | 团队负责人 | 产品经理 | 部门总监 |
| --- | :---: | :---: | :---: | :---: |
| 个人日报 | 是 | 是 | 是 | 是 |
| 成员日报 | 否 | 小组成员 | 否 | 部门成员 |
| 汇总日报 | 否 | 小组汇总 | 否 | 部门汇总 |

成员日报用于晨会快速浏览：折叠状态读取成员、提交状态和一行预览；展开后查看完整 Markdown 或复制全文。小组日报汇总本组成员已经保存的个人日报，部门日报汇总所属小组已经保存的小组日报；两者不使用个人 Session 选择器，也不会在下级报告缺失时回退读取成员原始 Session。打开小组汇总或展开部门汇总记录时，明日计划均位于完整正文下方。

## 7. 周报

个人周报按自然周管理。所有角色均可查看、展开、复制、编辑和补写自己的历史周报；生成前确认目标周，可按需选择 Session 切片。候选列表默认不限制日期，允许选择目标周以外或跨天切片；目标周只决定周报归属和默认取数周期，不会过滤已选切片。

| 视图 | 工程师 | 团队负责人 | 产品经理 | 部门总监 |
| --- | :---: | :---: | :---: | :---: |
| 个人周报 | 是 | 是 | 是 | 是 |
| 成员周报 | 否 | 小组成员 | 否 | 部门成员 |
| 汇总周报 | 否 | 小组汇总 | 否 | 部门汇总 |

成员周报适用于周会快速浏览。小组周报汇总成员已经保存的个人周报，部门周报汇总所属小组已经保存的小组周报；不会在下级报告缺失时回退读取原始 Session。AI 生成完成后正文已经自动保存，人工修改后再保存。

## 8. 角色主链路

### 工程师

AIDA 上传 Session → 工作台处理本人事项与阻塞 → 在需求中维护本人任务 → 填写个人日报 → 填写个人周报。

### 团队负责人

AIDA 上传 Session → 工作台处理本人和小组风险 → 创建或管理团队需求与任务 → 浏览成员日报并形成小组日报 → 浏览成员周报并形成小组周报。

### 产品经理

AIDA 上传 Session → 工作台关注跨团队交付 → 创建、拆解并推动跨团队需求 → 维护个人日报和周报。

### 部门总监

AIDA 上传 Session → 工作台查看部门风险和报告状态 → 从需求看板下钻跨团队问题 → 浏览部门成员日报并形成部门日报 → 浏览部门成员周报并形成部门周报。
