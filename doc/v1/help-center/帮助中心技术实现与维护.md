# 帮助中心技术实现与维护

## 1. 设计原则

帮助中心采用“一个内容模型、按角色过滤、按当前页面进入”的方案，不维护四套重复文档。

- 快速开始是第一个一级入口，以“保存第一份 AI 日报”为首次成功目标，串联 Token、客户端、Session 上传和日报生成。
- AIDA 客户端保留完整安装、登录、上传和排障说明，不与快速开始重复展开全部细节。
- 工作台、需求、日报、周报按用户任务组织文章，不按代码目录组织。
- 只有已配置帮助模块的业务路由显示入口；打开抽屉后默认进入“快速开始”，用户可继续浏览其他模块。
- 当前角色过滤文章、章节和截图。
- 正文优先：抽屉宽度为 `min(1040px, 100vw)`，左侧导航 184px，桌面端文章列表使用双列。
- 文章截图可点击预览原图。

## 2. 前端结构

```text
web/src/layouts/
  Header/
    Header.tsx                 顶部入口与管理员排除
  HelpCenter/
    HelpCenter.tsx             抽屉、搜索、文章、代码复制、截图预览
    HelpCenter.css             内容优先布局与响应式样式
    helpCenterConfig.ts        路由到帮助模块的映射
    helpCenterContent.ts       角色化文章数据

web/public/help-center/screenshots/
  v1/                          首版业务页面与旧客户端截图
  v2/                          页面或客户端改版后的替换截图
```

## 3. 内容模型

`HelpArticle` 以模块、角色、路由、关键词和章节组成。文章与章节都可限定角色；截图还可再次限定角色，因此同一篇文章可以只向当前身份展示对应界面。

章节支持：段落、步骤、要点、提示、可复制命令和截图。AIDA 客户端命令块使用深色高对比样式，复制操作兼容安全上下文 Clipboard API 与旧浏览器回退。

## 4. 路由映射

| 路径 | 帮助模块 |
| --- | --- |
| 全局一级栏目（无独立业务路由） | 快速开始 |
| `/sessions*` | AIDA 客户端 |
| `/dashboard` | 工作台 |
| `/requirements*`、`/tasks*` | 需求看板 |
| `/reports/daily*` | 日报 |
| `/reports/weekly*` | 周报 |

其他页面不显示使用指南。Header 在角色为 `admin` 时不创建入口。

业务角色首次进入系统时，Header 在“使用指南”入口展示一次锚定提示，不自动展开抽屉。提示按用户 ID 和引导版本记录在浏览器本地；点击页面其他区域不会关闭提示，用户打开指南或选择“稍后”后才记为已读，后续访问不再反复打扰。管理员不展示入口，也不创建首次提示记录。

## 5. 搜索与导航

搜索覆盖文章标题、摘要、关键词、章节正文、步骤、要点、提示和命令。输入只更新草稿，按 Enter 或选择搜索按钮后执行，清空输入立即恢复当前模块。

文章底部“前往对应页面”使用文章配置的路由导航，并关闭抽屉。打开新模块会清空搜索与文章选择，避免保留不相关状态。

## 6. 截图规范

1. 只通过真实登录账号和可见 UI 采集，不注入令牌。
2. 从本次规范生效后，业务页面截图统一使用 1680px 浏览器视口宽度；不得再新增小屏幕、窄窗口或移动端截图。既有截图无需追溯重拍，后续因页面改版而替换时再按 1680px 标准执行。
3. 截图前固定浏览器缩放为 100%，等待页面数据和动画稳定；同一批次尽量使用一致的视口高度，并裁掉与操作无关的大面积空白。
4. 文件名只使用 ASCII，按角色目录与页面顺序命名。
5. 不截登录表单、Token、Cookie、localStorage、开发者工具或终端凭据。
6. Session 摘要可能包含内部地址、命令和密码；未经逐条检查不得采集 Session 列表截图。
7. 页面改版或角色权限变化时更新截图并升级目录版本，例如 `v2/`；旧版本保留到文章引用迁移完成。

快速开始中的 Session 上传步骤使用真实 CLI 输出截图。客户端安装和登录直接使用可复制命令，不要求截图。更新 CLI 截图时，应使用专用安全 Session，并逐项检查 Token、内部地址、密码、项目路径和 Session 摘要；不得将未经脱敏的个人终端截图直接放入帮助中心。

当前全屏 Session 选择器截图位于 `web/public/help-center/screenshots/v2/quickstart/04-aida-cli-upload.png`。该图片必须由当前 AIDA 二进制在隔离 HOME 中读取专用安全 Session 后生成；`v1` 中的旧行式选择器截图仅保留历史，不再被文章引用。

## 7. 内容更新流程

1. 修改页面功能或权限，并先确认新的产品口径。
2. 更新 `helpCenterContent.ts` 中相关步骤、角色和关键词。
3. 使用对应角色登录，走完受影响流程。
4. 将浏览器视口宽度设为 1680px，更新截图资产和本目录截图索引。
5. 执行前端 lint、typecheck、test、build。
6. 在 14.157 开发环境使用对应测试角色执行 Playwright 浏览器回归；视觉判断无法自动确认时，再补充人工验收。
7. 检查所有图片请求成功，文章搜索与“前往对应页面”可用。
8. 发布时将代码和 `web/public/help-center/` 静态资产一起交付。

## 8. 为什么暂不做独立后台

当前帮助内容与前端路由、权限和页面版本强绑定，使用 TypeScript 内容源可以获得编译期校验、版本评审和同版本发布。内容规模明显增长、需要非研发人员频繁编辑、需要发布审批或多语言时，再将文章迁移到后端 CMS；迁移时保留现有 `HelpArticle` 契约作为 API DTO。

## 9. 回归要求

- 四个业务角色都能打开指南，并只看到自身可执行流程。
- “快速开始”始终是左侧第一个模块，AIDA 客户端紧随其后。
- 管理员看不到入口。
- `/tasks/*` 直接打开时仍归入需求指南。
- 搜索、返回、模块切换、代码复制、图片预览、页面跳转和遮罩关闭均可用。
- 桌面端正文有效宽度充分；小于 768px 时导航转为横向滚动且文章单列。

## 10. 需求负责人规则的一致性检查

产品规则与用户指南均按“创建和编辑需求时至少选择一名负责人”维护。前端创建、完整编辑和快捷编辑使用同一必填校验，后端也会拒绝空的 `responsible_user_ids`；后续修改任一入口时，必须同时回归其他入口和后端接口。
