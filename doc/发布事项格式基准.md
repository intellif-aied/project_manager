# 发布事项格式基准

本基准定义 `doc/发布事项/` 下单次发布文档的固定格式。发布文档用于执行、核对和记录，不用于记录讨论过程。

## 一、适用范围

适用于测试发布、生产发布、API/Web/CLI 发布、Skill/MCP/Agent 发布、数据库 migration 发布和回滚记录。

单次发布文档必须对应一次明确的发布范围。不同环境、不同版本或不同发布批次不得混写。

## 二、固定章节顺序

每份发布文档必须按以下顺序包含章节：

1. 发布元数据；
2. 发布范围；
3. 版本与代码证据；
4. 变更项清单；
5. 发布前检查；
6. 执行步骤；
7. 发布后验收；
8. 回滚与停止条件；
9. 最终结果。

不得删除章节。没有内容的章节填写“不涉及”，并说明核对依据。

## 三、发布元数据

必须填写：

| 字段 | 要求 |
| --- | --- |
| 发布编号 | 唯一、可检索，格式为 `YYYYMMDD-序号-简短名称` |
| 目标环境 | 明确填写测试服或生产，不得写“线上”或“环境” |
| 发布负责人 | 填写实际执行人 |
| 发布目标 | 一句话描述用户可见结果 |
| Git 基线 | API、Web、CLI 分别填写 SHA；同一仓库也要分别标明组件 |
| 版本 | 填写 API/Web/CLI/Skill/MCP 实际版本；不适用填写“不涉及” |
| 时间 | 记录开始时间、结束时间和时区 |

## 四、发布范围

发布范围表必须覆盖以下项目：

| 范围 | 可选状态 | 必填内容 |
| --- | --- | --- |
| API/后台 | 发布 / 仅核对 / 不涉及 / 阻断 | 镜像、SHA、接口和依赖 |
| Web | 发布 / 仅核对 / 不涉及 / 阻断 | 镜像、SHA、构建结果 |
| AIDA CLI | 发布 / 仅核对 / 不涉及 / 阻断 | 版本、平台产物、安装脚本、校验文件、版本发现文件 |
| PostgreSQL migration | 发布 / 仅核对 / 不涉及 / 阻断 | 文件、执行顺序、幂等和对账 |
| 历史数据回填 | 发布 / 仅核对 / 不涉及 / 阻断 | 命令、范围、数量、失败数和对账 |
| 数据清理/删除 | 发布 / 仅核对 / 不涉及 / 阻断 | 目标、授权、备份、恢复边界 |
| Report Skill | 发布 / 仅核对 / 不涉及 / 阻断 | owner、slug、version、SHA256 |
| MCP/默认 Agent | 发布 / 仅核对 / 不涉及 / 阻断 | URL、凭据槽、Agent 配置和调用结果 |
| MinIO/对象存储 | 发布 / 仅核对 / 不涉及 / 阻断 | 对象路径、权限、hash 和容量 |
| Digest/报告链路 | 发布 / 仅核对 / 不涉及 / 阻断 | Digest、Context、Run、报告写回 |
| 监控/配置/文档 | 发布 / 仅核对 / 不涉及 / 阻断 | 文件、配置、告警和链接 |

“发布”表示本次有实际变更；“仅核对”表示没有变更但必须验证兼容性；“不涉及”必须有依赖检查依据；“阻断”禁止继续发布。

## 五、变更项清单

每个变更项使用一行表格记录：

| 变更项 | 文件/提交/版本 | 状态 | 验证命令或运行证据 | 影响范围 |
| --- | --- | --- | --- | --- |

变更项只记录事实，不写讨论、争论、过程复盘或额外宣传语。用户指出遗漏时，只在对应范围补充项目。

## 六、发布前检查

必须逐项勾选并记录证据：

- [ ] 工作区状态和发布 SHA 已冻结；
- [ ] API/Web/CLI 构建结果已记录；
- [ ] migration 在空库和生产数据副本验证；
- [ ] 生产现有容器、镜像、配置和 migration 已记录；
- [ ] 数据库、配置和回退镜像备份已记录；
- [ ] Skill/MCP/Agent 的 owner、version、hash 和凭据槽已核对；
- [ ] 测试账号和生产测试账号已明确区分；
- [ ] 本次不涉及的组件已完成依赖检查；
- [ ] 生产停止条件和回滚边界已填写。

## 七、执行步骤

执行步骤必须按实际顺序编号，包含执行主机、命令或操作、预期结果和实际结果：

| 步骤 | 执行主机 | 操作/命令 | 预期结果 | 实际结果 |
| --- | --- | --- | --- | --- |

生产发布通常按以下顺序执行：

1. 冻结版本和范围；
2. 记录现状和备份；
3. 构建并推送不可变镜像；
4. 执行正向 migration；
5. 更新 API 并检查；
6. 更新 Skill/MCP/默认 Agent；
7. 更新 Web；
8. 构建并发布 AIDA CLI；
9. 从发布地址下载复验；
10. 执行发布后验收。

实际顺序不同必须在步骤表中记录原因和影响，不得只写“已部署”。

## 八、发布后验收

验收必须区分自动化、接口、真实账号和浏览器人工结果：

| 验收类别 | 用例 | 账号/数据 | 预期结果 | 实际结果 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 自动化 |  |  |  |  |  |
| API/接口 |  |  |  |  |  |
| AIDA CLI |  |  |  |  |  |
| Report Skill/MCP/Agent |  |  |  |  |  |
| Digest/报告 |  |  |  |  |  |
| Token/Session |  |  |  |  |  |
| Web 浏览器 |  |  |  |  |  |

生产验收账号必须使用生产测试账号，不得使用个人业务账号。测试账号、Session、Run、Report、请求时间和错误码必须可追溯。

## 九、回滚与停止条件

必须分别填写 API、Web、CLI、Skill/MCP/Agent、migration、数据回填和数据清理的回滚方式。

出现以下任一情况立即停止：

- 关键 API 持续 5xx；
- 数据对账不一致；
- migration、锁等待或连接池异常；
- Digest、报告、MCP 或旧客户端主链路回归；
- CLI 产物、版本、地址或 SHA256 不一致；
- 无法确认数据或配置的恢复边界。

migration 已执行后不得直接 DROP、TRUNCATE 或删除生产数据；优先使用 forward fix。

## 十、最终结果

文档末尾必须填写：

```text
发布范围已完整列出：是 / 否
发布项执行结果已记录：是 / 否
发布后验收已完成：是 / 否
阻断项数量：
最终状态：已发布 / 未发布 / 阻断 / 已回滚
```

最终状态为“已发布”前，所有发布项必须有实际结果和证据。未完成项必须列出后续动作，不得写成“完成”。

## 十一、禁止事项

- 不把对话过程、争论、情绪、解释或道歉写入发布文档；
- 不用“已处理”“已部署”“正常”替代版本、命令、状态码或运行证据；
- 不把测试服地址、凭据、CLI 产物带入生产发布；
- 不把未确认的假设写成已完成事实；
- 不因为补充一个遗漏项而扩展无关架构、策略或长期规划；
- 不修改长期部署手册来记录单次版本、镜像、备份或执行结果。
