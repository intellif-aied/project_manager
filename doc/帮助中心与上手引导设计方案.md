# 帮助中心与上手引导设计方案

## 结论

当前项目不建议做传统的“首次登录强制弹窗 + 多步骤遮罩引导”。这种方式容易打断用户，且用户在没有真实任务上下文时很难记住操作。

更合适的形态是：

1. 帮助中心：用户随时可打开，承载完整使用指南和常见问题。
2. 上手清单：首次登录时以轻量卡片展示，按角色给出 3-5 个关键动作。
3. 上下文帮助：在页面、空状态、禁用按钮、权限失败等场景给出就地解释。

整体目标不是“做一个文档站”，而是让用户在真实工作流里能快速知道下一步怎么做、为什么不能做、出问题怎么处理。

## 设计原则

- 不强制打断：首次登录不弹大遮罩，不强制用户点完所有步骤。
- 按角色展示：员工、TL、PM、总监、管理员看到的上手任务不同。
- 就地解释优先：能在按钮、空状态、表单旁解释的问题，不让用户再去翻文档。
- 短内容优先：文档以“如何完成一个动作”为单位，不写大段系统说明书。
- 一期轻量实现：先用前端静态配置和少量本地状态，不引入复杂 CMS。
- 可持续扩展：后续可以升级为后台配置、搜索、AI 问答或行为推荐。

## 信息架构

### 一级入口

建议在 Header 右侧增加一个帮助入口，使用问号图标或“帮助”图标按钮，位置靠近用户菜单。

入口点击后打开右侧 Drawer，不建议第一期新增左侧一级菜单。原因：

- 帮助是辅助能力，不应和核心业务模块平级。
- Drawer 可以保留用户当前页面上下文。
- 用户看完帮助后能直接回到当前操作。

### 帮助中心结构

帮助中心 Drawer 建议分为三个区域：

1. 当前页面帮助
2. 上手清单
3. 全部指南

“当前页面帮助”根据当前路由自动切换内容。例如：

- `/dashboard`：工作台指标、风险、快捷入口说明
- `/requirements`：需求、任务、权限、负责人、验收标准说明
- `/reports/daily`：日报生成、确认、编辑说明
- `/reports/weekly`：周报范围、汇总口径说明
- `/ai-assets`：Agent、Skill、MCP、定时任务、运行历史说明
- `/tokens`：Token 用量统计口径说明

“全部指南”建议按照任务分类：

- 快速开始
- 需求与任务
- 日报与周报
- AI 资产
- Token 用量
- 权限与角色
- 常见问题

## 上手清单设计

### 展示方式

首次登录后不弹 modal，建议在工作台顶部或右侧展示轻量卡片。

卡片标题建议：

- 完成你的工作台初始化
- 3 分钟了解 Aida 工作台
- 开始使用 Aida

卡片应支持：

- 标记完成
- 暂时收起
- 不再显示
- 从帮助中心重新打开

### 角色化清单

#### 工程师 employee

- 查看分配给我的任务
- 更新一次任务进度
- 查看或填写今日日报
- 查看我的 Token 用量
- 了解为什么有些任务不能改负责人

#### 团队负责人 team_leader

- 查看小组需求和风险
- 给小组成员创建或分配任务
- 查看小组日报
- 生成或检查小组周报
- 了解跨团队需求创建规则

#### 产品经理 pm

- 创建跨团队需求
- 查看需求进度和阻塞风险
- 跟进任务负责人和验收标准
- 查看日报/周报汇总
- 查看 AI Agent 生成结果

#### 部门总监 director

- 查看部门风险和跨团队进展
- 查看小组日报/周报汇总
- 查看 Token 用量趋势
- 检查重点需求状态

#### 管理员 admin

- 管理组织成员和角色
- 检查用户权限
- 查看 AI 资产配置
- 了解系统内置 Agent / Skill / MCP

## 上下文帮助设计

上下文帮助是一期最值得优先做的部分。

### 禁用按钮提示

所有关键按钮 disabled 时应说明原因。例如：

- 不能运行 Agent：缺少模型、缺少必填变量、缺少凭证
- 不能编辑负责人：当前角色不能重新分配任务
- 不能创建任务：需求已取消或不在当前团队范围
- 不能生成报告：缺少报告 Agent 或 MCP 配置

提示方式：

- 按钮外层 Tooltip
- 表单项 help 文案
- 空状态中的操作建议

### 权限失败提示

接口返回 403 时，不跳转 403 页面。建议按业务场景给出清晰 toast：

- 当前账号没有修改负责人权限
- 当前账号不能编辑该需求
- 当前账号不能管理该定时任务
- 当前账号不能访问该资源

如果用户已经能访问页面，只是某个动作没有权限，应停留在当前页面并提示原因。

### 空状态提示

空状态不要只写“暂无数据”，应告诉用户下一步。

示例：

- 暂无任务：你可以从需求详情中创建任务，或等待团队负责人分配。
- 暂无日报：今日还没有生成日报，可以手动填写或使用报告 Agent 生成。
- 暂无 Agent：你可以创建自定义 Agent，或使用系统报告 Agent。
- 暂无运行历史：运行 Agent 后会在这里显示执行记录。

## 帮助内容清单

一期建议先写 12 篇短文档，每篇控制在 300-800 字。

### 快速开始

1. Aida 工作台能做什么
2. 五类角色权限说明
3. 首次登录后应该先看哪里

### 需求与任务

4. 如何创建需求
5. 如何创建和分配任务
6. 为什么我不能修改负责人
7. 如何更新任务进度和状态

### 日报与周报

8. 如何生成个人日报
9. TL / 总监如何查看小组或部门报告
10. 报告由 Agent 生成后如何确认和编辑

### AI 资产

11. Agent、Skill、MCP 分别是什么
12. 定时任务和运行历史如何查看

### Token 用量

13. Token 用量统计口径说明

可以根据一期排期先做 8-10 篇，后续补齐。

## 一期功能范围

### 必做

- Header 右侧增加帮助入口。
- 帮助中心 Drawer。
- 当前页面帮助内容根据路由切换。
- 角色化上手清单。
- 上手清单可关闭。
- 任务、需求、AI 资产中的关键 disabled 操作补齐 Tooltip 或表单 help。
- 403 动作失败保持当前页面，只给明确中文提示。

### 可选

- 帮助内容搜索。
- 上手清单进度百分比。
- 每篇帮助文档的“相关页面”跳转。
- 在帮助中心展示最近访问过的帮助内容。

### 暂不做

- 独立帮助文档后台管理。
- 富文本编辑器。
- AI 问答式帮助。
- 复杂用户行为埋点推荐。
- 强制新手遮罩 tour。

## 技术实现建议

### 前端结构

建议新增一个轻量 feature：

```text
web/src/features/aidashboard/help/
  components/
    HelpDrawer.tsx
    HelpEntryButton.tsx
    OnboardingChecklist.tsx
    ContextHelp.tsx
  data/
    helpArticles.ts
    onboardingChecklists.ts
    routeHelpMap.ts
  types.ts
```

`Header.tsx` 中接入 `HelpEntryButton`。

`HelpDrawer` 可以放在 `MainLayout` 或 Header 内部，建议先放 Header 内部，状态更简单。

### 数据结构

帮助文档一期使用 TypeScript 静态配置：

```ts
type HelpArticle = {
  id: string;
  title: string;
  category: string;
  roles?: UserRole[];
  routes?: string[];
  summary: string;
  content: ReactNode | string;
};
```

上手清单使用静态配置：

```ts
type OnboardingItem = {
  id: string;
  title: string;
  description?: string;
  route?: string;
  roles: UserRole[];
};
```

### 状态存储

一期可以先用 localStorage：

- `aida_help_drawer_seen`
- `aida_onboarding_dismissed`
- `aida_onboarding_completed_item_ids`

如果后续需要跨设备同步，再增加后端用户偏好表：

```text
user_preferences
- user_id
- key
- value_json
- updated_at
```

### 权限与内容过滤

帮助内容按角色过滤：

- `roles` 为空：所有角色可见
- `roles` 有值：只展示给匹配角色

当前页面帮助按路由匹配：

- 精确路径优先
- 菜单父级路径兜底
- 无匹配时展示通用帮助

## 视觉方案

### 帮助入口

Header 右侧使用小图标按钮，不建议使用大文字按钮。

建议：

- 图标：`QuestionCircleOutlined`
- Hover tooltip：`帮助中心`
- 点击打开右侧 Drawer

### 帮助中心 Drawer

宽度建议：

- 桌面端：420-480px
- 移动端：100% 宽度

布局：

- 顶部：标题 + 搜索框或当前页面说明
- 中部：当前页面帮助
- 中部：上手清单
- 底部：全部指南分类

### 上手清单卡片

工作台中的上手清单不应过大，建议 3-5 行任务，完成后自动收起或弱化展示。

视觉上要和现有 Dashboard 卡片一致，不做营销式 hero。

## 与现有模块的关系

### 工作台

工作台适合承载首次上手清单，因为用户登录后默认进入这里。

建议将上手清单作为一块可关闭的小模块，而不是替代当前工作台核心内容。

### 需求看板

重点补上下文帮助：

- 新建需求权限
- 跨团队需求说明
- 任务负责人不可修改原因
- 验收标准填写建议
- 任务状态和进度关系

### 日报/周报

重点解释：

- 报告生成范围
- Agent 生成和人工编辑的关系
- TL、总监看到的汇总口径

### AI 资产

重点解释：

- Agent / Skill / MCP 的区别
- 模型 ID 为什么必填
- 凭证由谁提供
- 定时任务运行失败怎么看

### Token 用量

重点解释：

- 统计口径
- 时间范围
- 用户、小组、任务关联关系

## 分期计划

### 第一期：轻量上线

目标：让用户能找到帮助，关键操作能解释清楚。

范围：

- Header 帮助入口
- 帮助中心 Drawer
- 路由级当前页面帮助
- 角色化上手清单
- 关键 disabled tooltip
- 403 动作提示中文化

不引入后端表，不做后台配置。

### 第二期：体验增强

目标：减少重复咨询，提升自助解决能力。

范围：

- 帮助搜索
- 文档关联页面跳转
- 完成状态跨设备同步
- 常见错误码说明
- 更完整的 FAQ

### 第三期：智能帮助

目标：根据用户当前页面和问题提供即时答案。

范围：

- AI 问答式帮助
- 根据当前页面和用户角色推荐文档
- 根据接口错误自动推荐解决方案
- 后台可配置帮助内容

## 验收标准

一期完成后应满足：

1. 用户可以从 Header 打开帮助中心。
2. 用户在不同页面看到不同的当前页面帮助。
3. 不同角色看到不同的上手清单。
4. 上手清单可以关闭，刷新后不会反复打扰。
5. 关键禁用按钮能说明原因。
6. 接口 403 不跳页面，保留当前操作上下文并展示中文提示。
7. 帮助中心在移动端可正常打开和关闭。
8. 不影响现有菜单、权限和业务接口。

## 推荐命名

产品命名建议：

- 帮助入口：帮助中心
- 首次登录引导：上手清单
- 文档分类：使用指南

不建议使用：

- 新手教程
- 新手村
- 操作手册
- 文档模块

“帮助中心 + 上手清单”会比“帮助文档 + 首次登录引导”更轻，也更符合当前平台的企业级工作台定位。
