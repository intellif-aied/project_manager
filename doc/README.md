# Aida 文档导航

`doc/` 只保留当前入口、V2 文档和 V1 历史归档，不保存测试执行结果、回归报告、截图或临时数据库备份索引。

## 核心文档
- [生产部署与发布流程](Aida部署与运维基准.md)：源码构建、镜像推送、生产升级、回滚与 CLI 发布操作。

- [系统资源 Skill + MCP 管理文档](系统资源skill+mcp管理文档.md)：系统级 Skill、MCP、默认 Agent 及版本管理规则。该文档直接保留在 `doc/` 根目录。
- [V2 文档](v2/)：当前产品、架构、开发、测试方案、发布流程和 Bug 修复方案。
- [V1 历史文档](v1/)：旧版需求、架构、测试方案、原型、部署说明及阶段性材料，仅供追溯。
- [运营中心方案](../v2/doc/运营/)：独立维护的 V2 运营中心方案，不与 `doc/v2/` 建立实现依赖。

## 目录规则

```text
doc/
├── README.md
├── 系统资源skill+mcp管理文档.md
├── v1/
└── v2/
```

后续文档按以下规则维护：

1. 当前 V2 产品、架构、开发、测试方案统一放入 `doc/v2/<主题>/`；
2. V1 或已经停止演进的历史材料放入 `doc/v1/`；
3. 测试方案和测试用例可以保留，测试执行结果、验收报告、回归报告、截图和 JSON 结果不提交到 `doc/`；
4. 临时测试产物写入 `tmp/` 或外部制品目录，并由测试任务自行清理；
5. 系统资源 Skill/MCP 管理规则修改后，必须同步核对 Managed Agent 平台中实际生效的 owner、slug、version 和内容；
6. 文档移动或改名时同步修正仓库入口链接，避免继续引用旧路径。

## 阅读优先级

1. 先阅读本页和 `系统资源skill+mcp管理文档.md`；
2. 开发 V2 功能时，以对应的 `doc/v2/` 主题文档为准；
3. 只有在追溯旧业务背景时才读取 `doc/v1/`，不得从 V1 文档自动恢复或扩展当前需求。
