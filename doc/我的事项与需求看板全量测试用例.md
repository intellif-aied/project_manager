# 我的事项与需求看板全量测试用例

适用范围：`/dashboard`、`/requirements`

测试目标：

- 验证“我关注的、我负责的、我创建的”不再混用同一个关注概念。
- 验证创建需求、设置负责人、创建任务、设置执行人不会自动写入关注。
- 验证 Dashboard“我的事项”和需求看板范围筛选在 PM、总监、TL、员工 4 类角色下可用。
- 验证手动关注仍会进入关注列表，并参与关注度评分。

测试账号：

- 使用 `doc/测试账号文档.md`。
- PM：t01 / uid 303
- 总监：t02 / uid 304
- TL：t03 / uid 305，小组A
- 员工：t05 / uid 307，小组A

## 一、核心定义

1. 我的事项 = 我关注的 + 我负责的 + 我创建的。
2. 我关注的 = 用户主动点击星标写入 `user_follows`。
3. 我负责的 = 需求负责人包含当前用户，或任务执行人为当前用户。
4. 我创建的 = 需求创建者为当前用户，或任务创建者为当前用户。
5. 关注度 = 主动关注人的角色权重累计，不包含创建者、负责人、执行人关系。

## 六、建议自动化冒烟脚本

每次改完至少执行：

```bash
cd /home/intellif/dev/project_manager/api
go test ./...

cd /home/intellif/dev/project_manager/web
PATH=/home/intellif/.nvm/versions/node/v20.20.1/bin:$PATH ./node_modules/.bin/tsc --noEmit
```

建议接口冒烟：

1. 用 PM 创建临时需求，断言 `/follows` 未新增。
2. 用 PM 查 `/dashboard/my-items`，断言临时需求 `createdByMe=true`、`followedByMe=false`。
3. 给临时需求指定 TL，断言 TL `/dashboard/my-items` 有该需求且 `assignedToMe=true`。
4. 创建任务指定员工，断言员工 `/dashboard/my-items` 有该任务且 `assignedToMe=true`。
5. 手动关注需求，断言 `followedByMe=true` 且关注度提升。
6. 取消关注，断言仍可因创建/负责留在我的事项，但不再属于关注筛选。
7. 删除临时任务和需求。

建议 Playwright 截图：

- PM：`/dashboard`
- PM：`/requirements?view=tree&scope=mine`
- PM：`/requirements?view=tree&scope=followed`
- TL：`/requirements?view=tree&scope=assigned`
- 员工：`/requirements?view=tree&scope=assigned`

## 七、上线前风险检查

1. 历史 `user_follows` 里已有自动关注数据，本次代码不会自动清理。
2. 如果要让历史关注度也完全恢复语义，需要单独确认清理策略。
3. 清理历史前，先导出 `user_follows` 备份。
4. 如果生产环境都是测试数据，可以考虑上线前清空 `user_follows` 后重新手动关注验证。
