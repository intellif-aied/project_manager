# Aida 平台使用说明书

这是一份面向日常用户的快速上手说明。先看流程，再按需要进入对应模块。

## 1. 登录入口

生产地址：

```text
http://113.100.143.91:9180
```

使用公司分配的账号密码登录。不同角色看到的数据范围不同：

| 角色 | 主要使用重点 |
| --- | --- |
| 员工 | 我的任务、日报、AI 使用记录 |
| 小组负责人 | 小组任务、成员进展、阻塞风险 |
| PM | 需求推进、任务拆解、交付风险 |
| 总监 | 部门进度、重点风险、日报周报 |
| 管理员 | 用户、角色、小组、权限 |

## 2. 每天怎么用

建议按这个顺序使用：

1. 打开「工作台」，先看今天的重点事项、风险和进度。
2. 进入「需求看板」，确认需求阶段、任务完成度和阻塞。
3. 进入「日报」或「周报」，补充当天/本周工作总结。
4. 需要 AI 自动处理时，进入「AI 资产」运行 Agent。
5. 需要看 AI 消耗时，进入「Token 用量」查看统计。

## 3. 工作台

工作台是首页，用来快速判断当前是否有需要处理的事情。

你主要看三类信息：

- 需求和任务是否正常推进。
- 是否有阻塞、临期或异常事项。
- 自己或团队近期的 AI 使用情况。

如果不知道先处理什么，优先处理工作台上标出的风险和临期事项。

## 4. 需求看板

需求看板是项目推进的主入口。一个需求从提出、评审、执行到完成，都应该在这里维护。

常用操作：

- 「新建需求」：填写标题、描述、负责人、优先级、截止时间和验收标准。
- 「添加任务」：在需求详情里把需求拆成可执行任务。
- 「更新阶段」：按实际情况把需求调整为待开始、评审、进行中、已完成或已取消。
- 「关注需求」：对重点需求点关注，后续更容易追踪。

使用建议：

- 需求标题写清楚业务目标。
- 任务标题写清楚交付物。
- 有前后依赖时，给任务设置上游依赖。
- 遇到卡住的任务，及时标记为阻塞。

## 5. 任务

任务是需求落地的执行单位。

你需要维护：

- 状态：待办、进行中、阻塞、完成。
- 进度：按实际完成情况更新。
- 负责人：确保每个任务有人负责。
- 验收标准：说明什么情况下算完成。

如果保存时提示“版本冲突”，说明别人刚刚更新过同一条数据。刷新页面后再修改即可。

## 6. 日报和周报

日报用于记录当天工作，周报用于总结一周进展。

建议填写内容：

- 已完成事项。
- 正在推进事项。
- 遇到的阻塞或风险。
- 下一步计划。

小组负责人和总监可以查看更大范围的日报/周报，用来发现团队风险和协作问题。

## 7. AI 资产

AI 资产用于管理和运行 Agent、Skill、MCP 和定时任务。

常见页签：

| 页签 | 用途 |
| --- | --- |
| 我的 Agents | 查看、编辑、运行自己的 Agent |
| 我的 Skills | 管理 Agent 可使用的 Skill |
| 我的 MCP | 管理 Agent 可调用的工具服务 |
| 定时任务 | 设置 Agent 自动执行 |
| 运行历史 | 查看最近执行结果 |

推荐流程：

1. 先确认需要的 Skill 或 MCP 是否已存在。
2. 新建或编辑 Agent，绑定需要的能力。
3. 手动运行一次，确认输出结果。
4. 确认稳定后，再创建定时任务。

如果看到「Managed Agent 平台未配置」，说明后端 Agent 平台连接信息还没配置好，需要联系管理员。

## 8. Aida 命令行客户端

需要在本机终端使用 Aida 时，按系统安装：

Windows PowerShell：

```powershell
Invoke-RestMethod http://113.100.143.91:9180/statics-live/aida/install.ps1 | Invoke-Expression
```

Linux：

```bash
curl -fsSL http://113.100.143.91:9180/statics-live/aida/install.sh | bash
```

macOS：

```bash
curl -fsSL http://113.100.143.91:9180/statics-live/aida/install.sh | bash
```

安装后如果提示找不到 `aida` 命令，关闭终端重新打开一次。

## 9. Token 用量

Token 用量用于查看 AI 使用消耗。

你可以用它确认：

- 最近 AI 调用了多少。
- 个人或团队用量是否异常。
- 是否有 Agent 或定时任务产生了高消耗。

## 10. 组织成员

只有管理员能看到「组织成员」。

管理员可以在这里配置用户角色、小组、负责人和 Aida 访问权限。

如果用户能登录账号系统，但进不了 Aida，通常需要管理员检查该用户是否已加入 Aida，并且是否启用了 Aida 权限。

## 11. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| 登录失败 | 确认账号密码；仍失败则联系管理员 |
| 看不到菜单 | 通常是角色权限不足，联系管理员确认 |
| 保存提示冲突 | 刷新页面后重新编辑 |
| Agent 无法运行 | 检查平台配置、凭据、Skill/MCP 绑定 |
| 日报数据不完整 | 先检查需求和任务是否及时维护 |
| Token 用量异常 | 检查最近的 Agent 运行和定时任务 |

## 12. 只记住三件事

1. 每天先看「工作台」。
2. 工作推进以「需求看板」和「任务」为准。
3. AI 能力在「AI 资产」，消耗看「Token 用量」。
